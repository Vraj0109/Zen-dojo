## Clarify first
- How are the input lists structured? They are k sorted singly linked lists (or arrays representing linked lists).
- Can any of the k lists be empty? Yes, some or all lists may be empty.
- What if k is 0? The function should return null (or an empty list).
- Are node values within standard 32-bit integer limits? Yes, values range from -10000 to 10000.

## Examples to say out loud
- Consider lists `[[1, 4, 5], [1, 3, 4], [2, 6]]`.
  - Heads are `1, 1, 2`. The minimum is `1`.
  - Advance the first list to `4`. Remaining heads are `4, 1, 2`. Smallest is `1`.
  - Advance that list to `3`. Smallest is `2`.
  - Merged output: `1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6`.
- Edge cases:
  - Input `[]`: returns null.
  - Input `[[]]`: returns null.

## Brute force
A brute force approach traverses all k lists, dumps all N node values into a single array, sorts the array in O(N log N) time, and rebuilds a linked list. While straightforward, it ignores the preexisting sorted property of each individual list and requires O(N) extra space. Another naive approach merges lists one by one sequentially: merge list 1 with list 2, then with list 3, taking O(k * N) time in the worst case. We can optimize using a priority queue or divide-and-conquer to O(N log k).

## The key observation
At any given moment, the next node to append to the merged result is always the minimum among the current heads of the k lists. Maintaining the k current heads in a min-heap allows retrieving the smallest node and inserting its successor in O(log k) time. The heap never holds more than k elements at any point.

## Optimal approach
1. Initialize a min-heap (priority queue) ordered by node value. Store tuples of `(value, list_index, element_index)` (or direct `ListNode*` pointers).
2. For each non-empty list, push its head node into the min-heap.
3. Create a dummy head node and keep a tail pointer initialized to the dummy.
4. While the min-heap is not empty:
   - Pop the minimum node from the heap.
   - Append this node to `tail->next` and advance `tail`.
   - If the popped node has a successor in its original list, push that successor into the min-heap.
5. Return `dummy.next`.

Complexity:
- Time complexity: O(N log k) where N is the total number of nodes across all k lists. Each of the N nodes is pushed and popped from the min-heap of size at most k once.
- Space complexity: O(k) extra space for the min-heap storing at most one node per list at any time.

## Code walkthrough
- `priority_queue<tuple<int, int, int>, vector<tuple<int, int, int>>, greater<>> pq`: Maintains current head candidates ordered by smallest value.
- Initial loop: Pushes the first element of every non-empty list.
- `ListNode dummy(0); ListNode* tail = &dummy`: Anchors the resulting linked list to simplify appending.
- While loop: Pops the minimum element, appends a new node to `tail`, and if `j + 1 < lists[i].size()`, pushes the subsequent node into `pq`.
- Returns `dummy.next`.

## Test it out loud
- Test `lists = [[1, 4, 5], [1, 3, 4], [2, 6]]`:
  - Initial heap contains `(1, 0, 0), (1, 1, 0), (2, 2, 0)`.
  - Pop `(1, 0, 0)`, append 1, push `(4, 0, 1)`.
  - Pop `(1, 1, 0)`, append 1, push `(3, 1, 1)`.
  - Pop `(2, 2, 0)`, append 2, push `(6, 2, 1)`.
  - Correctly outputs ascending sequence `[1, 1, 2, 3, 4, 4, 5, 6]`.
- Test `lists = [[], []]`:
  - Heap remains empty; returns null immediately.

## Follow-ups
- Can this be solved with divide-and-conquer instead of a heap? Yes, pairing and merging lists two at a time like merge sort yields identical O(N log k) time and O(1) auxiliary space (iterative) or O(log k) call stack space.
- How would you handle merging streams when lists do not fit in memory? The min-heap approach excels in streaming external merge sort, as only one item per file/stream is held in memory.

## Common mistakes
- Comparing nodes without custom comparator when pushing raw pointer objects onto the priority queue.
- Not checking whether input lists or individual sublists are empty before accessing heads.
- Re-sorting all elements after each extraction instead of using a priority queue.
