## Clarify first
- How is the connectivity of cities represented? An n x n symmetric adjacency matrix `isConnected` where `isConnected[i][j] = 1` if cities `i` and `j` are directly connected, and 0 otherwise.
- What constitutes a province? A maximal connected component of cities that can reach one another either directly or transitively.
- Can a city form a province by itself? Yes, an isolated city with no external connections is counted as its own province.
- What are the constraints on n? `1 <= n <= 200`.

## Examples to say out loud
- Standard case: `isConnected = [[1,1,0],[1,1,0],[0,0,1]]`.
  - Cities 0 and 1 are connected to each other.
  - City 2 has no connections to 0 or 1.
  - Total provinces: 2.
- Completely disconnected: `[[1,0,0],[0,1,0],[0,0,1]]`.
  - 3 isolated cities, so 3 provinces.
- Fully connected: All entries are 1. Total provinces: 1.

## Brute force
A brute force or direct graph traversal starts a search (DFS or BFS) from each unvisited city. When starting a traversal from city `i`, it marks all transitively reachable cities as visited and increments the province count by 1. Checking the entire row of size n for each visited city takes O(n^2) time and O(n) space. Because the adjacency matrix contains n^2 entries, any full inspection is inherently O(n^2), which is already optimal.

## The key observation
The problem is mathematically equivalent to counting the number of connected components in an undirected graph given by an adjacency matrix.
We can either use depth-first search (DFS) with a visited array or Disjoint Set Union (DSU) starting with n disjoint sets, decrementing the set count on each successful union of connected city pairs `(i, j)`.

## Optimal approach
1. Initialize a boolean array `seen` of size `n` with all values set to false, and a counter `count = 0`.
2. Define a helper `dfs(u)`:
   - Mark `seen[u] = true`.
   - For each city `v` from 0 to `n - 1`:
     - If `isConnected[u][v] == 1` and `!seen[v]`: recursively call `dfs(v)`.
3. Iterate `i` from 0 to `n - 1`:
   - If `!seen[i]`:
     - Increment `count`.
     - Run `dfs(i)` to mark the entire component.
4. Return `count`.

Complexity:
- Time complexity: O(n^2) because we inspect every cell of the n x n matrix `isConnected` across all recursive calls.
- Space complexity: O(n) for the `seen` boolean array and the recursion call stack (at most n frames).

## Code walkthrough
- `vector<bool> seen(n, false)`: Tracks cities that have already been integrated into an identified province.
- `if (!seen[i]) { count++; dfs(isConnected, seen, i); }`: Discovers a new unvisited component, increments province count, and floods through all connected neighbors.
- `dfs(m, seen, u)`: Loops over all `v` from 0 to `n - 1`, branching when an edge `m[u][v] == 1` leads to an unvisited city.
- Returns `count`.

## Test it out loud
- Test `[[1, 1, 0], [1, 1, 0], [0, 0, 1]]`:
  - `i = 0`: unvisited. `count` becomes 1. `dfs(0)` marks 0 and 1.
  - `i = 1`: already seen.
  - `i = 2`: unvisited. `count` becomes 2. `dfs(2)` marks 2.
  - Loop finishes. Returns 2. Correct.
- Test `[[1]]`:
  - `i = 0`: `count = 1`, `dfs(0)` marks 0. Returns 1. Correct.

## Follow-ups
- How would you implement this with Disjoint Set Union (DSU)? Initialize parent array where `parent[i] = i` with `provinces = n`. For each pair `i < j`, if `isConnected[i][j] == 1`, union their sets. Each successful union reduces `provinces` by 1.
- When would DSU be preferred over DFS? DSU is preferred in dynamic connectivity scenarios where connections arrive as a stream of updates.

## Common mistakes
- Double counting components by forgetting to mark visited nodes before recurring.
- Trying to iterate only up to `u - 1` in the DFS neighbor loop, missing edges in directed or non-standard matrices.
- Allocating separate adjacency lists when traversing the existing matrix directly already suffices in O(n^2).
