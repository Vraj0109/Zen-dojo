## Clarify first
- What defines a bipartite graph? A graph whose vertices can be partitioned into two disjoint sets such that every edge connects a vertex in one set to a vertex in the other (no edge connects vertices within the same set).
- Can the graph have multiple disconnected components? Yes, and every component must be independently bipartite.
- Are self-loops or duplicate edges possible? No, the problem specifies no self-loops and no repeated neighbors in adjacency lists.
- What should be returned if a graph has isolated vertices or no edges? Isolated vertices do not violate bipartiteness; return true.

## Examples to say out loud
- Square (even cycle): `[[1,3],[0,2],[1,3],[0,2]]`.
  - Node 0 colored Red. Neighbors 1 and 3 colored Blue.
  - Node 2 is adjacent to 1 and 3, colored Red.
  - No edge connects vertices of the same color. Graph is bipartite. Output: true.
- Triangle (odd cycle): `[[1,2,3],[0,2],[0,1,3],[0,2]]`.
  - Subgraph `{0, 1, 2}` forms a 3-cycle.
  - Coloring 0 Red forces 1 and 2 to be Blue, but edge `(1, 2)` connects two Blue nodes. Output: false.

## Brute force
A brute force approach tests all `2^V` possible binary assignments of nodes into two sets. For each assignment, it iterates through all edges to check if any edge connects two nodes assigned to the same set. For V up to 100, `2^100` is impossible. We can determine bipartiteness in linear O(V + E) time using 2-coloring via Breadth-First Search or Depth-First Search.

## The key observation
A graph is bipartite if and only if it contains no odd-length cycles.
This property allows us to greedily color the graph using two colors (0 and 1):
- Pick an uncolored node, color it 0.
- Every neighbor must be assigned the opposite color `1 ^ color[u]`.
- If we encounter an already colored neighbor with the same color as the current node, an odd cycle exists and the graph cannot be bipartite.
Because the graph may be disconnected, we must loop through all vertices from 0 to `V - 1` to initiate the coloring process for every component.

## Optimal approach
1. Allocate an array `color` of size `n` initialized to -1 (indicating uncolored).
2. Loop through every vertex `s` from 0 to `n - 1`:
   - If `color[s] != -1`, it has already been colored; continue.
   - Set `color[s] = 0` and enqueue `s` into a BFS queue `q`.
   - While `q` is not empty:
     - Dequeue `u`.
     - For each neighbor `v` in `graph[u]`:
       - If `color[v] == -1`: set `color[v] = color[u] ^ 1` and enqueue `v`.
       - Else if `color[v] == color[u]`: a color conflict is detected; return false immediately.
3. If all components are successfully 2-colored without conflict, return true.

Complexity:
- Time complexity: O(V + E) where V is the number of vertices and E is the total number of undirected edges. Every vertex is enqueued once and each edge is examined twice.
- Space complexity: O(V) auxiliary space for the `color` array and the BFS queue.

## Code walkthrough
- `vector<int> color(n, -1)`: Tracks color assignments: `-1` (unvisited), `0` (color A), `1` (color B).
- Outer loop `for (int s = 0; s < n; s++)`: Ensures disconnected components and isolated vertices are handled.
- `color[v] = color[u] ^ 1`: Flips between 0 and 1 using bitwise XOR.
- `else if (color[v] == color[u]) return false`: Detects monochromatic edge (odd cycle) and returns false immediately.
- Returns true if all components pass.

## Test it out loud
- Test empty/isolated `[[]]`:
  - `color[0] = 0`, queue processes 0. No neighbors. Returns true. Correct.
- Test 2-node connected `[[1], [0]]`:
  - `s = 0`: `color[0] = 0`. Neighbor 1 gets `color[1] = 1`.
  - Queue empties. `s = 1` already colored. Returns true. Correct.
- Test 3-cycle `[[1,2], [0,2], [0,1]]`:
  - `color[0] = 0`.
  - Neighbors 1 and 2 get color 1.
  - From node 1, neighbor 2 has `color[2] == color[1] == 1`. Returns false. Correct.

## Follow-ups
- Can this be implemented with DFS instead of BFS? Yes, a recursive DFS passing the expected color achieves the same O(V + E) time complexity.
- How can Disjoint Set Union (DSU) be used to test bipartiteness? For each vertex `u`, union all its neighbors together into the same component. If `find(u) == find(v)` for any neighbor `v`, the graph is not bipartite.

## Common mistakes
- Running the search only from node 0 and failing to check disconnected components.
- Misinterpreting 1-based versus 0-based indices.
- Not returning false immediately upon encountering a color conflict.
