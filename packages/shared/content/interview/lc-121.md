## Clarify first

- Are we allowed to buy and sell on the same day? Buying and selling on the same day yields a profit of 0, which is equivalent to not trading.
- Can we complete multiple transactions? No, the problem specifies at most one buy and one sell, and you must buy before you sell.
- What if prices strictly decrease throughout the period? In that case, no positive profit can be made, so we should return 0.
- What are the input size bounds? The length of `prices` is between 1 and 100,000, with prices up to 10,000.

## Examples to say out loud

- Standard profitable case: `prices = [7, 1, 5, 3, 6, 4]`. The lowest price seen before day 4 is 1 (on day 1). Selling on day 4 at 6 gives a profit of `6 - 1 = 5`, which is the maximum achievable profit.
- Strictly decreasing case: `prices = [7, 6, 4, 3, 1]`. Every day is cheaper than the previous days. No trade yields positive profit, so we return 0.
- Single day edge case: `prices = [1]`. You cannot buy and sell on separate days, so return 0.

## Brute force

The brute-force solution evaluates every valid pair of days `(i, j)` where `i < j`. For each pair, we calculate `prices[j] - prices[i]` and record the maximum across all pairs, defaulting to 0 if all profits are negative. Because there are `n * (n - 1) / 2` pairs, this approach takes `O(n^2)` time and `O(1)` space. With `n = 100,000`, `n^2 = 10^{10}` operations, which will exceed typical interview time limits.

## The key observation

If we decide to sell on day `j`, our maximum profit is strictly determined by the minimum purchase price among all earlier days `0` through `j - 1`. As we iterate through the price list, we only need to maintain a running minimum of the prices observed so far, immediately comparing the current price against this minimum.

## Optimal approach

1. Initialize `low = infinity` (or `prices[0]`) to store the minimum price seen so far, and `best = 0` for the maximum profit.
2. Iterate through each price `p` in `prices`:
   a. Update `low = min(low, p)` to include the current day's price.
   b. Calculate potential profit `p - low` and update `best = max(best, p - low)`.
3. Return `best`.

Complexity:
- Time: `O(n)` because we iterate through the array of length `n` once, performing constant-time comparisons per element.
- Space: `O(1)` as we only maintain two scalar variables (`low` and `best`).

## Code walkthrough

In the reference implementation:
- `int low = INT_MAX, best = 0;`: tracks the cheapest buying opportunity seen so far and the best profit discovered.
- `low = min(low, p);`: updates the running minimum price.
- `best = max(best, p - low);`: updates maximum profit achievable by selling at price `p`.
- `return best;`: returns 0 if prices only decrease, or the highest profit found.

## Test it out loud

- `prices = [2, 4, 1]`:
  - Day 0 (`p = 2`): `low = 2`, `best = max(0, 2 - 2) = 0`.
  - Day 1 (`p = 4`): `low = 2`, `best = max(0, 4 - 2) = 2`.
  - Day 2 (`p = 1`): `low = min(2, 1) = 1`, `best = max(2, 1 - 1) = 2`.
  - Output is 2.
- `prices = [3, 2, 6, 5, 0, 3]`:
  - `p = 3`: `low = 3`, `best = 0`.
  - `p = 2`: `low = 2`, `best = 0`.
  - `p = 6`: `low = 2`, `best = 4`.
  - `p = 5`: `low = 2`, `best = 4`.
  - `p = 0`: `low = 0`, `best = 4`.
  - `p = 3`: `low = 0`, `best = max(4, 3 - 0) = 4`.
  - Output is 4.

## Follow-ups

- What if you are allowed to make as many transactions as you like (LeetCode 122)?
  Accumulate every positive price difference `prices[i] - prices[i - 1]` greedily in `O(n)` time and `O(1)` space.
- What if you are restricted to at most `k` transactions (LeetCode 188)?
  Use dynamic programming tracking buy and sell states for each transaction up to `k` in `O(n * k)` time.
- What if there is a transaction fee or cooldown day?
  Maintain state machine variables `hold`, `sold`, and `rest` updated day by day.

## Common mistakes

- Trying to sort the prices, which destroys the chronological order required for buying before selling.
- Updating `best` using a future minimum instead of the minimum strictly up to the current day.
- Initializing `best` to negative infinity and returning a negative value instead of 0 when prices only fall.
