## Clarify first
- What operators can appear in the expression? Only addition `+` and subtraction `-`, along with parentheses `(` and `)`.
- Can the expression have spaces or unary minus signs? Yes, spaces should be ignored, and unary minus can appear (e.g., `-2` or `-(2+3)`).
- Can numbers have multiple digits? Yes, numbers are non-negative integers parsed sequentially from digits.
- Is the expression guaranteed to be syntactically valid? Yes, valid parenthesis nesting and operator placement are guaranteed.

## Examples to say out loud
- Standard case: `"1 + 1"` evaluates to 2.
- With parenthesis and negation: `"(1+(4+5+2)-3)+(6+8)"`. Evaluating the inner addition `4+5+2 = 11`, adding 1 and subtracting 3 gives `9`. Adding `6+8 = 14` produces `23`.
- Unary minus with parenthesis: `"-(2 + 3)"`. Starting running total at 0, applying sign -1 to the grouped sum 5 produces `-5`.

## Brute force
A naive approach parses parentheses recursively: find the innermost balanced parentheses, compute the subexpression, replace the parenthesis span with the calculated number string, and repeat. Alternatively, building an abstract syntax tree or full Dijkstra shunting-yard algorithm to evaluate reverse Polish notation works, but carries overhead and requires handling unary negations explicitly. We can evaluate the expression in a single pass using a stack to preserve running contexts.

## The key observation
Since only addition and subtraction are present, operator precedence is flat; parentheses are the only grouping mechanism. An opening parenthesis `(` saves the accumulated result and the preceding sign onto a stack, then resets the accumulator to 0 with positive sign. A closing parenthesis `)` completes the current subtotal, applies the popped sign, and adds the popped previous accumulator.

## Optimal approach
1. Maintain running variables: `res = 0` (current scope total), `num = 0` (current number being read), and `sign = 1` (+1 for addition, -1 for subtraction).
2. Use a stack to hold pairs of previous results and signs upon encountering parentheses.
3. Iterate through each character `c` in the string:
   - If `c` is a digit: update `num = num * 10 + (c - '0')`.
   - If `c` is `+` or `-`: add `sign * num` to `res`, reset `num = 0`, and set `sign` to `1` or `-1`.
   - If `c` is `(`: push `res` and `sign` onto the stack, then reset `res = 0` and `sign = 1`.
   - If `c` is `)`: fold `sign * num` into `res`, reset `num = 0`. Pop the saved sign and previous accumulator from the stack, and update `res = prev + saved_sign * res`.
4. After scanning, add the remaining `sign * num` to `res` and return `res`.

Complexity:
- Time complexity: O(n) where n is the length of string `s`, as each character is processed exactly once.
- Space complexity: O(n) in the worst case to store stacked contexts for deeply nested parentheses.

## Code walkthrough
- `if (isdigit(c)) num = num * 10 + (c - '0');`: Accumulates multi-digit integers.
- `else if (c == '+' || c == '-')`: Commits the pending number into `res` using the active `sign`, resets `num`, and sets the new `sign`.
- `else if (c == '(')`: Saves current scope: pushes `res` then `sign`, resetting `res = 0, sign = 1` for the nested scope.
- `else if (c == ')')`: Commits inner number, pops `saved_sign` and `prev_res`, then sets `res = prev_res + saved_sign * res`.
- Final `res += sign * num`: Captures the trailing operand.

## Test it out loud
- Test `" 2-1 + 2 "`:
  - Spaces are ignored.
  - Read `2`, hit `-`: `res = 0 + 1 * 2 = 2`, `sign = -1`.
  - Read `1`, hit `+`: `res = 2 + (-1) * 1 = 1`, `sign = 1`.
  - Read `2`, loop ends: `res = 1 + 1 * 2 = 3`. Correct.
- Test `"-(2 + 3)"`:
  - Hit `-`: `res = 0`, `sign = -1`.
  - Hit `(`: push `res = 0`, push `sign = -1`. Reset `res = 0, sign = 1`.
  - Inner computation: `2 + 3 = 5`.
  - Hit `)`: `res = 5`. Pop sign `-1`, pop prev `0`. New `res = 0 + (-1) * 5 = -5`. Correct.

## Follow-ups
- How would you support multiplication and division? Use an operator stack or evaluate high-precedence operations immediately with the last parsed number before pushing onto a sum stack.
- Can this handle unary plus and minus consistently without special edge case checks? Yes, because initializing `res = 0` ensures unary operations behave as `0 - x` or `0 + x`.

## Common mistakes
- Forgetting to commit the last parsed `num` after exiting the iteration loop.
- Resetting `sign` incorrectly after popping from the stack upon closing parentheses.
- Failing to handle multi-digit numbers or whitespace properly.
