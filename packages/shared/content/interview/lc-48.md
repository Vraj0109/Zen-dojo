## Clarify first
- Is the matrix always square? Yes, the matrix is n x n.
- In what direction must the rotation happen? 90 degrees clockwise.
- Can we allocate a new matrix and copy the values? The goal is to rotate the matrix in place using O(1) auxiliary space.
- What are the dimensions constraints? n is between 1 and 20.

## Examples to say out loud
- Consider a 3x3 matrix:
  ```
  [1, 2, 3]
  [4, 5, 6]
  [7, 8, 9]
  ```
  - Transposing along the main diagonal swaps `a[i][j]` with `a[j][i]`:
    ```
    [1, 4, 7]
    [2, 5, 8]
    [3, 6, 9]
    ```
  - Reversing each row horizontally gives:
    ```
    [7, 4, 1]
    [8, 5, 2]
    [9, 6, 3]
    ```
- Edge case: A 1x1 matrix `[[7]]` remains `[[7]]`.

## Brute force
A simple approach creates a new n x n matrix `result` where each cell `matrix[i][j]` maps to `result[j][n - 1 - i]`, taking O(n^2) time and O(n^2) auxiliary memory. To satisfy the in-place constraint with O(1) extra memory, we can either perform a 4-way cyclical swap of elements along concentric rings, or decompose the rotation into two elementary linear algebra operations: transposition followed by row reversal.

## The key observation
Rotating a matrix 90 degrees clockwise moves cell `(i, j)` to `(j, n - 1 - i)`. This coordinate mapping is algebraically equivalent to transposing the matrix (swapping `(i, j)` to `(j, i)`), followed by reflecting the matrix horizontally across its vertical centerline (swapping `(j, i)` to `(j, n - 1 - i)`). Both transformations are cleanly executed in place.

## Optimal approach
1. Transpose the matrix: iterate row `i` from 0 to `n - 1`, and column `j` from `i + 1` to `n - 1`, swapping `matrix[i][j]` with `matrix[j][i]`.
2. Reverse each row: for each row `i` from 0 to `n - 1`, reverse the elements from index 0 to `n - 1` using two pointers moving inward.
3. Return the modified matrix in place.

Complexity:
- Time complexity: O(n^2) since transposing visits n*(n-1)/2 pairs and reversing each row performs n * (n / 2) swaps, making exactly one pass over all cells.
- Space complexity: O(1) auxiliary space as all modifications are performed in place using constant temporary variables.

## Code walkthrough
- `for (int i = 0; i < n; i++) for (int j = i + 1; j < n; j++) swap(a[i][j], a[j][i])`: Transposes elements strictly above the main diagonal with their symmetric counterparts below the diagonal.
- `for (auto& row : a) reverse(row.begin(), row.end())`: Reverses each row horizontally to complete the clockwise turn.
- Returns `a`.

## Test it out loud
- Test 2x2 matrix `[[1, 2], [3, 4]]`:
  - Transpose swaps (0,1) and (1,0): `[[1, 3], [2, 4]]`.
  - Reverse row 0: `[3, 1]`. Reverse row 1: `[4, 2]`. Result: `[[3, 1], [4, 2]]`. Correct.
- Test 1x1 matrix `[[7]]`:
  - Transpose inner loop does not run (`j = 1 < 1` is false).
  - Reverse row leaves `[7]`. Result: `[[7]]`. Correct.

## Follow-ups
- How would you rotate 90 degrees counter-clockwise? Either reverse each row first then transpose, or transpose along the main diagonal and then reverse each column vertically.
- How would you rotate 180 degrees? Reverse each row, then reverse the order of rows vertically (or reverse the entire flattened sequence).

## Common mistakes
- Running column loop from `j = 0` to `n - 1` during transposition, which swaps elements twice and reverts the matrix back to its original state.
- Attempting 4-way ring rotations but making index arithmetic mistakes when mapping ring offsets.
