## Clarify first

- What characters can the string contain? (Lowercase English letters and parentheses `'('` and `')'`).
- What if the input string is already valid? (Return a list containing the original string unchanged).
- What should be returned if no valid parentheses remain? (Return `[""]` or the string with all parentheses stripped, retaining any letters).
- Can the result list contain duplicate strings? (No, all returned strings must be unique).
- What are the length constraints? ($1 \le s.length \le 25$, with at most 20 parentheses).

## Examples to say out loud

- Single excess closing parenthesis: `s = "()())()"`. Removing the 4th char `')'` yields `"(())()"`; removing the 5th char `')'` yields `"()()()"`. Both are minimal (1 removal) and valid.
- Inverted single pair: `s = ")("`. Cannot pair them; must remove both `')'` and `'('`, resulting in `[""]`.
- Letters present: `s = "(a)())()"`. Characters like `'a'` are never removed and stay in their positions. Result is `["(a())()", "(a)()()"]`.

## Brute force

A naive approach generates all $2^n$ subsequences of $s$, tests each subsequence for parenthesis validity, and keeps only the valid ones with maximum length. For $n = 25$, $2^{25} \approx 3.3 \times 10^7$ substrings. Testing validity on each takes $O(n)$, which is too slow and produces massive duplicates when identical consecutive parentheses are removed.

## The key observation

We can determine the exact minimum number of left parentheses $remL$ and right parentheses $remR$ that must be removed in a single $O(n)$ pre-pass:
- Scan left to right; increment balance for `'('`. If `')'` occurs when balance is 0, increment $remR$. Otherwise decrement balance. At the end, any remaining balance equals $remL$.
With exact removal quotas $remL$ and $remR$, backtracking only explores paths that delete up to $remL$ left and $remR$ right brackets. To avoid duplicate valid strings during backtracking, whenever consecutive identical brackets appear (e.g. `(((`), we branch on how many to remove in a single step rather than permuting individual deletions.

## Optimal approach

1. Pre-calculate the exact removals required:
   - Initialize `remL = 0, remR = 0`.
   - For character `c` in `s`:
     - If `c == '('`: increment `remL`.
     - Else if `c == ')'`: if `remL > 0`, decrement `remL`; otherwise increment `remR`.
2. Define a backtracking function `dfs(s, idx, open, remL, remR, cur)`:
   - Base case: If `idx == s.size()`:
     - If `open == 0`, `remL == 0`, and `remR == 0`, append `cur` to result list `res`.
     - Return.
   - If current character `c` is a parenthesis that can be removed (`c == '('` and `remL > 0` or `c == ')'` and `remR > 0`):
     - Count consecutive identical brackets from `idx` up to $j$.
     - Loop $k$ from 1 to $\min(rem, count)$: recurse by skipping $k$ brackets and reducing removal allowance by $k$.
   - Branch by keeping the current character:
     - If `c == '('`: append `c`, recurse with `open + 1`, then pop.
     - If `c == ')'`: if `open > 0`, append `c`, recurse with `open - 1`, then pop. (Prunes invalid prefixes).
     - If `c` is a letter: append `c`, recurse with `open`, then pop.
3. De-duplicate and sort results (or collect in a set), returning `res`.

Complexity:
- Time: `O(2^(L + R) * n)` where $L = remL$ and $R = remR$ ($L + R \le 20$). Pruning invalid prefixes and grouping duplicate deletions reduces actual calls to a few hundred.
- Space: `O(n)` auxiliary space for the recursion call stack and current string buffer.

## Code walkthrough

In the reference implementation:
- `remL` and `remR` loop: calculates minimal misaligned bracket counts upfront.
- `int count = j - idx; for (int k = 1; k <= min(remL, count); k++)`: groups identical adjacent parentheses to eliminate redundant permutations.
- `if (open > 0) dfs(..., open - 1, ...)`: strictly forbids adding a `')'` when `open == 0`, cutting off invalid branches early.
- `cur.push_back(c); ... cur.pop_back();`: builds candidates in-place without copying strings across recursive levels.

## Test it out loud

- String with only letters: `s = "abc"`. $remL = 0, remR = 0$. DFS immediately traverses to end and outputs `["abc"]`.
- Empty string: `s = ""`. Output is `[""]`.
- All unbalanced brackets: `s = "((("`. $remL = 3, remR = 0$. Grouped removals remove all three, outputting `[""]`.

## Follow-ups

- Can this be solved with BFS?
  Yes, BFS can explore string states level by level (level = number of removals). The first level that contains any valid string contains all minimal removals, and search can terminate without exploring deeper levels.
- How does BFS compare to DFS with precomputed removals?
  DFS with precomputed $remL$ and $remR$ avoids storing thousands of intermediate strings in a BFS queue and uses only $O(n)$ recursion memory.
- What if multiple bracket types (e.g. `[]`, `{}`, `()`) are present?
  Tracking cannot use a simple integer counter `open`; a stack state or string stack would be required.

## Common mistakes

- Trying all possible removals without precomputing $remL$ and $remR$, requiring full $2^n$ state exploration.
- Forgetting to prune paths where a `')'` is added while `open == 0`, leading to strings like `")()("` being marked valid.
- Not handling consecutive duplicate brackets, causing combinatorial duplicates (e.g., removing the 1st vs 2nd `'('` in `"(("`).
