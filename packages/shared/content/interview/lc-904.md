## Clarify first

- What does the problem effectively ask for? Finding the length of the longest contiguous subarray that contains at most 2 distinct integer types.
- Can we choose any starting tree? Yes, we can pick any start index and move strictly rightwards picking one fruit per tree.
- What if there are only 0, 1, or 2 distinct fruit types in the entire array? We can pick from all trees in the array, returning `fruits.length`.
- What are the constraints on array length? Length is between 1 and 100,000, with tree fruit types from 0 to `fruits.length - 1`.

## Examples to say out loud

- Alternating types: `fruits = [1, 2, 1]`. Only 2 distinct fruit types exist (1 and 2), so we pick all 3 fruits. Result is 3.
- Switching fruit types: `fruits = [0, 1, 2, 2]`.
  - Window `[0, 1]` has 2 types (length 2).
  - Next tree is 2, creating 3 types (`{0, 1, 2}`). We must drop 0.
  - Window becomes `[1, 2, 2]`, containing 2 types (length 3). Max length is 3.
- Long contiguous stretch: `fruits = [1, 2, 3, 2, 2]`. Longest stretch with at most 2 types is `[2, 3, 2, 2]` of length 4.

## Brute force

A brute-force solution checks every possible subarray `fruits[i..j]` starting at index `i` and ending at `j`. For each subarray, count the number of unique fruit types using a set. If the set size is at most 2, update the maximum length. Because there are `O(n^2)` subarrays, this approach takes `O(n^2)` time. With `n = 100,000`, checking `10^{10}` subarrays times out.

## The key observation

The condition is monotonic: expanding the right boundary `right` monotonically adds fruit types, and contracting the left boundary `left` monotonically sheds fruit types. We can maintain a sliding window `[left, right]` alongside a frequency map of fruit types in the window. Whenever the map contains more than 2 distinct keys, we shrink from `left` until only 2 distinct keys remain.

## Optimal approach

1. Initialize `left = 0`, `best = 0`, and a hash map `basket` mapping fruit type to its count in the current window.
2. Iterate `right` from 0 to `fruits.length - 1`:
   a. Add `fruits[right]` to `basket` (increment its count).
   b. While `basket.size() > 2`:
      i. Decrement the count of `fruits[left]` in `basket`.
      ii. If its count reaches 0, erase `fruits[left]` from `basket`.
      iii. Increment `left`.
   c. Update `best = max(best, right - left + 1)`.
3. Return `best`.

Complexity:
- Time: `O(n)` because every tree index is added to the window once by `right` and removed by `left` at most once.
- Space: `O(1)` auxiliary space because `basket` stores at most 3 distinct keys at any moment before contracting.

## Code walkthrough

In the reference implementation:
- `unordered_map<int, int> basket;`: tracks the frequency of each fruit type currently buffered in the window.
- `basket[fruits[right]]++;`: ingests the fruit at tree `right`.
- `while (basket.size() > 2)`: detects whenever a third fruit type enters the selection.
- `if (--basket[fruits[left]] == 0) basket.erase(fruits[left]); left++;`: evicts fruits from the left and removes the key completely upon zero frequency.
- `best = max(best, right - left + 1);`: records the maximum valid window span observed.

## Test it out loud

- `fruits = [1, 2, 3]`:
  - `right = 0 (1)`: `basket = {1: 1}`, `best = 1`.
  - `right = 1 (2)`: `basket = {1: 1, 2: 1}`, `best = 2`.
  - `right = 2 (3)`: `basket = {1: 1, 2: 1, 3: 1}` (size 3 > 2).
    - Evict `fruits[0] (1)`: count drops to 0, erased. `left` becomes 1. `basket = {2: 1, 3: 1}`.
    - Window length `2 - 1 + 1 = 2`, `best = max(2, 2) = 2`.
  - Returns 2.
- `fruits = [1]`: returns 1.

## Follow-ups

- What if you had `k` baskets instead of 2?
  The logic generalizes identically: replace `2` with `k`, yielding `O(n)` time and `O(k)` map space (Longest Substring with At Most K Distinct Characters).
- Can this be optimized to avoid the `while` loop shrinking?
  Yes, let the window only expand: if `basket.size() > k`, slide `left` forward by exactly 1 without shrinking down to `k`, leaving `best = n - left` at the end.

## Common mistakes

- Decrementing the frequency in the map without erasing the key when the count reaches zero, causing `basket.size()` to falsely report the key as present.
- Restarting `left` from `right - 1` rather than monotonically sliding `left`, causing unnecessary recomputation.
- Conflating fruit type ID with the count of fruits.
