## Clarify first

- What does repeating string `a` mean? Concatenating string `a` with itself multiple times (e.g. `a * 3 = "abcabcabc"`).
- What should be returned if `b` can never be a substring of any repetition of `a`? Return -1.
- Can `a` or `b` contain uppercase or special characters? Constraints specify both `a` and `b` consist exclusively of lowercase English letters.
- What are the length limits? Both `a.length` and `b.length` are between 1 and 10,000.

## Examples to say out loud

- Repeated until match: `a = "abcd"`, `b = "cdabcdab"`.
  - Repeat 1: `"abcd"` (length 4 < length 8).
  - Repeat 2: `"abcdabcd"` (length 8 == length 8). `b` not present.
  - Repeat 3: `"abcdabcdabcd"` (length 12). `b` appears starting at index 2 (`"cdabcdab"`).
  - Result is 3.
- Immediate substring: `a = "a"`, `b = "a"`. Result is 1.
- Impossible match: `a = "abc"`, `b = "wxyz"`. Characters in `b` do not exist in `a`, returns -1.

## Brute force

A naive brute-force loop repeats `a` over and over (`k = 1, 2, 3, ...`), checking `s.find(b)` on each step until some arbitrary large limit is reached. If the termination condition is unclear or too large, this leads to unnecessary string allocations, memory bloat, and time limit exceeded errors.

## The key observation

How many repetitions of `a` can reasonably be needed?
1. The repeated string must be at least as long as `b`. The minimum integer copies of `a` needed to have length `>= |b|` is `k = \lceil |b| / |a| \rceil`.
2. Can `b` start at any position inside `a`?
   Yes. In the worst case, `b` begins at the very last character of a copy of `a` and spans across subsequent copies. Even in that extreme case, `b` can span at most across the initial partial copy, the full intermediate copies, and one final partial copy: a total of at most **`k + 1`** copies!
3. Any repetition beyond `k + 1` is completely redundant: if `b` does not appear in `k + 1` copies of `a`, it will **never** appear in any number of repetitions. Thus, we only need to test `k` and `k + 1`!

## Optimal approach

1. Calculate the base repeat count: `k = (|b| + |a| - 1) / |a|` (ceiling division).
2. Build string `s` containing `a` repeated `k` times.
3. Check if `b` is a substring of `s`:
   - If `s.find(b) != -1`, return `k`.
4. Append one more copy of `a` to `s` (now `k + 1` repetitions):
   - If `s.find(b) != -1`, return `k + 1`.
5. If `b` is still not found, return -1.

Complexity:
- Time: `O(|a| + |b|)` when using linear string search algorithms (such as KMP or standard optimized string matching). Even with standard library `find()`, it runs in `O(|b| \times (|a| + |b|))` which takes fewer than `10^7` operations.
- Space: `O(|a| + |b|)` auxiliary space to store the repeated string `s` of length at most `2 \times |a| + |b|`.

## Code walkthrough

In the reference implementation:
- `int k = ((int)b.size() + (int)a.size() - 1) / (int)a.size();`: computes `ceil(|b| / |a|)` in integer arithmetic.
- `string s; for (int i = 0; i < k; i++) s += a;`: constructs the minimum-length candidate string of `k` repetitions.
- `if (s.find(b) != string::npos) return k;`: checks if `b` already fits completely within `k` copies.
- `s += a; if (s.find(b) != string::npos) return k + 1;`: tests the `k + 1` spillover boundary case.
- `return -1;`: safely concludes that `b` cannot be formed by repeating `a`.

## Test it out loud

- `a = "abc", b = "cabcabca"`:
  - `|a| = 3, |b| = 8`.
  - `k = (8 + 3 - 1) / 3 = 10 / 3 = 3`.
  - `s = "abcabcabc"` (length 9). `s.find("cabcabca")` is -1.
  - Append `a`: `s = "abcabcabcabc"` (length 12, 4 copies).
  - `"cabcabca"` found starting at index 2 (`"c"` of first copy)!
  - Returns `k + 1 = 4`.
- `a = "a", b = "a"`:
  - `k = 1`, `s = "a"`, found at `k = 1`. Returns 1.
- `a = "abc", b = "d"`:
  - `k = 1`, `s = "abc"` (not found). `k + 1 = 2`, `s = "abcabc"` (not found).
  - Returns -1.

## Follow-ups

- How can we guarantee strict `O(|a| + |b|)` worst-case time?
  Use Knuth-Morris-Pratt (KMP) or Rabin-Karp rolling hash for the substring search instead of standard `find()`.
- What is an early pruning check for impossibility?
  Check if all unique characters present in `b` exist in `a`; if `b` contains any character not in `a`, return -1 immediately.

## Common mistakes

- Looping indefinitely until a random time or arbitrary repeat threshold (e.g. `while (s.length() < 100000)`), causing timeouts or memory limits.
- Testing only `k` repetitions and forgetting `k + 1`, failing on strings that start at the tail of the first copy (e.g. `a = "aab"`, `b = "ba"` where `k = 1` yields `"aab"`, but `k = 2` yields `"aabaab"` which contains `"ba"`).
- Testing `k + 2` or more, which is mathematically proven to be unnecessary.
