## Clarify first

- How is the median defined? (For odd $k$, the middle element of the sorted window; for even $k$, the average of the two middle elements).
- What exact value is returned? (To prevent floating point precision issues, return twice the median, so for odd $k$ it is $2 \times \text{mid}$, and for even $k$ it is the sum of the two middle elements).
- Can numbers cause 32-bit integer overflow when added? (Yes, $-2^{31} \le nums[i] \le 2^{31} - 1$; the sum of two middle numbers can exceed 32 bits, requiring 64-bit integers like `long long`).
- What are the input size bounds? ($1 \le k \le nums.length \le 100,000$).
- Can the window contain duplicates? (Yes, duplicates are allowed and must be preserved).

## Examples to say out loud

- Odd window length: `nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3`.
  - Window 1: `[1, 3, -1]` sorted is `[-1, 1, 3]`, median 1, doubled = 2.
  - Window 2: `[3, -1, -3]` sorted is `[-3, -1, 3]`, median -1, doubled = -2.
  - Result array has length $8 - 3 + 1 = 6$.
- Even window length: `nums = [1, 4, 2, 3], k = 4`. Sorted window is `[1, 2, 3, 4]`. The two middle numbers are 2 and 3. Average is 2.5, doubled is $2 + 3 = 5$.

## Brute force

A naive brute force extracts each window of length $k$, sorts it in $O(k \log k)$ time, and computes the median. Across $n - k + 1$ window positions, total time is $O(n \cdot k \log k)$. For $n = 100,000$ and $k = 50,000$, $10^5 \times 50000 \approx 5 \times 10^9$ operations, which results in Time Limit Exceeded.

## The key observation

As the window slides one position right, exactly one element leaves the left boundary ($nums[i - k]$) and exactly one new element enters the right boundary ($nums[i]$).
We can maintain the sorted window dynamically in $O(\log k)$ using either:
1. Two balanced heaps (or TreeMaps) with lazy deletion, keeping the lower half in a max-heap and the upper half in a min-heap.
2. An ordered multiset (`std::multiset` in C++) along with an iterator `mid` that always points to the element at index $k/2$. When an element is inserted or erased, `mid` shifts by at most one step based on whether the modified value was less than or greater than `*mid`.

## Optimal approach

1. Insert the first $k$ elements into an `std::multiset<int> window`.
2. Initialize an iterator `mid = std::next(window.begin(), k / 2)`.
3. Loop for each window position from $i = k$ to $n$:
   - Record the current doubled median:
     - If $k$ is odd: append `2LL * *mid`.
     - If $k$ is even: append `(long long)*mid + *prev(mid)`.
   - If $i == n$, break out of loop.
   - Insert incoming element $nums[i]$ into `window`:
     - If $nums[i] < *mid$, the insertion landed to the left of `mid`; decrement `mid--`.
   - Remove outgoing element $nums[i - k]$:
     - If $nums[i - k] \le *mid$, the deletion is at or before `mid`; increment `mid++`.
     - Erase the single instance of $nums[i - k]$ using `window.erase(window.lower_bound(nums[i - k]))`.
4. Return the recorded results.

Complexity:
- Time: $O(n \log k)$ because multiset insertions and `lower_bound` searches take $O(\log k)$, and iterator shifts take $O(1)$.
- Space: $O(k)$ auxiliary space to store the $k$ elements in the active window.

## Code walkthrough

In the reference implementation:
- `multiset<int> window(nums.begin(), nums.begin() + k);`: keeps $k$ elements sorted with duplicates supported.
- `auto mid = next(window.begin(), k / 2);`: maintains a persistent pointer to the median element.
- `if (k % 2) out.push_back(2LL * *mid); else out.push_back((long long)*mid + *prev(mid));`: evaluates doubled median in 64-bit integer arithmetic.
- `if (nums[i] < *mid) mid--;`: shifts median left when an incoming value is smaller than current median.
- `if (nums[i - k] <= *mid) mid++;`: adjusts median right before erasing an element on or to the left of the median.
- `window.erase(window.lower_bound(nums[i - k]));`: erases only one occurrence of the value without wiping duplicates.

## Test it out loud

- Window of size 1: `nums = [7], k = 1`. Multiset has `{7}`, `mid` at 7. Odd $k \implies 2 \times 7 = 14$. Returns `[14]`.
- Extreme values: `nums = [2147483647, 2147483647], k = 2`. Sum is $2^{31}-1 + 2^{31}-1 = 4294967294$. Using `long long` avoids 32-bit signed integer overflow.
- Window with all equal values: `nums = [5, 5, 5, 5, 5], k = 2`. Correctly shifts `mid` and erases exactly one instance per step, returning `[10, 10, 10, 10]`.

## Follow-ups

- How to implement this in languages without multiset iterators (Java / Python)?
  Use two balanced TreeMaps or heaps with lazy deletion (hash map of pending deletions). Rebalance heaps whenever sizes deviate from target partition sizes.
- How does the Two-Heap approach compare to Multiset?
  Two heaps (max-heap for lower half, min-heap for upper half) with hash-map lazy deletion also runs in $O(n \log k)$ time and generalizes easily to streaming median without fixed window size.
- What if $k$ is small ($k \le 50$)?
  An insertion sort / binary search array deletion (`std::vector` with `lower_bound`) has $O(k)$ shifts, which has better cache locality than pointer-based trees for small $k$.

## Common mistakes

- Using `window.erase(nums[i - k])` in C++ multiset: this erases ALL instances of the value rather than just one occurrence. Must erase via iterator `window.erase(window.lower_bound(...))`.
- 32-bit integer overflow: when $nums[i] = 2^{31} - 1$, adding two middle numbers exceeds `INT_MAX`. Must cast to `long long` before adding.
- Mismanaging the `mid` iterator when the element being removed is equal to `*mid`.
