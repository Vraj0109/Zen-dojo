## Clarify first
- How does each wheel turn? A wheel displays digits 0 through 9 and wraps circularly: turning up from 9 gives 0, and turning down from 0 gives 9.
- What constitutes a single move? Turning exactly one wheel by one step either up or down.
- What are dead ends? Combinations where the lock gets jammed and cannot be turned further.
- What if the starting combination "0000" is itself a dead end? Then no moves can be made; return -1 immediately (unless target is "0000", though constraints ensure target is not in deadends).
- What should be returned if target is unreachable? Return -1.

## Examples to say out loud
- Direct step: `target = "0009"`, `deadends = ["8888"]`.
  - From "0000", turn the 4th wheel down by 1 step to reach "0009". Takes 1 move.
- Dead end blocking start: `deadends = ["0000"]`, `target = "0202"`.
  - Cannot move from start. Return -1.
- Multiple steps around obstacles: `target = "0202"`, `deadends = ["0201","0101","0102","1212","2002"]`.
  - BFS routes around the dead ends to reach target in 6 moves.

## Brute force
A brute force approach without tracking visited states might perform a depth-first search trying wheel rotations, but because rotations can reverse or loop indefinitely, it risks infinite recursion. A standard Breadth-First Search over the implicit graph of 4-digit lock states guarantees finding the minimum number of turns in unweighted shortest-path order.

## The key observation
There are exactly `10^4 = 10,000` possible lock states from `"0000"` to `"9999"`.
Each state has exactly 8 outgoing transitions (4 wheels * 2 directions).
This represents an unweighted directed graph with 10,000 vertices and 80,000 edges.
A Breadth-First Search (BFS) seeded at `"0000"` exploring valid transitions level-by-level guarantees finding the minimum number of turns to reach `target`. Pre-populating a hash set with all `deadends` allows O(1) validity and visited checks.

## Optimal approach
1. Insert all strings from `deadends` into an `unordered_set<string>` named `seen`.
2. Check initial conditions:
   - If `"0000"` is in `seen`, return -1.
   - If `target == "0000"`, return 0.
3. Initialize a BFS queue `q` holding pairs of `{state, distance}`.
4. Push `{"0000", 0}` into `q` and mark `"0000"` in `seen`.
5. While `q` is not empty:
   - Pop `{s, d}`.
   - For each of the 4 wheel positions `i` from 0 to 3:
     - For both turn directions `delta` in `{1, 9}` (where +1 is forward and +9 is equivalent to -1 modulo 10):
       - Compute new string `t` where `t[i] = '0' + (s[i] - '0' + delta) % 10`.
       - If `seen.count(t)`: continue.
       - If `t == target`: return `d + 1`.
       - Insert `t` into `seen` and push `{t, d + 1}` into `q`.
6. If the queue is exhausted without finding `target`, return -1.

Complexity:
- Time complexity: O(10^4 * 8) = O(1) bounded operations because there are at most 10,000 unique 4-digit states and each state checks 8 neighbors.
- Space complexity: O(10^4) auxiliary space for the `seen` hash set and the BFS queue.

## Code walkthrough
- `unordered_set<string> seen(deadends.begin(), deadends.end())`: Unifies dead ends and visited states in a single lookup set.
- `if (seen.count("0000")) return -1`: Handles immediate blockage at start.
- `for (int delta : {1, 9})`: Adds 1 for clockwise rotation and adds 9 modulo 10 for counter-clockwise rotation, avoiding negative modulo issues.
- `if (t == target) return d + 1`: Early exit on reaching target when enqueuing neighbor.
- `seen.insert(t); q.push({t, d + 1})`: Prevents duplicate state insertions.

## Test it out loud
- Test `target = "0001", deadends = []`:
  - Enqueue `"0000"`.
  - From `"0000"`, position 3 with `delta = 1` yields `"0001"`. Matches target. Returns `0 + 1 = 1`. Correct.
- Test `target = "0202", deadends = ["0000"]`:
  - `"0000"` is in deadends; returns -1 immediately. Correct.

## Follow-ups
- Can bidirectional BFS be used? Yes, starting two simultaneous BFS searches from `"0000"` and `target` drastically reduces the number of visited states by meeting in the middle.
- How would this generalize to an n-digit lock? The state space grows to `10^n`, which quickly requires A* search with Manhattan heuristic distance on the wheels.

## Common mistakes
- Forgetting to check whether the initial state `"0000"` is a dead end.
- Handling modular arithmetic incorrectly for negative turns (e.g. `(0 - 1) % 10` yielding negative values in C++ instead of 9).
- Adding states to `seen` when popping from the queue rather than when pushing, resulting in redundant queue entries.
