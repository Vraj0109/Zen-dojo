## Clarify first
- What are the nodes and edges? There are n nodes (numbered 1 to n) and directed weighted edges `[u, v, w]`, where `w` is the signal travel time.
- Are edge weights non-negative? Yes, `0 <= w <= 100`.
- What should be returned if not all nodes can receive the signal? Return -1.
- What if there are isolated nodes? If any node remains unreachable from the starting node `k`, return -1.

## Examples to say out loud
- Standard tree/graph: `times = [[2,1,1],[2,3,1],[3,4,1]]`, `n = 4`, `k = 2`.
  - Signal starts at 2: arrives at 1 in 1 unit, at 3 in 1 unit.
  - From 3, signal arrives at 4 in `1 + 1 = 2` units.
  - Maximum time for all nodes to receive the signal is `max(1, 1, 2) = 2`.
- Disconnected case: `times = [[1,2,1]]`, `n = 2`, `k = 2`.
  - Signal at node 2 cannot reach node 1. Output: -1.
- Zero delay edges: `times = [[1,2,0]]`, `n = 2`, `k = 1`. Output: 0.

## Brute force
A brute force approach computes all paths from `k` using simple recursive DFS without pruning or memoization. Because weights are non-negative and directed cycles might exist, unpruned search can loop infinitely or take exponential O(V!) time. Since all edge weights are non-negative, Dijkstra's algorithm finds single-source shortest paths efficiently and optimally.

## The key observation
The time required for every node to receive the signal is determined by the node that receives the signal last. Therefore, the answer is the maximum shortest-path distance from the source `k` to any node `i` in the network:
`delay = max(dist[i])` for all `1 <= i <= n`.
Since all edge weights are non-negative, Dijkstra's algorithm using a min-heap finds the exact shortest distance to every node in O(E log V) time. If any node's distance remains infinity after Dijkstra completes, that node is unreachable, so we return -1.

## Optimal approach
1. Construct an adjacency list `g` of size `n + 1`, where `g[u]` stores pairs `{v, w}`.
2. Initialize a distance array `dist` of size `n + 1` filled with infinity (`INT_MAX`), setting `dist[k] = 0`.
3. Initialize a min-heap priority queue `pq` storing pairs `{distance, node}`, and push `{0, k}`.
4. While `pq` is not empty:
   - Extract `{d, u}` with the smallest distance.
   - If `d > dist[u]`: this is a stale entry; continue.
   - For each outgoing edge `{v, w}` in `g[u]`:
     - If `d + w < dist[v]`:
       - Update `dist[v] = d + w`.
       - Push `{dist[v], v}` into `pq`.
5. Compute `best = 0`. Iterate through all nodes `i` from 1 to `n`:
   - If `dist[i] == INT_MAX`, return -1.
   - Update `best = max(best, dist[i])`.
6. Return `best`.

Complexity:
- Time complexity: O(E log V) where E is the number of directed edges and V is `n`. Each edge relaxation inserts at most once into the priority queue of size V.
- Space complexity: O(V + E) auxiliary space for the adjacency list and the min-heap.

## Code walkthrough
- `vector<int> dist(n + 1, INT_MAX)`: Tracks shortest recorded distances from node `k`.
- `priority_queue<pair<int, int>, ..., greater<>> pq`: Min-heap ordered by smallest cumulative delay.
- `if (d > dist[u]) continue`: Skips outdated heap pairs when a shorter path to `u` was already relaxed.
- `if (d + w < dist[v])`: Relaxes the edge and enqueues `{dist[v], v}`.
- Max collection loop: Verifies reachability (`dist[i] == INT_MAX`) and finds the maximum delay among reachable nodes.

## Test it out loud
- Test `times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2`:
  - `dist[2] = 0`.
  - Relax 1: `dist[1] = 1`. Relax 3: `dist[3] = 1`.
  - Next from 3: relax 4: `dist[4] = 2`.
  - All nodes reachable: `dist = [-, 1, 0, 1, 2]`. Max is 2. Returns 2. Correct.
- Test `times = [], n = 1, k = 1`:
  - `dist[1] = 0`. Max is 0. Returns 0. Correct.

## Follow-ups
- What if edge weights could be negative? Dijkstra fails with negative weights; we would use the Bellman-Ford or SPFA algorithm running in O(V * E) time.
- What if the graph is a Directed Acyclic Graph (DAG)? We can solve single-source shortest paths in linear O(V + E) time using topological sort relaxation.

## Common mistakes
- Forgetting to skip stale entries (`if (d > dist[u]) continue`), causing duplicate edge relaxations and degrading performance.
- Returning the sum of edge weights rather than the maximum shortest-path distance.
- Off-by-one errors because nodes are 1-indexed from 1 to n.
