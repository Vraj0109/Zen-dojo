## Clarify first

- What characters can the string contain? (Only `'('` and `')'`).
- Can the string be empty? (Yes, $0 \le s.length \le 3 \cdot 10^4$; return 0 for an empty string).
- Are we finding a substring or a subsequence? (A contiguous substring that forms well-formed parentheses).
- What should be returned if no valid parentheses exist (e.g. `"((("` or `")"` )? (Return 0).
- Does nested or concatenated valid parentheses count? (Yes, e.g. `"(())"` has length 4 and `"()()"` has length 4).

## Examples to say out loud

- Nested parentheses: `"((()))"`. Completely matched; length is 6.
- Concatenated valid pairs: `"()()"`. Two pairs back-to-back form a continuous valid substring of length 4.
- Interrupted by invalid characters: `")()())"`.
  - Leading `')'` is invalid.
  - Middle `"()()"` is valid with length 4.
  - Trailing `')'` breaks validity.
  - Max valid length is 4.
- Incomplete open brackets: `"(()"`. The prefix `'('` has no matching closer; only the suffix `"()"` matches, giving length 2.

## Brute force

A naive brute force tests every even-length substring of $s$ (all pairs of indices $(i, j)$ with $j - i + 1$ even), checking validity in $O(n)$ by tracking the bracket balance. With $O(n^2)$ substrings, overall time complexity is $O(n^3)$ (or $O(n^2)$ if balance is checked incrementally). With $n = 3 \cdot 10^4$, $n^2 \approx 9 \times 10^8$ operations, which results in Time Limit Exceeded.

## The key observation

A stack can store the **indices** of unmatched parentheses. Any valid substring lies strictly between the current index $i$ and the index of the most recent unmatched character. If we push a dummy base index `-1` onto the stack initially, then whenever a valid pair is formed by popping `'('`, the top of the stack immediately reveals the boundary of the contiguous valid block ending at index $i$. If popping makes the stack empty, the current `')'` has no matching `'('`, so its index becomes the new base boundary.

## Optimal approach

1. Initialize a stack `st` and push `-1` as the initial baseline boundary.
2. Initialize `maxLen = 0`.
3. Iterate index $i$ from 0 to $s.length - 1$:
   - If $s[i] == \text{'('}$:
     - Push $i$ onto `st`.
   - Else ($s[i] == \text{')'}$):
     - Pop the top index from `st`.
     - If `st` is empty:
       - The current closing parenthesis is unmatched; push $i$ as the new baseline boundary.
     - Else:
       - A valid substring ends at $i$. Its length is $i - st.top()$.
       - Update `maxLen = max(maxLen, i - st.top())`.
4. Return `maxLen`.

Complexity:
- Time: `O(n)` because we iterate through the string of length $n$ once, performing $O(1)$ stack pushes and pops per character.
- Space: `O(n)` auxiliary space for the stack in the worst case (e.g., a string of all `'('`).

## Code walkthrough

In the reference implementation:
- `st.push(-1);`: serves as a virtual unmatched boundary before index 0, allowing expressions like `"()"` to calculate length $1 - (-1) = 2$.
- `if (s[i] == '(') st.push(i);`: remembers the position of open brackets waiting to be matched.
- `st.pop();`: matches the current `')'` with the most recent unmatched `'('`.
- `if (st.empty()) st.push(i);`: marks the current `')'` as an unmatchable barrier separating valid segments.
- `maxLen = max(maxLen, i - st.top());`: computes valid length dynamically spanning across nested and chained pairs.

## Test it out loud

- Empty string: `s = ""`. Loop does not execute; returns `maxLen = 0`.
- Single characters: `s = "("` pushes 0, returns 0. `s = ")"` pops -1, stack empty, pushes 0, returns 0.
- Prefix unmatched: `s = "(()"`.
  - Push -1, push 0 (`'('`), push 1 (`'('`).
  - At $i = 2$ (`')'`): pop 1. Top is 0. Length $2 - 0 = 2$. `maxLen = 2`. Correctly ignores the unmatched `'('` at 0.
- Concatenation: `s = "()()"`.
  - At $i = 1$: pop 0, length $1 - (-1) = 2$.
  - At $i = 3$: pop 2, length $3 - (-1) = 4$. Correctly chains adjacent pairs.

## Follow-ups

- Can we solve this in $O(1)$ extra space?
  Yes, two passes with two counters (`left` and `right`): scan left-to-right updating `maxLen` when `left == right` and resetting when `right > left`. Then scan right-to-left doing the symmetric check to catch excess `'('`.
- How to solve this using Dynamic Programming?
  Let `dp[i]` be the length of the longest valid substring ending at index $i$. If $s[i] == \text{')'}$, check $s[i - 1 - dp[i - 1]]$; if it is `'('`, then $dp[i] = dp[i - 1] + 2 + dp[i - 2 - dp[i - 1]]$.
- What if there are multiple types of brackets (e.g. `()[]{}`)?
  The two-pointer counter method no longer works; the index stack or DP approach must be adapted to verify bracket type matching.

## Common mistakes

- Storing characters instead of indices on the stack, making it impossible to compute substring spans across nested/chained valid pairs.
- Forgetting the baseline index `-1`, resulting in stack underflow on the first valid pair starting at index 0.
- Not resetting the baseline when an unmatched `')'` occurs, incorrectly including invalid characters in the computed length.
