## Clarify first
- Can the input array contain duplicate numbers? Yes, `nums` may contain duplicate elements.
- How are duplicate permutations avoided? Permutations that result in the identical sequence of values must be generated only once.
- Can permutations be returned in any order? Yes, any order is valid.
- What are the constraints on array length? `1 <= nums.length <= 8`.

## Examples to say out loud
- Duplicate elements: `nums = [1, 1, 2]`.
  - Distinct permutations: `[[1, 1, 2], [1, 2, 1], [2, 1, 1]]`.
  - Although there are `3! = 6` index permutations, there are only 3 distinct value permutations.
- All identical elements: `nums = [2, 2, 2]`.
  - Only 1 unique permutation: `[[2, 2, 2]]`.
- Distinct elements: `nums = [1, 2]`.
  - Permutations: `[[1, 2], [2, 1]]`.

## Brute force
A brute force approach generates all `n!` permutations using standard backtracking (or `std::next_permutation`), inserts each permutation into a hash set or tree set of vectors to filter out duplicates, and then converts the set to a list. This incurs unnecessary overhead from generating duplicate branches and sorting/hashing large vectors. Sorting the array upfront and enforcing an ordering condition on identical elements prevents duplicates at generation time.

## The key observation
If we sort the input array, identical elements become adjacent.
During permutation generation, we place numbers into positions one by one using a boolean `used` array.
To avoid generating duplicate permutations:
- When considering candidate index `i` to place in the current position:
- If `nums[i] == nums[i - 1]` and `!used[i - 1]`, we skip index `i`.
Why `!used[i - 1]`?
Because if `nums[i - 1]` has not been used yet in the current recursive path, choosing `nums[i]` now would explore the exact same choices that choosing `nums[i - 1]` would explore at this position.
Enforcing that identical numbers can only be chosen in strict left-to-right order (i.e. `nums[i]` is only picked if `nums[i - 1]` is already in use) guarantees that identical values produce exactly one canonical branch.

## Optimal approach
1. Sort `nums` in non-decreasing order.
2. Initialize an array `used` of size `n` with all false, a list `cur` for the current permutation, and an output container `out`.
3. Define recursive helper `go()`:
   - Base case: If `cur.size() == nums.size()`, append `cur` to `out` and return.
   - For `i` from 0 to `nums.size() - 1`:
     - If `used[i]` is true: continue.
     - If `i > 0` and `nums[i] == nums[i - 1]` and `!used[i - 1]`: continue (skip duplicate choice).
     - Mark `used[i] = true`, push `nums[i]` to `cur`.
     - Recurse: `go()`.
     - Backtrack: pop `nums[i]` from `cur`, set `used[i] = false`.
4. Call `go()` and return `out`.

Complexity:
- Time complexity: O(n * n!) where n is the length of `nums`. There are at most n! distinct permutations, and copying each to the output takes O(n) time.
- Space complexity: O(n) auxiliary space for the `used` array and recursion call stack (excluding output).

## Code walkthrough
- `sort(nums.begin(), nums.end())`: Places duplicate values in adjacent indices.
- `if (used[i]) continue`: Ensures each specific array element is placed at most once per permutation.
- `if (i > 0 && a[i] == a[i - 1] && !used[i - 1]) continue`: Enforces that identical elements are consumed strictly in increasing index order.
- `used[i] = true; cur.push_back(a[i]); go(...); cur.pop_back(); used[i] = false`: Standard choose-explore-unchoose cycle.

## Test it out loud
- Test `nums = [1, 1, 2]`:
  - Position 0: picks first 1 (`used[0]=true`).
    - Position 1: picks second 1 (`used[1]=true`).
      - Position 2: picks 2. Result: `[1, 1, 2]`.
    - Position 1: picks 2 (`used[2]=true`).
      - Position 2: picks second 1. Result: `[1, 2, 1]`.
  - Position 0: tries second 1 (`i = 1`). `nums[1] == nums[0]` and `!used[0]` is true! Skipped.
  - Position 0: picks 2 (`used[2]=true`).
    - Position 1: picks first 1 (`used[0]=true`).
      - Position 2: picks second 1 (`used[1]=true`). Result: `[2, 1, 1]`.
    - Position 1: skips second 1 because `!used[0]` would be false if already chosen, but here 0 was already unchosen.
  - Total: 3 permutations `[1,1,2], [1,2,1], [2,1,1]`. Correct.

## Follow-ups
- What if we used `used[i - 1]` instead of `!used[i - 1]`? Both work to break ties, but `!used[i - 1]` prunes redundant branches much earlier in the recursion tree, making it significantly faster in practice.
- How would you implement this iteratively? Repeatedly call an in-place `next_permutation` algorithm until the sequence wraps around.

## Common mistakes
- Forgetting to sort `nums` before starting backtracking.
- Omitting the `!used[i - 1]` check and simply checking `nums[i] == nums[i - 1]`, which prevents using the second copy of a duplicate anywhere in the permutation.
- Forgetting to reset `used[i] = false` during the backtrack step.
