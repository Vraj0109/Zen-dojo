## Clarify first

- What does `pos` represent in the input? (0-indexed position in `nums` where the tail node loops back to; `-1` means the tail points to null and there is no cycle).
- What should be returned if no cycle exists? (Return `-1`).
- What should be returned if a cycle exists? (Return the index of the node where the cycle begins).
- Can the list be empty? (Yes, $0 \le nums.length \le 100,000$; return `-1` if empty).
- What is the memory constraint? (Must run in strictly $O(1)$ auxiliary space without using hash sets or modifying node structures).

## Examples to say out loud

- Cycle starting at index 1: `nums = [3, 2, 0, -4]`, `pos = 1`. Tail `-4` points back to `2` (index 1). The cycle is 2 -> 0 -> -4 -> 2. Return index 1.
- Cycle covering the whole list: `nums = [1, 2]`, `pos = 0`. Tail points back to head. Cycle begins at index 0. Return 0.
- No cycle: `nums = [1]`, `pos = -1`. Head points to null; return -1.

## Brute force

A naive approach traverses the list while recording every visited node pointer or index in a hash set. At each step, check whether the current node already exists in the set: if found, that node is the start of the cycle; if the end of the list is reached, there is no cycle. While this takes $O(n)$ time, it requires $O(n)$ auxiliary space to store visited nodes, violating the strict $O(1)$ space requirement.

## The key observation

We use Floyd's Tortoise and Hare algorithm in two phases:
1. **Cycle Detection**: Move `slow` by 1 step and `fast` by 2 steps. If `fast` reaches null, no cycle exists. If they meet at some node inside the cycle, a cycle is guaranteed.
2. **Cycle Origin Finding**:
   - Let $L_1$ be the distance from head to cycle entrance.
   - Let $L_2$ be the distance from entrance to the meeting point.
   - Let $C$ be the cycle length.
   - When they meet: $2 \times \text{dist}(\text{slow}) = \text{dist}(\text{fast}) \implies 2(L_1 + L_2) = L_1 + L_2 + k \cdot C \implies L_1 = k \cdot C - L_2$.
   - This mathematical identity proves that the distance from the head to the cycle start ($L_1$) equals the distance from the meeting point to the cycle start going forward around the loop ($k \cdot C - L_2$).
   - Therefore, reset `slow` back to the head and keep `fast` at the meeting point. Advance both pointers 1 step at a time; their point of collision is precisely the cycle entrance.

## Optimal approach

1. Check base case: if $n == 0$, return -1.
2. Initialize pointers `slow = 0` and `fast = 0`.
3. Phase 1 (Find collision):
   - In a loop, advance `slow` by 1 step: `slow = next(slow)`.
   - Advance `fast` by 2 steps: `fast = next(next(fast))`.
   - If either pointer reaches null / -1, return -1 (no cycle).
   - If `slow == fast`, break out of loop.
4. Phase 2 (Find entrance):
   - Reset `slow = 0` (head of list).
   - While `slow != fast`:
     - Advance `slow = next(slow)` by 1 step.
     - Advance `fast = next(fast)` by 1 step.
5. Return `slow` (the node where they meet).

Complexity:
- Time: $O(n)$ time. In Phase 1, `slow` takes at most $n$ steps before meeting `fast`. In Phase 2, `slow` takes $L_1 \le n$ steps to reach the entrance.
- Space: $O(1)$ auxiliary space as only two pointer variables are maintained.

## Code walkthrough

In the reference implementation:
- next transition lambda: models linked list pointer transitions.
- slow and fast pointer loop: Phase 1 traversal at relative speed 1.
- `if (fast < 0) return -1;`: detects absence of cycle when tail points to -1.
- `slow = 0; while (slow != fast)`: Phase 2 synchronization where both advance at unit speed.
- `return slow;`: returns the exact index of the cycle entrance.

## Test it out loud

- Empty list: `nums = []`. Immediately returns -1.
- Self-loop on single node: `nums = [5], pos = 0`. `slow` moves $0 \to 0$, `fast` moves $0 \to 0 \to 0$. They meet at 0. Phase 2 starts with `slow = 0, fast = 0` (already equal), returns 0.
- Linear list without cycle: `nums = [1, 2, 3, 4, 5], pos = -1`. `fast` reaches -1, loop returns -1 immediately.
- Long lead-in before cycle: `nums = [1..8], pos = 3`. Phase 1 finds a meeting point inside cycle `3..7`; Phase 2 walks 3 steps from head and from meeting point, colliding at 3.

## Follow-ups

- How does this problem relate to LeetCode 287 (Find the Duplicate Number)?
  Array values can be viewed as pointers $i \to nums[i]$. A duplicate value creates two arrows entering the same node, forming a cycle entrance that can be found using the exact same two-pointer logic.
- Can we determine the length of the cycle?
  Yes, after the first meeting, hold `slow` stationary and advance `fast` by 1 step until it returns to `slow`, counting steps.
- How to detect cycles in a directed graph with multiple branches?
  Fast and slow pointers only work for linked structures with out-degree $\le 1$. General graphs require 3-color DFS or Kahn's topological sort.

## Common mistakes

- Moving `fast` by 2 steps in Phase 2 instead of 1 step: Phase 2 requires both pointers to move at identical speed 1.
- Failing to check null pointers on `fast->next` before accessing `fast->next->next`.
- Resetting both pointers to the head instead of leaving `fast` at the meeting point.
