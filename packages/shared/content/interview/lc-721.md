## Clarify first
- Can two different people share the same name? Yes, names are not unique identifiers; only email overlap determines that accounts belong to the same person.
- Can one person have multiple accounts with disjoint email subsets that get bridged by a third account? Yes, if account 1 has `{e1, e2}` and account 2 has `{e2, e3}`, all three emails belong to one person.
- What format should the output have? Each account list begins with the person's name, followed by their deduplicated email addresses sorted in ascending lexicographical order.
- Can accounts have only one email? Yes, single-email accounts are common.

## Examples to say out loud
- Consider:
  - Account 1: `["John", "a@mail.com", "b@mail.com"]`
  - Account 2: `["John", "b@mail.com", "c@mail.com"]`
  - Account 3: `["Mary", "m@mail.com"]`
  - Account 4: `["John", "d@mail.com"]`
  - Accounts 1 and 2 share `"b@mail.com"`, so they merge into `["John", "a@mail.com", "b@mail.com", "c@mail.com"]`.
  - Account 4 has no shared emails despite having the name "John", remaining `["John", "d@mail.com"]`.
  - Mary remains `["Mary", "m@mail.com"]`.

## Brute force
A brute force approach compares each account with every other account. If two accounts share at least one email, it merges their email lists, updates the account, and repeats the pairwise checking until no further merges occur. In the worst case, this repeated set-union process can take O(A^2 * E) where A is the number of accounts and E is the number of emails. Using Disjoint Set Union (DSU) or connected component graph traversal links all emails in near-linear time.

## The key observation
Emails act as nodes in a graph. An account with emails `[e1, e2, e3]` defines edges between `e1` and `e2`, and between `e1` and `e3`.
Using a Disjoint Set Union (DSU) data structure:
- Map every unique email to an integer ID.
- For each account, unite the ID of the first email with the IDs of all subsequent emails in that account.
- After processing all accounts, every connected component of email IDs represents one unique person.
- Group emails by their DSU root representative, sort the emails alphabetically, prepend the owner's name, and return the combined accounts.

## Optimal approach
1. Map each unique email to an integer ID from 0 to `N - 1`, recording its associated owner name in an `owner` array.
2. Initialize DSU parent pointers `par[i] = i` for all `N` unique emails.
3. For each account:
   - Identify the root of the first email: `root1 = find(id[account[1]])`.
   - For each subsequent email `account[i]` from index 2 onwards:
     - Unite by assigning `par[find(id[account[i]])] = root1`.
4. Group all emails by their component root: map `root -> list of emails`.
5. For each group:
   - Sort the list of emails lexicographically.
   - Insert the owner name `owner[root]` at the front of the list.
   - Add the resulting list to the output.
6. Return the merged accounts.

Complexity:
- Time complexity: O(N log N) where N is the total number of emails across all accounts. Building the DSU takes O(N * alpha(N)), and sorting the emails within each component takes O(N log N) overall.
- Space complexity: O(N) to store email IDs, DSU parent pointers, owner names, and grouped lists.

## Code walkthrough
- `map<string, int> id`: Assigns a unique integer index to each distinct email.
- `par.resize(emails.size()); iota(par.begin(), par.end(), 0)`: Sets up DSU parent array.
- `par[find(id[a[i]])] = find(id[a[1]])`: Connects each email in an account to the account's primary email.
- `groups[find((int)i)].push_back(emails[i])`: Partitions all emails into their respective root components.
- `sort(list.begin(), list.end()); list.insert(list.begin(), owner[root])`: Orders emails alphabetically and prepends the owner's name.

## Test it out loud
- Test `[["A", "a@x.com", "b@x.com"], ["A", "b@x.com", "c@x.com"]]`:
  - Emails `a, b, c` get IDs `0, 1, 2`.
  - Account 1 unions 0 and 1. Account 2 unions 1 and 2.
  - All three share root 0. Group for root 0: `["a@x.com", "b@x.com", "c@x.com"]`.
  - Name "A" prepended. Correct.
- Test single email: `[["A", "a@x.com"]]`:
  - No inner union loop runs. Root is 0, outputs `["A", "a@x.com"]`. Correct.

## Follow-ups
- Can this be solved using DFS instead of DSU? Yes, build an undirected graph where emails are nodes and edges connect adjacent emails within the same account. Run DFS from unvisited emails to collect components.
- How would you handle case-insensitivity in email addresses? Normalize all email strings to lowercase before mapping and hashing.

## Common mistakes
- Grouping by person name first, which incorrectly merges distinct individuals who happen to share the same name.
- Forgetting to deduplicate and sort emails within each merged account.
- Missing path compression in the DSU `find` method, leading to degraded performance.
