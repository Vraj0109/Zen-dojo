## Clarify first

- Can `needle` be an empty string? The problem specifies `needle` is never empty (`1 <= needle.length`).
- What should be returned if `needle` is not part of `haystack`? Return -1.
- Are strings composed strictly of lowercase English letters? Yes, constraints state only lowercase English letters appear.
- What if `needle.length > haystack.length`? It cannot appear in `haystack`, immediately return -1.

## Examples to say out loud

- Direct match: `haystack = "sadbutsad"`, `needle = "sad"`. First occurrence starts at index 0. Returns 0.
- No match: `haystack = "leetcode"`, `needle = "leeto"`. Substring `"leeto"` does not occur in `"leetcode"`. Returns -1.
- Embedded match: `haystack = "hello"`, `needle = "ll"`. Found at index 2. Returns 2.
- Equal strings: `haystack = "a"`, `needle = "a"`. Starts at index 0. Returns 0.

## Brute force

A naive brute-force algorithm tests every possible starting index `i` from 0 to `n - m` in `haystack`. For each `i`, compare characters `haystack[i + j]` with `needle[j]` for `j` from 0 to `m - 1`. If all match, return `i`. On inputs with repeated prefixes (such as `haystack = "aaaaaaaaab"` and `needle = "aaab"`), each mismatch resets the comparison, requiring `O(n * m)` time in the worst case.

## The key observation

When a mismatch occurs after matching several characters, we have already inspected a prefix of `needle`. The Knuth-Morris-Pratt (KMP) algorithm precomputes a failure table `fail` (longest proper prefix that is also a suffix) for `needle`. This allows us to shift `needle` forward without backtracking the pointer in `haystack`, achieving linear runtime.

## Optimal approach

1. Let `n = haystack.length()` and `m = needle.length()`.
2. Construct the KMP failure table `fail` of size `m`:
   a. Initialize `fail[0] = 0`, and pointer `k = 0`.
   b. For `i` from 1 to `m - 1`:
      i. While `k > 0` and `needle[i] != needle[k]`, backtrack `k = fail[k - 1]`.
      ii. If `needle[i] == needle[k]`, increment `k`.
      iii. Set `fail[i] = k`.
3. Search `haystack` using pointer `j = 0` (tracking matched characters in `needle`):
   a. For `i` from 0 to `n - 1`:
      i. While `j > 0` and `haystack[i] != needle[j]`, backtrack `j = fail[j - 1]`.
      ii. If `haystack[i] == needle[j]`, increment `j`.
      iii. If `j == m`, return the start index `i - m + 1`.
4. If loop completes without matching, return -1.

Complexity:
- Time: `O(n + m)` where `m` is needle length (building failure table) and `n` is haystack length (single forward pass).
- Space: `O(m)` auxiliary space to store the failure table `fail`.

## Code walkthrough

In the reference implementation:
- `vector<int> fail(m, 0);`: allocates the prefix function table for `needle`.
- `while (k > 0 && needle[i] != needle[k]) k = fail[k - 1];`: jumps to the next best candidate prefix when a character mismatch occurs during preprocessing.
- `fail[i] = k;`: stores length of longest proper prefix matching a suffix up to index `i`.
- `while (j > 0 && haystack[i] != needle[j]) j = fail[j - 1];`: repositions `needle` match pointer upon mismatch during haystack traversal without moving `i` backward.
- `if (j == m) return i - m + 1;`: terminates upon a full pattern match, returning the starting index.

## Test it out loud

- `haystack = "mississippi", needle = "issip"`:
  - `fail` table for `"issip"` is `[0, 0, 0, 1, 0]`.
  - At index 4 of `haystack`, `"issi"` matches, next char `'s'` mismatches `'p'`.
  - Fall back `j = fail[3] = 1`, avoiding re-checking the first `'i'`.
  - Match succeeds from index 4 to 8, returns `8 - 5 + 1 = 4`.
- `haystack = "aaa", needle = "aaaa"`: `n < m`, loop completes, returns -1.

## Follow-ups

- How would you find all occurrences of `needle` in `haystack`?
  Instead of returning immediately on `j == m`, record `i - m + 1`, reset `j = fail[m - 1]`, and continue the loop.
- What other string matching algorithms exist?
  Rabin-Karp (rolling hash, expected `O(n + m)`), Boyer-Moore (often faster in practice by scanning needle backwards and skipping chunks).

## Common mistakes

- Re-scanning characters in `haystack` in naive `O(n * m)` code without mentioning worst-case inputs to the interviewer.
- Off-by-one errors in KMP failure table indices (e.g. `fail[k]` instead of `fail[k - 1]`).
- Miscalculating the match start index as `i - m` instead of `i - m + 1`.
