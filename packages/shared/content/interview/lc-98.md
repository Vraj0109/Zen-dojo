## Clarify first

- Are duplicate values allowed in a valid BST? No, the definition requires strictly smaller values in the left subtree and strictly larger values in the right subtree (`val <= low` or `val >= high` is invalid).
- What values can nodes hold? Values range between `-2^31` and `2^31 - 1`, covering the entire 32-bit signed integer range.
- Does verifying the local condition `node->left->val < node->val < node->right->val` suffice? No, every ancestor imposes a global boundary on all descendant subtrees.
- Can the tree be empty? Constraints indicate at least 1 node up to 10,000 nodes.

## Examples to say out loud

- Valid BST: `root = [2, 1, 3]`. Node 1 is strictly less than 2, and node 3 is strictly greater than 2. Valid, returns true.
- Subtree violation that passes local checks: `root = [5, 1, 4, null, null, 3, 6]`. Locally, 4 has left child 3 and right child 6, which seems ordered. However, 3 is in the right subtree of the root 5 and `3 < 5`, violating the BST property. Returns false.
- Duplicate values edge case: `root = [2, 2, 2]`. Returns false because children must be strictly smaller or larger.

## Brute force

A brute-force strategy performs an in-order traversal of the tree, appends all node values into an array, and checks whether the array is strictly monotonically increasing. While this runs in `O(n)` time, it uses `O(n)` auxiliary space to store all values. Alternatively, inspecting the entire subtree at every node takes `O(n^2)` time in an unbalanced tree.

## The key observation

Every node in a BST must fall within an open value range `(low, high)` determined by its chain of ancestors. The root starts with bounds `(-infinity, +infinity)`. When traversing into a left child, the upper bound is narrowed to `node.val` (all left descendants must be `< node.val`). When traversing into a right child, the lower bound is updated to `node.val` (all right descendants must be `> node.val`).

## Optimal approach

1. Define a helper function `ok(node, low, high)`.
2. Base case: If `node == null`, return true.
3. If `node.val <= low` or `node.val >= high`, return false.
4. Recursively validate left and right children:
   - For left child: `ok(node.left, low, node.val)`.
   - For right child: `ok(node.right, node.val, high)`.
5. In the main function, call `ok(root, LLONG_MIN, LLONG_MAX)` using 64-bit bounds so that standard 32-bit `INT_MIN` and `INT_MAX` node values are not prematurely rejected.

Complexity:
- Time: `O(n)` because each node in the tree of size `n` is visited once.
- Space: `O(h)` stack space, where `h` is the tree height (`O(log n)` for balanced trees, `O(n)` worst-case for degenerate skewed trees).

## Code walkthrough

In the reference implementation:
- `bool ok(TreeNode* n, long long low, long long high)`: validates that `n` satisfies the bounding interval.
- `if (!n) return true;`: an empty subtree is unconditionally valid.
- `if (n->val <= low || n->val >= high) return false;`: rejects nodes violating ancestor bounds or containing duplicates.
- `return ok(n->left, low, n->val) && ok(n->right, n->val, high);`: tightens bounds when branching left and right.
- `isValidBST(TreeNode* root)`: passes 64-bit extremes `LLONG_MIN` and `LLONG_MAX` to avoid integer overflow issues.

## Test it out loud

- `root = [2, 1, 3]`:
  - Root 2: check against `(-inf, inf)`. Valid.
  - Left child 1: check against `(-inf, 2)`. `1 < 2`, valid.
  - Right child 3: check against `(2, inf)`. `3 > 2`, valid.
  - Result: true.
- `root = [5, 4, 6, null, null, 3, 7]`:
  - Root 5: valid with `(-inf, inf)`.
  - Right child 6: valid with `(5, inf)`.
  - Node 3 (left child of 6): check with range `(5, 6)`. But `3 <= 5`, fails immediately!
  - Result: false.

## Follow-ups

- How would you solve this iteratively without 64-bit sentinel bounds?
  Perform an iterative in-order traversal using a stack, keeping track of the previous node's value and asserting `prev < cur->val` at each step.
- Can we reconstruct a BST from only preorder traversal?
  Yes, using the upper-bound monotonicity property in `O(n)` time.

## Common mistakes

- Only checking immediate children (`node->left->val < node->val`), which misses violations deeper in subtrees.
- Using 32-bit `INT_MIN` and `INT_MAX` as default bounds, causing false failures when a node's value is actually `INT_MIN` or `INT_MAX`.
- Using `<=` or `>=` instead of `<` and `>`, accidentally permitting duplicate keys.
