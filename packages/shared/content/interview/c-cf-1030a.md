## Clarify first
- What do the opinions represent? An array `opinions` of length $n$, where each entry is either $0$ (person considers the problem easy) or $1$ (person considers the problem hard).
- What is the decision rule?
  - If at least one person answered $1$ (hard), the problem is classified as `"HARD"`.
  - If everyone answered $0$ (easy), the problem is classified as `"EASY"`.
- What are the constraints? The array length $n$ is between 1 and 100, and all elements are either 0 or 1.
- What should be returned? The string `"HARD"` or `"EASY"`.

## Examples to say out loud
- Consider `opinions = [0, 0, 1]`.
  The third respondent answered 1 (hard).
  Because at least one person found it hard $\to$ return `"HARD"`.
- Consider `opinions = [0, 0, 0, 0]`.
  Everyone answered 0 $\to$ return `"EASY"`.
- Consider `opinions = [1]`.
  Only one respondent, answered 1 $\to$ return `"HARD"`.

## Brute force
A brute force approach scans through the array of opinions from left to right. If a 1 is encountered, we can stop immediately and return `"HARD"`. If the loop finishes without seeing any 1, return `"EASY"`. Because this is a single linear scan with early exit, it is already optimal in $O(n)$ time and $O(1)$ space.

## The key observation
The problem is mathematically equivalent to computing the logical OR over all boolean values in the array:
$\text{is\_hard} = \bigvee_{i=0}^{n-1} (\text{opinions}[i] == 1)$.
Alternatively, we can sum all values in the array: if $\sum \text{opinions}[i] > 0$, return `"HARD"`; otherwise return `"EASY"`.
An early exit upon finding the first 1 achieves the best performance.

## Optimal approach
1. Iterate through each opinion `op` in array `opinions`:
   - If `op == 1`, return `"HARD"` immediately.
2. If the loop completes without finding 1, return `"EASY"`.
3. Complexity:
   - Time Complexity: $O(n)$, where $n$ is the length of `opinions` (at most 100). The loop takes $O(1)$ time in the best case (when the first person says 1) and $O(n)$ time in the worst case.
   - Space Complexity: $O(1)$, using no extra storage.

## Code walkthrough
- `string evaluateDifficulty(vector<int> opinions)`: Function accepting the list of opinions.
- `for (int op : opinions) if (op == 1) return "HARD";`: Scan elements; early exit on first difficulty flag.
- `return "EASY";`: Fallback when all elements are 0.

## Test it out loud
- Test 1: `[1]` $\to 1$ found $\to$ `"HARD"`.
- Test 2: `[0, 0, 0, 0]` $\to$ no 1s $\to$ `"EASY"`.
- Test 3: `[1, 0, 0, 0]` $\to 1$ at start $\to$ `"HARD"`.
- Test 4: `[0, 1, 0, 0]` $\to 1$ at index 1 $\to$ `"HARD"`.
- Test 5: `[0, 0, 0, 1]` $\to 1$ at end $\to$ `"HARD"`.

## Follow-ups
- How would you implement this using the standard library?
  In C++: `any_of(opinions.begin(), opinions.end(), [](int x) { return x == 1; }) ? "HARD" : "EASY"`.
  In Python: `"HARD" if 1 in opinions else "EASY"`.
- What if a majority vote was required instead of any single person?
  Count total ones and check whether $\text{count} > n / 2$.

## Common mistakes
- Counting the total ones when an early exit can return immediately upon encountering the first 1.
- Inverting the returned strings or casing (e.g. returning `"Hard"` or `"Easy"` instead of all uppercase `"HARD"` and `"EASY"`).
- Checking if ALL elements are 1 instead of ANY element being 1.
