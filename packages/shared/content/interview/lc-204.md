## Clarify first
- Is `n` inclusive or exclusive? Strictly less than `n`.
- What are the smallest possible values of `n`? `n` can be 0, 1, or 2, all of which contain 0 primes strictly less than `n`.
- What is the maximum value of `n`? `n <= 5000000`.
- What type should the answer be? An integer representing the count of primes.

## Examples to say out loud
- Consider `n = 10`:
  - Primes strictly less than 10 are 2, 3, 5, and 7.
  - Count is 4.
- Consider `n = 2`:
  - There are no primes strictly less than 2.
  - Return 0.
- Consider `n = 0` or `n = 1`:
  - Neither contains primes; return 0.

## Brute force
A brute-force solution checks every integer `x` from 2 up to `n - 1` for primality by trial division up to `sqrt(x)`. Across `n` numbers, this takes `O(n sqrt(n))` time. For `n = 5 * 10^6`, `5 * 10^6 * 2236 ≈ 1.1 * 10^10` operations, which will exceed time limits. We need the Sieve of Eratosthenes.

## The key observation
Instead of checking whether each number is prime, mark multiples of known primes as composite. When processing a prime `p`, all composite multiples of `p` smaller than `p * p` have already been marked by some smaller prime factor. Thus, we only need to start crossing out multiples from `p * p`, and we only need outer loop iterations for `p` where `p * p < n`.

## Optimal approach
1. If `n < 3`, return 0 immediately.
2. Initialize a boolean array `comp` of size `n` with `false`, where `comp[x] == true` indicates `x` is composite.
3. For each integer `p` starting from 2 up to `p * p < n`:
   - If `comp[p]` is false, `p` is prime:
     - Mark every multiple `m = p * p, p * p + p, p * p + 2p, ...` as true (composite) while `m < n`.
4. Count all indices `i` from 2 up to `n - 1` where `comp[i]` is false.
5. Return the count.

Complexity:
- Time: `O(n log log n)` time because the sum of reciprocals of primes up to `n` grows proportionally to `log log n`.
- Space: `O(n)` auxiliary space for the boolean array.

## Code walkthrough
- `if (n < 3) return 0;` handles base cases `n = 0, 1, 2` where no primes exist below `n`.
- `vector<bool> comp(n, false);` provides an efficient bitset-like array tracking composites.
- `for (long long p = 2; p * p < n; p++)` only checks candidates whose squares do not exceed `n`.
- Inside the loop, `if (comp[p]) continue;` skips already marked composites.
- The inner loop `for (long long m = p * p; m < n; m += p)` flags all multiples starting from `p * p`.
- `for (int i = 2; i < n; i++) if (!comp[i]) count++;` aggregates the remaining prime count.

## Test it out loud
- Test `n = 2`: `n < 3` returns 0.
- Test `n = 3`: Array size 3. Loop `p * p < 3` ends at `p = 2` (`2 * 2 = 4 > 3`). Count loop checks `i = 2` which is not composite. Returns 1.
- Test `n = 4`: `p = 2` marks `m = 4` (out of bounds for size 4). Primes checked are 2 and 3. Returns 2.
- Test `n = 20`: Multiples of 2 and 3 marked. Surviving primes are 2, 3, 5, 7, 11, 13, 17, 19. Count is 8.
- Test `n = 100`: Known prime counting function value `pi(99) = 25`. Correct.

## Follow-ups
- Can we reduce memory consumption further?
  - Yes, by storing only odd numbers (skipping all evens), cutting space in half.
- What if `n` is up to `10^12` and we need the count of primes?
  - Sublinear prime counting algorithms such as Meissel-Lehmer or Lucy Hedgehog's algorithm run in `O(n^(2/3))` or `O(n^(3/4))`.

## Common mistakes
- Starting the inner loop at `2 * p` instead of `p * p`, performing redundant work.
- Integer overflow when calculating `p * p` without using 64-bit integer types when `n` is large.
- Counting `n` itself when the problem requires strictly less than `n`.
