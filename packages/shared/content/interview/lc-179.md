## Clarify first

- Can the array contain zeros? Yes, values range from 0 to 1,000,000,000.
- What if the array contains only zeros, like `[0, 0]`? The output should be `"0"`, not `"00"`.
- Can we reorder the individual digits of a number? No, each number is kept as an atomic block; we only decide the sequence in which the numbers are concatenated.
- What are the constraints on array length? Length is between 1 and 100.

## Examples to say out loud

- Ordering based on prefix: `nums = [10, 2]`.
  - Comparing `"102"` vs `"210"` shows that 2 must come before 10.
  - Result: `"210"`.
- Multi-digit numbers with overlapping prefixes: `nums = [3, 30, 34, 5, 9]`.
  - Comparing pairs: `"9"` comes first, then `"34"`, then `"3"`, then `"30"`. Note that 3 comes before 30 because `"330" > "303"`.
  - Result: `"9534330"`.
- Multiple zeros edge case: `nums = [0, 0]`. Returns `"0"`.

## Brute force

A brute-force solution generates all `n!` permutations of the array, concatenates each permutation into a string, and finds the lexicographically largest string. For `n = 100`, `100!` is vastly larger than the number of atoms in the universe, making this completely impossible.

## The key observation

To determine whether number `a` should precede number `b`, we directly compare their concatenations as strings: `a + b` versus `b + a`. If `a + b > b + a`, then `a` must come before `b`. This pairwise comparison relation is transitive and defines a valid total order over the set of string representations. Sorting the array using this custom comparator guarantees the globally largest concatenated number.

## Optimal approach

1. Convert every integer in `nums` into its string representation.
2. Sort the list of strings using a custom comparator: string `a` precedes string `b` if `a + b > b + a`.
3. If the first string in the sorted list is `"0"`, the largest possible number is zero, so return `"0"`.
4. Concatenate all sorted strings into a single string `out`.
5. Return `out`.

Complexity:
- Time: `O(n log n * L)` where `n` is `nums.length` and `L` is the maximum number of digits (at most 10). String comparisons during sorting take `O(L)` time.
- Space: `O(n * L)` auxiliary space to store the string representations.

## Code walkthrough

In the reference implementation:
- `vector<string> s; for (int x : nums) s.push_back(to_string(x));`: converts input integers into strings.
- `sort(s.begin(), s.end(), [](const string& a, const string& b) { return a + b > b + a; });`: sorts elements according to the concatenation total order.
- `if (s[0] == "0") return "0";`: collapses leading zeros when the maximum element is 0 (such as `[0, 0]`).
- `string out; for (auto& x : s) out += x;`: joins the sorted string segments into the final answer.
- `return out;`: returns the largest composite number string.

## Test it out loud

- `nums = [3, 30]`:
  - `a = "3", b = "30"`.
  - `a + b = "330"`, `b + a = "303"`. Since `"330" > "303"`, `"3"` precedes `"30"`.
  - Returns `"330"`.
- `nums = [0, 0]`:
  - Sorted strings: `["0", "0"]`.
  - `s[0] == "0"`, returns `"0"`.
- `nums = [1]`: returns `"1"`.

## Follow-ups

- Prove that the relation `a + b > b + a` is transitive.
  Viewing string concatenation as base-10 numerical values: `a \cdot 10^{|b|} + b > b \cdot 10^{|a|} + a \iff a / (10^{|a|} - 1) > b / (10^{|b|} - 1)`. Because each string maps to a real number, the ordering is strictly transitive.
- What if numbers can be negative?
  Negative numbers would require separating signs and minimizing magnitude for negatives placed at the end.

## Common mistakes

- Sorting strings lexicographically (`a > b`), which incorrectly places `"30"` before `"3"`.
- Forgetting to handle the all-zero case, returning `"000"` instead of `"0"`.
- Using 64-bit integer parsing on `a + b`, which can overflow since concatenated strings can exceed 20 digits.
