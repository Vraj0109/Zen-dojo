## Clarify first
- Are we allowed to modify the array? No, the array must remain read-only.
- What are the constraints on extra space? The solution must use only constant O(1) auxiliary space.
- Can the duplicate number appear more than twice? Yes, it can repeat two or more times.
- What are the value ranges? There are n + 1 integers, and each integer is between 1 and n inclusive.

## Examples to say out loud
- Consider `nums = [1, 3, 4, 2, 2]`:
  - `n = 4`, array length 5. Values are within `[1, 4]`.
  - The number 2 is duplicated. Return 2.
- Multiple repetitions: `nums = [2, 2, 2, 2, 2]`.
  - Returns 2.
- Value appears three times: `nums = [1, 4, 4, 2, 4]`.
  - Returns 4.

## Brute force
A brute force nested loop compares every pair `(i, j)` to find matching numbers in O(n^2) time and O(1) space. A hash set tracks seen numbers in O(n) time but takes O(n) space. Sorting places duplicates adjacent in O(n log n) time but modifies the array. In-place index negation solves it in O(n) time and O(1) space, but mutates the input. We can meet all constraints simultaneously using cycle detection.

## The key observation
Since each value `nums[i]` is between 1 and n, we can view `nums` as a directed functional graph where an edge exists from index `i` to index `nums[i]`.
Because index 0 has no incoming edges (no element has value 0), starting at index 0 and repeatedly following `i -> nums[i]` guarantees we will eventually enter a cycle. Furthermore, because a number is duplicated, at least two different indices point to that same duplicate value. In graph terms, that duplicate value has an in-degree of at least two, which makes it the entrance of the cycle.
Finding the duplicate is identical to finding the start of a cycle in a linked list using Floyd's Tortoise and Hare algorithm.

## Optimal approach
1. Phase 1 (Detect intersection in cycle):
   - Initialize two pointers `slow = nums[0]` and `fast = nums[0]`.
   - In a loop, advance `slow` by 1 step (`slow = nums[slow]`) and `fast` by 2 steps (`fast = nums[nums[fast]]`).
   - Continue until `slow == fast`.
2. Phase 2 (Find cycle entrance):
   - Reset `slow = nums[0]` while keeping `fast` at the meeting point.
   - Advance both `slow` and `fast` by 1 step at a time (`slow = nums[slow]`, `fast = nums[fast]`).
   - The node where they meet again is the entrance of the cycle, which is the duplicate number.
3. Return `slow`.

Complexity:
- Time complexity: O(n) because the hare catches the tortoise within one cycle traversal, and phase 2 traverses at most the length of the list before the cycle.
- Space complexity: O(1) auxiliary space as only two integer pointer variables are maintained.

## Code walkthrough
- `int slow = nums[0], fast = nums[0]`: Starts both pointers at the value pointed to by index 0.
- `do { slow = nums[slow]; fast = nums[nums[fast]]; } while (slow != fast)`: Advances `slow` 1 step and `fast` 2 steps until they intersect within the cycle.
- `slow = nums[0]`: Teleports `slow` back to the starting node.
- `while (slow != fast) { slow = nums[slow]; fast = nums[fast]; }`: Walks both pointers at identical single-step speed. Mathematical properties of Floyd's algorithm guarantee they meet at the entrance.
- Returns `slow`.

## Test it out loud
- Test `nums = [1, 3, 4, 2, 2]`:
  - Start: `slow = 1, fast = 1`.
  - Step 1: `slow = nums[1] = 3`, `fast = nums[nums[1]] = nums[3] = 2`.
  - Step 2: `slow = nums[3] = 2`, `fast = nums[nums[2]] = nums[4] = 2`. They meet at 2.
  - Phase 2: `slow = nums[0] = 1`, `fast = 2`.
  - Step 1: `slow = nums[1] = 3`, `fast = nums[2] = 4`.
  - Step 2: `slow = nums[3] = 2`, `fast = nums[4] = 2`. They meet at 2.
  - Returns 2. Matches expected output.

## Follow-ups
- Can this be solved using binary search? Yes, binary search on the range `[1, n]`. For each candidate `mid`, count how many elements in `nums` are `<= mid`. If `count > mid`, the duplicate lies in `[1, mid]`, otherwise in `[mid + 1, n]`. This runs in O(n log n) time and O(1) space without modifying the array.
- What if the elements were in range `[0, n - 1]`? Index 0 could then be part of a cycle, requiring care with the starting point or shifting values by +1.

## Common mistakes
- Starting `slow = 0, fast = 0` and using a standard `while (slow != fast)` loop, which terminates immediately before any steps are taken.
- Modifying the array with sign-flipping tricks when the interviewer explicitly requested a read-only input.
