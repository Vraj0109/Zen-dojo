## Clarify first
- What are the graph nodes and edges? Airports are nodes (3 capital letters), and flight tickets are directed edges `[from, to]`.
- Must every ticket be used? Yes, every ticket must be used exactly once (an Eulerian path).
- Where must the journey start? The itinerary must always start at `"JFK"`.
- If multiple valid itineraries exist, which one should be returned? The itinerary that has the smallest lexical order when reading airport names sequentially.
- Can duplicate tickets exist between the same pair of airports? Yes, multiple identical tickets may exist (multigraph).

## Examples to say out loud
- Consider `tickets = [["MUC","LHR"],["JFK","MUC"],["SFO","SJC"],["LHR","SFO"]]`:
  - Path: `JFK -> MUC -> LHR -> SFO -> SJC`.
  - All 4 tickets used. Output: `["JFK","MUC","LHR","SFO","SJC"]`.
- Branching with dead ends: `tickets = [["JFK","KUL"],["JFK","NRT"],["NRT","JFK"]]`:
  - From `"JFK"`, both `"KUL"` and `"NRT"` are available.
  - If we greedily take `"KUL"`, we get stuck because `"KUL"` has no outgoing flights, leaving two unused tickets.
  - Valid path: `JFK -> NRT -> JFK -> KUL`. Output: `["JFK","NRT","JFK","KUL"]`.

## Brute force
A brute force backtracking approach sorts tickets alphabetically and tries building paths using recursive DFS, undoing choices when reaching dead ends before all tickets are used. While this guarantees the lexicographically smallest path, backtracking on dense Eulerian graphs can take exponential time in the worst case due to repeated cycle exploration. Hierholzer's algorithm finds the Eulerian path in linear time without backtracking.

## The key observation
An itinerary that uses every flight exactly once is an Eulerian path in a directed multigraph.
Standard greedy forward traversal fails when an airport is a dead end (a node where all outgoing edges are exhausted before other sub-cycles are visited).
Hierholzer's algorithm handles this naturally:
- Always greedily visit the lexicographically smallest available outgoing edge.
- When an airport has no remaining outgoing edges (it is at a dead end), append it to the route.
- Airports that run out of outgoing edges first are pushed to the route first.
Reversing the final route list unwinds the dead ends to the correct place in the sequence, producing the complete, valid, lexicographically smallest Eulerian path in O(E log E) time.

## Optimal approach
1. Represent the directed multigraph using an adjacency map where each airport maps to a multiset (or min-heap) of destination airports. This automatically orders outgoing flights lexicographically.
2. Define a recursive helper `visit(airport)`:
   - While the current `airport` has remaining outgoing flights:
     - Extract the smallest destination `next_airport` and remove the edge from the graph.
     - Recursively call `visit(next_airport)`.
   - When no outgoing edges remain, push `airport` to the back of `route`.
3. Call `visit("JFK")`.
4. Reverse `route` and return it.

Complexity:
- Time complexity: O(E log E) where E is the number of tickets. Sorting edges in multisets or priority queues takes O(E log E). Each edge is removed and traversed exactly once.
- Space complexity: O(E) auxiliary space for the adjacency graph, recursion call stack, and result route.

## Code walkthrough
- `map<string, multiset<string>> g`: Stores sorted outgoing flights per airport, accommodating duplicate tickets cleanly.
- `while (!g[a].empty())`: Consumes outgoing edges from airport `a`.
- `string next = *g[a].begin(); g[a].erase(g[a].begin()); visit(next)`: Greedily explores the lexicographically first available destination.
- `route.push_back(a)`: Post-order insertion: only records the airport once all of its outgoing edges have been exhausted.
- `reverse(route.begin(), route.end())`: Reverses post-order traversal to obtain the chronological itinerary.

## Test it out loud
- Test `[["JFK","KUL"],["JFK","NRT"],["NRT","JFK"]]`:
  - At JFK: choices are `"KUL"` and `"NRT"`. Pops `"KUL"`.
  - At KUL: no outgoing edges. `route` pushes `"KUL"`.
  - Unwinds to JFK. Remaining edge is `"NRT"`.
  - At NRT: edge to `"JFK"`.
  - At JFK: no outgoing edges left. `route` pushes `"JFK"`.
  - Unwinds to NRT: pushes `"NRT"`.
  - Unwinds to initial JFK: pushes `"JFK"`.
  - `route = ["KUL", "JFK", "NRT", "JFK"]`.
  - Reversed: `["JFK", "NRT", "JFK", "KUL"]`. Valid and optimal.

## Follow-ups
- Can this be written iteratively? Yes, maintain an explicit stack of airports. When the top airport has no outgoing edges, pop it and append to `route`; otherwise push its next unvisited neighbor onto the stack.
- What if an Eulerian path was not guaranteed to exist? We would need to verify that in-degrees and out-degrees satisfy Eulerian path criteria (`out - in == 1` at start, `in - out == 1` at end, and all others balanced).

## Common mistakes
- Appending airports to the itinerary on the way down before exploring children, which gets trapped in dead ends.
- Using `std::set` instead of `std::multiset` or `std::priority_queue`, which drops duplicate tickets between the same pair of airports.
- Erasing by value in `std::multiset` (`g[a].erase(val)`), which deletes all duplicate instances rather than a single edge; must erase by iterator (`g[a].erase(g[a].begin())`).
