## Clarify first

- What do the vertices and edges represent? (Courses are vertices `0` to `numCourses - 1`; a pair `[a, b]` means directed edge `b -> a`, taking `b` before `a`).
- Can there be self-loops or duplicate prerequisites? (Problem specifies pairs are distinct, but a self-loop `[a, a]` should immediately make it impossible).
- What if there are disconnected components or courses with no prerequisites? (Courses with no dependencies can be completed immediately).
- Can `prerequisites` be empty? (Yes; if there are no constraints, all courses can be finished, returning true).
- Are we returning boolean possibility or the actual topological ordering? (Returning boolean `true` if all courses can be finished, `false` if impossible).

## Examples to say out loud

- Linear dependency: `numCourses = 2, prerequisites = [[1, 0]]`. Course 0 has in-degree 0; take course 0, which unlocks course 1 (in-degree drops to 0). Both taken; return `true`.
- Direct 2-cycle: `numCourses = 2, prerequisites = [[1, 0], [0, 1]]`. Both courses have in-degree 1. No course can be started. Neither course is taken; return `false`.
- Disconnected graph: `numCourses = 3, prerequisites = []`. All 3 courses start with in-degree 0 and can be finished without constraint; return `true`.

## Brute force

A naive approach attempts to find cycles by running simple depth-first searches from every single node without memoizing visited states, or by checking all permutations of courses to verify if any ordering satisfies all prerequisites. Testing permutations requires `O(n!)` time, which is impossible even for `numCourses = 20`. Unmemoized path tracking can explore exponential paths in dense directed acyclic graphs.

## The key observation

The problem asks whether a directed graph has a valid topological ordering, which is true if and only if the directed graph contains no directed cycles. Using Kahn's algorithm (BFS with in-degrees), we can repeatedly remove vertices with zero prerequisites. If the total number of removed vertices equals `numCourses`, the graph is cycle-free; otherwise, any remaining vertices are trapped in one or more cycles.

## Optimal approach

1. Build an adjacency list `g` of size `numCourses` where `g[b]` contains `a` for each prerequisite pair `[a, b]`.
2. Compute an array `indegree` of size `numCourses`, where `indegree[a]` is the number of incoming prerequisites for course `a`.
3. Enqueue all courses with `indegree[i] == 0` into a FIFO queue `q`.
4. Initialize a counter `taken = 0`.
5. While `q` is not empty:
   a. Dequeue a course `u` and increment `taken`.
   b. For each neighbor `v` in `g[u]`, decrement `indegree[v]`.
   c. If `indegree[v]` becomes 0, push `v` into `q`.
6. Return `taken == numCourses`.

Complexity:
- Time: `O(V + E)` where `V = numCourses` and `E = prerequisites.length`. Building the graph takes `O(V + E)`, and every vertex and edge is processed at most once during queue processing.
- Space: `O(V + E)` to store the adjacency list `g`, in-degree array, and queue.

## Code walkthrough

In the reference implementation:
- `vector<vector<int>> g(numCourses); vector<int> indeg(numCourses, 0);`: builds adjacency and in-degree tables.
- `for (auto& p : prerequisites) { g[p[1]].push_back(p[0]); indeg[p[0]]++; }`: establishes directed prerequisite edges `b -> a`.
- `queue<int> q; for (int i = 0; i < numCourses; i++) if (indeg[i] == 0) q.push(i);`: initializes queue with independent courses.
- `taken++`: counts every valid course completed.
- `if (--indeg[v] == 0) q.push(v);`: unlocks dependent courses dynamically as prerequisites clear.
- `return taken == numCourses;`: confirms no cyclical blockage prevented full completion.

## Test it out loud

- 3-cycle: `numCourses = 3, prerequisites = [[1, 0], [2, 1], [0, 2]]`:
  - `indeg = [1, 1, 1]`. Queue is initially empty.
  - While loop does not run. `taken = 0 != 3`, returns `false`.
- Tree dependencies: `numCourses = 4, prerequisites = [[1, 0], [2, 0], [3, 1], [3, 2]]`:
  - `indeg[0] = 0`, queue gets `[0]`.
  - Process 0: unlocks 1 and 2 (`indeg` both 0).
  - Process 1 and 2: both decrement `indeg[3]`, which reaches 0.
  - Process 3: all 4 courses taken. Returns `true`.

## Follow-ups

- How to return the actual order of courses? (LeetCode 210 Course Schedule II):
  Append each dequeued course to an order list; if `taken == numCourses`, return the list, otherwise return empty.
- How to detect cycles using DFS instead of Kahn's BFS?
  Use a three-state coloring system: unvisited (0), currently visiting on the current recursion stack (1), and completely processed (2). Finding a neighbor in state 1 indicates a back-edge and cycle.
- What if there are edge weights or we want the minimum time with parallel course completion?
  Use topological sort with dynamic programming: compute earliest completion time `dist[v] = max(dist[v], dist[u] + time[v])`.

## Common mistakes

- Inverting edge direction (`a -> b` instead of `b -> a`): while cycle detection still succeeds because cycles exist regardless of reversal, topological ordering and prerequisite logic become inverted.
- Using simple two-state boolean visited flags in DFS, which fails to distinguish between already finished subtrees and cycles in directed graphs.
- Forgetting to handle disconnected components or courses that have zero incoming and outgoing edges.
