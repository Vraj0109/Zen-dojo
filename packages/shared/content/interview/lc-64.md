## Clarify first

- Can values in the grid be negative? No, values are non-negative integers (`0 <= grid[i][j] <= 200`).
- Are valid movements strictly right and down? Yes, you can only move right or down from each cell.
- Can we modify the grid in-place to save space? Yes, mutating `grid[r][c]` directly achieves `O(1)` auxiliary space.
- What are the dimensions of the grid? Both rows and columns are between 1 and 200.

## Examples to say out loud

- Rectangular grid: `grid = [[1, 3, 1], [1, 5, 1], [4, 2, 1]]`.
  - Path `1 -> 3 -> 1 -> 1 -> 1` sums to 7.
  - Path `1 -> 1 -> 4 -> 2 -> 1` sums to 9.
  - Path `1 -> 1 -> 5 -> 1 -> 1` sums to 9.
  - Minimum path sum is 7.
- Single cell: `grid = [[5]]`. Start and destination are the same cell, result is 5.
- Single row: `grid = [[1, 2, 3]]`. Can only move right, result is `1 + 2 + 3 = 6`.

## Brute force

A brute-force recursive solution computes `minCost(r, c) = grid[r][c] + min(minCost(r + 1, c), minCost(r, c + 1))`. Because every cell branches into two subproblems, the recursion tree has depth `(rows - 1) + (cols - 1)`. Without memoization, this explores `2^{rows + cols}` paths, which is unfeasible for a `200 \times 200` grid.

## The key observation

The cheapest way to reach cell `(r, c)` must come from the cheaper of the two possible preceding cells: the cell above `(r - 1, c)` or the cell to the left `(r, c - 1)`. Therefore, the recurrence is `dp[r][c] = grid[r][c] + min(dp[r - 1][c], dp[r][c - 1])`. Because each cell only depends on cells above and to the left, we can update the grid in standard row-major reading order directly in-place.

## Optimal approach

1. Let `rows = grid.length` and `cols = grid[0].length`.
2. Iterate `r` from 0 to `rows - 1`:
   - Iterate `c` from 0 to `cols - 1`:
     - If `r == 0 && c == 0`, continue (starting cell is unchanged).
     - Let `up = (r > 0) ? grid[r - 1][c] : infinity`.
     - Let `left = (c > 0) ? grid[r][c - 1] : infinity`.
     - Update `grid[r][c] += min(up, left)`.
3. Return `grid[rows - 1][cols - 1]`.

Complexity:
- Time: `O(rows * cols)` because every cell is visited and updated once in a double loop.
- Space: `O(1)` auxiliary space by reusing the input grid in-place (or `O(cols)` if the input must remain immutable).

## Code walkthrough

In the reference implementation:
- `if (r == 0 && c == 0) continue;`: preserves the initial cost of the starting square.
- `int up = r > 0 ? grid[r - 1][c] : INT_MAX;`: checks the top neighbor cost, guarding against out-of-bounds at the top border.
- `int left = c > 0 ? grid[r][c - 1] : INT_MAX;`: checks the left neighbor cost, guarding against out-of-bounds at the left border.
- `grid[r][c] += min(up, left);`: accumulates the minimum incoming cost into the current cell.
- `return grid[rows - 1][cols - 1];`: extracts the accumulated minimum path cost reaching the bottom-right target.

## Test it out loud

- `grid = [[1, 2], [1, 1]]`:
  - `(0, 0) = 1`.
  - `(0, 1)`: top is inf, left is 1 -> `2 + 1 = 3`.
  - `(1, 0)`: top is 1, left is inf -> `1 + 1 = 2`.
  - `(1, 1)`: top is 3, left is 2 -> `1 + min(3, 2) = 3`.
  - Returns 3.
- `grid = [[1, 2, 5], [3, 2, 1]]`:
  - Row 0: `[1, 3, 8]`.
  - Row 1: `(1, 0) = 3 + 1 = 4`. `(1, 1) = 2 + min(3, 4) = 5`. `(1, 2) = 1 + min(8, 5) = 6`.
  - Returns 6.

## Follow-ups

- What if the input grid is strictly read-only and cannot be mutated?
  Use a 1D rolling array of size `cols`, achieving `O(cols)` auxiliary space.
- How would you reconstruct the path of coordinates chosen?
  Trace backward from `(rows - 1, cols - 1)` to `(0, 0)` by moving to whichever of `(r - 1, c)` or `(r, c - 1)` has the smaller value.
- What if negative weights or 4-directional moves are allowed?
  Use Dijkstra's algorithm (for non-negative weights) or Bellman-Ford / SPFA (for negative weights).

## Common mistakes

- Defaulting missing boundary neighbors to 0 instead of infinity, causing edge cells to mistakenly pick 0 as the cheaper incoming cost.
- Mutating cells before their neighbors have been read, which can happen if loops don't follow reading order.
- Not handling the `r == 0 && c == 0` starting condition.
