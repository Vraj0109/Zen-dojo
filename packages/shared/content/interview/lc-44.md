## Clarify first
- What special characters are present in the pattern?
  - `?` matches any single character.
  - `*` matches any sequence of characters (including the empty sequence of length 0).
- Does `*` depend on a preceding character? No, unlike regular expressions, `*` stands completely on its own as a multi-character wildcard.
- Must the entire string `s` match the entire pattern `p`? Yes, full string matching is required.
- Can strings be empty? Yes, lengths can be 0 up to 2000.

## Examples to say out loud
- Star matching empty: `s = "aa"`, `p = "*"`.
  - `*` matches `"aa"`. Output: true.
- Star matching zero characters: `s = "abc"`, `p = "a*c"`.
  - 'a' matches 'a', `*` matches 'b', 'c' matches 'c'. Output: true.
- Question mark: `s = "cb"`, `p = "?a"`.
  - '?' matches 'c', but 'a' does not match 'b'. Output: false.
- Both empty: `s = ""`, `p = ""`. Output: true. `s = ""`, `p = "*"`. Output: true.

## Brute force
A brute force recursive backtracking approach tests both possibilities for each `*`: either match 0 characters from `s` or consume 1 character from `s` and retry matching. Without memoization, patterns with multiple consecutive stars or overlapping prefixes branch exponentially into O(2^(|s| + |p|)) time. Dynamic programming caches prefix matches and runs in O(|s| * |p|) time.

## The key observation
Define subproblem `dp[i][j]` as: does prefix `s[0..i-1]` match prefix `p[0..j-1]`?
- Base cases:
  - `dp[0][0] = true` (empty string matches empty pattern).
  - For empty string `s` with pattern prefix `p[0..j-1]`: `dp[0][j] = dp[0][j - 1]` if `p[j - 1] == '*'`. (A leading sequence of stars matches the empty string).
- For each character pair:
  - If `p[j - 1] == '*'`:
    - Option 1 (matches 0 characters): `dp[i][j - 1]`.
    - Option 2 (matches 1 or more characters): `dp[i - 1][j]`.
    - Thus: `dp[i][j] = dp[i][j - 1] || dp[i - 1][j]`.
  - Else if `p[j - 1] == '?'` or `p[j - 1] == s[i - 1]`:
    - Exact 1-to-1 match: `dp[i][j] = dp[i - 1][j - 1]`.
  - Else:
    - Characters conflict: `dp[i][j] = false`.

## Optimal approach
1. Let `n = s.length()` and `m = p.length()`.
2. Allocate a 2D boolean array `dp` of size `(n + 1) x (m + 1)` initialized to false.
3. Set `dp[0][0] = true`.
4. Initialize the first row for empty `s`:
   - For `j` from 1 to `m`:
     - If `p[j - 1] == '*'`: `dp[0][j] = dp[0][j - 1]`.
5. Iterate `i` from 1 to `n`:
   - Iterate `j` from 1 to `m`:
     - If `p[j - 1] == '*'`:
       - `dp[i][j] = dp[i][j - 1] || dp[i - 1][j]`.
     - Else:
       - `dp[i][j] = dp[i - 1][j - 1] && (p[j - 1] == '?' || p[j - 1] == s[i - 1])`.
6. Return `dp[n][m]`.

Complexity:
- Time complexity: O(|s| * |p|) where each state `(i, j)` is evaluated once in O(1) time.
- Space complexity: O(|s| * |p|) for the full table, or O(|p|) auxiliary space by maintaining only the previous and current rows.

## Code walkthrough
- `dp[0][0] = true`: Empty string matches empty pattern.
- `for (int j = 1; j <= m; j++) if (p[j - 1] == '*') dp[0][j] = dp[0][j - 1]`: Initializes leading asterisks that match empty prefixes.
- `if (p[j - 1] == '*') dp[i][j] = dp[i][j - 1] || dp[i - 1][j]`: Evaluates `*` as empty or consuming the current character `s[i - 1]`.
- `else dp[i][j] = dp[i - 1][j - 1] && (...)`: Validates single character match against letter or '?'.
- Returns `dp[n][m]`.

## Test it out loud
- Test `s = "aa", p = "*"`:
  - `dp[0][0] = true`, `dp[0][1] = true` (p[0]=='*').
  - `i = 1` ('a'): `dp[1][1] = dp[1][0] || dp[0][1] = false || true = true`.
  - `i = 2` ("aa"): `dp[2][1] = dp[2][0] || dp[1][1] = false || true = true`.
  - Returns true. Correct.
- Test `s = "cb", p = "?a"`:
  - `dp[1][1]` ('c' vs '?') = true.
  - `dp[2][2]` ('b' vs 'a') = false.
  - Returns false. Correct.

## Follow-ups
- Can this be solved in O(1) extra space with two pointers? Yes, a greedy two-pointer algorithm maintains `s_ptr`, `p_ptr`, `star_idx`, and `match_s`. Whenever mismatch occurs, backtrack to the last seen `*` and advance `match_s`. This uses O(1) auxiliary space and runs in average O(|s| + |p|) time.
- Why does the two-pointer greedy approach work for Wildcard Matching but not Regular Expression Matching? In wildcard matching, `*` matches any character uniformly, so the latest star can greedily absorb characters without needing backtracking across multiple choices of previous characters.

## Common mistakes
- Forgetting to initialize the first row `dp[0][j]` for patterns with leading `*` characters.
- Confusing 1-based DP indices `i, j` with 0-based string indices `s[i - 1], p[j - 1]`.
- Mixing up wildcard `*` with regex `*` rules.
