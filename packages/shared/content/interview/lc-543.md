## Clarify first

- Is diameter measured in number of nodes or number of edges? The problem defines diameter as the number of edges on the longest path between any two nodes.
- Does the longest path have to pass through the root? No, the longest path can reside entirely within a single subtree.
- Can the tree contain only a single node? Yes, if there is 1 node, there are no edges, so diameter is 0.
- How large can the tree be? The tree contains between 1 and 10,000 nodes.

## Examples to say out loud

- Standard case passing through root: `root = [1, 2, 3, 4, 5]`.
  - Node 2 has children 4 and 5 (height 2).
  - Node 3 has no children (height 1).
  - Path from 4 through 2, 1 to 3 has 3 edges: `4 -> 2 -> 1 -> 3`. Diameter is 3.
- Subtree-only case: A tree where the root's right child is null, but the left subtree has two deep branches that do not pass through the root.
- Single node edge case: `root = [1]`. Has 0 edges, diameter is 0.

## Brute force

A brute-force solution calculates the depth of the left and right subtrees for every node `u` in the tree using a standalone depth function. For each node, it computes `depth(u->left) + depth(u->right)` and takes the maximum over all nodes. Because calculating depth takes `O(n)` time, calling it for all `n` nodes leads to `O(n^2)` time in an unbalanced tree.

## The key observation

The longest path that peaks at any node `u` has length equal to the maximum depth of its left subtree plus the maximum depth of its right subtree (`left_height + right_height`). We can compute subtree heights bottom-up with a single post-order depth-first search (DFS), updating the global diameter at each node while returning `1 + max(left_height, right_height)` to the parent.

## Optimal approach

1. Maintain a global integer variable `best = 0` to record the maximum diameter.
2. Define a recursive helper function `height(node)`:
   a. If `node == null`, return 0.
   b. Recursively compute `l = height(node.left)` and `r = height(node.right)`.
   c. Update the maximum path: `best = max(best, l + r)`.
   d. Return `1 + max(l, r)` to inform the parent of this subtree's height.
3. Call `height(root)` and return `best`.

Complexity:
- Time: `O(n)` because each node in the tree is visited exactly once during the post-order traversal.
- Space: `O(h)` call stack space, where `h` is the height of the tree (`O(log n)` for balanced trees, `O(n)` for degenerated linked-list shaped trees).

## Code walkthrough

In the reference implementation:
- `int best = 0;`: tracks the longest edge path encountered across all subtrees.
- `int height(TreeNode* n)`: computes height and updates diameter as a side effect.
- `if (!n) return 0;`: base case; null nodes contribute 0 height.
- `int l = height(n->left), r = height(n->right);`: recursively fetches child heights.
- `best = max(best, l + r);`: tests the path bending at node `n`.
- `return 1 + max(l, r);`: returns height of the current node to its caller.

## Test it out loud

- `root = [1, 2, 3, 4, 5]`:
  - Leaf 4: `l = 0, r = 0`, `best = max(0, 0) = 0`, returns 1.
  - Leaf 5: `l = 0, r = 0`, `best = max(0, 0) = 0`, returns 1.
  - Node 2: `l = 1, r = 1`, `best = max(0, 1 + 1) = 2`, returns `1 + 1 = 2`.
  - Leaf 3: `l = 0, r = 0`, `best = max(2, 0) = 2`, returns 1.
  - Root 1: `l = 2, r = 1`, `best = max(2, 2 + 1) = 3`, returns `1 + 2 = 3`.
  - Final diameter is 3.
- `root = [1]`:
  - `l = 0, r = 0`, `best = 0`, returns 1. Result is 0.

## Follow-ups

- What if node values can be weighted or negative (Binary Tree Maximum Path Sum, LeetCode 124)?
  Instead of edges, accumulate node values, clamping negative child path sums to 0 before combining.
- How would you return the actual sequence of nodes forming the diameter?
  Reconstruct the path by recording the node that achieved `best` along with pointers down the deepest branch of its left and right subtrees.

## Common mistakes

- Returning number of nodes instead of number of edges (e.g. `l + r + 1` instead of `l + r`).
- Assuming the diameter path must pass through the tree root.
- Re-calculating subtree heights from scratch at each node, degrading time complexity from `O(n)` to `O(n^2)`.
