## Clarify first

- What is the width of each bar in the histogram? Each bar has width 1.
- Can bar heights be zero? Yes, a bar of height 0 contributes 0 area and acts as a boundary barrier.
- What if the histogram has only 1 bar? The area is `heights[0] * 1 = heights[0]`.
- What are the input constraints? Length is between 1 and 100,000, and heights are between 0 and 10,000.

## Examples to say out loud

- Standard histogram: `heights = [2, 1, 5, 6, 2, 3]`.
  - The bars at index 2 (height 5) and index 3 (height 6) can form a rectangle of height 5 and width 2 (`6 - 2 = 2`), giving area `5 * 2 = 10`.
  - This is the maximum rectangle area that fits in the histogram.
- Flat histogram: `heights = [2, 2, 2]`. Rectangle spans all 3 bars: `2 * 3 = 6`.
- Single bar: `heights = [4]`. Area is 4.
- All zero bar: `heights = [0]`. Area is 0.

## Brute force

A brute-force solution considers every bar `i` as the bottleneck height of a rectangle. For each bar `i`, scan left to find the first bar shorter than `heights[i]`, and scan right to find the first bar shorter than `heights[i]`. The width is `(right_index - 1) - (left_index + 1) + 1 = right_index - left_index - 1`. The area is `heights[i] * width`. Since scanning left and right takes `O(n)` per bar, this takes `O(n^2)` time. With `n = 100,000`, `10^{10}` operations will exceed time limits.

## The key observation

For each bar `i`, we need its nearest strictly smaller bar to the left and its nearest strictly smaller bar to the right. A monotonic increasing stack of bar indices provides exactly this: when a new bar `i` is shorter than the bar at the top of the stack, bar `i` serves as the right boundary for the popped bar, and the newly exposed top of the stack serves as its left boundary. Adding a dummy bar of height 0 at the end cleanly flushes all remaining bars.

## Optimal approach

1. Let `n = heights.length`, and initialize `best = 0`.
2. Initialize an empty stack `st` of integer indices.
3. Iterate `i` from 0 to `n`:
   a. Let `h = (i == n) ? 0 : heights[i]`.
   b. While `st` is not empty and `heights[st.back()] > h`:
      i. Pop `idx = st.back()`.
      ii. Let `height = heights[idx]`.
      iii. Let `left = st.empty() ? 0 : st.back() + 1`.
      iv. Calculate width `w = i - left`.
      v. Update `best = max(best, height * w)`.
   c. Push `i` onto `st`.
4. Return `best`.

Complexity:
- Time: `O(n)` because every bar index is pushed onto the stack once and popped at most once, performing `O(1)` amortized work per bar.
- Space: `O(n)` auxiliary space for the stack storing at most `n + 1` indices.

## Code walkthrough

In the reference implementation:
- `for (int i = 0; i <= n; i++)`: loops up to `n` to include the virtual 0-height sentinel that flushes the stack.
- `int h = (i == n) ? 0 : heights[i];`: assigns sentinel height 0 at index `n`.
- `while (!st.empty() && heights[st.back()] > h)`: identifies that the current bar `i` strictly caps the rightward extension of `st.back()`.
- `int height = heights[idx]; int left = st.empty() ? 0 : st.back() + 1;`: computes the maximum width the popped bar can span across without dipping below its height.
- `best = max(best, height * (i - left));`: updates maximum rectangular area.
- `st.push_back(i);`: preserves the monotonic ascending invariant.

## Test it out loud

- `heights = [2, 1, 2]`:
  - `i = 0 (2)`: push 0. Stack `[0]`.
  - `i = 1 (1)`: `heights[0] (2) > 1`. Pop 0: `height = 2`, `left = 0`, width `1 - 0 = 1`, area `2 * 1 = 2`. Push 1. Stack `[1]`.
  - `i = 2 (2)`: push 2. Stack `[1, 2]`.
  - `i = 3 (sentinel 0)`:
    - Pop 2: `height = 2`, `left = 1 + 1 = 2`, width `3 - 2 = 1`, area `2`.
    - Pop 1: `height = 1`, stack empty so `left = 0`, width `3 - 0 = 3`, area `1 * 3 = 3`.
  - Max area is 3.

## Follow-ups

- How does this solve Maximal Rectangle in a binary matrix (LeetCode 85)?
  Treat each row of the matrix as a histogram baseline (accumulating consecutive 1s down the columns) and run the histogram algorithm on each row in `O(R * C)` time.
- What if bar widths are variable?
  Accumulate widths rather than index differences.

## Common mistakes

- Forgetting to flush remaining bars at the end of the loop, which fails on non-decreasing inputs like `[1, 2, 3, 4]`.
- Miscalculating the left boundary when the stack is empty (it should be 0, not `idx`).
- Scanning left and right naively with nested loops, leading to quadratic time complexity.
