## Clarify first

- What does the grid initially contain? (An empty grid of size $m \times n$ containing only water `0`).
- What does each entry in `positions` represent? (A coordinate `[r, c]` where water is converted into land `1`).
- What happens if the same cell is added multiple times? (Repeated additions to an existing land cell have no effect; return the current island count).
- Can $m \times n$ be up to $10^4$? (Yes, $m \cdot n \le 10^4$, and `positions.length` $\le 10^4$).
- How are islands defined? (4-directionally connected components of land cells).

## Examples to say out loud

- Progressive land additions: `m = 3, n = 3`, `positions = [[0, 0], [0, 1], [1, 2], [2, 1]]`.
  - Add `(0, 0)`: 1 new island $\to 1$.
  - Add `(0, 1)`: adjacent to `(0, 0)`, merges with it $\to 1$.
  - Add `(1, 2)`: isolated island $\to 2$.
  - Add `(2, 1)`: isolated island $\to 3$.
  - Result: `[1, 1, 2, 3]`.
- Duplicate addition: `positions = [[0, 0], [0, 1], [2, 2], [2, 2]]`. Second addition of `(2, 2)` does nothing; output is `[1, 1, 2, 2]`.
- Central bridge merging four islands: Four separate islands around `(1, 1)`. When `(1, 1)` is added, count drops from 4 to 1 because all 4 neighbors merge into a single component.

## Brute force

The brute force runs standard BFS or DFS across the entire $m \times n$ grid after every single land placement in `positions`. With $k$ operations, re-running BFS takes $O(m \cdot n)$ per query, resulting in $O(k \cdot m \cdot n)$ total time. For $k = 10^4$ and $m \cdot n = 10^4$, this requires $10^8$ operations, which is far too slow for an interactive stream of operations.

## The key observation

This is a dynamic connectivity problem where edges and vertices are added incrementally. Disjoint Set Union (DSU / Union-Find) supports near-$O(1)$ component unions and root lookups. By flattening 2D coordinates $(r, c)$ into a 1D index $r \cdot n + c$, each new land cell starts as an isolated component of size 1 (incrementing `count`). Checking its 4 cardinal neighbors and performing `unite` whenever a neighbor is already land decrements `count` for each distinct component merged.

## Optimal approach

1. Flatten the $m \times n$ grid into 1D indices: $\text{idx} = r \cdot n + c$.
2. Initialize a `parent` array of size $m \cdot n$ filled with `-1` (indicating water).
3. Initialize `count = 0` and an empty list `res`.
4. For each `[r, c]` in `positions`:
   - Compute $\text{idx} = r \cdot n + c$.
   - If `parent[idx] != -1` (cell is already land):
     - Append `count` to `res` and continue.
   - Mark cell as land by setting `parent[idx] = idx`.
   - Increment `count++` (temporary new island).
   - Check all 4 cardinal neighbors `(nr, nc)`:
     - If `(nr, nc)` is within grid bounds:
       - Compute $\text{nidx} = nr \cdot n + nc$.
       - If `parent[nidx] != -1`:
         - Attempt `unite(idx, nidx)`.
         - If `unite` succeeds (roots were different), decrement `count--`.
   - Append current `count` to `res`.
5. Return `res`.

Complexity:
- Time: `O(k * alpha(m * n))` where $k$ is the number of positions and $\alpha$ is the Inverse Ackermann function (effectively constant, $\le 4$).
- Space: `O(m * n)` auxiliary space for the `parent` array of size $m \cdot n$.

## Code walkthrough

In the reference implementation:
- `parent.assign(m * n, -1);`: distinguishes water (`-1`) from land (`>= 0`).
- `int findRoot(int i)`: finds the canonical representative with path compression.
- `bool unite(int i, int j)`: joins two sets and returns `true` only if they were previously separate.
- `if (parent[idx] != -1)`: detects duplicate coordinates and appends the existing count unchanged.
- `if (unite(idx, nidx)) count--;`: decrements the island count on every successful merge.

## Test it out loud

- Single cell: `1x1` grid with `[[0, 0]]`. Starts with count 0, sets `parent[0] = 0`, count becomes 1, no neighbors, outputs `[1]`.
- Bridge connection: `1x4` grid, add `0` then `2` (count becomes 2). Adding `1` connects both, count drops from $2 + 1 = 3$ to 1, then adding `3` merges, keeping 1. Output `[1, 2, 1, 1]`.
- Enclosing ring: Multiple additions form a loop; redundant edges do not reduce count below 1 because `unite` returns `false` on identical roots.

## Follow-ups

- What if positions can also be removed (dynamic deletions)?
  Union-Find does not natively support deletions; we would need offline queries with time-travel / rollback DSU and divide-and-conquer on query intervals, or dynamic graph connectivity (Euler Tour Tree / Holm-de Lichtenberg-Thorup).
- What if the grid dimensions $m$ and $n$ are very large (e.g. $10^9$) but $k \le 10^4$?
  Instead of a fixed size $m \times n$ array, use a hash map for `parent` where coordinates are mapped as `(long long)r << 32 | c`.
- How to return the size of the largest island after each step?
  Maintain a `size` array in DSU; during `unite`, sum the component sizes and track a running `maxSize`.

## Common mistakes

- Forgetting to handle duplicate positions in `positions`: re-processing an existing land cell as a new island will corrupt the island count.
- Decrementing island count on every neighbor check without checking if the neighbor's root is already identical to the current root (e.g., cell adjacent to two cells of the same island).
- Incorrect 2D to 1D index mapping: using `r * m + c` instead of `r * n + c`.
