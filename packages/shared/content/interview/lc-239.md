## Clarify first

- What should be returned if `nums` is empty or `k = 0`? Return an empty array.
- Can `k` be greater than `nums.length`? Constraints guarantee `1 <= k <= nums.length`.
- What values can elements take? Negative and positive numbers between -10,000 and 10,000.
- In what order should the maximums be returned? In chronological order as the window moves from left to right (total `n - k + 1` window maximums).

## Examples to say out loud

- Standard sliding window: `nums = [1, 3, -1, -3, 5, 3, 6, 7]`, `k = 3`.
  - Window `[1, 3, -1]`: max is 3.
  - Window `[3, -1, -3]`: max is 3.
  - Window `[-1, -3, 5]`: max is 5.
  - Window `[-3, 5, 3]`: max is 5.
  - Window `[5, 3, 6]`: max is 6.
  - Window `[3, 6, 7]`: max is 7.
  - Output is `[3, 3, 5, 5, 6, 7]`.
- Single element window: `nums = [1]`, `k = 1`. Output is `[1]`.
- Decreasing sequence: `nums = [9, 8, 7, 6]`, `k = 2`. Output is `[9, 8, 7]`.

## Brute force

A brute-force solution slides the window of size `k` over the array. For each of the `n - k + 1` positions, it scans all `k` elements in the window to find the maximum value. This takes `O((n - k + 1) * k) = O(n * k)` time. For `n = 100,000` and `k = 50,000`, this requires `2.5 \times 10^9` operations, which exceeds time limits.

## The key observation

If an older element in the current window is smaller than or equal to a newer element (`nums[j] <= nums[i]` where `j < i`), that older element can **never** be the maximum of the current window or any future window, because the newer element is both larger and will stay in the window longer. We can maintain a monotonic deque of indices with strictly decreasing values:
1. The front of the deque always holds the maximum of the active window.
2. When the front index slides out of the window (`<= i - k`), pop it from the front.
3. Before pushing index `i`, pop all indices from the back whose values are `<= nums[i]`.

## Optimal approach

1. Initialize a double-ended queue `dq` to store indices, and an array `ans` to store results.
2. Iterate `i` from 0 to `nums.length - 1`:
   a. While `dq` is not empty and `dq.front() <= i - k`: pop from the front (evict indices outside the active window).
   b. While `dq` is not empty and `nums[dq.back()] <= nums[i]`: pop from the back (eliminate dominated smaller elements).
   c. Push the current index `i` to the back of `dq`.
   d. If `i >= k - 1`: the first window of size `k` has formed; append `nums[dq.front()]` to `ans`.
3. Return `ans`.

Complexity:
- Time: `O(n)` because every index is pushed into the deque once and popped at most once, taking amortized `O(1)` per element.
- Space: `O(k)` auxiliary space for the deque, which stores at most `k` indices at any time.

## Code walkthrough

In the reference implementation:
- `deque<int> dq;`: holds indices in monotonically decreasing order of their array values.
- `while (!dq.empty() && dq.front() <= i - k) dq.pop_front();`: discards the oldest element when the sliding window moves past its index.
- `while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();`: flushes smaller earlier elements that are rendered obsolete by `nums[i]`.
- `dq.push_back(i);`: registers the current element index.
- `if (i >= k - 1) ans.push_back(nums[dq.front()]);`: records the current window maximum from the front of the deque once window size `k` is reached.

## Test it out loud

- `nums = [1, 3, -1, -3, 5], k = 3`:
  - `i = 0 (1)`: `dq = [0]`.
  - `i = 1 (3)`: `nums[0] <= 3`, pop 0. Push 1. `dq = [1]`.
  - `i = 2 (-1)`: push 2. `dq = [1, 2]`. `i = 2 >= 2`: window complete! Front is 1 -> add `nums[1] = 3`.
  - `i = 3 (-3)`: push 3. `dq = [1, 2, 3]`. Front 1 not `<= 0`. Add `nums[1] = 3`.
  - `i = 4 (5)`: front 1 `<= 4 - 3 = 1` -> pop front. Back elements 3 and 2 are `< 5`, pop back. Push 4. `dq = [4]`. Add `nums[4] = 5`.
  - Output: `[3, 3, 5]`.

## Follow-ups

- What if we used a max-heap instead?
  A max-heap storing `(nums[i], i)` achieves `O(n log n)` time by lazily popping out-of-window elements from the top.
- Can this be solved in `O(n)` without a deque?
  Yes, block partitioning (splitting the array into blocks of size `k` and taking prefix/suffix maxes) achieves `O(n)` time and `O(n)` space.

## Common mistakes

- Storing values in the deque instead of indices, which makes it impossible to verify whether the front element has expired past `i - k`.
- Using `<` instead of `<=` when popping from the back, allowing duplicate values to linger unnecessarily.
- Using a heap or multiset without realizing it introduces an extra `O(log k)` factor per element.
