## Clarify first

- In what order should the result elements be returned? The answer can be returned in any order.
- Is the answer guaranteed to be unique? Yes, constraints ensure the top `k` frequent elements set is uniquely defined.
- What are the constraints on `nums.length` and `k`? `nums.length` is up to 100,000, and `1 <= k <= distinct values`.
- Is `O(n log n)` acceptable? The problem statement explicitly prompts for better than `O(n log n)` time.

## Examples to say out loud

- Standard array: `nums = [1, 1, 1, 2, 2, 3]`, `k = 2`.
  - Frequency count: `1: 3`, `2: 2`, `3: 1`.
  - The 2 most frequent numbers are 1 and 2. Output is `[1, 2]`.
- Single element: `nums = [1]`, `k = 1`. Frequency `1: 1`. Output is `[1]`.
- Negative numbers: `nums = [-1, -1, 2, 2, 3]`, `k = 2`. Frequencies are `-1: 2, 2: 2, 3: 1`. Output is `[-1, 2]`.

## Brute force

A brute-force strategy counts element frequencies using a hash map, extracts all unique `(value, count)` pairs into a list, and sorts the list descending by count. Sorting `m` unique elements takes `O(m log m)` time, where `m <= n`. For `n = 100,000`, this takes `O(n log n)` time. We can beat this using bucket sort or a min-heap.

## The key observation

The maximum possible frequency of any element in an array of length `n` is `n`. Since the frequency domain is bounded between 1 and `n`, we can use bucket sort: create an array of lists `bucket` of size `n + 1`, where `bucket[c]` contains all numbers that occur exactly `c` times. Scanning the buckets from frequency `n` down to 1 allows us to collect the top `k` elements in linear `O(n)` time without any comparison-based sorting.

## Optimal approach

1. Count the frequency of every number in `nums` using a hash map `count`.
2. Allocate an array of lists `bucket` of size `nums.length + 1`.
3. For each pair `(val, freq)` in `count`:
   - Append `val` to `bucket[freq]`.
4. Initialize an empty list `out`.
5. Iterate `c` from `nums.length` down to 1:
   - For each number `v` in `bucket[c]`:
     - If `out.size() < k`, append `v` to `out`.
     - If `out.size() == k`, break early and return `out`.
6. Return `out`.

Complexity:
- Time: `O(n)` because counting takes `O(n)`, populating buckets takes `O(m)` where `m <= n`, and iterating buckets visits each distinct element at most once.
- Space: `O(n)` auxiliary space to store the hash map and bucket lists.

## Code walkthrough

In the reference implementation:
- `unordered_map<int, int> count; for (int x : nums) count[x]++;`: counts frequencies in a single linear pass.
- `vector<vector<int>> bucket(nums.size() + 1);`: allocates buckets where the array index directly represents frequency.
- `for (auto& [value, c] : count) bucket[c].push_back(value);`: groups elements by frequency.
- `for (int c = (int)nums.size(); c >= 1 && (int)out.size() < k; c--)`: scans from highest frequency to lowest.
- `if ((int)out.size() < k) out.push_back(v);`: collects results until exactly `k` elements are gathered.

## Test it out loud

- `nums = [4, 4, 4, 5, 5, 6], k = 1`:
  - `count = {4: 3, 5: 2, 6: 1}`.
  - `bucket[3] = [4]`, `bucket[2] = [5]`, `bucket[1] = [6]`.
  - Scan from `c = 6` down to 3: at `c = 3`, take 4. Size hits `k = 1`.
  - Returns `[4]`.
- `nums = [1, 2], k = 2`:
  - `bucket[1] = [1, 2]`.
  - At `c = 1`, take 1, then take 2.
  - Returns `[1, 2]`.

## Follow-ups

- What if data arrives in a continuous stream where `n` is unknown or infinite?
  Use a min-heap of size `k` storing `(count, value)`. Inserting each of the `m` unique elements takes `O(log k)`, running in `O(n + m log k)` time and `O(k)` heap memory.
- Can Quickselect be used here?
  Yes, Quickselect on the unique elements by frequency achieves `O(n)` average time, though worst-case is `O(n^2)` without median-of-medians.

## Common mistakes

- Allocating `bucket` of size `max_element` instead of size `n + 1`, which fails when numbers are large or negative.
- Using a max-heap of all `m` elements taking `O(m log m)` instead of a bounded min-heap of size `k` (`O(m log k)`).
- Forgetting that an element's frequency can equal `n` (requiring `bucket` size `n + 1`, not `n`).
