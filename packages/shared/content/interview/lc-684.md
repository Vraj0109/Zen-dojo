## Clarify first
- How many nodes and edges are in the graph? There are n nodes (numbered 1 to n) and exactly n edges, meaning the graph is a tree with exactly one additional cycle-forming edge.
- If multiple edges could be removed to restore a tree, which one should be returned? Return the edge that appears last in the given input array of edges.
- Is the graph guaranteed to be connected? Yes, the given graph is connected.
- What are the vertex numbering limits? Vertices are 1-indexed from 1 to n, where `3 <= n <= 1000`.

## Examples to say out loud
- Triangle case: `edges = [[1, 2], [1, 3], [2, 3]]`.
  - Adding `(1, 2)` connects 1 and 2.
  - Adding `(1, 3)` connects 1, 2, and 3.
  - Adding `(2, 3)` joins two vertices already in the same connected component, forming a cycle. Return `[2, 3]`.
- Later cycle edge: `edges = [[1, 2], [2, 3], [3, 4], [1, 4], [1, 5]]`.
  - Edge `[1, 4]` connects 1 and 4, which were already connected via `1 -> 2 -> 3 -> 4`.
  - Edge `[1, 4]` is returned even though `[1, 5]` appears later, because `[1, 4]` is the one that created the cycle.

## Brute force
A brute force approach removes edges one by one starting from the back of the input list. For each removed edge, it runs a DFS or BFS from node 1 to check if the remaining `n - 1` edges form a connected tree (visiting all n nodes without cycles). Testing each edge takes O(n) time, resulting in O(n^2) time overall. We can process edges sequentially in a single pass using Disjoint Set Union (DSU).

## The key observation
A tree on n vertices has no cycles. If we start with an empty graph and add edges one by one:
- If an edge connects two vertices that belong to different connected components, it safely connects them without creating a cycle.
- If an edge connects two vertices that are already in the same connected component, there was already an existing path between them; adding this edge creates the unique cycle.
Because edges are given in chronological addition order and only one extra edge exists, the first edge whose endpoints already share a component is guaranteed to be the redundant edge that closed the cycle.

## Optimal approach
1. Initialize a DSU parent array `par` of size `n + 1` with `par[i] = i` for all `1 <= i <= n`.
2. Define a `find(x)` helper with path compression: `par[x] = find(par[x])`.
3. Iterate through each edge `[u, v]` in `edges`:
   - Compute `root_u = find(u)` and `root_v = find(v)`.
   - If `root_u == root_v`: both endpoints are already connected. Return `[u, v]` immediately.
   - Otherwise, union the components: `par[root_u] = root_v`.
4. If no cycle is found (which will not occur under problem constraints), return an empty array `{}`.

Complexity:
- Time complexity: O(n * alpha(n)) where alpha is the inverse Ackermann function (effectively constant). Each edge involves two `find` operations and one union.
- Space complexity: O(n) auxiliary space for the DSU parent array of size `n + 1`.

## Code walkthrough
- `vector<int> par(n + 1)` and `iota(par.begin(), par.end(), 0)`: Initializes disjoint sets for 1-indexed nodes.
- `int find(int x)`: Recursively resolves the component representative while flattening the tree via path compression.
- `int a = find(e[0]), b = find(e[1])`: Finds the roots of both endpoints of the edge.
- `if (a == b) return e`: Detects that the current edge closes the cycle and returns it directly.
- `par[a] = b`: Merges the two sets if they were previously disjoint.

## Test it out loud
- Test `edges = [[1, 2], [2, 3], [1, 3]]`:
  - Edge `[1, 2]`: `find(1) != find(2)`, union 1 and 2.
  - Edge `[2, 3]`: `find(2) != find(3)`, union 2 and 3. All in same set `{1, 2, 3}`.
  - Edge `[1, 3]`: `find(1) == find(3)`. Return `[1, 3]`. Correct.
- Test `edges = [[1, 4], [3, 4], [1, 3], [1, 2], [4, 5]]`:
  - `[1, 4]`: union 1, 4.
  - `[3, 4]`: union 3, 4. Set `{1, 3, 4}`.
  - `[1, 3]`: `find(1) == find(3)`. Returns `[1, 3]`. Correct.

## Follow-ups
- How does this differ from Redundant Connection II (directed graph)? In a directed graph, a redundant edge can create a directed cycle, give a vertex an in-degree of 2, or both. That requires tracking parent pointers and candidate edges before running DSU.
- Can this be solved using DFS? Yes, before adding edge `(u, v)`, run a DFS to check if `v` is reachable from `u`. If reachable, `(u, v)` is redundant. This takes O(n^2) time compared to DSU's nearly O(n).

## Common mistakes
- Returning the last edge in the entire `edges` array instead of the specific edge that formed the cycle.
- Failing to use 1-based indexing for the parent array, leading to out-of-bounds errors on node `n`.
- Forgetting path compression in `find`, which degrades union-find tree height to linear.
