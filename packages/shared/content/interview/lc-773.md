## Clarify first
- What are the board dimensions? A fixed 2x3 grid.
- What values appear on the board? The tiles 1 through 5, and 0 representing the empty sliding space.
- What constitutes a valid move? Swapping the 0 tile with an adjacent tile (up, down, left, right).
- What is the target winning configuration? `[[1, 2, 3], [4, 5, 0]]`.
- What should be returned if the board configuration is impossible to solve? Return -1.

## Examples to say out loud
- One step from goal: `board = [[1, 2, 3], [4, 0, 5]]`.
  - Swapping 0 with right neighbor 5 produces `[[1, 2, 3], [4, 5, 0]]`.
  - Takes 1 move. Return 1.
- Already solved: `[[1, 2, 3], [4, 5, 0]]`.
  - Takes 0 moves. Return 0.
- Unsolvable case: `[[1, 2, 3], [5, 4, 0]]`.
  - Inversion count parity shows this state cannot reach the goal. Return -1.

## Brute force
A brute force recursive search without visited state tracking could loop endlessly between swapped positions. Because the board has only 6 tiles, the total number of permutations of the tiles is `6! = 720`. Exactly half of these permutations (360) are reachable due to permutation parity. Breadth-First Search over this tiny state space exhaustively finds the shortest path in milliseconds.

## The key observation
Flatten the 2x3 board into a 6-character string where indices 0..5 map to grid coordinates:
- Index 0: `(0, 0)`, neighbors `{1, 3}` (right, down)
- Index 1: `(0, 1)`, neighbors `{0, 2, 4}` (left, right, down)
- Index 2: `(0, 2)`, neighbors `{1, 5}` (left, down)
- Index 3: `(1, 0)`, neighbors `{0, 4}` (up, right)
- Index 4: `(1, 1)`, neighbors `{1, 3, 5}` (up, left, right)
- Index 5: `(1, 2)`, neighbors `{2, 4}` (up, left)
Each board state has at most 3 possible moves depending on where '0' is located.
Running BFS from the initial state toward the goal `"123450"` guarantees finding the minimal number of sliding moves.

## Optimal approach
1. Serialize the initial 2x3 board into a 6-character string `start`.
2. Define the goal string: `goal = "123450"`.
3. If `start == goal`, return 0 immediately.
4. Precompute the neighbor index list `nb` for each position 0 through 5:
   `{{1, 3}, {0, 2, 4}, {1, 5}, {0, 4}, {1, 3, 5}, {2, 4}}`.
5. Initialize a hash set `seen` and insert `start`.
6. Initialize a BFS queue `q` holding pairs `{state, distance}` and push `{start, 0}`.
7. While `q` is not empty:
   - Pop `{s, d}`.
   - If `s == goal`, return `d`.
   - Find the index `z` where `s[z] == '0'`.
   - For each neighbor index `j` in `nb[z]`:
     - Create candidate string `t = s` and swap `t[z]` with `t[j]`.
     - If `seen.insert(t).second` succeeds (new unvisited state):
       - Push `{t, d + 1}` into `q`.
8. Return -1.

Complexity:
- Time complexity: O(720) because there are at most `6! = 720` states and each state generates at most 3 transitions. Runs in effectively O(1) constant time.
- Space complexity: O(720) auxiliary space for the `seen` set and the BFS queue.

## Code walkthrough
- `string start`: Flattens the 2D board row-by-row into a concise string format.
- `vector<vector<int>> nb`: Encodes grid adjacency directly on flattened 1D indices.
- `int z = (int)s.find('0')`: Locates the empty slot.
- `swap(t[z], t[j])`: Generates the board resulting from sliding a tile into the blank position.
- `if (seen.insert(t).second)`: Atomically checks visited status and marks visited, preventing queue bloating.

## Test it out loud
- Test `[[1, 2, 3], [4, 5, 0]]`:
  - `start = "123450"`. Matches `goal` immediately, returns 0. Correct.
- Test `[[1, 2, 0], [4, 5, 3]]`:
  - `start = "120453"`.
  - Zero is at index 2. Neighbors of 2 are `{1, 5}`.
  - Swapping with 5 (index 5) produces `"123450"`, which matches `goal`.
  - Distance is `0 + 1 = 1`. Returns 1. Correct.

## Follow-ups
- How can we verify solvability without BFS? Check the number of inversions among the numbers 1 to 5. Since the grid width is 3 (odd), a state is solvable if and only if its number of inversions has the same parity as the goal (which has 0 inversions, meaning inversions must be even).
- How would you scale this to a 3x3 (8-puzzle) or 4x4 (15-puzzle)? For larger boards with millions of states, standard BFS exhausts memory; A* search with Manhattan distance heuristic or IDA* is used.

## Common mistakes
- Allowing invalid moves between wrapped rows (e.g. thinking index 2 can wrap to index 3 on a 1D string).
- Forgetting to return -1 for unreachable configurations.
- Using 2D matrix copies in queue states instead of lightweight 6-character strings.
