## Clarify first
- What is a truncatable prime? A prime number with at least two digits that remains prime as you repeatedly remove digits from left to right, AND also remains prime as you repeatedly remove digits from right to left.
- Give an example of truncation: 3797 is prime.
  - Right-truncations: 379, 37, 3 (all prime).
  - Left-truncations: 797, 97, 7 (all prime).
- Do single-digit primes (2, 3, 5, 7) count? No, single-digit primes are explicitly excluded.
- What if a left-truncation has a leading zero? Leading zeros are not allowed; if stripping the leftmost digit produces a number with a leading zero (e.g. 103 $\to$ 03), it is not a valid truncation.
- How many truncatable primes exist in total? There are famously only 11 truncatable primes in the entire set of integers, the largest being 739,397.
- What is the constraint on `limit`? $1 \le \text{limit} \le 10,000,000$.

## Examples to say out loud
- Consider `limit = 30`.
  The two-digit primes are 11, 13, 17, 19, 23, 29.
  Let us test 23:
  - Right-truncation: 2 (prime).
  - Left-truncation: 3 (prime).
  Both directions remain prime, so 23 is truncatable.
  Other primes under 30 (like 11: left is 1, not prime; 13: left is 3, right is 1, not prime; 29: left is 9, not prime) fail.
  Sum below 30 is 23.
- Consider `limit = 100`.
  Truncatable primes below 100 are 23, 37, 53, 73.
  Sum: $23 + 37 + 53 + 73 = 186$.

## Brute force
A naive approach would iterate over all numbers up to `limit`, and for each number run trial-division primality tests on the number and all of its left and right truncations. For $10^7$, doing $O(\sqrt{v})$ trial divisions on millions of numbers is slow. Instead, precomputing a Sieve of Eratosthenes up to `limit` allows $O(1)$ primality lookups.

## The key observation
1. With $\text{limit} \le 10^7$, running the Sieve of Eratosthenes takes $O(\text{limit} \log \log \text{limit})$ time and consumes 10 MB of memory.
2. For each candidate prime $p \ge 11$:
   - Right-truncations are generated by integer division: $v = p / 10, p / 100, \dots$ until $v = 0$.
   - Left-truncations are generated by modulo operations: $p \pmod{10^k}$ for $10 \le 10^k \le p$. If $p \pmod{10^k} < 10^{k-1}$, it has an illegal leading zero.
3. Because all truncations are strictly smaller than $p$, their primality can be checked immediately against the precomputed sieve table in $O(1)$ time per truncation.

## Optimal approach
1. Allocate a boolean / byte array `comp` of size `limit + 2` initialized to false. Mark `comp[0] = comp[1] = true`.
2. Sieve composites up to `limit`: for $i = 2$ while $i^2 \le \text{limit}$, if `!comp[i]`, mark all multiples $j = i^2, i^2 + i, \dots \le \text{limit}$ as composite.
3. Initialize `total = 0`.
4. Loop prime candidate $p$ from 11 up to $\text{limit} - 1$:
   - If `comp[p]` is true, continue.
   - Check right-truncations: loop $v = p / 10$ while $v > 0$, if `comp[v]` is true, mark candidate invalid.
   - Check left-truncations: loop $m = 10$ while $m \le p$:
     - Let $v = p \% m$.
     - If $v < m / 10$ (leading zero) or `comp[v]` is true, mark candidate invalid.
     - Multiply $m$ by 10.
   - If both tests pass, add $p$ to `total`.
5. Return `total`.
6. Complexity:
   - Time Complexity: $O(\text{limit} \log \log \text{limit})$ for sieving, plus $O(\text{digits})$ per prime for truncation tests. Total runtime is under 100 milliseconds for $\text{limit} = 10^7$.
   - Space Complexity: $O(\text{limit})$ to store the primality table.

## Code walkthrough
- `vector<char> comp(limit + 2, 0);`: Prime sieve table.
- `for (long long i = 2; i * i <= limit; i++) ...`: Standard sieve of Eratosthenes.
- `for (int p = 11; p < limit; p++)`: Only evaluate numbers $\ge 11$ as single-digit primes are excluded.
- `for (int v = p / 10; v > 0 && ok; v /= 10) if (!prime(v)) ok = false;`: Validate right truncations.
- `for (long long m = 10; m <= p && ok; m *= 10)`: Validate left truncations and guard against leading zeros via `v < m / 10`.
- `if (ok) total += p;`: Sum valid truncatable primes.

## Test it out loud
- Test 1: `limit = 1` $\to$ returns 0.
- Test 2: `limit = 11` $\to$ returns 0.
- Test 3: `limit = 24` $\to$ includes 23 $\to$ returns 23.
- Test 4: `limit = 100` $\to$ includes 23, 37, 53, 73 $\to$ returns 186.

## Follow-ups
- Can this be solved with DFS tree generation instead of full sieving?
  Yes, since right-truncatable primes must be grown by appending digits $\{1, 3, 7, 9\}$ to existing right-truncatable primes starting from $\{2, 3, 5, 7\}$, a branch-and-bound search finds the 11 primes in less than 1 millisecond.
- What are all 11 truncatable primes?
  23, 37, 53, 73, 313, 317, 373, 797, 3137, 3797, 739397. Their sum is 742,746.

## Common mistakes
- Counting 2, 3, 5, 7 as truncatable primes (the problem explicitly excludes single digits).
- Allowing left-truncations with leading zeros (e.g. 103 $\to 03 = 3$ is not a valid decimal representation).
- Modulo multiplier overflow when $m$ exceeds 32-bit signed integer limits ($m$ can reach $10^{10}$ if limit is large).
