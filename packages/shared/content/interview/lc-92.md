## Clarify first

- Are `left` and `right` 1-indexed? Yes, 1-indexed where `1 <= left <= right <= list length`.
- Can `left == right`? Yes, in which case reversing a sublist of length 1 leaves the list unchanged.
- Can `left` be 1 (the head of the list)? Yes, the head itself might be reversed, which is why a dummy node helps.
- Should this be done in-place without creating new nodes? Yes, modify node pointers directly in `O(1)` auxiliary space.

## Examples to say out loud

- Middle sublist: `head = [1, 2, 3, 4, 5]`, `left = 2`, `right = 4`. The sublist `[2, 3, 4]` is reversed to `[4, 3, 2]`. The resulting list is `[1, 4, 3, 2, 5]`.
- No-op edge case: `head = [5]`, `left = 1`, `right = 1`. Sublist length is 1, returns `[5]`.
- Entire list reversed: `head = [1, 2]`, `left = 1`, `right = 2`. Result is `[2, 1]`.

## Brute force

A brute-force approach traverses the list, copies all node values into an array, reverses the elements between index `left - 1` and `right - 1`, and writes the values back into the linked list nodes. Alternatively, we could disconnect the sublist into a new list and reconnect it. The array-copying method uses `O(n)` extra space and violates the standard interview expectation of in-place pointer manipulation.

## The key observation

Instead of a full multi-pass reversal, we can place a dummy node before the head and advance a pointer `prev` to position `left - 1`. Let `cur` be `prev->next` (the first node of the sublist). We repeatedly take the node immediately following `cur` (`nxt = cur->next`) and insert it directly after `prev`. Doing this `right - left` times shifts each successive node to the front of the reversed sublist while `cur` naturally slides toward the end.

## Optimal approach

1. Create a `dummy` node pointing to `head` to handle cases where `left = 1`.
2. Advance `prev` starting from `dummy` by `left - 1` steps so that `prev` rests at the node immediately preceding the reversal window.
3. Set `cur = prev->next`, which points to the start of the sublist to reverse.
4. Loop `right - left` times:
   a. Set `nxt = cur->next`.
   b. Point `cur->next` to `nxt->next` (detaching `nxt`).
   c. Point `nxt->next` to `prev->next` (linking `nxt` to the head of the reversed portion).
   d. Point `prev->next` to `nxt` (placing `nxt` immediately after `prev`).
5. Return `dummy.next`.

Complexity:
- Time: `O(n)` because we advance `prev` up to `left` steps and perform `right - left` pointer operations, visiting nodes at most once.
- Space: `O(1)` auxiliary space since only pointer variables are manipulated in place.

## Code walkthrough

In the reference implementation:
- `ListNode dummy(0, head);`: provides a safe anchor before `head`.
- `for (int i = 1; i < left; i++) prev = prev->next;`: locates the node directly preceding position `left`.
- `ListNode* cur = prev->next;`: marks the anchor node that will end up at position `right`.
- `cur->next = nxt->next; nxt->next = prev->next; prev->next = nxt;`: extracts `nxt` and inserts it between `prev` and `prev->next`.
- `return dummy.next;`: yields the new head even if original head was moved.

## Test it out loud

- `head = [1, 2, 3, 4, 5], left = 2, right = 4`:
  - `prev` stops at node 1. `cur` is node 2.
  - Step 1 (`nxt = 3`): node 3 moves between 1 and 2. List order: `1 -> 3 -> 2 -> 4 -> 5`.
  - Step 2 (`nxt = 4`): node 4 moves between 1 and 3. List order: `1 -> 4 -> 3 -> 2 -> 5`.
  - Loop terminates after 2 iterations (`4 - 2 = 2`). Returns `dummy.next` (`1`).
- `head = [1, 2], left = 1, right = 2`:
  - `prev` is `dummy`. `cur` is node 1.
  - Step 1 (`nxt = 2`): node 2 moves before 1. List order: `dummy -> 2 -> 1 -> null`.
  - Returns `2 -> 1`.

## Follow-ups

- How would you reverse the entire list using the same strategy?
  Set `left = 1` and `right = length`, or use the standard three-pointer iterative reversal pattern.
- Can this be done recursively?
  Yes, recurse down to position `left`, reverse `k` nodes recursively, and re-link the tail, though recursion consumes `O(n)` stack space.

## Common mistakes

- Not using a dummy head, leading to special cases and segmentation faults when `left == 1`.
- Advancing `cur` inside the loop instead of keeping it fixed as the trailing tail of the reversed section.
- Forgetting that the loop runs `right - left` times rather than `right` times.
