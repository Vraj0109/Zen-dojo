## Clarify first

- Are we looking for the side length or the area of the maximal square? Return the **area** (side length squared).
- What if the grid contains no 1s at all? Return 0.
- Does the square have to contain only 1s? Yes, every cell inside the square must be 1.
- What are the dimensions of the grid? Rows and columns are between 1 and 300, containing characters or integers 0 and 1.

## Examples to say out loud

- Multi-row square:
  - Row 0: `[1, 0, 1, 0, 0]`
  - Row 1: `[1, 0, 1, 1, 1]`
  - Row 2: `[1, 1, 1, 1, 1]`
  - Row 3: `[1, 0, 0, 1, 0]`
  - A 2x2 square of 1s spans rows 1-2 and cols 2-3 (or rows 1-2 and cols 3-4). Side length = 2, area = 4.
- Single cell square: `matrix = [[0, 1], [1, 0]]`. Largest square is 1x1, area = 1.
- All zeros: `matrix = [[0]]`. Area = 0.

## Brute force

A brute-force solution checks every cell `(r, c)` as a potential top-left corner of a square. For each cell with a 1, it tries expanding side length `k = 1, 2, ...`, validating whether all cells in the newly enclosed row and column are 1s. Validating each candidate square takes `O(k^2)` time, resulting in `O(R \times C \times \min(R, C)^2) = O(N^4)` time for an `N \times N` matrix. For `N = 300`, this takes `8 \times 10^9` operations and times out.

## The key observation

Let `dp[i][j]` be the maximum side length of an all-1 square whose bottom-right corner is at `(i - 1, j - 1)`.
If `matrix[i - 1][j - 1] == 1`, can we extend a square?
A square can only be as large as the bottleneck of three adjacent overlapping sub-squares: the square ending above `dp[i - 1][j]`, the square ending to the left `dp[i][j - 1]`, and the square ending diagonally above-left `dp[i - 1][j - 1]`.
Therefore: `dp[i][j] = 1 + \min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])`.

## Optimal approach

1. Let `R = matrix.length` and `C = matrix[0].length`.
2. Allocate a 2D table `dp` of size `(R + 1) \times (C + 1)` filled with zeros, and initialize `best = 0`.
3. Iterate `i` from 1 to `R`:
   - Iterate `j` from 1 to `C`:
     - If `matrix[i - 1][j - 1] == 1`:
       - `dp[i][j] = 1 + min({dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]})`.
       - Update `best = max(best, dp[i][j])`.
4. Return `best * best` (the area).

Complexity:
- Time: `O(R \times C)` because each cell in the `R \times C` matrix is visited once with constant-time min operations.
- Space: `O(R \times C)` auxiliary space for the DP matrix (can be optimized to `O(C)` using a 1D rolling array).

## Code walkthrough

In the reference implementation:
- `vector<vector<int>> dp(R + 1, vector<int>(C + 1, 0));`: 1-padded table eliminates boundary checks for row 0 and column 0.
- `if (matrix[i - 1][j - 1] == 1)`: only cells holding 1 can act as the bottom-right corner of an all-ones square.
- `dp[i][j] = 1 + min({dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]});`: grows square by 1 over the limiting neighbor.
- `best = max(best, dp[i][j]);`: tracks the longest square side length found.
- `return best * best;`: squares the side length to produce area.

## Test it out loud

- `matrix = [[1, 1], [1, 1]]`:
  - `(1, 1)`: top 0, left 0, diag 0 -> `1 + 0 = 1`.
  - `(1, 2)`: top 0, left 1, diag 0 -> `1 + 0 = 1`.
  - `(2, 1)`: top 1, left 0, diag 0 -> `1 + 0 = 1`.
  - `(2, 2)`: top 1, left 1, diag 1 -> `1 + min(1, 1, 1) = 2`.
  - `best = 2`, area = `2 * 2 = 4`.
- `matrix = [[0]]`: `matrix[0][0] == 0`, `best` remains 0, area = 0.

## Follow-ups

- How would you reduce auxiliary memory to `O(C)`?
  Maintain a single 1D array `dp` of size `C + 1` and a scalar `prevDiag` storing `dp[i - 1][j - 1]` before updating.
- How does this differ from Maximal Rectangle (LeetCode 85)?
  Maximal Rectangle allows unequal width and height, requiring a monotonic stack on row histograms in `O(R \times C)` time.

## Common mistakes

- Returning the maximum side length `best` instead of the area `best * best`.
- Forgetting that matrix elements may be given as characters (`'0'` and `'1'`) rather than numbers.
- Off-by-one errors when padding the DP array indices.
