## Clarify first

- What range of integers should be evaluated? Every integer from 0 up to `n`, inclusive (an array of length `n + 1`).
- What is the definition of the answer array? `ans[i]` is the number of 1 bits in the binary representation of integer `i` (Hamming weight).
- Can `n` be 0? Yes, constraints specify `0 <= n <= 100,000`.
- What is the target time complexity? The problem specifies achieving linear `O(n)` total time rather than `O(n \log n)`.

## Examples to say out loud

- Base case `n = 2`:
  - 0: `0` (0 ones).
  - 1: `1` (1 one).
  - 2: `10` (1 one).
  - Output: `[0, 1, 1]`.
- Larger case `n = 5`:
  - 0: 0
  - 1: 1
  - 2: 1
  - 3: `11` (2 ones)
  - 4: `100` (1 one)
  - 5: `101` (2 ones)
  - Output: `[0, 1, 1, 2, 1, 2]`.

## Brute force

A brute-force solution counts the set bits of each number `i` individually using built-in popcount functions or a loop testing bits `while (x > 0) { count += x & 1; x >>= 1; }`. Since each 32-bit number has `O(\log n)` bits, doing this for all `n` numbers takes `O(n \log n)` time. We can improve upon this by reusing the bit counts of smaller numbers using dynamic programming.

## The key observation

Notice how binary representations relate through bit shifts: shifting a number right by 1 bit (`i >> 1`) divides it by 2 and drops its least significant bit.
The number of set bits in `i` is simply the number of set bits in `i >> 1` plus 1 if the dropped lowest bit was a 1 (`i & 1`):
`bits[i] = bits[i >> 1] + (i & 1)`.
Since `i >> 1 < i`, the value `bits[i >> 1]` has already been computed by earlier iterations of the loop!

## Optimal approach

1. Allocate an array `bits` of size `n + 1` filled with zeros.
2. The base case `bits[0] = 0` is already set.
3. Iterate `i` from 1 to `n`:
   - Compute `bits[i] = bits[i >> 1] + (i & 1)`.
4. Return `bits`.

Complexity:
- Time: `O(n)` because we compute the answer for each integer from 1 to `n` in `O(1)` time with two basic bitwise operations.
- Space: `O(n)` auxiliary space to store and return the `n + 1` results.

## Code walkthrough

In the reference implementation:
- `vector<int> bits(n + 1, 0);`: creates the result buffer of size `n + 1`.
- `for (int i = 1; i <= n; i++)`: iterates sequentially from 1 to `n`.
- `bits[i >> 1]`: retrieves the precomputed bit count for the prefix without the least significant bit.
- `(i & 1)`: checks whether the least significant bit is set (odd number).
- `bits[i] = bits[i >> 1] + (i & 1);`: synthesizes the total set bit count in a single operation.
- `return bits;`: outputs the complete popcount array.

## Test it out loud

- `n = 4`:
  - `i = 0`: `bits[0] = 0`.
  - `i = 1`: `bits[1 >> 1] + (1 & 1) = bits[0] + 1 = 0 + 1 = 1`.
  - `i = 2`: `bits[2 >> 1] + (2 & 1) = bits[1] + 0 = 1 + 0 = 1`.
  - `i = 3`: `bits[3 >> 1] + (3 & 1) = bits[1] + 1 = 1 + 1 = 2`.
  - `i = 4`: `bits[4 >> 1] + (4 & 1) = bits[2] + 0 = 1 + 0 = 1`.
  - Result: `[0, 1, 1, 2, 1]`.

## Follow-ups

- What are alternative dynamic programming relations?
  - Last set bit removal: `bits[i] = bits[i & (i - 1)] + 1` (clearing the lowest set bit).
  - Most significant bit offset: `bits[i] = bits[i - offset] + 1` where `offset` is the largest power of 2 `<= i`.
- What is Brian Kernighan's algorithm?
  Counting set bits by repeatedly computing `x = x & (x - 1)` in time proportional to the number of set bits.

## Common mistakes

- Recomputing bit counts from scratch using a loop per number, resulting in `O(n \log n)` time.
- Forgetting operator precedence: `+` has higher precedence than `&` in C++, so parentheses are required around `(i & 1)`: `bits[i >> 1] + (i & 1)`.
- Allocating an array of size `n` instead of `n + 1` (missing space for index `n`).
