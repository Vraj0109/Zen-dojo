## Clarify first

- What characters can be added via `addWord`? (Only lowercase English letters `'a'` through `'z'`).
- What wildcard characters can appear in `search`? (The dot `'.'` character, which matches any single lowercase letter).
- How many wildcard dots can appear in a single query? (The problem states at most 2 dots per search word).
- What are the length bounds and call frequencies? (Word length up to 25; up to 50,000 total calls).
- What should be returned if a word of different length is matched? (Must match exact length and character alignment; prefixes of different lengths do not match).

## Examples to say out loud

- Wildcard matching:
  - Add words: `"bad"`, `"dad"`, `"mad"`
  - `search("pad")` $\implies$ `false` (no word starts with `'p'`)
  - `search("bad")` $\implies$ `true`
  - `search(".ad")` $\implies$ `true` (matches `"bad"`, `"dad"`, or `"mad"`)
  - `search("b..")` $\implies$ `true` (matches `"bad"`)
- Length mismatch: Search for `".a"` or `".ad."` when only `"bad"` exists returns `false`.

## Brute force

A naive brute-force maintains a list of all inserted words. On each `search(word)`, iterate through every stored word: if the stored word has identical length, check character by character whether `word[i] == '.' || word[i] == stored[i]`. With $N = 50,000$ words and length up to 25, every search takes $O(N \cdot L)$ time, leading to around $1.25 \times 10^9$ operations and Time Limit Exceeded.

## The key observation

A Trie naturally stores words by common prefixes. When searching a concrete character `'a'`-`'z'`, we take the deterministic single child branch in $O(1)$. When encountering a wildcard `'.'`:
- A dot can match any existing letter.
- We branch by recursively searching across all 26 possible non-null children of the current node.
Because the problem constraints guarantee at most $d \le 2$ dots per search word, branching occurs at most twice per query, bounding search time to $O(26^2 \cdot L) \approx 676 \cdot 25 \approx 1.7 \times 10^4$ operations in the absolute worst case.

## Optimal approach

1. Implement a Trie `Node` structure:
   - `Node* next[26] = {}`
   - `bool endsHere = false`
2. Root node initialized as `new Node()`.
3. Operation `addWord(word)`:
   - Walk from `root` inserting characters, creating missing nodes on demand.
   - Mark `endsHere = true` on the final node.
4. Operation `search(word)`:
   - Define a recursive helper `match(node, word, i)`:
     - Base case: If $i == word.length()$, return `node->endsHere`.
     - Character $w[i] == \text{'.'}'$:
       - For each non-null `child` in `node->next`:
         - If `match(child, word, i + 1)` returns `true`, return `true` immediately.
       - If no child branch matches, return `false`.
     - Standard character $w[i] \in \text{['a'..'z']}$:
       - Let `child = node->next[w[i] - 'a']`.
       - If `child == nullptr`, return `false`.
       - Return `match(child, word, i + 1)`.
   - Return `match(root, word, 0)`.

Complexity:
- Time: `addWord` takes $O(L)$ time where $L$ is word length. `search` takes $O(L)$ when there are no dots, and $O(26^d \cdot L)$ with $d$ dots ($d \le 2$).
- Space: $O(N \cdot L)$ total auxiliary space for the Trie nodes across $N$ inserted words.

## Code walkthrough

In the reference implementation:
- `Node* next[26] = {};`: 26 branches per node for fast indexed lookup.
- `if (i == (int)w.size()) return node->endsHere;`: verifies that all characters were matched and terminates at a completed word.
- `if (w[i] == '.') for (Node* child : node->next)`: evaluates all existing outgoing branches recursively on wildcard match.
- `return child && match(child, w, i + 1);`: deterministic single-branch path for standard letters.

## Test it out loud

- Empty search on empty dictionary: `search("a")` or `search(".")` on empty trie returns `false`.
- Search with multiple wildcards: `addWord("abc")`.
  - `search("...")`: root tries branch `'a'`, which tries branch `'b'`, which tries branch `'c'`. Reaches end of string at node `'c'` with `endsHere = true`. Returns `true`.
- Wildcard that matches prefix but fails on full word length: `addWord("at")`. `search(".at")` tries branches at length 3, fails since tree only goes up to depth 2. Returns `false`.

## Follow-ups

- What if words have unlimited dots (e.g. `d` up to 25)?
  Search can become $O(26^L)$ on pathological trees. We could group words by length into separate Tries, or prune using bitmasks of available depths/characters.
- How to support prefix search with wildcards (`startsWith` with dots)?
  Change the base case in `match` to return `true` when $i == prefix.length()$ without checking `endsHere`.
- What if wildcards can match 0 or more characters (like `*` in regex)?
  This converts the problem into standard regex matching / NFA traversal, requiring dynamic programming or memoized DFS on state `(node, string_index)`.

## Common mistakes

- Missing the base condition check `node->endsHere`: returning `true` at $i == word.length()$ matches prefixes of longer words rather than complete words.
- Iterating through all 26 indices for regular letters instead of directly indexing `w[i] - 'a'`.
- Not returning `false` after testing all 26 children on a dot mismatch.
