## Clarify first
- What is a palindrome partition? A partition of string `s` into contiguous substrings such that every substring reads the same forwards and backwards.
- What should be returned? A list containing all valid palindrome partitions, where each partition is an ordered list of its substring parts.
- Can substrings be of length 1? Yes, any single character is a valid palindrome.
- What is the maximum length of `s`? `1 <= s.length <= 16`.

## Examples to say out loud
- Consider `s = "aab"`:
  - Cut after first 'a': piece `"a"` (palindrome), remaining `"ab"`. Substring `"a"` + `"b"` gives `["a", "a", "b"]`.
  - Cut after second 'a': piece `"aa"` (palindrome), remaining `"b"`. Gives `["aa", "b"]`.
  - Cut after 'b': piece `"aab"` is not a palindrome.
  - Output: `[["a", "a", "b"], ["aa", "b"]]`.
- Single character `s = "a"`: Output: `[["a"]]`.
- Palindromic string `s = "aba"`: Output: `[["a", "b", "a"], ["aba"]]`.

## Brute force
A brute force approach considers all `2^(n - 1)` ways to place cut marks between characters of string `s`. For each partition, it iterates through all resulting substring pieces and verifies whether each piece is a palindrome using two pointers in O(n) time. Total time is O(n * 2^n). By precomputing palindrome validity in a 2D table and pruning non-palindromic prefixes during backtracking, we avoid generating invalid partitions entirely.

## The key observation
We can formulate the problem as choosing cuts sequentially from left to right:
- From current starting index `start`, we iterate through every possible cut point `end` from `start` to `n - 1`.
- If the prefix `s[start..end]` is a palindrome, we append it to our active partition list `cur` and recursively solve the suffix starting at `end + 1`.
- If `s[start..end]` is not a palindrome, we immediately skip `end`, effectively pruning that entire subtree.
We can precompute an `n x n` boolean table `pal[i][j]` where `pal[i][j]` is true if and only if `s[i..j]` is a palindrome, allowing O(1) checks during the search.

## Optimal approach
1. Precompute palindrome table `pal`:
   - An `n x n` boolean table initialized to false.
   - For `i` from `n - 1` down to 0:
     - For `j` from `i` to `n - 1`:
       - `pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i + 1][j - 1])`.
2. Define recursive helper `go(start)`:
   - Base case: If `start == n`, all characters have been consumed in palindromic pieces; append a copy of `cur` to `out` and return.
   - For `end` from `start` to `n - 1`:
     - If `!pal[start][end]`: continue.
     - Add `s.substr(start, end - start + 1)` to `cur`.
     - Recurse: `go(end + 1)`.
     - Backtrack: remove the last piece from `cur`.
3. Call `go(0)` and return `out`.

Complexity:
- Time complexity: O(n * 2^n) in the worst case (e.g. `s = "aaaa"` where every substring is a palindrome, generating 2^(n-1) partitions, each taking O(n) to copy). Precomputing the table takes O(n^2).
- Space complexity: O(n^2) for the palindrome lookup table, plus O(n) for the recursion stack and `cur` buffer.

## Code walkthrough
- `pal[i][j] = s[i] == s[j] && (j - i < 2 || pal[i + 1][j - 1])`: Standard DP to precompute all substring palindromes in O(n^2) time.
- `if (start == (int)s.size()) { out.push_back(cur); return; }`: Commits complete partition when all characters are segmented.
- `if (!pal[start][end]) continue`: Pruning check: skips non-palindromic prefixes in O(1) time.
- `cur.push_back(...); go(end + 1); cur.pop_back()`: Appends valid palindromic piece, processes the remaining suffix, and backtracks.

## Test it out loud
- Test `s = "aab"`:
  - `pal["a"] = true`, `pal["aa"] = true`, `pal["aab"] = false`, `pal["b"] = true`.
  - Branch 1: cut `"a"`. Suffix `"ab"` cuts `"a"`, suffix `"b"` cuts `"b"`. Yields `["a", "a", "b"]`.
  - Branch 2: cut `"aa"`. Suffix `"b"` cuts `"b"`. Yields `["aa", "b"]`.
  - Branch 3: cut `"aab"`: `pal[0][2]` is false, skipped.
  - Returns `[["a", "a", "b"], ["aa", "b"]]`. Correct.
- Test `s = "a"`:
  - Cut `"a"`, `start = 1 == n`. Returns `[["a"]]`. Correct.

## Follow-ups
- How does Palindrome Partitioning II differ? Palindrome Partitioning II asks for the minimum number of cuts needed, which is an optimization problem solved in O(n^2) time with 1D DP rather than enumerating all subsets.
- What if the string length were up to 1000? Enumerating all partitions is impossible because output size is exponential; only min-cut or feasibility DP would scale.

## Common mistakes
- Running an O(n) palindrome check inside the backtracking loop without precomputation, which increases runtime to O(n^2 * 2^n).
- Filling the DP table in top-down order without ensuring `pal[i + 1][j - 1]` has already been computed (must loop `i` from `n - 1` down to 0).
- Incorrect substring length calculation (`end - start + 1`).
