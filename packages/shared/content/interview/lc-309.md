## Clarify first

- How many shares can you hold at a time? At most one share at any time.
- What is the cooldown restriction? After you sell a stock on day `i`, you cannot buy stock on day `i + 1` (you can buy again starting on day `i + 2`).
- Can you buy and sell on the same day? No, buying and selling on the same day results in 0 profit and immediately triggers cooldown.
- What are the constraints? `prices.length` is between 1 and 5,000, and prices are non-negative up to 1,000.

## Examples to say out loud

- Profitable sequence with cooldown: `prices = [1, 2, 3, 0, 2]`.
  - Day 0: buy at 1.
  - Day 1: sell at 2 (profit = 1).
  - Day 2: cooldown (cannot buy).
  - Day 3: buy at 0.
  - Day 4: sell at 2 (profit = 2).
  - Total profit = `1 + 2 = 3`.
- Strictly falling: `prices = [5, 4, 3, 2, 1]`. No trades made, profit = 0.
- Single day edge case: `prices = [1]`. Cannot sell, profit = 0.

## Brute force

A brute-force recursive solution maintains the current day `i` and state (holding a share, cooldown, or resting). On each day, branch into valid choices: if holding, either hold or sell; if in cooldown, transition to rest; if resting, either buy or remain resting. This generates a decision tree of height `n`, taking `O(2^n)` exponential time. For `n = 5,000`, this times out immediately.

## The key observation

The daily financial state can be modeled cleanly as a 3-state finite state machine:
1. `hold`: Maximum profit while currently holding 1 share. You either held yesterday, or bought today from the `rest` state: `hold = max(hold, rest - price)`.
2. `sold`: Maximum profit immediately after selling today: `sold = hold + price`.
3. `rest`: Maximum profit when not holding a share and free from cooldown. You either rested yesterday, or transitioned out of yesterday's `sold` state: `rest = max(rest, prevSold)`.
Because today's state depends strictly on yesterday's values, we only need three scalar variables.

## Optimal approach

1. Initialize state variables:
   - `hold = -infinity` (cannot hold without buying).
   - `sold = 0`.
   - `rest = 0`.
2. For each price `p` in `prices`:
   a. Cache previous sold state: `prevSold = sold`.
   b. Update `sold = hold + p` (sell stock held from earlier).
   c. Update `hold = max(hold, rest - p)` (either keep holding, or buy from rest).
   d. Update `rest = max(rest, prevSold)` (either keep resting, or enter rest from yesterday's sale).
3. Return `max(sold, rest)`.

Complexity:
- Time: `O(n)` because we iterate through the price list of length `n` once in a single pass.
- Space: `O(1)` auxiliary space since only a few scalar variables are maintained.

## Code walkthrough

In the reference implementation:
- `int hold = INT_MIN / 2, sold = 0, rest = 0;`: uses a sufficiently large negative sentinel to avoid integer underflow when subtracting `p`.
- `int prevSold = sold;`: captures the sales state of the previous day before updating.
- `sold = hold + p;`: realizes revenue by selling the active share at price `p`.
- `hold = max(hold, rest - p);`: enforces that buying can only occur when in the `rest` state (respecting the 1-day cooldown).
- `rest = max(rest, prevSold);`: advances the cooldown into an actionable resting state.
- `return max(sold, rest);`: takes the best outcome between having just sold or resting on the final day.

## Test it out loud

- `prices = [1, 2, 4]`:
  - Day 0 (`p = 1`): `prevSold = 0`, `sold = -inf`, `hold = max(-inf, 0 - 1) = -1`, `rest = 0`.
  - Day 1 (`p = 2`): `prevSold = -inf`, `sold = -1 + 2 = 1`, `hold = max(-1, 0 - 2) = -1`, `rest = max(0, -inf) = 0`.
  - Day 2 (`p = 4`): `prevSold = 1`, `sold = -1 + 4 = 3`, `hold = max(-1, 0 - 4) = -1`, `rest = max(0, 1) = 1`.
  - Result: `max(3, 1) = 3`.
- `prices = [1]`: returns 0.

## Follow-ups

- What if the cooldown duration was `k` days instead of 1 day?
  Maintain a queue of length `k` for sold values before they transition into `rest`.
- What if there was a transaction fee in addition to cooldown?
  Subtract `fee` when transitioning into `sold` or `hold`.

## Common mistakes

- Updating `rest` using the current day's `sold` instead of `prevSold`, which would allow buying on the same day or skipping the cooldown day.
- Initializing `hold = 0` instead of negative infinity, falsely implying you can hold a stock without paying for it.
- Allocating full `3 \times n` DP tables when three scalar variables suffice.
