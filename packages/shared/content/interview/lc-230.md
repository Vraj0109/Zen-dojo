## Clarify first

- Is `k` 1-indexed? Yes, `k` counts from 1 up to the total number of nodes `n`.
- Is the tree guaranteed to be a valid BST? Yes, all left subtree keys are smaller, and right subtree keys are larger.
- Can `k` be greater than the number of nodes in the tree? Constraints guarantee `1 <= k <= n <= 10,000`.
- Can the tree be modified during this query? Modifying the tree is not required, and in-place reads preserve concurrent access.

## Examples to say out loud

- Simple BST: `root = [3, 1, 4, null, 2]`, `k = 1`.
  - In-order traversal visits nodes in ascending order: 1, 2, 3, 4.
  - The 1st smallest element is 1.
- Larger tree: `root = [5, 3, 6, 2, 4, null, null, 1]`, `k = 3`.
  - Sorted order: 1, 2, 3, 4, 5, 6.
  - The 3rd smallest element is 3.

## Brute force

A brute-force strategy traverses the entire BST (using any traversal order like preorder or BFS), appends all `n` values to an array, sorts the array, and returns the element at index `k - 1`. Sorting takes `O(n log n)` time and `O(n)` extra memory. Even an in-order traversal that writes all `n` elements into an array takes `O(n)` time and `O(n)` space, which does unnecessary work when `k` is small.

## The key observation

An in-order traversal (left, root, right) of a binary search tree visits nodes in strictly ascending numerical order. Instead of traversing the whole tree, we can simulate an iterative in-order traversal using an explicit stack, stopping immediately once we have popped exactly `k` nodes.

## Optimal approach

1. Initialize an empty stack of node pointers and set pointer `cur = root`.
2. While `cur != null` or the stack is not empty:
   a. Push `cur` onto the stack and move `cur = cur.left` until `cur` is null (reaching the minimum of the current subtree).
   b. Pop node `cur` from the stack.
   c. Decrement `k`. If `k == 0`, return `cur.val` immediately.
   d. Set `cur = cur.right` to explore the right subtree.
3. If loop exits without returning, return -1 (unreachable given constraints).

Complexity:
- Time: `O(h + k)` where `h` is the height of the tree. Reaching the smallest node takes `O(h)`, and visiting the first `k` elements takes `O(k)` steps. In balanced trees, this is `O(log n + k)`.
- Space: `O(h)` stack space to store nodes along the current path (`O(log n)` on average, `O(n)` worst-case).

## Code walkthrough

In the reference implementation:
- `vector<TreeNode*> st; TreeNode* cur = root;`: tracks the path of left-leaning ancestors.
- `while (cur) { st.push_back(cur); cur = cur->left; }`: descends to the smallest unprocessed element.
- `cur = st.back(); st.pop_back();`: retrieves the next smallest node in sorted order.
- `if (--k == 0) return cur->val;`: decrements the rank counter and immediately terminates when the target rank is hit.
- `cur = cur->right;`: pivots to the right subtree to continue the in-order sequence.

## Test it out loud

- `root = [3, 1, 4, null, 2], k = 1`:
  - Push 3, push 1. `cur` reaches null.
  - Pop 1. `--k` becomes 0. Return `1`.
- `root = [3, 1, 4, null, 2], k = 2`:
  - Push 3, push 1.
  - Pop 1. `--k` becomes 1. `cur` moves to `1->right` (2).
  - Push 2.
  - Pop 2. `--k` becomes 0. Return `2`.

## Follow-ups

- What if the BST is modified frequently (insertions/deletions) and you need to find the kth smallest element often?
  Augment each tree node with a `subtree_size` count. At any node, if `left.size + 1 == k`, return `node.val`; if `k <= left.size`, go left; otherwise `k -= left.size + 1` and go right. This achieves `O(h)` query time.
- Can we achieve `O(1)` space?
  Yes, using Morris in-order traversal, though it temporarily modifies tree pointers during traversal.

## Common mistakes

- Traversing the entire tree into an array when `k` might be 1, doing `O(n)` work instead of `O(h)`.
- Off-by-one errors with `k` (e.g. checking `k == 0` before decrementing).
- Using preorder or postorder traversal instead of inorder, which does not visit nodes in sorted order.
