## Clarify first
- What does the distance between two nodes represent? The number of edges along the unique simple path between them in the tree.
- What should `answer[i]` contain? The sum of distances from node `i` to every other node in the tree.
- How large can n be? Up to 30,000 nodes, meaning an O(n^2) approach will time out.
- Are node indices 0 to n - 1 contiguous? Yes, and exactly n - 1 edges are given forming a connected tree.

## Examples to say out loud
- Consider `n = 6`, edges `[[0,1],[0,2],[2,3],[2,4],[2,5]]`.
  - Distances from node 0: to 1 is 1, to 2 is 1, to 3 is 2, to 4 is 2, to 5 is 2. Total = `1 + 1 + 2 + 2 + 2 = 8`.
  - When moving focus from 0 to 2: subtree of 2 has nodes `{2, 3, 4, 5}` (size 4). Moving closer to 2 decreases distances to those 4 nodes by 1, and increases distances to the other `6 - 4 = 2` nodes (`{0, 1}`) by 1.
  - So `ans[2] = ans[0] - 4 + 2 = 8 - 4 + 2 = 6`.
  - Repeating this rerooting for all nodes yields `[8, 12, 6, 10, 10, 10]`.

## Brute force
A brute force approach runs a BFS or DFS from each of the n nodes individually. For each starting node `i`, the search finds the depth of every other node and computes the sum of distances in O(n) time. Repeating this across all n nodes takes O(n^2) time. For n = 30,000, n^2 is 9 * 10^8 operations, which exceeds time limits. We can achieve O(n) time overall using tree DP with the rerooting technique.

## The key observation
Suppose we root the tree arbitrarily at node 0 and compute:
1. `cnt[u]`: the number of nodes in the subtree rooted at `u`.
2. `ans[0]`: the sum of distances from node 0 to all other nodes.
Now consider moving the root from a parent node `u` to one of its children `v`:
- Every node inside `v`'s subtree is now 1 edge closer to `v` than it was to `u`. That reduces the distance sum by `cnt[v]`.
- Every node outside `v`'s subtree (there are `n - cnt[v]` such nodes) is now 1 edge farther from `v` than it was to `u`. That increases the distance sum by `n - cnt[v]`.
Therefore, the exact transition formula is:
`ans[v] = ans[u] - cnt[v] + (n - cnt[v])`.
This allows us to compute all answers in linear time once the root answer is established.

## Optimal approach
1. Build an adjacency list representation of the tree.
2. Perform a tree traversal (using DFS or an explicit stack to prevent stack overflow on deep paths up to 30,000) starting at node 0 to establish parent pointers and a post-order traversal ordering.
3. First pass (bottom-up in reverse topological order):
   - For each node `u` from leaves up to root:
     - Add `cnt[u]` to `cnt[parent[u]]`.
     - Add `ans[u] + cnt[u]` to `ans[parent[u]]`.
   - After this step, `cnt[i]` stores subtree sizes and `ans[0]` stores the complete distance sum for root 0.
4. Second pass (top-down in preorder from root to leaves):
   - For each child `v` of parent `u`:
     - Compute `ans[v] = ans[u] - cnt[v] + (n - cnt[v])`.
5. Return the array `ans`.

Complexity:
- Time complexity: O(n) because building the tree, post-order bottom-up aggregation, and top-down rerooting each visit every node and edge a constant number of times.
- Space complexity: O(n) to store the adjacency list, parent array, subtree sizes, and answer buffer.

## Code walkthrough
- `while (!st.empty())`: Performs an iterative DFS using a stack to collect nodes in topological `order` and build `parent` pointers safely avoiding recursion limit issues.
- `for (int i = n - 1; i > 0; i--)`: Bottom-up pass accumulating `cnt` and `ans[0]`.
- `for (int i = 1; i < n; i++)`: Top-down rerooting pass computing `ans[u] = ans[parent[u]] - cnt[u] + (n - cnt[u])`.
- Returns `ans`.

## Test it out loud
- Test `n = 2, edges = [[1, 0]]`:
  - `cnt[1] = 1, cnt[0] = 2`.
  - `ans[0] = 1`.
  - For node 1: `ans[1] = ans[0] - cnt[1] + (2 - cnt[1]) = 1 - 1 + 1 = 1`.
  - Output: `[1, 1]`. Correct.
- Test `n = 1, edges = []`:
  - Root 0 has no edges; `ans[0] = 0`. Output: `[0]`. Correct.

## Follow-ups
- Why use an explicit stack instead of recursion? Trees can be degenerate lines of up to 30,000 nodes, which can cause a stack overflow in standard recursion frames depending on environment limits.
- How can rerooting tree DP be applied to other metrics? Rerooting applies to any tree metric where removing a subtree and adding the complement can be computed in O(1), such as tree diameter, subtree products, or maximum path lengths.

## Common mistakes
- Running recursive DFS without considering maximum call stack depth for linear line trees.
- Forgetting that when moving to child `v`, the nodes inside `v`'s subtree get closer (subtract `cnt[v]`), while nodes outside get farther (add `n - cnt[v]`).
