## Clarify first

- Do diagonal connections count as part of the same island? No, connectivity is strictly 4-directional (up, down, left, right).
- Can the grid be empty? Constraints indicate rows and columns are between 1 and 300.
- Is modifying the grid allowed in-place? Yes, sinking visited land cells by mutating `'1'` to `'0'` saves allocating a separate visited matrix.
- What values appear in the grid? Only characters (or strings) `"1"` (land) and `"0"` (water).

## Examples to say out loud

- Single large island: A grid where all `'1'`s are connected into one component. After traversing the first `'1'`, all adjacent `'1'`s are marked visited, returning count 1.
- Multiple separated islands:
  - Row 0: `["1", "1", "0", "0", "0"]`
  - Row 1: `["1", "1", "0", "0", "0"]`
  - Row 2: `["0", "0", "1", "0", "0"]`
  - Row 3: `["0", "0", "0", "1", "1"]`
  - Returns 3 separate connected components.
- All water edge case: A grid filled entirely with `"0"`, returning 0.

## Brute force

A brute-force search is not fundamentally different in complexity, but a naive implementation might search paths without marking visited cells, causing infinite cycles between adjacent land cells. Alternatively, computing connected components via full transitive closure on an adjacency matrix takes `O((rows * cols)^2)` time, which for a 300x300 grid (`90,000` cells) would require over `8 \times 10^9` operations.

## The key observation

The grid can be modeled as an undirected graph where each `'1'` cell is a vertex and edges connect adjacent `'1'`s. The number of islands equals the number of connected components. When an unvisited `'1'` is discovered, we increment the island count and execute a flood fill (DFS or BFS) to visit and sink all reachable land cells in that component before continuing the scan.

## Optimal approach

1. Initialize `count = 0`, and get grid dimensions `rows` and `cols`.
2. Define directional vectors for 4-way movement: `(1, 0), (-1, 0), (0, 1), (0, -1)`.
3. Iterate `r` from 0 to `rows - 1`, and `c` from 0 to `cols - 1`:
   a. If `grid[r][c] == "1"`:
      i. Increment `count`.
      ii. Start an iterative DFS (or BFS) from `(r, c)`.
      iii. Mark `grid[r][c] = "0"` and push `(r, c)` onto a stack.
      iv. While the stack is not empty, pop `(x, y)` and inspect its 4 neighbors. For each neighbor `(nx, ny)` within bounds that equals `"1"`, set `grid[nx][ny] = "0"` and push onto the stack.
4. Return `count`.

Complexity:
- Time: `O(rows * cols)` because every cell is visited by the outer loops once and touched by the flood fill at most once.
- Space: `O(rows * cols)` worst-case auxiliary space for the DFS stack if the entire grid is land.

## Code walkthrough

In the reference implementation:
- `const int dr[4] = {1, -1, 0, 0}, dc[4] = {0, 0, 1, -1};`: encapsulates 4-directional orthogonal neighbor offsets.
- `if (grid[r][c] != "1") continue;`: skips already sunken land or water cells.
- `count++;`: registers discovery of an independent landmass.
- `grid[nx][ny] = "0";`: immediately sinks a neighboring land cell upon enqueueing to prevent duplicate stack entries.
- `vector<pair<int, int>> st;`: utilizes an explicit stack to avoid deep call-stack recursion on large grids.

## Test it out loud

- `grid = [["1", "0"], ["0", "1"]]`:
  - `(0, 0)` is `"1"`: `count` becomes 1. Sink `(0, 0)`. Neighbors `(1, 0)` and `(0, 1)` are `"0"`. Flood fill terminates.
  - `(0, 1)` is `"0"`, `(1, 0)` is `"0"`.
  - `(1, 1)` is `"1"`: `count` becomes 2. Sink `(1, 1)`.
  - Return 2.
- `grid = [["0"]]`: returns 0 immediately.

## Follow-ups

- What if the grid cannot be modified?
  Maintain an auxiliary 2D boolean `visited` array of size `rows x cols` or use a hash set of coordinate pairs.
- Can this be solved using Disjoint Set Union (Union-Find)?
  Yes, initialize a DSU with all land cells as independent sets, union adjacent land cells, and return the number of distinct roots.

## Common mistakes

- Marking a cell as visited when popping from the stack rather than when pushing, leading to redundant pushes and memory exhaustion on large grids.
- Using unbounded recursive DFS, which can trigger stack overflow when `rows * cols = 90,000`.
- Allowing diagonal transitions when the problem specifies orthogonal adjacency.
