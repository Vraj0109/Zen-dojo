## Clarify first
- How are prerequisites structured? A pair `[a, b]` indicates that course `b` must be taken before course `a` (a directed edge `b -> a`).
- What should be returned if a valid schedule is impossible due to cyclic dependencies? Return an empty array `[]`.
- If multiple valid topological orders exist, which one should be returned? Return the lexicographically smallest order: at each step, select the smallest available course index.
- Can courses have zero prerequisites? Yes, courses without prerequisites can be taken immediately.

## Examples to say out loud
- Consider `numCourses = 4`, `prerequisites = [[1,0],[2,0],[3,1],[3,2]]`:
  - Course 0 has in-degree 0 and is taken first.
  - Courses 1 and 2 become available. Because 1 is smaller than 2, take 1 next.
  - Then take 2.
  - Finally, course 3 becomes available and is taken last.
  - Output: `[0, 1, 2, 3]`.
- Cycle case: `numCourses = 2, prerequisites = [[1,0],[0,1]]`. Both courses require each other. Output: `[]`.
- No dependencies: `numCourses = 3, prerequisites = []`. Output is `[0, 1, 2]`.

## Brute force
A brute force backtracking approach generates permutations of course schedules and validates each against the prerequisite constraints until finding a valid one. With `numCourses` up to 2000, checking `N!` permutations is impossible. Standard Kahn's algorithm or DFS topological sort finds an order in O(V + E) time, but standard FIFO queues do not guarantee the lexicographically smallest ordering.

## The key observation
To ensure the lexicographically smallest topological sort, we replace the standard FIFO queue in Kahn's algorithm with a min-heap (priority queue).
Whenever a course's in-degree drops to 0, it is pushed into the min-heap. At each step, popping the minimum course number from the heap greedily selects the smallest available course. If the final order contains fewer than `numCourses` elements, a cycle exists in the dependency graph.

## Optimal approach
1. Build an adjacency list `g` of size `numCourses` and an in-degree array `indeg`. For each relation `[a, b]`, add edge `b -> a` and increment `indeg[a]`.
2. Initialize a min-heap `pq` and push all courses with `indeg[i] == 0`.
3. Initialize an empty result list `order`.
4. While `pq` is not empty:
   - Extract the smallest course `u = pq.top()`.
   - Append `u` to `order`.
   - For each neighbor `v` in `g[u]`:
     - Decrement `indeg[v]`.
     - If `indeg[v] == 0`, push `v` into `pq`.
5. If `order.size() != numCourses`, a cycle exists; return an empty vector `{}`.
6. Return `order`.

Complexity:
- Time complexity: O((V + E) log V) where V is `numCourses` and E is the number of prerequisite edges. Every vertex is pushed and popped from the min-heap in O(log V) time, and each edge is traversed once.
- Space complexity: O(V + E) auxiliary space for the adjacency list graph, in-degree array, and priority queue.

## Code walkthrough
- `g[p[1]].push_back(p[0]); indeg[p[0]]++`: Translates `[a, b]` into directed edge `b -> a` and records prerequisites.
- `priority_queue<int, vector<int>, greater<int>> pq`: Min-heap storing all immediately available courses with in-degree 0.
- `for (int i = 0; i < numCourses; i++) if (indeg[i] == 0) pq.push(i)`: Collects initial zero in-degree courses in ascending numerical order.
- `if (--indeg[v] == 0) pq.push(v)`: Discovers freshly unblocked courses and adds them to the min-heap.
- `if ((int)order.size() != numCourses) return {}`: Detects cycles and returns an empty schedule if not all courses can be taken.

## Test it out loud
- Test `numCourses = 3, prerequisites = [[0, 1], [1, 2]]`:
  - `indeg = [1, 1, 0]`. Edge: `2 -> 1 -> 0`.
  - Heap starts with `[2]`.
  - Pop 2: order `[2]`, `indeg[1]` becomes 0. Push 1.
  - Pop 1: order `[2, 1]`, `indeg[0]` becomes 0. Push 0.
  - Pop 0: order `[2, 1, 0]`.
  - Full length 3, returns `[2, 1, 0]`. Correct.
- Test cyclic `[[1, 0], [2, 1], [0, 2]]`:
  - All in-degrees are 1. Heap is empty from start.
  - Returns `[]`. Correct.

## Follow-ups
- What if any valid order were acceptable without lexicographical tie-breaking? We could replace the min-heap with a standard FIFO queue, reducing time complexity from O((V + E) log V) to pure linear O(V + E).
- Can this be solved with DFS? DFS with recursion can find a topological sort by post-order reversal, but constructing the lexicographically smallest ordering using DFS is unnatural and prone to suboptimal choices without a global priority queue.

## Common mistakes
- Inverting the edge direction (adding `a -> b` instead of `b -> a`), which reverses prerequisite dependencies.
- Using a plain FIFO queue and sorting the output at the end, which does not yield a valid topological order.
- Forgetting to check if `order.size() == numCourses`, returning a partial schedule when cycles exist.
