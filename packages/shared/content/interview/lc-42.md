## Clarify first

- What is the width of each bar? Each elevation bar has width 1.
- Can water leak out off the left or right edges? Yes, water can only be trapped between taller boundaries; water outside the leftmost or rightmost boundaries spills away.
- What if `height.length < 3`? At least 3 bars are needed to form a basin; arrays of length 0, 1, or 2 trap 0 water.
- What are the constraints on array length and bar heights? Array length is up to 20,000, and heights range from 0 to 100,000.

## Examples to say out loud

- Standard basin: `height = [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]`.
  - Water accumulates over index 2 (1 unit), index 4 (1 unit), index 5 (2 units), index 6 (1 unit), index 9 (1 unit).
  - Total trapped rain water is `1 + 1 + 2 + 1 + 1 = 6`.
- Symmetric valley: `height = [2, 0, 2]`. Basin at index 1 is bounded by 2 on both sides: `min(2, 2) - 0 = 2`. Total is 2.
- Monotonic slope: `height = [1, 2, 3, 4]`. No depression exists to hold water, returns 0.

## Brute force

A brute-force solution determines the water trapped directly above each individual bar `i`: water held at bar `i` is `max(0, min(max_left, max_right) - height[i])`. To compute this, for each bar `i`, scan left from `i` to 0 to find `max_left`, and scan right from `i` to `n - 1` to find `max_right`. Doing two linear scans for all `n` bars takes `O(n^2)` time and `O(1)` space, which is too slow for `n = 20,000`.

## The key observation

The water held at index `i` is strictly determined by the bottleneck: `min(leftMax, rightMax) - height[i]`. If we place two pointers at the ends (`l = 0`, `r = n - 1`) and maintain running maximums `leftMax` and `rightMax`, whenever `height[l] < height[r]`, we know with certainty that `leftMax < rightMax` (or will be capped by `height[r]`), so the water level above bar `l` depends exclusively on `leftMax`, regardless of the remaining bars to the right. Thus, we can process bar `l` immediately and advance `l`.

## Optimal approach

1. Initialize two pointers: `l = 0` and `r = height.length - 1`.
2. Initialize `leftMax = 0`, `rightMax = 0`, and `water = 0`.
3. While `l < r`:
   a. If `height[l] < height[r]`:
      - Update `leftMax = max(leftMax, height[l])`.
      - Add trapped water at `l`: `water += leftMax - height[l]`.
      - Increment `l`.
   b. Otherwise:
      - Update `rightMax = max(rightMax, height[r])`.
      - Add trapped water at `r`: `water += rightMax - height[r]`.
      - Decrement `r`.
4. Return `water`.

Complexity:
- Time: `O(n)` because in each step either pointer `l` advances or pointer `r` recedes, visiting every bar once.
- Space: `O(1)` auxiliary space as only pointer variables and scalar trackers are used.

## Code walkthrough

In the reference implementation:
- `int l = 0, r = height.length - 1;`: anchors the two-pointer scan at opposite ends.
- `if (height[l] < height[r])`: identifies that the left side acts as the limiting wall.
- `leftMax = Math.max(leftMax, height[l]); water += leftMax - height[l]; l++;`: updates left boundary, accumulates water, and advances left pointer.
- `rightMax = Math.max(rightMax, height[r]); water += rightMax - height[r]; r--;`: symmetrically handles the right-side bottleneck.
- `return water;`: returns the total trapped volume.

## Test it out loud

- `height = [2, 0, 2]`:
  - `l = 0 (2), r = 2 (2)`. `height[l] < height[r]` is false.
  - Process `r`: `rightMax = max(0, 2) = 2`, `water += 2 - 2 = 0`. `r` becomes 1.
  - Next: `l = 0 (2), r = 1 (0)`. `height[0] < height[1]` (`2 < 0`) is false.
  - Process `r`: `rightMax = max(2, 0) = 2`, `water += 2 - 0 = 2`. `r` becomes 0.
  - `l == r`, loop terminates. Output is 2.
- `height = [1, 2]`:
  - `l = 0 (1), r = 1 (2)`: `height[l] < height[r]`.
  - `leftMax = 1`, `water += 1 - 1 = 0`. `l` becomes 1.
  - `l == r`, loop terminates. Output is 0.

## Follow-ups

- Can this be solved with a monotonic stack?
  Yes, maintain a decreasing stack of bar indices. When a taller bar is encountered, pop the bottom of the basin, calculate bounded height and width, and add water layer by layer in `O(n)` time and `O(n)` space.
- What if the terrain is 2D (Trapping Rain Water II, LeetCode 407)?
  Use a min-heap initialized with all boundary cells and run Dijkstra-like BFS inward in `O(R * C log(R * C))` time.

## Common mistakes

- Using prefix and suffix max arrays of size `n`, which achieves `O(n)` time but consumes `O(n)` unnecessary auxiliary memory.
- Forgetting to update `leftMax` or `rightMax` before subtracting `height[l]` or `height[r]`, resulting in negative water values.
- Off-by-one errors with pointer convergence condition (`l < r` vs `l <= r`).
