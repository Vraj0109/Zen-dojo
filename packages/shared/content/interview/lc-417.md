## Clarify first
- Where are the Pacific and Atlantic oceans located relative to the island grid? Pacific touches the top and left edges; Atlantic touches the bottom and right edges.
- How does water flow? Water can flow from a cell to an adjacent cell (up, down, left, right) if the adjacent cell's height is less than or equal to the current cell's height.
- What if water can flow from a cell to both oceans? Then that cell's coordinates `[r, c]` must be included in the return list.
- Can cells be returned in any order? Yes, any permutation of coordinate pairs is accepted.

## Examples to say out loud
- Consider a 1x1 matrix `[[1]]`:
  - The cell touches top, bottom, left, and right borders simultaneously. It can flow to both oceans. Output: `[[0, 0]]`.
- Uniform 2x2 matrix `[[1, 1], [1, 1]]`:
  - Since all heights are equal, water can flow in any direction freely. All four cells can reach both oceans. Output: `[[0, 0], [0, 1], [1, 0], [1, 1]]`.
- Peak surrounded by slopes: A central high peak can flow outward to all edges and reaches both oceans.

## Brute force
A brute force approach starts a DFS or BFS from every single cell `(i, j)` in the grid. From each cell, it traverses reachable cells going downhill (`heights[next] <= heights[curr]`) and checks if the search reaches both a Pacific boundary and an Atlantic boundary. For a grid with `r` rows and `c` columns, running a separate search from every cell takes `O((r * c)^2)` time, which is too slow for 200x200 grids (4 * 10^4 cells). We can reverse the direction of search to achieve linear O(r * c) time.

## The key observation
Instead of checking whether water from cell `(r, c)` can flow downhill to an ocean, we invert the question: can water flow uphill from an ocean to cell `(r, c)`?
- If we start at the Pacific borders (top row and left column) and walk uphill to adjacent cells with height greater than or equal to the current cell, every cell visited can flow downhill to the Pacific Ocean.
- Similarly, starting at the Atlantic borders (bottom row and right column) and walking uphill marks every cell that can flow downhill to the Atlantic Ocean.
- The cells that can reach both oceans are simply the intersection of cells reachable in both uphill searches.

## Optimal approach
1. Allocate two 2D boolean matrices of size `r x c`: `pac` (reachable from Pacific) and `atl` (reachable from Atlantic), both initialized to false.
2. Define a multi-source BFS or DFS helper `fill(seen, starts)`:
   - For each start coordinate, mark it visited in `seen` and push to queue.
   - While the queue is not empty, pop `(x, y)` and inspect 4 neighbors `(nx, ny)`.
   - If neighbor is within bounds, not yet seen, and satisfies `heights[nx][ny] >= heights[x][y]`: mark `seen[nx][ny] = true` and enqueue `(nx, ny)`.
3. Run `fill` for `pac` using all cells on the top row (`(0, j)`) and left column (`(i, 0)`).
4. Run `fill` for `atl` using all cells on the bottom row (`(r - 1, j)`) and right column (`(i, c - 1)`).
5. Iterate through all cells `(i, j)`. If both `pac[i][j]` and `atl[i][j]` are true, append `[i, j]` to the output.
6. Return the output list.

Complexity:
- Time complexity: O(r * c) because each cell is visited at most once during the Pacific search and at most once during the Atlantic search.
- Space complexity: O(r * c) auxiliary space for the two boolean reachability matrices and BFS queues.

## Code walkthrough
- `vector<vector<bool>> pac(r, ...), atl(r, ...)`: Tracks whether a cell can drain into the respective ocean.
- `if (h[nx][ny] < h[x][y]) continue`: Inverts the water flow condition: since we are searching backwards from ocean to peaks, the next step must go uphill (`h[nx][ny] >= h[x][y]`).
- Boundary seeding: Initializes Pacific search along top and left borders, Atlantic search along bottom and right borders.
- Intersection collection: Gathers cells where `pac[i][j] && atl[i][j]`.

## Follow-ups
- Can this be implemented recursively with DFS? Yes, recursive DFS works and is concise, but for large grid constraints, BFS or iterative DFS avoids stack overflows.
- What if water could also flow diagonally? We would simply expand the direction vectors from 4 neighbors to 8 neighbors without altering the reverse search logic.

## Common mistakes
- Searching downhill from each cell rather than searching uphill from the ocean borders.
- Using `<` instead of `<=` for valid water flow; water can flow across flat plateaus of equal height.
- Forgetting that corner cells touch both oceans and must be seeded for both searches.
