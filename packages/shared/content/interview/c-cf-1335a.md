## Clarify first
- What are the inputs? An integer `n` representing the total number of candies.
- What are the rules for distributing the candies between two sisters, Alice and Betty?
  - Both Alice (`a`) and Betty (`b`) must receive a strictly positive integer number of candies: `a > 0` and `b > 0`.
  - Alice must receive strictly more candies than Betty: `a > b`.
  - All candies must be distributed: `a + b = n`.
- What is the output? The total number of valid ways to distribute the candies.
- What are the constraints on `n`? `1 <= n <= 2 * 10^9`, with up to 10^4 test cases `t`.

## Examples to say out loud
- For `n = 7`: Valid pairs `(a, b)` are `(6, 1)`, `(5, 2)`, `(4, 3)`. There are 3 ways.
- For `n = 1`: No way to give both positive integers such that `a > b`. Answer is 0.
- For `n = 2`: Only distribution is `(1, 1)`, but `a > b` is not satisfied. Answer is 0.

## Brute force
A brute force approach iterates over all possible values of `b` from 1 up to `n - 1`, setting `a = n - b` and checking if `a > b`. With `n <= 2 * 10^9`, this loop would execute up to 10^9 times per test case, leading to Time Limit Exceeded. We must derive an O(1) closed-form formula.

## The key observation
Since `b` is a positive integer, `b >= 1`.
Additionally, we need `a > b`, which means `n - b > b`, or `2 * b < n`, which simplifies to `b < n / 2`.
Therefore, `b` can be any integer in the range `1 <= b <= (n - 1) / 2`.
The number of such integers is simply `floor((n - 1) / 2)`.

## Optimal approach
1. Take the given number of candies `n`.
2. Compute `(n - 1) / 2` using integer division.
3. Return the result.
4. Process each test case in O(1) time.

Complexity:
- Time complexity: O(1) per query, or O(t) total for `t` queries.
- Space complexity: O(1) auxiliary space.

## Code walkthrough
- `long long ans = (n - 1) / 2`: Uses integer floor division to count integer choices of `b` from 1 to `floor((n - 1) / 2)`.
- If `n <= 2`, `(n - 1) / 2` yields `0`, which correctly handles all edge cases without extra branches.
- `return ans`: Returns the number of ways.

## Test it out loud
- `n = 7`: `(7 - 1) / 2 = 6 / 2 = 3`. Correct.
- `n = 1`: `(1 - 1) / 2 = 0`. Correct.
- `n = 2`: `(2 - 1) / 2 = 0`. Correct.
- `n = 8`: `(8 - 1) / 2 = 7 / 2 = 3` (pairs are `(7,1), (6,2), (5,3)`). Correct.

## Follow-ups
- What if there were three sisters `a > b > c > 0` with `a + b + c = n`? We could iterate over `c` or use generating functions / integer partition math to count combinations in O(n) or O(1).

## Common mistakes
- Dividing `n / 2` directly without subtracting 1 first; for even `n = 8`, `8 / 2 = 4`, which incorrectly includes the invalid pair `(4, 4)` where `a == b`.
- Using 32-bit signed integer types that could overflow during intermediate operations if not careful (though `n <= 2 * 10^9` fits in standard 32-bit signed int, 64-bit int is best practice).
