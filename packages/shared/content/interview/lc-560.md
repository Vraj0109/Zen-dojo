## Clarify first

- Can the numbers in `nums` be negative or zero? (Yes, numbers range from -1000 to 1000, so running sums are non-monotonic).
- Can `k` be negative or zero? (Yes, `k` can be zero or negative, ranging between -10,000,000 and 10,000,000).
- Does an empty subarray count? (No, subarrays must be non-empty and contiguous).
- Can two different subarrays share identical elements or indices? (Yes, every distinct pair of start and end indices `(i, j)` that sums to `k` counts as a separate subarray).
- Can we use a sliding window with two pointers? (No, because negative values make subarray sums increase or decrease unpredictably as the window grows).

## Examples to say out loud

- Basic example: `nums = [1, 1, 1]`, `k = 2`.
  - Prefix sums: `P = [0, 1, 2, 3]`.
  - At index 1 (prefix 2): `prefix - k = 2 - 2 = 0`. Prefix 0 was seen once, count += 1 (`[1, 1]`).
  - At index 2 (prefix 3): `prefix - k = 3 - 2 = 1`. Prefix 1 was seen once, count += 1 (`[1, 1]`).
  - Total count is 2.
- Zero elements: `nums = [0, 0, 0]`, `k = 0`.
  - Prefixes are `[0, 0, 0, 0]`. Any pair of indices forms a valid subarray. Total count is `3 * 4 / 2 = 6`.
- Negative numbers: `nums = [1, -1, 0]`, `k = 0`.
  - Subarrays `[1, -1]`, `[0]`, and `[1, -1, 0]` all sum to 0. Total count is 3.

## Brute force

The brute-force solution evaluates all pairs of indices `(i, j)` with `i <= j`. We could compute the sum of each subarray directly, which takes `O(n^3)` time, or compute prefix sums first so that any range sum `nums[i...j]` is evaluated in `O(1)` as `prefix[j + 1] - prefix[i]`. Checking all pairs takes `O(n^2)` time and `O(1)` space. For `n = 20,000`, `n^2` is `4 * 10^8` operations, which exceeds time limits in competitive and interview settings.

## The key observation

The sum of a contiguous subarray `nums[i...j]` is mathematically equivalent to `prefix[j] - prefix[i - 1]`. Setting this sum equal to `k` yields `prefix[i - 1] = prefix[j] - k`. As we calculate the cumulative prefix sum `prefix` at index `j`, any earlier index whose prefix sum equaled `prefix - k` defines a valid subarray ending at `j`. Maintaining a frequency map of previous prefix sums lets us count all matching subarrays in `O(1)` time per step.

## Optimal approach

1. Maintain a hash map `seen` mapping each prefix sum value to how many times it has occurred.
2. Initialize `seen[0] = 1` to account for valid subarrays that start at index 0.
3. Initialize `prefix = 0` and `total = 0`.
4. Iterate through each number `x` in `nums`:
   a. Add `x` to `prefix`.
   b. If `prefix - k` exists in `seen`, add `seen[prefix - k]` to `total`.
   c. Increment the count of `prefix` in `seen`: `seen[prefix] = seen[prefix] + 1`.
5. Return `total`.

Complexity:
- Time: `O(n)` because we make a single pass through `nums`, doing `O(1)` average work per number for hash map lookup and insertion.
- Space: `O(n)` auxiliary space to store at most `n + 1` unique prefix sums in `seen`.

## Code walkthrough

In the reference implementation:
- `unordered_map<long long, int> seen; seen[0] = 1;`: seeds the base prefix sum 0 with count 1.
- `long long prefix = 0; int total = 0;`: tracks the running sum and total matching subarray count.
- `prefix += x;`: computes the current cumulative sum.
- `auto it = seen.find(prefix - k); if (it != seen.end()) total += it->second;`: adds all previously recorded starting points that form sum `k`.
- `seen[prefix]++;`: logs the current cumulative sum so subsequent elements can pair with it.

## Test it out loud

- Single element matching: `nums = [3]`, `k = 3`:
  - `prefix = 3`, `prefix - k = 0`. `seen[0]` is 1, so `total = 1`. `seen[3]` becomes 1. Returns 1.
- Single element not matching: `nums = [1]`, `k = 0`:
  - `prefix = 1`, `prefix - k = 1`. Not in map, `total = 0`. Returns 0.
- `nums = [3, 4, 7, 2, -3, 1, 4, 2]`, `k = 7`:
  - Prefixes hit matching complements at `[3, 4]`, `[7]`, `[7, 2, -3, 1]`, and `[1, 4, 2]`. Total returns 4.

## Follow-ups

- Why does two-pointer sliding window fail here?
  Because negative numbers mean expanding the window does not monotonically increase the sum, and shrinking does not monotonically decrease it.
- What if we need the maximum length of a subarray summing to `k`?
  Store the earliest index of each prefix sum instead of counts; when `prefix - k` is found, candidate length is `j - seen[prefix - k]`.
- What if numbers are only positive?
  Then a two-pointer sliding window achieves `O(n)` time and `O(1)` extra space.

## Common mistakes

- Forgetting to initialize `seen[0] = 1`, which fails whenever a prefix itself equals `k` (subarrays starting at index 0).
- Updating `seen[prefix]++` before querying `seen[prefix - k]`: when `k = 0`, this mistakenly allows an empty subarray (`prefix - prefix = 0`) to be counted.
- Attempting to sort the array: reordering elements destroys the contiguous subarray structure.
