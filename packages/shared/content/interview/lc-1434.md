## Clarify first

- How many people and how many hats can there be? ($1 \le n \le 10$ people; hat IDs range from 1 to 40, so $H = 40$).
- Can a person wear more than one hat? (No, each person must wear exactly one distinct hat).
- Can two people wear the same hat? (No, all worn hats must be distinct).
- What should be returned if not everyone can receive a hat? (Return 0).
- Should the result be modulo something? (Yes, modulo $10^9 + 7$).

## Examples to say out loud

- Two people, one shared hat: `hats = [[1], [1]]`. Both want hat 1, but hats cannot be shared. No valid assignment exists; returns 0.
- Single choice per person: `hats = [[3, 4], [4, 5], [5]]`. Person 3 can only wear 5. That leaves hat 4 for Person 2, and hat 3 for Person 1. Exactly 1 valid assignment.
- Overlapping choices: `hats = [[3, 5, 1], [3, 5]]`. Person 1 takes 1 and Person 2 takes 3 or 5 (2 ways); Person 1 takes 5 and Person 2 takes 3 (1 way); Person 1 takes 3 and Person 2 takes 5 (1 way). Total 4 ways.

## Brute force

A naive backtracking tries assigning each person $p$ from $0$ to $n-1$ one of their preferred hats, marking used hats in a set. Since there are 40 hats and up to 10 people, searching through hat assignments per person can explore up to $40^{10} \approx 10^{16}$ states. Even with pruning, the search space over people is too vast because hat IDs range up to 40.

## The key observation

Notice the asymmetry: $n \le 10$, while there are 40 hats. If we try DP over people (where the state is the subset of used hats), there are $\binom{40}{10} \approx 8.4 \times 10^8$ subsets, which is too large. Instead, invert the assignment: iterate over hats $h \in [1, 40]$ and maintain a bitmask representing the subset of **people** who have received a hat so far. Since $n \le 10$, there are only $2^{10} = 1024$ states. For each hat, we either give it to nobody or give it to any person $p$ who likes it and has not yet received a hat.

## Optimal approach

1. Invert the input into an adjacency list `hatToPeople` where `hatToPeople[h]` stores all people $p$ who like hat $h \in [1, 40]$.
2. Initialize a DP array `dp` of size $2^n$ with zeros, and set `dp[0] = 1` (1 way to have 0 people wearing hats with 0 hats considered).
3. For each hat $h$ from 1 to 40:
   - Create a copy `nextDp = dp` to account for the option of skipping hat $h$.
   - For each person $p$ in `hatToPeople[h]`:
     - Set bit `pBit = 1 << p`.
     - For each mask from 0 to $2^n - 1$:
       - If bit $p$ is not set in `mask` (`(mask & pBit) == 0`) and `dp[mask] > 0`:
         - Add `dp[mask]` to `nextDp[mask | pBit]` modulo $10^9 + 7$.
   - Set `dp = nextDp`.
4. Return `dp[(1 << n) - 1]`, which represents the number of ways to assign hats such that all $n$ people have one.

Complexity:
- Time: `O(H * n * 2^n)` where $H = 40$ and $n \le 10$. The total operations are roughly $40 \times 10 \times 1024 \approx 4 \times 10^5$, running in just a few milliseconds.
- Space: `O(2^n)` auxiliary space to maintain the DP state table ($2^{10} = 1024$ integers).

## Code walkthrough

In the reference implementation:
- `vector<vector<int>> hatToPeople(41)`: maps each hat ID to the list of people who can wear it.
- `int targetMask = (1 << n) - 1`: the terminal bitmask where all $n$ bits are 1 (everyone has a hat).
- `vector<int> nextDp = dp;`: represents skipping current hat $h$ entirely.
- `if ((mask & pBit) == 0 && dp[mask] > 0)`: checks person $p$ does not already have a hat and current configuration is reachable.
- `nextDp[mask | pBit] = (nextDp[mask | pBit] + dp[mask]) % MOD`: transitions from state `mask` by assigning hat $h$ to person $p$.
- `dp = move(nextDp)`: advances to the next hat stage.

## Test it out loud

- Everyone wants same single hat: `hats = [[1], [1]]`. For hat 1, mask 0 transitions to mask 1 (`01`) and mask 2 (`10`). Neither reaches `11`. Hats 2..40 have no candidates. Returns `dp[3] = 0`.
- Single person: `hats = [[1, 2]]`. Hat 1 sets `mask 1` to 1. Hat 2 sets `mask 1` to $1 + 1 = 2$. Returns 2.
- Disjoint preferences: `hats = [[1], [2]]`. Hat 1 transitions $0 \to 1$. Hat 2 transitions $0 \to 2$ and $1 \to 3$. Output is `dp[3] = 1`.

## Follow-ups

- What if $n$ and $H$ were reversed ($H \le 10, n \le 40$)?
  We would iterate over people and keep a bitmask of used hats of size $2^H \le 2^{10}$.
- Can we optimize space to a single array?
  Yes, but we must be careful with inner loop ordering: since a hat can be assigned to at most one person, running the mask iteration in reverse avoids counting multiple assignments of the same hat within the same step.
- What if hats have costs and we want the minimum cost assignment?
  Replace counting DP with min-cost DP, changing addition to $\min(\dots + \text{cost})$.

## Common mistakes

- Iterating over people on the outside and bitmasking hats: causes state space of $2^{40}$, which causes Memory Limit Exceeded and Time Limit Exceeded.
- Allowing a hat to be assigned to multiple people in the same step by modifying `dp` in-place while iterating forwards through people.
- Off-by-one errors with 1-indexed hat numbers (hats range from 1 to 40, requiring size 41 for `hatToPeople`).
