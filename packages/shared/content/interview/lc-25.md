## Clarify first

- What should happen if the remaining nodes at the end are fewer than `k`? They must remain in their original order.
- Can we simply swap the node values instead of changing pointers? No, the problem specifies modifying node links directly, which is also the standard expectation in system design and low-level interviews.
- What if `k = 1`? Reversing groups of 1 leaves the entire list unchanged.
- What are the constraints on list length? Length is between 1 and 5,000, and `1 <= k <= length`.

## Examples to say out loud

- Even grouping with remainder: `head = [1, 2, 3, 4, 5]`, `k = 2`. First group `[1, 2]` becomes `[2, 1]`. Second group `[3, 4]` becomes `[4, 3]`. Node `5` is a leftover (< 2 nodes) so it remains unchanged. Result is `[2, 1, 4, 3, 5]`.
- Larger group size: `head = [1, 2, 3, 4, 5]`, `k = 3`. First group `[1, 2, 3]` becomes `[3, 2, 1]`. Remaining nodes `[4, 5]` are fewer than 3, remaining as `[4, 5]`. Result is `[3, 2, 1, 4, 5]`.
- Exact multiple: `head = [1, 2, 3, 4]`, `k = 2`. Result is `[2, 1, 4, 3]`.

## Brute force

A straightforward non-optimal solution traverses the list into an array of node pointers, iterates in chunks of size `k`, reverses each chunk of size `k`, leaves any remaining chunk alone, and then rewires all `.next` pointers along the array. While this takes `O(n)` time, it requires `O(n)` auxiliary space for the array of pointers. We want to achieve `O(1)` auxiliary space by reversing links directly in-place.

## The key observation

Before reversing any group, look ahead `k` steps from the node preceding the group (`groupPrev`). If fewer than `k` nodes exist before reaching null, stop immediately. If `k` nodes exist, reverse the sublist of `k` nodes, point `groupPrev->next` to the newly promoted head of the group (`kth`), connect the old head of the group (now tail) to the start of the next group, and advance `groupPrev` to that tail.

## Optimal approach

1. Prepend a `dummy` node pointing to `head` and initialize `groupPrev = dummy`.
2. In a loop:
   a. Check if there are at least `k` nodes ahead: traverse `kth` starting from `groupPrev` by `k` steps. If `kth == null`, break.
   b. Record `groupNext = kth->next`.
   c. Reverse the `k` nodes between `groupPrev->next` and `groupNext`: initialize `prev = groupNext` and `cur = groupPrev->next`. While `cur != groupNext`, save `nx = cur->next`, point `cur->next = prev`, shift `prev = cur`, and advance `cur = nx`.
   d. Save `oldFirst = groupPrev->next`.
   e. Connect `groupPrev->next = kth`.
   f. Advance `groupPrev = oldFirst`.
3. Return `dummy.next`.

Complexity:
- Time: `O(n)` because each node is visited once during the lookahead and once during the reversal.
- Space: `O(1)` auxiliary memory since only pointer reassignments are performed in place.

## Code walkthrough

In the reference implementation:
- `ListNode dummy(0, head); ListNode* groupPrev = &dummy;`: anchors the list to handle head swaps cleanly.
- `for (int i = 0; i < k && kth; i++) kth = kth->next;`: counts ahead `k` steps; exits if fewer than `k` nodes remain.
- `ListNode* prev = groupNext;`: pre-links the tail of the reversed segment directly to the next group, avoiding a separate re-linking step.
- `while (cur != groupNext) { ... }`: standard iterative reversal loop over the `k` nodes.
- `groupPrev->next = kth; groupPrev = oldFirst;`: hooks the previous group to the new front and repositions `groupPrev` to the new rear.

## Test it out loud

- `head = [1, 2, 3, 4, 5], k = 2`:
  - Pass 1: `groupPrev` is `dummy`. `kth` reaches node 2. `groupNext` is node 3.
  - Nodes 1 and 2 reversed: `dummy -> 2 -> 1 -> 3`.
  - `groupPrev` moves to node 1.
  - Pass 2: from node 1, `kth` reaches node 4. `groupNext` is node 5.
  - Nodes 3 and 4 reversed: `1 -> 4 -> 3 -> 5`.
  - `groupPrev` moves to node 3.
  - Pass 3: from node 3, only node 5 exists. Cannot take 2 steps, `kth` becomes null. Break.
  - Return `dummy.next`: `[2, 1, 4, 3, 5]`.

## Follow-ups

- What if incomplete groups at the end should also be reversed?
  Count total remaining nodes; if `< k`, still perform reversal instead of breaking.
- Can this be written recursively?
  Yes, verify `k` nodes exist, reverse `k` nodes, and recursively call `reverseKGroup(groupNext, k)`, which uses `O(n / k)` stack frames.

## Common mistakes

- Reversing the tail segment when fewer than `k` nodes remain.
- Losing track of `groupNext` before starting the reversal of the current group.
- Forgetting to update `groupPrev` to point to the tail of the newly reversed group.
