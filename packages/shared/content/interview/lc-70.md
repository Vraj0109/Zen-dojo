## Clarify first

- Can `n` be 0 or negative? Constraints specify `1 <= n <= 45`.
- Can we take 3 or more steps at a time? No, each move is strictly 1 or 2 steps.
- Does the order of steps matter? Yes, sequences such as `1 + 2` and `2 + 1` count as distinct ways to reach step 3.
- Will the final result exceed standard 32-bit signed integer limits? For `n = 45`, the number of ways is 1,836,311,903, which comfortably fits inside a 32-bit signed integer (`INT_MAX` is ~2.14 billion).

## Examples to say out loud

- Base case `n = 2`: We can take `[1, 1]` or `[2]`. Total ways = 2.
- Base case `n = 3`: We can take `[1, 1, 1]`, `[1, 2]`, or `[2, 1]`. Total ways = 3.
- Edge case `n = 1`: The only possible way is `[1]`, total ways = 1.

## Brute force

A brute-force recursive formulation branches into two calls at each step: `ways(n) = ways(n - 1) + ways(n - 2)`. Because each state branches twice and tree height is `n`, this recursion does redundant work, running in `O(2^n)` exponential time. For `n = 45`, `2^{45} \approx 3.5 \times 10^{13}` operations, which causes call stack overflow or severe timeout.

## The key observation

To reach step `n`, your final move must either be a 1-step leap from step `n - 1` or a 2-step leap from step `n - 2`. The events are mutually exclusive and collectively exhaustive, so `ways(n) = ways(n - 1) + ways(n - 2)`. This recurrence is the Fibonacci sequence, where calculating step `n` only requires the immediate two preceding values.

## Optimal approach

1. If `n <= 2`, return `n` directly.
2. Maintain two integer variables: `a = 1` (ways to reach step 1) and `b = 2` (ways to reach step 2). Equivalently, seed `a = 1` for step 0 and `b = 1` for step 1.
3. For step `i` from 2 up to `n`:
   a. Compute `c = a + b`.
   b. Shift `a = b` and `b = c`.
4. Return `b`.

Complexity:
- Time: `O(n)` because we compute each consecutive step once up to `n`.
- Space: `O(1)` as we only store the two most recent values.

## Code walkthrough

In the reference implementation:
- `int a = 1, b = 1;`: sets base states corresponding to `ways(0) = 1` and `ways(1) = 1`.
- `for (int i = 2; i <= n; i++)`: loops from step 2 to step `n`.
- `int c = a + b;`: computes the current step count by adding the preceding two step counts.
- `a = b; b = c;`: rolls the sliding window forward by one step.
- `return b;`: returns the total distinct combinations reaching step `n`.

## Test it out loud

- `n = 1`: The loop from 2 to 1 does not execute; returns `b = 1`.
- `n = 4`:
  - `i = 2`: `c = 1 + 1 = 2`, `a = 1`, `b = 2`.
  - `i = 3`: `c = 1 + 2 = 3`, `a = 2`, `b = 3`.
  - `i = 4`: `c = 2 + 3 = 5`, `a = 3`, `b = 5`.
  - Result is 5.
- `n = 5`:
  - `i = 5`: `c = 3 + 5 = 8`, `a = 5`, `b = 8`.
  - Result is 8.

## Follow-ups

- What if you can take steps of sizes from a set `steps = [1, 2, 3, 5]`?
  Use dynamic programming where `dp[i] = sum(dp[i - s])` for each valid `s` in `steps`, leading to `O(n * |steps|)` time.
- What if `n` is up to `10^9` modulo `10^9 + 7`?
  Use `2x2` matrix exponentiation on `[[1, 1], [1, 0]]` to compute the Fibonacci value in `O(log n)` time.
- What if each step has an associated monetary cost (LeetCode 746: Min Cost Climbing Stairs)?
  Transition `dp[i] = cost[i] + min(dp[i - 1], dp[i - 2])`.

## Common mistakes

- Using unmemoized recursion, which results in `O(2^n)` exponential time.
- Allocating a full array of size `n + 1` when only the last two values are needed, using `O(n)` unnecessary space.
- Off-by-one errors with base cases when seeding `a` and `b`.
