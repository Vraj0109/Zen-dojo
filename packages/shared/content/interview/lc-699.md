## Clarify first
- How are squares represented? `positions[i] = [left, side]`, spanning interval `[left, left + side)`.
- Do touching edges count as landing on top of each other? No, boundary-only contacts (e.g. `[1, 2)` and `[2, 4)`) do not overlap and do not stack vertically.
- What should be recorded after each square lands? The maximum stack height among all squares placed up to that point.
- How large can coordinates and sizes be? `left <= 10^8, side <= 10^6`, with at most `1000` squares.

## Examples to say out loud
- Consider `positions = [[1, 2], [2, 3], [6, 1]]`:
  - Square 1: spans `[1, 3)`, height 2. Max height = 2.
  - Square 2: spans `[2, 5)`, overlaps `[1, 3)` in `[2, 3)`. Lands on top of square 1, new top = `2 + 3 = 5`. Max height = 5.
  - Square 3: spans `[6, 7)`, does not overlap `[1, 5)`. Lands on ground (height 0), top = 1. Max height = 5.
  - Result: `[2, 5, 5]`.
- Consider `positions = [[100, 100], [200, 100]]`:
  - Intervals `[100, 200)` and `[200, 300)`. Touching at 200 does not overlap. Both land on ground.
  - Result: `[100, 100]`.

## Brute force
Simulating every discrete point along the number line would require an array of size `10^8`, which is far too large for memory. Interval-based simulation is required.

## The key observation
With `n <= 1000`, an interval scan over previously landed squares runs in `O(n^2)` time, which easily executes within milliseconds. For a new square with interval `[l, r)` and side length `s`, two intervals `[l, r)` and `[ql, qr)` strictly overlap if and only if `l < qr` and `ql < r`. The new square lands directly on top of the tallest overlapping landed square, so `new_top = s + max(q.top)` across all strictly overlapping squares `q`. If no previous square overlaps, it lands on the ground (`base = 0`).

## Optimal approach
1. Initialize an empty list `placed` storing tuples `(left, right, top)` and an empty list `ans`.
2. Maintain a running maximum `best = 0`.
3. For each square `[left, side]` in `positions`:
   - Compute `l = left` and `r = left + side`.
   - Initialize `base = 0`.
   - Iterate over all previously placed squares `q` in `placed`:
     - If `l < q.right` and `q.left < r`, update `base = max(base, q.top)`.
   - The top of the new square is `top = base + side`.
   - Append `(l, r, top)` to `placed`.
   - Update `best = max(best, top)`.
   - Append `best` to `ans`.
4. Return `ans`.

Complexity:
- Time: `O(n^2)` time because the `i`-th square checks `i - 1` previously placed squares. For `n = 1000`, `1000^2 / 2 ≈ 5 * 10^5` operations.
- Space: `O(n)` auxiliary space to store the `placed` intervals and the answer array.

## Code walkthrough
- `vector<array<int, 3>> placed;` stores `[left, right, top]` for each settled square.
- `int l = p[0], r = p[0] + p[1];` computes the half-open interval `[l, r)`.
- `for (auto& q : placed)` compares with prior squares:
  - `if (l < q[1] && q[0] < r)` determines strict interval intersection.
  - `base = max(base, q[2]);` identifies the highest contact surface beneath the falling square.
- `int top = base + p[1];` determines the new square's top elevation.
- `best = max(best, top);` tracks the overall maximum height observed so far.

## Test it out loud
- Test single square `[[1, 1]]`: Lands on ground, returns `[1]`.
- Test identical position squares `[[1, 2], [1, 2]]`: First square has top 2. Second overlaps completely, lands on top giving 4. Returns `[2, 4]`.
- Test adjacent non-overlapping squares `[[1, 2], [3, 2]]`: Intervals `[1, 3)` and `[3, 5)` do not overlap. Both have top 2. Returns `[2, 2]`.
- Test step progression `[[1, 5], [2, 2], [3, 1]]`:
  - First: top 5.
  - Second: lands on first, top `5 + 2 = 7`.
  - Third: lands on second, top `7 + 1 = 8`.
  - Returns `[5, 7, 8]`.

## Follow-ups
- How to scale this if `n` were up to `10^5`?
  - Coordinate compress all `left` and `right` boundary coordinates (at most `2n` values) and use a Segment Tree with lazy propagation supporting range maximum query and range update in `O(n log n)` time.

## Common mistakes
- Using non-strict inequality `<=`, which treats touching side boundaries as overlaps and artificially stacks squares.
- Returning the height of each newly placed square rather than the running maximum height of all squares placed so far.
