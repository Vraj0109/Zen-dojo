## Clarify first
- Can a cell be used more than once in the same word path? No, each grid cell can be used at most once per path.
- In what directions can the word be constructed? 4 cardinal directions (up, down, left, right).
- Does the search have to match case? Yes, uppercase and lowercase letters are treated as distinct.
- What are the grid and word dimensions? Rows and columns are between 1 and 6; word length is between 1 and 15.

## Examples to say out loud
- Standard positive path: Grid 3x4:
  ```
  [["A","B","C","E"],
   ["S","F","C","S"],
   ["A","D","E","E"]]
  ```
  - For word `"ABCCED"`: starts at (0, 0) 'A' -> (0, 1) 'B' -> (0, 2) 'C' -> (1, 2) 'C' -> (2, 2) 'E' -> (2, 1) 'D'. Found; return true.
  - For word `"SEE"`: starts at (1, 3) 'S' -> (2, 3) 'E' -> (2, 2) 'E'. Found; return true.
- Negative case (cell reuse disallowed): For word `"ABCB"`:
  - From (0, 2) 'C', the only adjacent 'B' is (0, 1), which was already visited. Path cannot reuse it; return false.

## Brute force
A brute force approach starts a DFS from every cell in the grid. Without pruning, searching all self-avoiding paths can take exponential time. However, by pruning immediately whenever the current cell's character fails to match the corresponding character in `word`, and terminating as soon as a full match is found, DFS with backtracking explores only matching prefixes.

## The key observation
We must test every cell `(r, c)` in the `R x C` grid as a potential starting letter `word[0]`.
Once a starting cell matches:
- We recursively search its 4 cardinal neighbors for `word[1]`, then `word[2]`, and so on.
- To prevent reusing the current cell in the active path, we temporarily mutate `board[r][c]` to a sentinel character (such as `'#'`).
- When the recursive branch finishes, we restore `board[r][c]` back to its original character (backtrack).
- If any directional branch returns true, we immediately propagate `true` upward without exploring further.

## Optimal approach
1. Define recursive helper `dfs(r, c, i)`:
   - Base case: If `i == word.length()`, the entire word has been matched; return true.
   - Boundary & match check: If `r < 0 || c < 0 || r >= R || c >= C || board[r][c] != word[i]`, return false.
   - Temporarily mark cell as visited: `saved = board[r][c]`, `board[r][c] = "#"`.
   - Explore all 4 neighbors:
     `ok = dfs(r + 1, c, i + 1) || dfs(r - 1, c, i + 1) || dfs(r, c + 1, i + 1) || dfs(r, c - 1, i + 1)`.
   - Backtrack: restore `board[r][c] = saved`.
   - Return `ok`.
2. Iterate `r` from 0 to `R - 1` and `c` from 0 to `C - 1`:
   - If `dfs(r, c, 0)` is true, return true immediately.
3. Return false.

Complexity:
- Time complexity: O(R * C * 3^L) where R is rows, C is columns, and L is the length of `word`. From the second character onwards, we only have at most 3 directions to explore since we cannot return to the parent cell.
- Space complexity: O(L) auxiliary space for the recursion call stack, with O(1) extra space because visited state is marked directly in the board.

## Code walkthrough
- `if (i == (int)w.size()) return true`: Base success condition when all characters in `w` are matched.
- `if (r < 0 || c < 0 || r >= R || c >= C || b[r][c][0] != w[i]) return false`: Prunes invalid branches and out-of-bounds coordinates immediately.
- `string saved = b[r][c]; b[r][c] = "#"`: Marks the cell in place to avoid allocating a separate 2D visited array.
- Short-circuiting `||`: Aborts neighbor exploration as soon as one branch finds a valid full path.
- `b[r][c] = saved`: Restores original board character during backtrack.

## Test it out loud
- Test `board = [["a"]], word = "a"`:
  - `dfs(0, 0, 0)`: `b[0][0] == "a"`, `i = 0`.
  - Next calls `dfs(..., 1)`: hits `i == 1 == w.size()`, returns true.
  - Output: true. Correct.
- Test `board = [["a", "b"]], word = "aba"`:
  - 'a' at (0, 0), 'b' at (0, 1). To get second 'a', only neighbor is (0, 0), which is currently marked `'#'`.
  - Returns false. Correct.

## Follow-ups
- How can we optimize when word's last characters are much rarer than its first? Count frequencies of `word[0]` and `word.back()` on the board; if the last character occurs less frequently, reverse `word` before searching to prune earlier.
- How would you search for multiple words simultaneously (Word Search II)? Build a Trie of all dictionary words and run a single backtracking traversal over the board, matching against Trie nodes.

## Common mistakes
- Forgetting to restore `board[r][c] = saved` when returning from the DFS, corrupting the board for subsequent starting positions.
- Allocating a full `visited` matrix on each recursive call rather than updating in place or maintaining a single reusable boolean grid.
- Not short-circuiting neighbor searches when a path has already succeeded.
