## Clarify first

- Does `t` contain duplicate characters? Yes, if `t` has two `'A'`s, the window must contain at least two `'A'`s.
- What should be returned if no window covers all characters in `t`? Return an empty string `""`.
- Are characters case-sensitive? Yes, `'A'` and `'a'` are distinct characters.
- What are the length bounds? Both `s.length` and `t.length` can be up to 100,000.
- Is the shortest window guaranteed to be unique if it exists? Yes, the problem constraints state that tests have a unique shortest valid window.

## Examples to say out loud

- Standard matching window: `s = "ADOBECODEBANC"`, `t = "ABC"`.
  - Windows like `"ADOBEC"` contain `'A'`, `'B'`, `'C'`.
  - Expanding further and contracting from the left yields `"BANC"`, which has length 4 and contains all three required characters. Result is `"BANC"`.
- Single character exact match: `s = "a"`, `t = "a"`. Result is `"a"`.
- Insufficient characters: `s = "a"`, `t = "aa"`. `s` only has one `'a'`, so no valid window exists; return `""`.

## Brute force

A brute-force solution enumerates every substring `s[i..j]` where `0 <= i <= j < |s|`. For each substring, count its character frequencies and check whether every character frequency is at least that of `t`. There are `O(|s|^2)` substrings, and checking frequencies takes `O(alphabet)` time, yielding `O(|s|^2 * alphabet)` time. With `|s| = 100,000`, this requires `10^{10}` operations and times out.

## The key observation

The window boundaries `[left, right]` move monotonically to the right. We expand `right` until the current window satisfies all character requirements from `t`. Once valid, we contract `left` to discard non-essential leading characters, updating the shortest window found. As soon as contracting `left` removes a character required by `t`, the window becomes invalid, and we resume expanding `right`.

## Optimal approach

1. Build a frequency array `need` of size 128 (ASCII characters) initialized with character counts of `t`.
2. Maintain `missing = t.length()`, tracking how many characters are still needed to make the window valid.
3. Initialize `left = 0`, `bestStart = 0`, and `bestLen = infinity`.
4. Iterate `right` from 0 to `s.length() - 1`:
   a. If `need[s[right]] > 0`, decrement `missing`.
   b. Decrement `need[s[right]]`.
   c. While `missing == 0` (window is valid):
      i. If `right - left + 1 < bestLen`, record `bestLen = right - left + 1` and `bestStart = left`.
      ii. Increment `need[s[left]]`.
      iii. If `need[s[left]] > 0`, increment `missing` (since an essential character was evicted).
      iv. Increment `left`.
5. Return empty string `""` if `bestLen == infinity`, otherwise `s.substr(bestStart, bestLen)`.

Complexity:
- Time: `O(|s| + |t|)` because counting `t` takes `O(|t|)` and each character in `s` enters via `right` once and leaves via `left` at most once.
- Space: `O(alphabet)` which is `O(1)` fixed auxiliary space (128 ASCII table).

## Code walkthrough

In the reference implementation:
- `vector<int> need(128, 0);`: precomputes target counts for each character.
- `if (need[(unsigned char)s[right]]-- > 0) missing--;`: consumes character `s[right]`; decrements `missing` only when that character was needed.
- `while (missing == 0)`: enters contraction phase whenever the window is valid.
- `if (right - left + 1 < bestLen) { bestLen = right - left + 1; bestStart = left; }`: updates minimal substring bounds.
- `if (++need[(unsigned char)s[left]] > 0) missing++; left++;`: evicts `s[left]`; if it was essential, breaks the valid state to force expansion.

## Test it out loud

- `s = "ab", t = "b"`:
  - `need['b'] = 1`, `missing = 1`.
  - `right = 0 ('a')`: `need['a']` becomes -1, `missing` stays 1.
  - `right = 1 ('b')`: `need['b']` was 1 > 0, `missing` becomes 0.
  - Contract: `bestLen = 2 - 0 = 2`, `bestStart = 0`. Evict `'a'`: `need['a']` becomes 0, not > 0, so `missing` remains 0!
  - `left` becomes 1. Window `"b"`: length 1 < 2, update `bestLen = 1, bestStart = 1`. Evict `'b'`: `need['b']` becomes 1 > 0, `missing` becomes 1. `left` becomes 2.
  - Returns `s.substr(1, 1) = "b"`.
- `s = "a", t = "aa"`:
  - `missing` starts at 2. After `right = 0`, `missing` is 1. Loop finishes.
  - `bestLen` remains infinity, returns `""`.

## Follow-ups

- What if `s` is very long and contains mostly characters not in `t`?
  Filter `s` to create a list of pairs `(index, char)` containing only characters that appear in `t`, and run the two-pointer window over this filtered list.
- How does this compare to Longest Substring Without Repeating Characters (LeetCode 3)?
  LeetCode 3 contracts when a duplicate is found (maintaining an invariant of at most 1 of each char), whereas LeetCode 76 expands until at least `k` of each target char are contained.

## Common mistakes

- Re-checking entire map equality inside the loop in `O(alphabet)` time rather than maintaining an integer `missing` variable.
- Forgetting that negative values in `need` represent surplus characters inside the window.
- Extracting substrings repeatedly with `s.substr()` inside the loop, adding `O(n^2)` string copying overhead.
