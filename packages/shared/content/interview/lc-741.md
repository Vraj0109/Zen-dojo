## Clarify first
- What do grid cell values mean? `1` contains a cherry, `0` is empty, and `-1` is a thorn (blocked obstacle).
- How do paths work? Walk from `(0, 0)` to `(n-1, n-1)` moving only right or down, then walk back from `(n-1, n-1)` to `(0, 0)` moving only left or up.
- Can cherries be collected twice? No, once a cherry is collected on either walk, the cell becomes 0 (empty).
- What should be returned if no valid round trip exists through the thorns? Return 0.

## Examples to say out loud
- Consider 3x3 grid:
  ```
  [ 0,  1, -1]
  [ 1,  0, -1]
  [ 1,  1,  1]
  ```
  - Path 1 from (0,0) to (2,2): (0,0) -> (1,0) -> (2,0) -> (2,1) -> (2,2), collecting 3 cherries.
  - Return path from (2,2) to (0,0) (or second forward path): (2,2) -> (2,1) -> (2,0) is empty, but moving through (0,1) collects 1 more cherry.
  - Total collected: 5.
- Completely blocked: Thorns block all paths to `(n-1, n-1)`. Output: 0.
- Single cell: `[[1]]`. Output: 1. `[[0]]`. Output: 0.

## Brute force
A naive approach finds the best path from `(0, 0)` to `(n - 1, n - 1)` that maximizes collected cherries, clears those cherries to 0, and then finds the best path back. However, this two-pass greedy approach fails: picking the optimal first path can trap or starve the return journey of cherries. Both paths must be optimized simultaneously.

## The key observation
Walking from `(n - 1, n - 1)` back to `(0, 0)` using only left and up moves is equivalent to a second person walking from `(0, 0)` to `(n - 1, n - 1)` using only right and down moves.
Suppose both people start at `(0, 0)` at time `t = 0` and take one step at each time `t`:
- After `t` steps, any position `(r, c)` must satisfy `r + c = t`. Therefore, `c = t - r`.
- We can describe the state at step `t` solely by `(t, r1, r2)`, where `r1` is the row of the first person and `r2` is the row of the second person. Their columns are `c1 = t - r1` and `c2 = t - r2`.
- If both people land on the same cell (`r1 == r2`), the cherry in that cell is collected only once: `gain = grid[r1][c1]`.
- If they land on distinct cells (`r1 != r2`), both cherries are collected: `gain = grid[r1][c1] + grid[r2][c2]`.
At each step, each person could have arrived from the top or from the left (4 possible predecessor transitions).

## Optimal approach
1. Let `dp[r1][r2]` be the maximum cherries collected when person 1 is at row `r1` and person 2 is at row `r2` after `t` steps. Initialize `dp` with negative infinity (`NEG = INT_MIN / 2`).
2. Base case: `dp[0][0] = grid[0][0]`.
3. Iterate total steps `t` from 1 to `2 * n - 2`:
   - Initialize `next_dp` with `NEG`.
   - Iterate `r1` and `r2` within valid bounds `[max(0, t - (n - 1)), min(n - 1, t)]`:
     - Calculate `c1 = t - r1` and `c2 = t - r2`.
     - If `grid[r1][c1] == -1` or `grid[r2][c2] == -1`: continue (thorn cell).
     - Check the 4 previous states `dp[r1 - d1][r2 - d2]` for `d1, d2 in {0, 1}` and find `best`.
     - If `best == NEG`: continue (unreachable).
     - Calculate `gain = grid[r1][c1] + (r1 != r2 ? grid[r2][c2] : 0)`.
     - `next_dp[r1][r2] = best + gain`.
   - Update `dp = next_dp`.
4. Return `max(0, dp[n - 1][n - 1])`.

Complexity:
- Time complexity: O(n^3) because there are `2n - 1` steps, and for each step we iterate over pairs of rows `r1, r2` with 4 constant-time transitions.
- Space complexity: O(n^2) space by rolling the DP table across time steps `t`.

## Code walkthrough
- `const int NEG = INT_MIN / 2`: Uses safe negative infinity to prevent integer underflow during addition.
- `int c1 = t - r1, c2 = t - r2`: Implicitly computes columns from step count `t`.
- `for (int d1 = 0; d1 < 2; d1++) for (int d2 = 0; d2 < 2; d2++)`: Evaluates all 4 incoming step combinations (Down-Down, Down-Right, Right-Down, Right-Right).
- `gain = grid[r1][c1] + (r1 != r2 ? grid[r2][c2] : 0)`: Deduplicates cherry collection when both walkers occupy the same cell.
- `return max(0, dp[n - 1][n - 1])`: Returns 0 if destination was unreachable or negative.

## Test it out loud
- Test `[[1]]`:
  - `t = 0`: `dp[0][0] = 1`. Loop from `t = 1` to `0` does not execute.
  - Returns `max(0, dp[0][0]) = 1`. Correct.
- Test `[[1, 1], [1, 1]]`:
  - `n = 2, steps = 2`.
  - Both paths collect all 4 cherries independently without stepping on thorns. Returns 4. Correct.

## Follow-ups
- How does Cherry Pickup II differ? In Cherry Pickup II, two walkers start at the top corners and move down simultaneously to the bottom row, with 3 choices each (down-left, down, down-right), running in O(rows * cols^2) DP.
- Could this be solved with network flow? Yes, min-cost max-flow on a grid graph where each cherry cell has capacity 1 with cost -1 and infinite capacity with cost 0, pushing 2 units of flow. However, O(n^3) DP is much simpler and faster.

## Common mistakes
- Running two sequential greedy passes instead of simultaneous DP.
- Adding `grid[r2][c2]` twice when `r1 == r2`.
- Not using a sufficiently negative sentinel, causing invalid paths through thorns to look valid.
