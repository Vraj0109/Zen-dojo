## Clarify first
- What are the allowed values in the array? Only integers 0, 1, and 2.
- Are we allowed to use library sorting functions? No, library sorting is prohibited.
- Must the array be modified in place? Yes, the array should be sorted in place.
- Can we do this in a single pass? Yes, the Dutch National Flag algorithm partitions into three zones in a single pass.

## Examples to say out loud
- Standard case: `nums = [2, 0, 2, 1, 1, 0]`.
  - Grouping 0s at front, 1s in middle, 2s at back gives `[0, 0, 1, 1, 2, 2]`.
- Minimal case: `nums = [2, 0, 1]`.
  - Swapping produces `[0, 1, 2]`.
- Boundary case: `nums = [0]` remains `[0]`.

## Brute force
A straightforward counting sort counts the frequencies of 0s, 1s, and 2s during a first pass, then overwrites the array with the corresponding number of 0s, 1s, and 2s during a second pass. While this achieves O(n) time and O(1) space, it requires two passes over the array. We can achieve the same result in a single pass using a three-pointer partition.

## The key observation
The array can be partitioned into four regions using three pointers: `lo`, `i`, and `hi`:
1. `nums[0..lo-1]` contains all 0s.
2. `nums[lo..i-1]` contains all 1s.
3. `nums[i..hi]` contains uninspected elements.
4. `nums[hi+1..n-1]` contains all 2s.
When inspecting `nums[i]`:
- If `0`: swap with `nums[lo]`, then increment both `lo` and `i` (the swapped element is guaranteed to be 1 or 0).
- If `1`: leave it in place and increment `i`.
- If `2`: swap with `nums[hi]` and decrement `hi`. Do not increment `i`, because the element swapped from `hi` is unknown and must be inspected next.

## Optimal approach
1. Initialize `lo = 0`, `i = 0`, and `hi = n - 1`.
2. While `i <= hi`:
   - If `nums[i] == 0`: swap `nums[lo]` and `nums[i]`, increment `lo`, increment `i`.
   - Else if `nums[i] == 2`: swap `nums[i]` and `nums[hi]`, decrement `hi`. (Keep `i` unchanged).
   - Else (`nums[i] == 1`): increment `i`.
3. Return `nums`.

Complexity:
- Time complexity: O(n) because each iteration either increments `i` or decrements `hi`, guaranteeing at most n operations in a single pass.
- Space complexity: O(1) auxiliary space as all swaps occur in place.

## Code walkthrough
- `int lo = 0, i = 0, hi = (int)nums.size() - 1`: Sets up the boundaries.
- `if (nums[i] == 0) swap(nums[lo++], nums[i++])`: Advances 0s to the front. Since `lo <= i`, the element brought to `i` is known (always 1), so `i` can safely advance.
- `else if (nums[i] == 2) swap(nums[i], nums[hi--])`: Moves 2s to the rear. Crucially, `i` is not incremented so that the incoming value is evaluated.
- `else i++`: 1 is already in its valid middle partition.

## Test it out loud
- Test `nums = [2, 0, 1]`:
  - `lo = 0, i = 0, hi = 2`.
  - `nums[0] == 2`: swap with `nums[2] (1)`, `hi = 1`. Array: `[1, 0, 2]`.
  - Next step at `i = 0`: `nums[0] == 1`, `i = 1`.
  - Next step at `i = 1`: `nums[1] == 0`, swap with `nums[lo] (nums[0])`, `lo = 1, i = 2`. Array: `[0, 1, 2]`.
  - `i = 2 > hi = 1`. Loop terminates. Correct.

## Follow-ups
- How does this relate to QuickSort? This three-way partitioning (Dijkstra's Dutch National Flag) is used in 3-way QuickSort to handle arrays with duplicate keys efficiently in O(n log n) without degrading to O(n^2).
- Can this be generalized to k distinct values? For small fixed k, chaining partitions takes O(k * n) time and O(1) space, but for general k, counting sort is simpler.

## Common mistakes
- Incrementing `i` when swapping with `hi`, which misses inspecting the element swapped from the back.
- Terminating loop with condition `i < hi` instead of `i <= hi`, which leaves the last uninspected element at `hi` unplaced.
