## Clarify first

- What characters can the expression string contain? (Digits `'0'`-`'9'`, operators `'+'`, `'-'`, `'*'`, `'/'`, parentheses `'('`, `')'`, and spaces `' '`).
- How does integer division behave? (Truncates toward zero, matching standard integer division).
- What is operator precedence? (Parentheses highest, followed by `'*'` and `'/'`, followed by `'+'` and `'-'`).
- Can numbers have multiple digits? (Yes, e.g. `"14"`).
- Can the expression be malformed or cause division by zero? (The problem guarantees a valid expression and no division by zero or integer overflow).

## Examples to say out loud

- Operator precedence: `"6-4/2"`. Division happens first: $4 / 2 = 2$, then subtraction: $6 - 2 = 4$.
- Nested parentheses: `"2*(5+5*2)/3+(6/2+8)"`.
  - Inside `(5+5*2)`: $5 \times 2 = 10 \implies 5 + 10 = 15$.
  - Next: $2 \times 15 = 30$, then $30 / 3 = 10$.
  - Inside `(6/2+8)`: $3 + 8 = 11$.
  - Sum: $10 + 11 = 21$.
- Spaces and single numbers: `" 3/2 "`. Spaces are ignored; $3/2$ evaluates to $1$.

## Brute force

A naive brute force uses repeated string pattern matching and replacements: find the innermost parentheses using regex or substring search, evaluate them, replace them in the string, and repeat. Since each string replacement can take $O(n)$ time and there can be $O(n)$ nested operations, repeated string manipulation results in $O(n^2)$ time and excessive string allocations.

## The key observation

The expression can be parsed linearly using the standard precedence trick with a stack or recursion. Notice that whenever an opening parenthesis `'('` is encountered, the sub-expression within `(...)` can be evaluated recursively as if it were a single combined number. Within each recursive level (flat expression with no parentheses), higher precedence operators (`*` and `/`) immediately consume and update the top of the stack, while lower precedence operators (`+` and `-`) push values (or negated values) onto the stack. At the end of the level, summing the stack gives the result.

## Optimal approach

1. Pass a shared index pointer `i` through a recursive parsing function `parse(s, i)`.
2. Inside `parse(s, i)`:
   - Initialize a stack/vector `nums`, `char op = '+'`, and `cur = 0`.
   - While `i < s.size()`:
     - Read `c = s[i++]`.
     - If `c` is a digit: update `cur = cur * 10 + (c - '0')`.
     - Else if `c == '('`: recursively evaluate `cur = parse(s, i)`.
     - If `c` is an operator, closing parenthesis, or we reached the end of the string (and `c != ' '`):
       - If `op == '+'`: push `cur` onto `nums`.
       - If `op == '-'`: push `-cur` onto `nums`.
       - If `op == '*'`: pop `top` from `nums`, push `top * cur`.
       - If `op == '/'`: pop `top` from `nums`, push `top / cur` (truncated toward zero).
       - Set `op = c` and reset `cur = 0`.
     - If `c == ')'`: break out of the loop and return.
   - Return the sum of all elements in `nums`.
3. Invoke `parse(s, 0)` and return the result.

Complexity:
- Time: `O(n)` because each character of the string is processed exactly once by the shared pointer `i`.
- Space: `O(n)` auxiliary space for the recursion call stack and the `nums` vectors across nested parentheses levels.

## Code walkthrough

In the reference implementation:
- `size_t& i`: passes the string index by reference so recursive calls consume characters and return control right after matching `')'`.
- `else if (c == '(') cur = parse(s, i);`: treats parenthesized sub-expressions identically to an ordinary numeric token.
- `if (op == '*') nums.push_back(top * cur);`: immediately resolves multiplicative precedence without delaying until end-of-string.
- `if (c == ')') break;`: terminates the current recursion frame immediately after pushing the finalized operand for the preceding operator.
- `long long sum = 0; for (long long x : nums) sum += x;`: collapses the delayed additions and subtractions.

## Test it out loud

- Single number: `s = "0"`. Reads `0`, reaches end of string, pushes `0` with default `op = '+'`, returns 0.
- Simple parenthesized number: `s = "(1)"`. Outer frame encounters `'('`, recurse on `"1)"`. Inner frame pushes `1`, breaks on `')'`. Outer frame assigns `cur = 1`, finishes with 1.
- Negative intermediate results: `"1-2+3"`. Pushes `1`, then `-2`, then `3`. Sum is $1 - 2 + 3 = 2$.

## Follow-ups

- How to handle unary minus signs like `"-1 + (-2)"`?
  Initialize `cur = 0` and insert a dummy 0 before unary operators, or set a flag when an operator is preceded immediately by another operator or `'('`.
- How does the Shunting-Yard algorithm compare?
  Dijkstra's Shunting-Yard uses two explicit stacks (operators and operands) to convert to Reverse Polish Notation (RPN), achieving the same $O(n)$ time iteratively without recursion.
- What if numbers can be floating point?
  Replace integer division with floating division and parse decimals (`c == '.'`).

## Common mistakes

- Advancing index independently inside both the main loop and the recursive step, causing double character skipping.
- Forgetting that the last number must be committed when reaching the end of the string (`i == s.size()`).
- In Python, using `//` for integer division with negative numbers instead of `int(top / cur)` (which truncates toward zero).
