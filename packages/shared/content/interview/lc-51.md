## Clarify first
- What are the attacking rules for queens in chess? A queen can attack any piece sharing the same row, column, or diagonal.
- How is the board represented in the output? A vector of strings where `'Q'` denotes a placed queen and `'.'` denotes an empty cell.
- What are the values of n? `1 <= n <= 9`.
- What if no valid placement exists? Return an empty list `[]` (e.g. for `n = 2` or `n = 3`).

## Examples to say out loud
- For `n = 4`:
  - Solution 1: `[".Q..", "...Q", "Q...", "..Q."]`. Queens at `(0, 1), (1, 3), (2, 0), (3, 2)`.
  - Solution 2: `["..Q.", "Q...", "...Q", ".Q.."]`. Queens at `(0, 2), (1, 0), (2, 3), (3, 1)`.
  - Total solutions: 2.
- For `n = 1`: Single square `[["Q"]]`.
- For `n = 2` or `n = 3`: No placements possible; return `[]`.

## Brute force
A naive approach places n queens randomly across the `n^2` chessboard cells, which requires testing `C(n^2, n)` configurations. For `n = 8`, `C(64, 8) = 4.4 * 10^9`, which is far too slow. Since no two queens can share a row, we can place exactly one queen per row, reducing the search space to `n!` permutations of column assignments.

## The key observation
By placing queens row by row from row 0 to `n - 1`, row conflicts are avoided by construction.
For each row, we need only choose a column `c` that does not conflict with previously placed queens.
A queen at `(r, c)` threatens:
1. Column `c`.
2. Main diagonal: all cells sharing the value `r + c` (ranging from 0 to `2n - 2`).
3. Anti-diagonal: all cells sharing the value `r - c + n - 1` (ranging from 0 to `2n - 2`).
Using three boolean arrays (or bitmasks) for columns, main diagonals, and anti-diagonals allows checking safety in O(1) time before placing a queen.

## Optimal approach
1. Allocate boolean arrays:
   - `cols` of size `n`
   - `d1` of size `2 * n` for main diagonals (`r + c`)
   - `d2` of size `2 * n` for anti-diagonals (`r - c + n - 1`)
   - `pos` of size `n` where `pos[r]` records the column chosen for queen in row `r`.
2. Define recursive helper `go(row)`:
   - Base case: If `row == n`, all n queens have been safely placed. Construct the `n x n` board representation from `pos`, append to `out`, and return.
   - For `c` from 0 to `n - 1`:
     - If `cols[c] || d1[row + c] || d2[row - c + n - 1]`: continue (square is attacked).
     - Place queen: mark `cols[c] = d1[row + c] = d2[row - c + n - 1] = true`.
     - Record `pos[row] = c`.
     - Recurse: `go(row + 1)`.
     - Backtrack: unmark `cols[c] = d1[row + c] = d2[row - c + n - 1] = false`.
3. Call `go(0)` and return `out`.

Complexity:
- Time complexity: Roughly O(n!) time with pruning, as the first row has n choices, second has at most n - 2 choices, etc. For `n = 9`, the search tree finishes in tens of milliseconds.
- Space complexity: O(n) auxiliary space for the tracking arrays, `pos` array, and recursion stack (excluding output boards).

## Code walkthrough
- `cols[c] || d1[row + c] || d2[row - c + n - 1]`: O(1) safety check without scanning the board.
- `pos[row] = c`: Stores the column for row `row` to construct board strings only upon reaching valid full placements.
- `d1[row + c] = true` and `d2[row - c + n - 1] = true`: Marks both diagonal directions simultaneously.
- `cols[c] = d1[...] = d2[...] = false`: Backtracks state cleanly for sibling choices.
- Board construction: Builds an array of `string(n, '.')` and sets `board[r][pos[r]] = 'Q'`.

## Test it out loud
- Test `n = 1`:
  - `row = 0`: places queen at `c = 0`.
  - `row = 1 == n`: builds board `["Q"]`. Output: `[["Q"]]`. Correct.
- Test `n = 2`:
  - `row = 0`, `c = 0`: `cols[0]=true, d1[0]=true, d2[1]=true`.
  - `row = 1`: `c = 0` (blocked by col), `c = 1` (blocked by `d1[1+1=2]`? No, `r=1, c=1 => r-c+1 = 1` blocked by d2).
  - All choices for `c` blocked.
  - Backtracks; no valid boards found. Returns `[]`. Correct.

## Follow-ups
- How can we speed this up further using bit manipulation? Represent `cols`, `d1`, and `d2` as integer bitmasks. Available positions can be extracted in parallel using `available = (~(cols | d1 | d2)) & ((1 << n) - 1)` and bit operations `c = available & -available`.
- What if we only need to count total solutions (N-Queens II)? Return integer count directly without materializing string board representations.

## Common mistakes
- Scanning the 2D board in O(n) time on every check rather than using O(1) boolean lookups.
- Forgetting the offset `+ n - 1` in `r - c + n - 1`, causing negative array indexing for anti-diagonals.
- Failing to unmark all three state flags during backtracking.
