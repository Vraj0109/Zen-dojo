## Clarify first

- How are houses numbered? (1-indexed from $1$ to $n$).
- What are the two ways a house can receive water? (Either by building a well inside the house at cost `wells[i - 1]`, or via pipes connected to another house that has water).
- Can pipes form cycles, and are pipe costs non-negative? (Yes, pipes can form arbitrary graph structures; edge costs are $\ge 0$).
- Can the `pipes` list be empty? (Yes, in which case every house must dig its own well).
- What are the bounds on $n$ and pipe counts? ($2 \le n \le 10^4$ and $0 \le pipes.length \le 10^4$).

## Examples to say out loud

- Cheaper pipes than wells: $n = 3$, `wells = [1, 2, 2]`, `pipes = [[1, 2, 1], [2, 3, 1]]`. Dig a well at house 1 (cost 1), pipe water $1 \to 2$ (cost 1), pipe water $2 \to 3$ (cost 1). Total cost = 3.
- No pipes available: $n = 3$, `wells = [10, 10, 10]`, `pipes = []`. Every house must build its own well; total cost = 30.
- Expensive pipes: $n = 2$, `wells = [100, 100]`, `pipes = [[1, 2, 5]]`. Dig 1 well at house 1 (cost 100) and pipe to house 2 (cost 5); total cost = 105.

## Brute force

A naive approach considers all $2^n$ subsets of houses at which to build wells. For each subset with at least one well, we run a multi-source Dijkstra or Prim's algorithm to connect the remaining houses at minimum pipe cost. With $n$ up to $10^4$, evaluating $2^{10^4}$ well configurations is completely infeasible.

## The key observation

The challenge is handling two different types of costs: vertex costs (wells) and edge costs (pipes). We can unify them by introducing a **virtual source node 0** representing a master water reservoir. Building a well at house $i$ at cost `wells[i - 1]` is mathematically equivalent to laying a pipe from virtual node 0 to house $i$ with weight `wells[i - 1]`. Now every house receiving water corresponds to that house being connected (directly or indirectly) to node 0. The problem reduces directly to finding the standard Minimum Spanning Tree (MST) on $n + 1$ vertices (nodes $0, 1, \dots, n$).

## Optimal approach

1. Introduce virtual node `0`.
2. Construct an edge list `edges`:
   - For each house $i \in [1, n]$, add edge `(wells[i - 1], 0, i)`.
   - For each pipe `[u, v, cost]` in `pipes`, add edge `(cost, u, v)`.
3. Sort all edges in non-decreasing order of cost.
4. Initialize a Disjoint Set Union (DSU) structure with $n + 1$ elements ($0$ to $n$), where `parent[i] = i`.
5. Initialize `totalCost = 0` and `edgesCount = 0`.
6. Iterate through sorted edges:
   - For edge `(cost, u, v)`:
     - If `unite(u, v)` succeeds (they were in different components):
       - Add `cost` to `totalCost`.
       - Increment `edgesCount++`.
       - If `edgesCount == n`, stop early (a spanning tree of $n + 1$ vertices has exactly $n$ edges).
7. Return `totalCost`.

Complexity:
- Time: `O(E log E)` where $E = n + \text{pipes.length}$. Constructing edges takes $O(E)$, sorting edges takes $O(E \log E)$, and Kruskal's algorithm with path compression takes $O(E \alpha(V))$ which is dominated by sorting.
- Space: `O(V + E)` auxiliary space to store the unified edge list of size $n + \text{pipes.length}$ and the DSU parent array of size $n + 1$.

## Code walkthrough

In the reference implementation:
- `edges.push_back({wells[i - 1], 0, i});`: converts vertex well costs into edges connected to virtual source 0.
- `edges.push_back({p[2], p[0], p[1]});`: adds standard piping edges.
- `sort(edges.begin(), edges.end(), ...);`: sorts all options greedily by cost.
- `if (unite(u, v))`: Kruskal's cycle check via Union-Find.
- `if (edgesCount == n) break;`: early termination once all $n + 1$ vertices are connected.

## Test it out loud

- All wells cheaper than pipes: `n = 4, wells = [1, 1, 1, 1], pipes = [[1, 2, 2], [2, 3, 2], [3, 4, 2], [4, 1, 2]]`. Virtual edges have weight 1, pipes weight 2. Kruskal selects all 4 virtual edges to node 0; total cost = 4.
- Disconnected pipes: If pipes cannot reach all houses, Kruskal will naturally select well edges for isolated components to connect them to node 0.
- Identical costs: Multiple minimal spanning trees exist, but all yield the identical minimum total cost.

## Follow-ups

- Can we solve this using Prim's algorithm instead of Kruskal's?
  Yes, push all virtual edges `(wells[i - 1], i)` into a min-heap priority queue initially, then expand the cut in $O(E \log V)$ time.
- What if some houses cannot build wells (wells cost is $\infty$)?
  Set their well edge weights to $\infty$ or omit those edges; if `edgesCount < n` at the end, return -1.
- What if water flow has capacity limits on pipes?
  This transforms into a Min-Cost Max-Flow problem rather than a simple Minimum Spanning Tree.

## Common mistakes

- Treating wells as separate from pipes and trying to run connected component algorithms first, failing when a single component should have multiple wells.
- Off-by-one errors mapping between 1-indexed houses and 0-indexed `wells[i - 1]`.
- Forgetting to size the DSU array to $n + 1$ to accommodate virtual node 0.
