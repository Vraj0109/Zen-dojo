## Clarify first

- Are node values guaranteed to be unique? Yes, constraints state all values in preorder and inorder are distinct.
- Are both traversals guaranteed to represent the exact same valid binary tree? Yes, inputs are valid and non-empty.
- What are the length constraints of the arrays? Length is between 1 and 3,000, with values between -3,000 and 3,000.
- What order of reconstruction is required? The function should return the pointer to the root of the constructed binary tree.

## Examples to say out loud

- Standard binary tree: `preorder = [3, 9, 20, 15, 7]`, `inorder = [9, 3, 15, 20, 7]`.
  - First element of `preorder` is 3, which is the root.
  - In `inorder`, 3 sits at index 1. Everything left of index 1 (`[9]`) forms the left subtree; everything to the right (`[15, 20, 7]`) forms the right subtree.
  - The left subtree has size 1 (`preorder = [9]`). The right subtree has size 3 (`preorder = [20, 15, 7]`).
  - Output root is 3 with left child 9 and right child 20 (having children 15 and 7).
- Single node edge case: `preorder = [-1]`, `inorder = [-1]`. Root is -1 with no children.

## Brute force

A recursive brute-force algorithm picks the root value from the first element of preorder, searches linearly through the inorder array to locate its index `mid`, and creates slices or substrings for the left and right subtrees. Because finding `mid` takes `O(n)` linear search at each recursive step, this leads to `O(n^2)` time in unbalanced trees (such as a line of nodes).

## The key observation

The preorder array dictates the sequence of roots visited: the next unprocessed element in `preorder` is always the root of the subtree being built. By precomputing a hash map mapping each value in `inorder` to its index, we can determine the partition boundary `mid` in `O(1)` time. Building the left subtree before the right subtree ensures a single moving index into `preorder` matches the recursive calls.

## Optimal approach

1. Build a hash map `pos` mapping each value in `inorder` to its array index.
2. Maintain a global pointer `next = 0` indicating the current index in `preorder`.
3. Define a recursive helper `build(lo, hi)` that constructs the tree from `inorder` bounds `lo` to `hi`:
   a. If `lo > hi`, return null.
   b. Read `val = preorder[next++]` and create a new `TreeNode(val)`.
   c. Find root index `mid = pos[val]`.
   d. Recursively construct left child: `node.left = build(lo, mid - 1)`.
   e. Recursively construct right child: `node.right = build(mid + 1, hi)`.
   f. Return `node`.
4. Call `build(0, inorder.length - 1)` and return the root.

Complexity:
- Time: `O(n)` because creating the hash map takes `O(n)` time, and each of the `n` nodes is created in `O(1)` time.
- Space: `O(n)` auxiliary space for the hash map and the recursion stack (`O(h)` stack depth, up to `O(n)`).

## Code walkthrough

In the reference implementation:
- `unordered_map<int, int> pos; int next = 0;`: caches inorder indices for `O(1)` lookup and tracks current preorder element.
- `if (lo > hi) return nullptr;`: base case for an empty subtree span.
- `int v = pre[next++]; TreeNode* node = new TreeNode(v);`: creates node using next available preorder element.
- `int mid = pos[v];`: pinpoints root position in inorder in constant time.
- `node->left = build(pre, lo, mid - 1);`: recursively builds left subtree from elements left of `mid`.
- `node->right = build(pre, mid + 1, hi);`: recursively builds right subtree from elements right of `mid`.

## Test it out loud

- `preorder = [1, 2], inorder = [2, 1]`:
  - `pos` maps `2 -> 0, 1 -> 1`.
  - Root: `v = pre[0] = 1`, `next = 1`. `mid = pos[1] = 1`.
  - Left subtree: `build(0, 0)` -> `v = pre[1] = 2`, `mid = pos[2] = 0`. Left and right of 2 are empty (`lo > hi`). Returns node 2.
  - Right subtree: `build(2, 1)` -> `lo > hi`, returns null.
  - Result: `1` with left child `2`.
- `preorder = [1, 2], inorder = [1, 2]`:
  - Root: `v = 1`, `mid = pos[1] = 0`.
  - Left subtree: `build(0, -1)` returns null.
  - Right subtree: `build(1, 1)` returns node 2.
  - Result: `1` with right child `2`.

## Follow-ups

- What if duplicate values are allowed?
  The tree cannot be uniquely reconstructed without additional structure or parent pointers.
- How would you reconstruct from inorder and postorder traversals (LeetCode 106)?
  Traverse `postorder` from right to left, constructing the right subtree before the left subtree.

## Common mistakes

- Reversing the order of recursive calls (building right subtree before left subtree while advancing `preorder` left-to-right), which misassigns nodes.
- Doing linear search in `inorder` on each recursive call, causing `O(n^2)` runtime.
- Forgetting to reset global/class variables like `next` across multiple test runs.
