## Clarify first

- What ranges do $a$ and $b$ cover? (Both $a$ and $b$ are integers satisfying $2 \le a \le n$ and $2 \le b \le n$).
- What constitutes a distinct value? (The numerical value of $a^b$, so $2^4$ and $4^2$ both evaluate to 16 and count as one distinct value).
- What is the maximum value of $n$? ($2 \le n \le 1000$).
- Can the values of $a^b$ be computed directly? (No: for $a = 1000$ and $b = 1000$, $1000^{1000} = 10^{3000}$, which has 3001 digits and cannot fit into primitive integer types; computing and hashing full big integers is inefficient).
- What should be returned? (The total count of distinct numerical values generated by the $(n - 1)^2$ pairs).

## Examples to say out loud

- Base case: `n = 2`. Only pair is $a = 2, b = 2$. $2^2 = 4$. Count is 1.
- Small case: `n = 3`. Powers generated:
  - $a = 2$: $2^2 = 4, 2^3 = 8$.
  - $a = 3$: $3^2 = 9, 3^3 = 27$.
  - All 4 values $\{4, 8, 9, 27\}$ are distinct. Output is 4.
- Stated example: `n = 5`. Total pairs is $(5 - 1)^2 = 16$.
  - Note $2^4 = 16$ and $4^2 = (2^2)^2 = 2^4 = 16$.
  - The distinct count is $16 - 1 = 15$.

## Brute force

A brute-force approach evaluates $a^b$ using an arbitrary-precision big integer library for every pair $(a, b) \in [2, n] \times [2, n]$, serializes each big integer into a string or byte array, and inserts all $(n - 1)^2$ strings into a hash set. For $n = 1000$, there are nearly $1,000,000$ powers, each with hundreds to thousands of digits. Big-integer exponentiation and hashing across $10^6$ instances would consume hundreds of megabytes of memory and take tens of seconds, leading to timeouts.

## The key observation

Two powers $a_1^{b_1}$ and $a_2^{b_2}$ can only be equal if their bases $a_1$ and $a_2$ share the same minimal integer root $r$ that is not itself a perfect power. Every integer $a \ge 2$ can be uniquely decomposed into $a = r^k$, where $r$ is the minimal base and $k \ge 1$ is an integer exponent (for example, $4 = 2^2, 8 = 2^3, 9 = 3^2, 12 = 12^1$). Then $a^b = (r^k)^b = r^{k \times b}$. Thus, equality between two powers $a_1^{b_1} = a_2^{b_2}$ is equivalent to the equality of the integer pairs $(r_1, k_1 \times b_1) = (r_2, k_2 \times b_2)$. We can simply count distinct integer tuples $(r, k \times b)$.

## Optimal approach

1. Initialize a hash set or balanced tree set `seen` of integer pairs `(r, kb)`.
2. For each base `a` from 2 up to `n`:
   a. Find the minimal base `r` and exponent `k` such that $a = r^k$:
      - Default to $r = a, k = 1$.
      - Test potential roots `base` starting from 2 while $\text{base}^2 \le a$:
        - Compute successive powers of `base` ($x = \text{base}, e = 1$). If $x == a$, assign $r = \text{base}, k = e$ and break.
   b. For each exponent `b` from 2 up to `n`:
      - Insert the pair `(r, k * b)` into `seen`.
3. Return `seen.size()`.

Complexity:
- Time: `O(n^2)` pairs inserted. Finding the root $r$ takes at most $O(\sqrt{a}) \le 31$ operations for $a \le 1000$. Inserting at most $10^6$ integer pairs into a hash set takes $O(n^2)$ time, completing in under 0.5 seconds.
- Space: `O(n^2)` auxiliary space to store at most $(n - 1)^2 \approx 10^6$ small integer pairs in the set.

## Code walkthrough

In the reference implementation:
- `set<pair<int, int>> seen;`: stores unique representations $(r, k \times b)$.
- `for (int base = 2; base * base <= a; base++)`: extracts the canonical base $r$ by finding whether $a$ is an exact power of any smaller base.
- `if (x == a) { r = base; k = e; break; }`: factors $a = r^k$ with the smallest possible base $r$.
- `for (int b = 2; b <= n; b++) seen.insert({r, k * b});`: maps $a^b$ to $(r, k \times b)$, automatically deduplicating representations across equivalent powers.
- `return (int)seen.size();`: returns the count of unique pairs.

## Test it out loud

- `n = 2`:
  - $a = 2 \implies r = 2, k = 1$. Pair $(2, 1 \times 2) = (2, 2)$ inserted. Size is 1. Returns 1.
- `n = 4`:
  - $a = 2 \implies r = 2, k = 1$. Inserts $(2, 2), (2, 3), (2, 4)$ (3 pairs).
  - $a = 3 \implies r = 3, k = 1$. Inserts $(3, 2), (3, 3), (3, 4)$ (3 pairs).
  - $a = 4 \implies r = 2, k = 2$.
    - $b = 2 \implies (2, 4)$ (already present from $2^4$).
    - $b = 3 \implies (2, 6)$ (new).
    - $b = 4 \implies (2, 8)$ (new).
  - Total size: $3 + 3 + 2 = 8$. Returns 8.

## Follow-ups

- How to optimize to $O(n \log n)$ time and $O(n)$ space without a large set?
  Group values of $a$ by their minimal root $r$. For a maximal exponent $M = \lfloor \log_r n \rfloor$, count distinct products $\{k \times b \mid 1 \le k \le M, 2 \le b \le n\}$ once for each chain length $M$ using boolean arrays, multiplying the distinct count by the number of roots having depth $M$.
- What if $n = 100,000$?
  The depth $M$ is bounded by $\log_2(100,000) \le 16$. Precomputing the overlap sizes for $M \in [1, 16]$ allows answering in $O(n)$.

## Common mistakes

- Computing $a^b$ with standard double-precision floats (`pow(a, b)`): floating-point numbers have only 53 bits of precision, causing distant powers like $2^{60}$ and $2^{60} - 1$ to collide due to rounding.
- Failing to reduce the base completely (e.g., stopping at $16 = 4^2$ instead of reducing to $2^4$), which fails to identify equivalence between $16^3 = 2^{12}$ and $8^4 = 2^{12}$.
- Using 32-bit integer sets without properly pairing $(r, k \times b)$, causing different roots to collide if hashed improperly.
