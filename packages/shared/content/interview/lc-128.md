## Clarify first

- Does the consecutive sequence have to appear contiguously in the original array? (No, elements can appear in any order in `nums`; consecutive refers to numerical values $x, x+1, x+2, \dots$).
- Can the array contain duplicate numbers? (Yes, duplicates can exist, but only unique values contribute to the sequence length).
- Can the array be empty? (Yes, $0 \le nums.length \le 10^5$; return 0 for an empty array).
- Can numbers be negative? (Yes, $-10^9 \le nums[i] \le 10^9$).
- What is the time complexity requirement? (Must run in strictly $O(n)$ time, ruling out standard $O(n \log n)$ sorting).

## Examples to say out loud

- Unsorted array: `nums = [100, 4, 200, 1, 3, 2]`. The numbers 1, 2, 3, 4 form a consecutive streak of length 4.
- Array with duplicates and 0: `nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]`. Unique values form sequence $0$ through $8$, with length 9.
- Negative numbers: `nums = [-1, -2, -3, 0, 1]`. Numbers $-3, -2, -1, 0, 1$ form a consecutive streak of length 5.

## Brute force

A sorting approach sorts the array in $O(n \log n)$ time, then iterates through comparing adjacent elements while skipping duplicates. While easy to write and using $O(1)$ extra space, it violates the problem's explicit $O(n)$ time complexity requirement. A naive search without sorting checks for each number $x$ whether $x+1, x+2, \dots$ exist by scanning the raw array, leading to $O(n^3)$ worst-case time.

## The key observation

If we insert all numbers into a hash set, membership queries take $O(1)$ on average. To ensure overall linear time, we must avoid redundantly scanning sequences starting from middle elements (e.g. Scanning $2 \to 3 \to 4$ when we already scanned $1 \to 2 \to 3 \to 4$).
A number $x$ can only be the **beginning** of a consecutive sequence if $x - 1$ is NOT in the hash set. If $x - 1$ exists, we skip $x$ immediately. Because every consecutive streak is traversed only once starting from its unique minimum element, each number is checked at most twice, yielding guaranteed $O(n)$ total time.

## Optimal approach

1. Build a hash set `s` from `nums`, which de-duplicates values and provides $O(1)$ average lookups.
2. Initialize `best = 0`.
3. For each number `x` in `s`:
   - Check if `x - 1` is in `s`.
   - If `x - 1` is NOT in `s`:
     - This means `x` is the starting element of a sequence.
     - Initialize `len = 1`.
     - While `x + len` is in `s`:
       - Increment `len++`.
     - Update `best = max(best, len)`.
4. Return `best`.

Complexity:
- Time: `O(n)` on average because inserting $n$ elements into the hash set takes $O(n)$, and the inner `while` loop visits each number at most once across the entire algorithm (only from sequence starts).
- Space: `O(n)` auxiliary space to store at most $n$ distinct numbers in the hash set.

## Code walkthrough

In the reference implementation:
- `unordered_set<int> s(nums.begin(), nums.end());`: converts array to hash set, removing duplicates in $O(n)$.
- `if (!s.count(x - 1))`: key optimization filter that ensures only sequence starting points trigger counting.
- `while (s.count(x + len)) len++;`: expands forward through the streak in $O(1)$ lookups per element.
- `best = max(best, len);`: tracks the longest discovered sequence length.

## Test it out loud

- Empty array: `nums = []`. Set is empty; loop does not run, returns 0.
- Single element: `nums = [7]`. $7 - 1 = 6$ is not in set. While loop checks 8 (not in set). Streak length is 1, returns 1.
- All identical elements: `nums = [1, 1, 1, 1]`. Set contains only `{1}`. Evaluates once, returns 1.
- Array with gaps: `nums = [10, 5, 12, 3, 55, 30, 4, 11, 2]`.
  - Sequences: `{2, 3, 4, 5}` (length 4), `{10, 11, 12}` (length 3), `{30}` (1), `{55}` (1).
  - Starts checked: 2 (scans up to 5), 10 (scans up to 12), 30, 55.
  - Numbers 3, 4, 5, 11, 12 are skipped because $x - 1$ exists.
  - Max length 4 returned.

## Follow-ups

- What if an adversary designs hash collisions to force $O(n^2)$ worst-case time in `unordered_set`?
  Use a custom hash function with a randomized salt / splitmix64 hash to prevent hash collision denial-of-service.
- Can this be solved with Disjoint Set Union (Union-Find)?
  Yes, map each number $x$ to $x + 1$ if $x + 1$ exists in the set, and maintain component sizes in DSU.
- What if numbers stream in dynamically one by one?
  Maintain a hash map `bounds` where `map[x]` stores the length of the consecutive sequence it belongs to, merging adjacent intervals `map[x - left]` and `map[x + right]`.

## Common mistakes

- Omitting the `if (!s.count(x - 1))` check, which degrades performance to $O(n^2)$ on sequences like `[5, 4, 3, 2, 1]`.
- Iterating over the original array `nums` instead of iterating over the unique elements in the set `s`, causing redundant checks on duplicate values.
- Assuming numbers fit in an array lookup table (range is $-10^9$ to $10^9$, requiring a hash set rather than a direct-mapped frequency array).
