## Clarify first
- What are the task constraints? `1 <= tasks.length <= 14`, and each task duration `tasks[i]` is between 1 and 10 hours.
- Can tasks be split across multiple sessions? No, each task must be completed entirely within a single work session.
- What is `sessionTime`? The maximum duration of each work session, where `max(tasks[i]) <= sessionTime <= 15`.
- What are we minimizing? The minimum number of work sessions required to complete all tasks.

## Examples to say out loud
- Consider `tasks = [1, 2, 3]`, `sessionTime = 3`:
  - Session 1: tasks 1 and 2 (`1 + 2 = 3` hours).
  - Session 2: task 3 (3 hours).
  - Total sessions: 2.
- Fits in one session: `tasks = [1, 2, 3, 4, 5]`, `sessionTime = 15`:
  - Sum of all tasks is 15. All fit in 1 session. Output: 1.
- Each requires own session: `tasks = [5, 5, 5]`, `sessionTime = 5`: Output: 3.

## Brute force
A brute force approach uses backtracking to place tasks one by one into sessions, trying to fit each task into every existing session or opening a new session. With up to 14 tasks, the number of partitions (Bell number B_14 = 1.9 * 10^8) is large and can time out without advanced pruning. Bitmask Dynamic Programming over the 2^n subsets computes the optimal session count in O(2^n * n) time.

## The key observation
With `n <= 14`, we can represent the subset of completed tasks as a bitmask of length n.
For each subset `mask`:
We want to minimize the number of sessions used, and secondarily minimize the hours accumulated in the latest session (so that maximum room is left for future tasks).
Thus, the state value for `dp[mask]` is a pair:
`(sessions, time_in_last_session)`
When we compare two pairs, we compare them lexicographically:
fewer sessions is strictly better; for equal sessions, less time used in the last session is better.
When transitioning from `mask` by adding an unused task `tasks[i]`:
- If `time_in_last_session + tasks[i] <= sessionTime`: the task fits in the current session. The new state is `(sessions, time_in_last_session + tasks[i])`.
- If it does not fit: we must open a new session. The new state is `(sessions + 1, tasks[i])`.

## Optimal approach
1. Let `n = tasks.size()`.
2. Allocate an array `dp` of size `1 << n` where each element is a pair `{sessions, last_session_time}` initialized to `{INT_MAX, INT_MAX}`.
3. Base case: `dp[0] = {1, 0}` (starting with 1 open session with 0 hours used).
4. Iterate `mask` from 0 to `(1 << n) - 1`:
   - If `dp[mask].first == INT_MAX`: continue (unreachable state).
   - For `i` from 0 to `n - 1`:
     - If `mask & (1 << i)` is non-zero: continue (task `i` already completed).
     - Let `cur = dp[mask]`.
     - If `cur.second + tasks[i] <= sessionTime`:
       - `cur.second += tasks[i]`.
     - Else:
       - `cur.first++`.
       - `cur.second = tasks[i]`.
     - Let `nm = mask | (1 << i)`.
     - If `cur < dp[nm]`:
       - `dp[nm] = cur`.
5. Return `dp[(1 << n) - 1].first`.

Complexity:
- Time complexity: O(2^n * n) because there are 2^n masks, and from each mask we try adding n tasks in O(1) time. For `n = 14`, `16384 * 14 = 2.3 * 10^5` operations, executing in under 5ms.
- Space complexity: O(2^n) auxiliary space for the `dp` array of size `2^14 = 16,384`.

## Code walkthrough
- `vector<pair<int, int>> dp(1 << n, {INT_MAX, INT_MAX})`: Stores `{sessions, last_session_time}` per bitmask.
- `dp[0] = {1, 0}`: Seeds DP with 1 session using 0 hours.
- `if (cur.second + tasks[i] <= sessionTime)`: Greedily packs task into the active session if capacity permits.
- `else { cur.first++; cur.second = tasks[i]; }`: Starts a new session when the task exceeds remaining hours.
- `if (cur < dp[nm]) dp[nm] = cur`: Leverages C++ `std::pair` lexicographical comparison (`sessions` primary, `last_session_time` secondary).
- Returns `dp[(1 << n) - 1].first`.

## Test it out loud
- Test `tasks = [1, 2, 3], sessionTime = 3`:
  - `mask = 0`: `{1, 0}`.
    - Add task 0 (1): mask 1 gets `{1, 1}`.
    - Add task 1 (2): mask 2 gets `{1, 2}`.
    - Add task 2 (3): mask 4 gets `{1, 3}`.
  - From mask 1 (`{1, 1}`):
    - Add task 1 (2): `1 + 2 = 3 <= 3`. Mask 3 (`tasks {0, 1}`) gets `{1, 3}`.
  - From mask 3 (`{1, 3}`):
    - Add task 2 (3): `3 + 3 = 6 > 3`, new session opened. Mask 7 gets `{2, 3}`.
  - Final mask 7 has `sessions = 2`. Output: 2. Correct.
- Test `tasks = [5], sessionTime = 5`: Output: 1. Correct.

## Follow-ups
- How does this relate to the Bin Packing Problem? Finding the minimum number of work sessions of fixed capacity to pack items of varying sizes is the classic NP-hard Bin Packing problem.
- Could this be solved by precomputing all valid single sessions and doing submask DP? Yes, precompute all masks whose sum `<= sessionTime` and run `dp[mask] = min(dp[mask ^ sub] + 1)` over all valid submasks `sub`. That takes O(3^n) time (`3^14 = 4.78 * 10^6`), but the pair-based DP in O(2^n * n) is faster and uses less memory.

## Common mistakes
- Tracking only `sessions` in `dp[mask]` without tracking `time_in_last_session`, which loses critical information about remaining session capacity.
- Trying a greedy heuristic (like sorting descending and packing first-fit), which fails to find the global optimum for bin packing.
- Not initializing `dp[0] = {1, 0}` properly.
