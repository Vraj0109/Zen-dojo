## Clarify first
- How is effort along a route defined? The maximum absolute height difference between any two consecutive cells along the path.
- In what directions can you move? Up, down, left, and right (4 cardinal directions).
- What are the starting and destination cells? Start at the top-left cell `(0, 0)` and end at the bottom-right cell `(rows - 1, cols - 1)`.
- Can the route pass through any cell multiple times? A simple path is always optimal because repeating cells never decreases maximum effort.

## Examples to say out loud
- Consider 3x3 grid:
  ```
  [1, 2, 2]
  [3, 8, 2]
  [5, 3, 5]
  ```
  - Path `(0,0) -> (0,1) -> (0,2) -> (1,2) -> (2,2)` visits heights `1 -> 2 -> 2 -> 2 -> 5`.
  - Consecutive differences are `|1-2|=1, |2-2|=0, |2-2|=0, |2-5|=3`. Max effort is 3.
  - Alternative path `1 -> 3 -> 5 -> 3 -> 5` has max difference 2 (`|1-3|=2, |3-5|=2, |5-3|=2, |3-5|=2`).
  - Smallest effort over all routes is 2.
- Single cell: `[[7]]`. Effort is 0.

## Brute force
A brute force DFS explores every possible path from top-left to bottom-right, computing the maximum step along each path and taking the global minimum. With a 100x100 grid, there are exponentially many paths, leading to time limit exceeded. Binary search on the answer combined with BFS works in O(R * C log(max_height)), but Dijkstra's algorithm tailored to minimax paths solves it directly.

## The key observation
This is a bottleneck shortest path problem. Instead of summing edge weights, the path cost is the maximum edge weight encountered along the route:
`cost(path) = max(|height[u] - height[v]|)`.
Dijkstra's algorithm applies directly:
- Let `dist[r][c]` be the minimum effort required to reach cell `(r, c)`.
- When relaxing from cell `(x, y)` to an adjacent neighbor `(nx, ny)`, the candidate effort is `max(dist[x][y], |height[nx][ny] - height[x][y]|)`.
- Because edge weights are non-negative, extracting the cell with the minimum current effort from a priority queue ensures that its distance is final.

## Optimal approach
1. Initialize a 2D distance array `dist` of size `r x c` with `INT_MAX`, setting `dist[0][0] = 0`.
2. Initialize a min-heap `pq` storing tuples `{effort, x, y}` and push `{0, 0, 0}`.
3. While `pq` is not empty:
   - Extract `{d, x, y}`.
   - If `d > dist[x][y]`: continue (stale entry).
   - If `x == r - 1` and `y == c - 1`: return `d` immediately.
   - For each of the 4 cardinal neighbors `(nx, ny)`:
     - Compute step effort: `nd = max(d, abs(heights[nx][ny] - heights[x][y]))`.
     - If `nd < dist[nx][ny]`:
       - Update `dist[nx][ny] = nd`.
       - Push `{nd, nx, ny}` into `pq`.
4. Return 0.

Complexity:
- Time complexity: O(R * C log(R * C)) where R is rows and C is columns. Each cell is pushed and popped from the min-heap at most once.
- Space complexity: O(R * C) auxiliary space for the distance matrix and min-heap.

## Code walkthrough
- `vector<vector<int>> dist(r, vector<int>(c, INT_MAX))`: Tracks minimax effort to each grid position.
- `priority_queue<tuple<int, int, int>, ..., greater<>> pq`: Orders exploration by smallest known bottleneck effort.
- `if (x == r - 1 && y == c - 1) return d`: Returns the optimal effort as soon as the destination is dequeued.
- `int nd = max(d, abs(h[nx][ny] - h[x][y]))`: Computes the candidate bottleneck path cost to the neighbor.
- `if (nd < dist[nx][ny])`: Standard Dijkstra relaxation step for minimax metrics.

## Test it out loud
- Test single cell `[[7]]`:
  - `dist[0][0] = 0`, `pq = [(0, 0, 0)]`.
  - Pops `(0, 0, 0)`. `x == 0 && y == 0`, returns 0. Correct.
- Test 1x2 grid `[[1, 10]]`:
  - `dist[0][0] = 0`.
  - Neighbor `(0, 1)` has diff `abs(10 - 1) = 9`. `dist[0][1] = 9`.
  - Next pop is `(9, 0, 1)`, which is bottom-right. Returns 9. Correct.

## Follow-ups
- Can this be solved with Disjoint Set Union (Kruskal's algorithm)? Yes, collect all internal grid edges, sort them by height difference, and add edges until `(0, 0)` and `(r-1, c-1)` are connected. The weight of the connecting edge is the answer.
- What about binary search + BFS? Binary search the answer between 0 and 1,000,000. In each check, run a simple BFS allowing only transitions where difference is `<= mid`.

## Common mistakes
- Summing differences along the path instead of taking the maximum consecutive difference.
- Forgetting to ignore stale entries with `d > dist[x][y]`, degrading priority queue efficiency.
- Returning when adding to the queue rather than when popping from the priority queue.
