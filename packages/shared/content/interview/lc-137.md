## Clarify first
- How many times does each element appear? Every number in the array appears exactly three times, except for one unique element that appears exactly once.
- Can numbers be negative? Yes, values range across standard 32-bit signed integers from -2^31 to 2^31 - 1.
- What are the time and space constraints? Linear O(n) time and constant O(1) auxiliary space (no hash maps or frequency arrays allowed).
- How large can the input array be? Up to 30,000 integers.

## Examples to say out loud
- Standard case: `nums = [2, 2, 3, 2]`.
  - 2 appears three times; 3 appears once. Return 3.
- Mixed positive integers: `nums = [0, 1, 0, 1, 0, 1, 99]`.
  - 0 appears three times; 1 appears three times; 99 appears once. Return 99.
- Negative integer: `nums = [-2, -2, 1, -2]`.
  - -2 appears three times; 1 appears once. Return 1.

## Brute force
A brute force approach uses a hash map to count the frequencies of every element, then scans the map to find the element with frequency 1. While this runs in linear O(n) time, it consumes O(n) auxiliary space to store frequency counts, violating the O(1) space requirement. Sorting takes O(n log n) time and either O(1) or O(n) space. We can achieve O(n) time and true O(1) auxiliary space using bit manipulation.

## The key observation
Consider the binary representation of every number across the array.
Focus on an individual bit position `b` (from 0 to 31):
- If the unique single number has a 0 at bit `b`, every other number contributing a 1 to bit `b` appears exactly three times. Thus, the total count of 1-bits at position `b` across all numbers is a multiple of 3.
- If the unique single number has a 1 at bit `b`, that 1 appears once, and all other 1-bits at position `b` appear in triplets. Thus, the sum of bits at position `b` leaves a remainder of 1 modulo 3.
Therefore, for each bit position `b`, `(sum_of_bits % 3)` gives the exact value of bit `b` for the single number.

## Optimal approach
1. Initialize an unsigned 32-bit integer `res = 0`.
2. Iterate through each bit position `b` from 0 to 31:
   - Count how many numbers in `nums` have their `b`-th bit set:
     - `cnt = 0`.
     - For each number `x` in `nums`: add `((unsigned)x >> b) & 1` to `cnt`.
   - If `cnt % 3 != 0`:
     - Set the `b`-th bit of `res`: `res |= (1u << b)`.
3. Cast `res` back to a signed 32-bit integer `(int)res` and return it.

Complexity:
- Time complexity: O(32 * n) = O(n) because we perform 32 passes over an array of size n, which takes at most ~10^6 operations for n = 30,000.
- Space complexity: O(1) auxiliary space as only a few primitive integer counters are used.

## Code walkthrough
- `unsigned res = 0`: Accumulates the reconstructed bits using unsigned typing to avoid signed overflow undefined behavior during bit shifts.
- `for (int b = 0; b < 32; b++)`: Inspects each of the 32 bits independently.
- `cnt += ((unsigned)x >> b) & 1u`: Extracts the `b`-th bit of `x` safely for negative and positive integers.
- `if (cnt % 3) res |= (1u << b)`: If the remainder is non-zero, the unique element must have had a 1 at bit position `b`.
- `return (int)res`: Re-interprets the unsigned bit pattern as a 32-bit signed two's-complement integer.

## Test it out loud
- Test `nums = [2, 2, 3, 2]`:
  - In binary: `2 = 0010_2`, `3 = 0011_2`.
  - Bit 0: values are `0, 0, 1, 0`. Sum is 1. `1 % 3 = 1`. Bit 0 is 1.
  - Bit 1: values are `1, 1, 1, 1`. Sum is 4. `4 % 3 = 1`. Bit 1 is 1.
  - Higher bits: all sums are 0.
  - Reconstructed binary: `0011_2 = 3`. Return 3. Correct.
- Test `nums = [-1]`:
  - -1 has all 32 bits set to 1.
  - Every bit sum is 1, so `cnt % 3 = 1` for all 32 bits.
  - `res` gets all bits set, which casts back to -1. Correct.

## Follow-ups
- How can this be done in a single pass without looping 32 times? Use two integer bitmasks, `ones` and `twos`, to simulate a digital base-3 counter for all 32 bits in parallel using bitwise logic gates (`ones = (ones ^ x) & ~twos; twos = (twos ^ x) & ~ones;`). This runs in O(n) time with a small constant factor of 1 pass.
- What if every number appeared k times except one that appeared once? The same bit-sum approach works by taking `cnt % k`.

## Common mistakes
- Right-shifting negative signed integers using signed shifts, which performs arithmetic shift (sign extension) and may introduce unexpected 1s if not using unsigned cast or logical shifts.
- Forgetting that the unique number can be negative, so bit 31 must correctly reflect the two's-complement sign bit.
- Using extra memory like hash maps when the interview explicitly requests O(1) space.
