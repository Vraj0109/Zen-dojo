## Clarify first

- What should be placed in `answer[i]` if no warmer day occurs in the future? Put 0, as specified.
- Does "warmer" mean strictly greater temperature? Yes, equal temperatures do not count as warmer (`temperatures[j] > temperatures[i]`).
- What are the array constraints? Length is between 1 and 100,000, and temperatures are between 30 and 100 degrees.
- Should we return the waiting distance (number of days) or the actual future temperature? Return the distance in days (`j - i`).

## Examples to say out loud

- Normal mixed progression: `temperatures = [73, 74, 75, 71, 69, 72, 76, 73]`.
  - Day 0 (73) waits 1 day for Day 1 (74).
  - Day 1 (74) waits 1 day for Day 2 (75).
  - Day 2 (75) waits 4 days until Day 6 (76).
  - Day 3 (71) waits 2 days until Day 5 (72).
  - Day 4 (69) waits 1 day until Day 5 (72).
  - Day 5 (72) waits 1 day until Day 6 (76).
  - Days 6 and 7 have no warmer future day, returning 0.
  - Result: `[1, 1, 4, 2, 1, 1, 0, 0]`.
- Strictly decreasing: `temperatures = [90, 80, 70]`. No day sees a warmer future day, output is `[0, 0, 0]`.

## Brute force

A brute-force solution uses two nested loops: for each index `i`, scan every index `j > i` to find the first position where `temperatures[j] > temperatures[i]`, setting `ans[i] = j - i`. If no such `j` exists, `ans[i] = 0`. In the worst case (a strictly decreasing array), each element scans all remaining elements, taking `O(n^2)` time. With `n = 100,000`, `O(n^2)` is `10^{10}` operations and exceeds time limits.

## The key observation

Unresolved days that are still waiting for a warmer temperature naturally form a monotonically decreasing sequence of temperatures. As we scan left-to-right, if the current day's temperature is strictly warmer than the temperature at the top index of our stack, the current day is guaranteed to be the *very next* warmer day for that waiting index. We can pop that index, record the difference `i - index`, and continue resolving older waiting days.

## Optimal approach

1. Initialize an array `ans` of size `n` with all zeros.
2. Initialize an empty stack `st` to store day indices.
3. Iterate `i` from 0 to `n - 1`:
   a. While `st` is not empty and `temperatures[st.back()] < temperatures[i]`:
      - Let `idx = st.back()`, pop it from `st`.
      - Record the distance: `ans[idx] = i - idx`.
   b. Push the current index `i` onto `st`.
4. Return `ans` (any indices remaining on `st` stay 0).

Complexity:
- Time: `O(n)` because every index is pushed onto the stack once and popped at most once, performing `O(1)` amortized work per day.
- Space: `O(n)` auxiliary space to maintain the monotonic stack.

## Code walkthrough

In the reference implementation:
- `vector<int> ans(n, 0);`: creates the default zero-filled answer array.
- `vector<int> st;`: acts as the monotonic stack holding indices of colder previous days.
- `while (!st.empty() && temperatures[st.back()] < temperatures[i])`: checks if today resolves pending days.
- `ans[st.back()] = i - st.back(); st.pop_back();`: records day difference and discards resolved day index.
- `st.push_back(i);`: pushes today onto the stack to await future warmer days.

## Test it out loud

- `temperatures = [30, 40, 50, 60]`:
  - `i = 0 (30)`: stack `[0]`.
  - `i = 1 (40)`: 40 > 30, pop 0, `ans[0] = 1 - 0 = 1`. Stack pushes 1 (`[1]`).
  - `i = 2 (50)`: 50 > 40, pop 1, `ans[1] = 2 - 1 = 1`. Stack pushes 2 (`[2]`).
  - `i = 3 (60)`: 60 > 50, pop 2, `ans[2] = 3 - 2 = 1`. Stack pushes 3 (`[3]`).
  - Loop finishes. `ans = [1, 1, 1, 0]`.
- `temperatures = [70, 70, 70]`:
  - Stack fills with `0, 1, 2` because equal temperatures do not trigger the `<` condition.
  - All entries remain 0: `[0, 0, 0]`.

## Follow-ups

- What if the calendar was circular (temperatures wrap around to day 0)?
  Loop from `0` to `2 * n - 1` using modulo `i % n`, while only pushing indices when `i < n` (Next Greater Element II).
- What if temperatures range is very small (30 to 100) and we want `O(1)` extra space besides output?
  Iterate right-to-left, using `ans` jumps to hop directly to warmer days without a separate stack.

## Common mistakes

- Storing temperatures on the stack instead of indices, which makes it impossible to compute distance `i - idx`.
- Using `<=` instead of `<` when resolving temperatures, which treats equal temperatures as warmer.
- Scanning backward from each day inside a loop, keeping `O(n^2)` time.
