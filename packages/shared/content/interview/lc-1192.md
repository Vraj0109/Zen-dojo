## Clarify first
- What defines a critical connection? A cable (edge) whose removal disconnects the network (a bridge in graph theory).
- Is the original network connected? Yes, the input graph is guaranteed to be a single connected component.
- Can there be duplicate edges between two servers? No, there are no parallel edges or self-loops.
- In what format should the bridges be returned? A list of pairs `[u, v]`, in any order, with either orientation.

## Examples to say out loud
- Consider `n = 4, connections = [[0,1],[1,2],[2,0],[1,3]]`:
  - Nodes 0, 1, and 2 form a cycle (3-cycle). Any cable between them can be removed without disconnecting them.
  - Node 3 is a pendant node attached only via edge `[1, 3]`.
  - Removing `[1, 3]` leaves server 3 isolated.
  - Critical connection: `[[1, 3]]`.
- Complete cycle: `n = 3, connections = [[0,1],[1,2],[2,0]]`. Removing any edge leaves a spanning path; no bridge exists. Output: `[]`.

## Brute force
A brute force approach tests each cable one by one. For each cable `e`, it temporarily removes `e` and runs a BFS or DFS starting from node 0 to count reachable servers. If the search reaches fewer than n servers, `e` is critical. Testing each of the E cables takes O(V + E) time, giving O(E * (V + E)) time overall. For `V, E <= 100,000`, this takes 10^10 operations and times out. We can identify all bridges in a single pass using Tarjan's bridge-finding algorithm.

## The key observation
An edge `(u, v)` is a bridge if and only if it is not part of any cycle.
In a DFS spanning tree, we assign two values to each vertex:
1. `disc[u]`: the discovery timestamp when vertex `u` was first visited.
2. `low[u]`: the earliest discovery time reachable from `u`'s subtree via tree edges and at most one back-edge.
For any tree edge from parent `u` to child `v`:
If `low[v] > disc[u]`, then no vertex in the subtree of `v` has a back-edge to `u` or any ancestor of `u`. Therefore, the only way into or out of `v`'s subtree is the edge `(u, v)`, making `(u, v)` a bridge.
If `low[v] <= disc[u]`, a back-edge exists that provides an alternate route, so `(u, v)` is part of a cycle and not a bridge.

## Optimal approach
1. Build an adjacency list `g` where each neighbor entry stores `{neighbor, edge_id}` so we can distinguish back-edges from the edge directly to the parent.
2. Allocate arrays `disc` and `low` initialized to -1, a `parent` array, and an explicit DFS stack to handle `n = 100,000` safely without risking stack overflows.
3. Traverse the graph using DFS starting from node 0:
   - When discovering a node `u`, set `disc[u] = low[u] = ++timer`.
   - For each adjacent edge `{v, id}`:
     - If `id == parent_edge[u]`, skip it (do not traverse the direct parent edge backward).
     - If `v` is unvisited: recurse on `v`. Upon return, update `low[u] = min(low[u], low[v])`. If `low[v] > disc[u]`, record `{u, v}` as a critical bridge.
     - If `v` is already visited: this is a back-edge; update `low[u] = min(low[u], disc[v])`.
4. Return all recorded bridges.

Complexity:
- Time complexity: O(V + E) because every vertex and edge is traversed exactly once during the DFS.
- Space complexity: O(V + E) auxiliary space for the adjacency list, discovery arrays, and DFS stack.

## Code walkthrough
- `g[connections[i][0]].push_back({connections[i][1], i})`: Attaches edge IDs to differentiate parallel or parent edges cleanly.
- `disc` and `low`: `disc[v]` tracks entry order; `low[v]` tracks lowest ancestor reachable through back-edges.
- `if (id == parentEdge[u]) continue`: Prevents updating `low[u]` using the immediate parent edge.
- `low[u] = min(low[u], disc[v])`: Relaxes `low[u]` using back-edges to earlier ancestors.
- `if (low[u] > disc[p]) out.push_back({p, u})`: Tests the fundamental bridge condition: child `u` cannot reach `p` or any node above `p` without this edge.

## Test it out loud
- Test `[3, [[0,1],[1,2],[2,0]]]`:
  - `disc = [0, 1, 2]`.
  - From 2, edge to 0 is a back-edge: `low[2] = min(2, disc[0]) = 0`.
  - Unwinding: `low[1] = 0`, `low[0] = 0`.
  - For all edges, `low[child] <= disc[parent]`.
  - No bridges recorded. Returns `[]`. Correct.
- Test `[2, [[0,1]]]`:
  - `disc[0] = 0`, `disc[1] = 1`, `low[1] = 1`.
  - `low[1] (1) > disc[0] (0)`. Edge `[0, 1]` is recorded. Output: `[[0, 1]]`. Correct.

## Follow-ups
- How does bridge finding differ from finding articulation points (cut vertices)? An articulation point condition is `low[v] >= disc[u]` (non-strict) for internal nodes, with special root handling (root is an articulation point if it has `>= 2` tree children).
- Why is an explicit stack used in the reference implementation? With `n = 100,000`, a degenerate linear graph has recursion depth 100,000, which can exceed the default call stack limit in languages like C++ or Python unless recursion limits are raised.

## Common mistakes
- Comparing against `low[v]` instead of `disc[v]` when updating `low[u]` on a back-edge.
- Using `low[v] >= disc[u]` instead of strict `low[v] > disc[u]` for bridges.
- Treating the direct parent edge as a back-edge, which erroneously neutralizes every bridge.
