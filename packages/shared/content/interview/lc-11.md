## Clarify first

- Can lines have height 0? Yes, heights range from 0 to 10,000.
- Can we tilt the container? No, lines are vertical and the container cannot be slanted.
- What is the minimum number of vertical lines? Constraints specify `2 <= height.length <= 100,000`.
- How is the capacity calculated? The volume of water is `(right_index - left_index) * min(height[left], height[right])`.

## Examples to say out loud

- Standard case: `height = [1, 8, 6, 2, 5, 4, 8, 3, 7]`.
  - Widest pair is index 0 (height 1) and index 8 (height 7): area = `(8 - 0) * min(1, 7) = 8`.
  - The pair at index 1 (height 8) and index 8 (height 7): area = `(8 - 1) * min(8, 7) = 7 * 7 = 49`. This gives the maximum possible container capacity.
- Two identical heights edge case: `height = [1, 1]`. Width is 1, minimum height is 1, giving area `1 * 1 = 1`.
- Zero height edge case: `height = [0, 2]`. Area = `(1 - 0) * min(0, 2) = 0`.

## Brute force

A brute-force strategy computes the area between every pair of indices `(i, j)` where `0 <= i < j < n`. With `n * (n - 1) / 2` pairs, this takes `O(n^2)` time and `O(1)` space. Given `n = 100,000`, checking `10^{10}` pairs will exceed the time limit in an interview.

## The key observation

Start with the widest container using two pointers at the boundaries `l = 0` and `r = n - 1`. The area is constrained by the shorter line: `(r - l) * min(height[l], height[r])`. If we move the taller line inward, the width decreases while the height upper bound remains at most the shorter line's height, guaranteeing no improvement. Therefore, to find a strictly larger area, we must advance the pointer with the shorter height inward.

## Optimal approach

1. Initialize two pointers: `l = 0` at the left boundary and `r = height.length - 1` at the right boundary.
2. Initialize `best = 0` to track the maximum area seen.
3. While `l < r`:
   a. Compute the current area: `current = (r - l) * min(height[l], height[r])`.
   b. Update `best = max(best, current)`.
   c. If `height[l] < height[r]`, increment `l`.
   d. Otherwise, decrement `r`.
4. Return `best`.

Complexity:
- Time: `O(n)` because in every iteration at least one pointer moves inward, visiting each of the `n` positions at most once.
- Space: `O(1)` auxiliary space as we only use pointers and scalar trackers.

## Code walkthrough

In the reference implementation:
- `int l = 0, r = (int)height.size() - 1, best = 0;`: establishes pointers at both array ends and sets max area tracker.
- `while (l < r)`: iterates until the boundaries converge.
- `best = max(best, (r - l) * min(height[l], height[r]));`: evaluates water volume supported by lines `l` and `r`.
- `if (height[l] < height[r]) l++; else r--;`: greedily discards the shorter boundary which cannot form a larger area with any inner line.
- `return best;`: outputs peak water capacity.

## Test it out loud

- `height = [4, 3, 2, 1, 4]`:
  - `l = 0 (4), r = 4 (4)`: area `4 * 4 = 16`. Since `height[l] == height[r]`, decrement `r` to 3.
  - `l = 0 (4), r = 3 (1)`: area `3 * 1 = 3`. `height[r] < height[l]`, decrement `r` to 2.
  - `l = 0 (4), r = 2 (2)`: area `2 * 2 = 4`. Decrement `r` to 1.
  - `l = 0 (4), r = 1 (3)`: area `1 * 3 = 3`. Decrement `r` to 0. Loop ends.
  - Returns 16.
- `height = [1, 2, 1]`:
  - `l = 0 (1), r = 2 (1)`: area `2 * 1 = 2`. Decrement `r` to 1.
  - `l = 0 (1), r = 1 (2)`: area `1 * 1 = 1`. Increment `l` to 1. Loop ends.
  - Returns 2.

## Follow-ups

- What if you also need to find the specific pair of indices that yield the maximum area?
  Store `best_l` and `best_r` whenever `current > best`.
- What is the difference between this and Trapping Rain Water (LeetCode 42)?
  Container With Most Water selects two single bounding pillars without interior obstructions, while Trapping Rain Water calculates water held between all pillars across the terrain.

## Common mistakes

- Moving both pointers inward simultaneously when heights are equal or not considering that equal heights can advance either pointer safely.
- Moving the taller pointer inward in hope of finding an even taller line, which mathematically cannot beat the current area bounded by the shorter line at the wider span.
- Forgetting that the width is `r - l`, not `r - l + 1`.
