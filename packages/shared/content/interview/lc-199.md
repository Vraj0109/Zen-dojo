## Clarify first

- What should be returned for an empty tree? Return an empty list `[]`.
- Is a left child visible from the right side if the right child at that level is missing? Yes, any node that is the rightmost occupant of its level is visible from the right side.
- What are the tree constraints? Number of nodes is between 0 and 100, and node values range from -100 to 100.
- How should the output array be ordered? From top to bottom (root level down to the deepest leaf level).

## Examples to say out loud

- Tree with obscured left children: `root = [1, 2, 3, null, 5, null, 4]`.
  - Level 0: `[1]`, visible node is 1.
  - Level 1: `[2, 3]`, visible node is 3.
  - Level 2: `[5, 4]`, visible node is 4.
  - Output is `[1, 3, 4]`.
- Asymmetric tree exposing a left branch: `root = [1, 2, 3, 4]`.
  - Level 0: `[1]`, rightmost is 1.
  - Level 1: `[2, 3]`, rightmost is 3.
  - Level 2: `[4]` (child of 2; 3 has no children), rightmost is 4.
  - Output is `[1, 3, 4]`.
- Empty tree: `root = []`, returns `[]`.

## Brute force

A brute-force strategy performs a full level-order traversal (like LeetCode 102), collecting all node values into lists per level. After constructing all level lists, it iterates through each list and appends its last element to the result array. While this takes `O(n)` time, it stores all node values across all levels in intermediate arrays, consuming `O(n)` unnecessary auxiliary memory.

## The key observation

The right side view consists of exactly one node per depth level: the rightmost node. During level-by-level BFS traversal, when iterating through the `n` nodes of the current level, the node at index `n - 1` is the rightmost node. We only need to record that specific node's value.

## Optimal approach

1. If `root == null`, return an empty list.
2. Initialize a queue with `root` and an empty list `out`.
3. While the queue is not empty:
   a. Let `n = queue.size()`.
   b. Iterate `i` from 0 to `n - 1`:
      i. Dequeue node `x`.
      ii. If `i == n - 1`, append `x.val` to `out`.
      iii. If `x.left` exists, enqueue `x.left`.
      iv. If `x.right` exists, enqueue `x.right`.
4. Return `out`.

Complexity:
- Time: `O(n)` because every node is visited and processed once.
- Space: `O(w)` auxiliary queue memory, where `w` is the maximum level width.

## Code walkthrough

In the reference implementation:
- `if (!root) return out;`: handles empty tree edge cases immediately.
- `queue<TreeNode*> q; q.push(root);`: sets up the BFS frontier.
- `int n = (int)q.size();`: locks the count of nodes at the current level.
- `if (i == n - 1) out.push_back(x->val);`: captures only the final node at this level.
- `if (x->left) q.push(x->left); if (x->right) q.push(x->right);`: enqueues children left-to-right for the subsequent level.

## Test it out loud

- `root = [1, null, 3]`:
  - Level 0: queue `[1]`, `n = 1`. `i = 0`: `0 == 0`, add 1 to `out`. Enqueue right child 3.
  - Level 1: queue `[3]`, `n = 1`. `i = 0`: `0 == 0`, add 3 to `out`.
  - Queue is empty, returns `[1, 3]`.
- `root = [1, 2]`:
  - Level 0: queue `[1]`, `n = 1`. Add 1. Enqueue left child 2.
  - Level 1: queue `[2]`, `n = 1`. Add 2.
  - Returns `[1, 2]`.

## Follow-ups

- Can we solve this with DFS instead of BFS?
  Yes, traverse root -> right -> left, passing `depth`. If `depth == out.size()`, append `node.val` because the rightmost node at this depth is encountered first.
- What if we need the left side view?
  With BFS, record when `i == 0`. With DFS, traverse root -> left -> right.

## Common mistakes

- Assuming the right view is formed solely by following right pointers (`root = root.right`), missing left subtrees that extend deeper than right subtrees.
- Storing entire levels in memory when only the last element of each level is needed.
- Pushing null pointers into the queue, causing null reference exceptions when inspecting `x->val`.
