## Clarify first

- Are there any parentheses in the expression? No, there are no parentheses; only non-negative integers and operators `+`, `-`, `*`, `/`.
- Can the string contain whitespace spaces? Yes, spaces can appear anywhere and should be ignored.
- Does division truncate toward zero? Yes, integer division truncates toward zero (e.g. `3 / 2 = 1`, `-3 / 2 = -1`).
- What is operator precedence? Multiplication and division have higher precedence and must be evaluated before addition and subtraction.
- Will numbers fit in standard 32-bit signed integers? Constraints guarantee intermediate values fit in a 32-bit signed integer.

## Examples to say out loud

- Precedence ordering: `s = "3+2*2"`.
  - Multiplication `2 * 2 = 4` happens first.
  - Then `3 + 4 = 7`. Result is 7.
- Division with truncation: `s = " 3/2 "`. Spaces are skipped, `3 / 2 = 1`. Result is 1.
- Interleaved operations: `s = " 3+5 / 2 "`.
  - Division `5 / 2 = 2` first.
  - Then `3 + 2 = 5`. Result is 5.

## Brute force

A brute-force strategy parses the entire string into an expression tree or tokens, scans repeatedly to perform all multiplications and divisions left-to-right, contracts those tokens, and then performs a second pass to execute additions and subtractions. While this runs in `O(n)` time, storing tokens and strings consumes `O(n)` extra memory. We can evaluate it in a single pass with `O(1)` space using state accumulation.

## The key observation

Because multiplication and division have higher precedence, their operations must be performed immediately with the most recent operand. Conversely, addition and subtraction can be deferred: when an addition or subtraction operator is encountered, the completed previous product/quotient is finalized and folded into a running `total`. By maintaining only `last` (the current multiplication/division chain value) and `total` (the cumulative sum of completed additive terms), we eliminate the stack entirely, achieving `O(1)` auxiliary space.

## Optimal approach

1. Initialize `total = 0`, `last = 0`, `cur = 0`, and `op = '+'` (representing the operation preceding the current number).
2. Append a sentinel `'+'` to the end of the string loop (or check when `i == s.length()`).
3. Iterate `i` from 0 to `s.length()`:
   a. Let `c = (i < s.length()) ? s[i] : '+'`.
   b. If `c` is a digit: `cur = cur * 10 + (c - '0')`.
   c. If `c == ' '`: skip space.
   d. If `c` is an operator or the sentinel:
      - If `op == '+'`: `total += last`, `last = cur`.
      - If `op == '-'`: `total += last`, `last = -cur`.
      - If `op == '*'`: `last *= cur`.
      - If `op == '/'`: `last /= cur`.
      - Update operator `op = c`, and reset `cur = 0`.
4. Return `(int)(total + last)`.

Complexity:
- Time: `O(n)` because we parse each character in the string of length `n` exactly once in a single forward pass.
- Space: `O(1)` auxiliary space since only a few scalar variables are maintained.

## Code walkthrough

In the reference implementation:
- `long long total = 0, last = 0, cur = 0; char op = '+';`: tracks completed sum, active multiplicative term, incoming number, and previous operator.
- `if (isdigit(c)) { cur = cur * 10 + (c - '0'); continue; }`: parses multi-digit numbers.
- `if (op == '+') { total += last; last = cur; }`: commits the finished previous term into `total` and seeds the next term.
- `else if (op == '*') last *= cur;`: evaluates multiplication eagerly against the pending operand.
- `else last /= cur;`: evaluates division eagerly with integer truncation.
- `return (int)(total + last);`: adds the final trailing term into the grand total.

## Test it out loud

- `s = "3+2*2"`:
  - `c = '3'`: `cur = 3`. Next `c = '+'`: `op` was `'+'` -> `total += 0`, `last = 3`. `op = '+'`, `cur = 0`.
  - `c = '2'`: `cur = 2`. Next `c = '*'`: `op` was `'+'` -> `total += 3 = 3`, `last = 2`. `op = '*'`, `cur = 0`.
  - `c = '2'`: `cur = 2`. Sentinel `'+'`: `op` was `'*'` -> `last = 2 * 2 = 4`.
  - Return `total + last = 3 + 4 = 7`.
- `s = "14-3/2"`:
  - 14: `last = 14`.
  - `-`: `total = 14`, `op = '-'`.
  - 3, `/`: `last = -3`, `op = '/'`.
  - 2, sentinel: `last = -3 / 2 = -1`.
  - Return `total + last = 14 + (-1) = 13`.

## Follow-ups

- What if parentheses are added (Basic Calculator, LeetCode 224)?
  Use recursion or an explicit stack of `(total, last, op)` pushed upon `'('` and popped upon `')'`.
- What if numbers can be negative at input (unary minus)?
  Treat unary minus as subtracting from 0 or toggle sign flags.

## Common mistakes

- Applying operators immediately upon reading them rather than caching `op` until the entire number following it has been parsed.
- Forgetting to process the final number at the end of the string (resolved cleanly by looping up to `n` with a sentinel operator).
- Using a stack of size `O(n)` when only the last operand is required for `*` and `/`.
