## Clarify first

- What numbers are included in the sequence? (Strictly positive integers $1, 2, 3, \dots$ that are NOT divisible by $n$: $x \pmod n \ne 0$).
- How is the target requested? (We must find the $k$-th number in this strictly increasing sequence).
- What are the constraints on $n$ and $k$? ($2 \le n \le 1,000,000,000$ and $1 \le k \le 1,000,000,000$).
- Can the answer exceed 32-bit signed integers? (Yes, for $n = 2$ and $k = 10^9$, the answer is $1,999,999,999$, and in general can reach $\approx 2 \times 10^9$, requiring 64-bit integer types like `long long` to prevent intermediate overflow).
- What should be returned? (A 64-bit integer representing the $k$-th non-multiple of $n$).

## Examples to say out loud

- Standard case: `n = 3, k = 7`.
  - Non-multiples of 3: 1, 2 (skip 3), 4, 5 (skip 6), 7, 8 (skip 9), 10, ...
  - The 7th element in this sequence is 10. Output is 10.
- Small case: `n = 4, k = 12`.
  - Blocks of 4 contain 3 non-multiples: $\{1, 2, 3\}$, $\{5, 6, 7\}$, $\{9, 10, 11\}$, $\{13, 14, 15\}$.
  - 12th non-multiple is 15. Output is 15.
- Extreme case: `n = 2, k = 1`.
  - Sequence of non-multiples of 2: 1, 3, 5, 7, ...
  - The 1st odd number is 1. Output is 1.

## Brute force

A direct simulation iterates through positive integers $x = 1, 2, 3, \dots$, maintaining a counter of non-multiples whenever $x \bmod n \ne 0$, stopping when the counter reaches $k$. Because $k \le 10^9$, this loop requires up to $2 \times 10^9$ iterations, which takes multiple seconds and times out.

## The key observation

The integers naturally partition into periodic blocks of size $n$:
$[1 \dots n], [n+1 \dots 2n], [2n+1 \dots 3n], \dots$
Within each block of $n$ consecutive integers, exactly $n - 1$ numbers are not divisible by $n$, and exactly 1 number is a multiple of $n$ (the last element of the block).
To reach the $k$-th non-multiple, we can determine how many full blocks of $(n - 1)$ valid numbers precede it:
$$\text{full\_blocks} = \lfloor (k - 1) / (n - 1) \rfloor$$
Each full block contains exactly one skipped multiple of $n$. Therefore, exactly $\text{full\_blocks}$ multiples of $n$ must be skipped before reaching the $k$-th non-multiple. Shifting the index $k$ by the count of skipped multiples gives the exact value in $O(1)$:
$$\text{answer} = k + \lfloor (k - 1) / (n - 1) \rfloor$$

## Optimal approach

1. Cast $k$ and $n$ to 64-bit signed integers.
2. Compute the number of skipped multiples prior to the $k$-th valid number:
   `skipped = (k - 1) / (n - 1)`.
3. Add the skipped count directly to $k$:
   `result = k + skipped`.
4. Return `result`.

Complexity:
- Time: `O(1)` as only basic integer division and addition are performed.
- Space: `O(1)` auxiliary space for scalar registers.

## Code walkthrough

In the reference implementation:
- `(long long)k`: promotes $k$ to a 64-bit integer to prevent integer overflow during addition.
- `(k - 1) / (n - 1)`: computes the number of complete $(n - 1)$-sized groups of non-multiples strictly before the $k$-th term, which equals the exact number of skipped multiples.
- `return (long long)k + (k - 1) / (n - 1);`: adds the offset to $k$ in constant time.

## Test it out loud

- `n = 3, k = 7`:
  - `skipped = (7 - 1) / (3 - 1) = 6 / 2 = 3`.
  - `result = 7 + 3 = 10`. Returns 10.
- `n = 2, k = 1`:
  - `skipped = (1 - 1) / (2 - 1) = 0 / 1 = 0`.
  - `result = 1 + 0 = 1`. Returns 1.
- `n = 2, k = 2`:
  - `skipped = (2 - 1) / 1 = 1`.
  - `result = 2 + 1 = 3`. Returns 3.
- `n = 1000000000, k = 1000000000`:
  - `(10^9 - 1) / (10^9 - 1) = 1`.
  - `result = 10^9 + 1 = 1000000001`. Returns 1000000001.

## Follow-ups

- Can this be solved using binary search?
  Yes, for any candidate value $X$, the number of integers up to $X$ not divisible by $n$ is $f(X) = X - \lfloor X / n \rfloor$. Because $f(X)$ is monotonically increasing, we can binary search $X \in [1, 2 \times 10^9]$ for the smallest $X$ such that $f(X) = k$ in $O(\log(\text{max\_val})) \approx 31$ iterations.
- What if numbers cannot be divisible by any of multiple numbers $\{n_1, n_2\}$?
  With multiple divisors, the block length becomes $\text{lcm}(n_1, n_2)$, and we count non-multiples using inclusion-exclusion within the period.

## Common mistakes

- Using `k / (n - 1)` instead of `(k - 1) / (n - 1)`: when $k$ is an exact multiple of $n - 1$ (e.g., $n = 3, k = 2$), $2 / 2 = 1 \implies 2 + 1 = 3$, which is divisible by 3 and incorrect! The correct formula $(2 - 1) / 2 = 0 \implies 2 + 0 = 2$.
- 32-bit signed overflow when $k = 10^9$ and $n = 2$, yielding $\approx 2 \times 10^9$, which can overflow signed 32-bit integer limits if intermediate additions exceed $2^{31} - 1$.
- Simulating with a loop instead of the closed-form equation.
