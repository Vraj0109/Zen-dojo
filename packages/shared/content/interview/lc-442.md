## Clarify first

- What is the range of values in `nums`? Every value `v` satisfies `1 <= v <= n`, where `n` is the array length.
- How many times can an element appear? Each value appears either exactly once or exactly twice.
- What order should the duplicates be returned in? Any order is acceptable.
- Can we use extra space? The problem specifies an algorithm running in `O(n)` time using `O(1)` auxiliary memory (modifying the input array in-place is permitted).

## Examples to say out loud

- Mixed frequencies: `nums = [4, 3, 2, 7, 8, 2, 3, 1]`.
  - Values 2 and 3 each appear twice.
  - Return `[2, 3]` (or `[3, 2]`).
- Small duplicate pair: `nums = [1, 1, 2]`. 1 appears twice, return `[1]`.
- All unique elements: `nums = [1, 2, 3, 4]`. No value appears twice, return `[]`.

## Brute force

A brute-force approach inserts elements into a hash set; if an element is already present in the set, add it to the result list. While this runs in `O(n)` time, the hash set uses `O(n)` auxiliary memory. Alternatively, sorting the array takes `O(n log n)` time to find adjacent equal values, which fails the `O(n)` time requirement.

## The key observation

Because every element `v` is strictly between `1` and `n`, every value directly corresponds to a valid index `v - 1 \in [0, n - 1]`. We can use the array itself as an in-place visited table: when we encounter value `v = |nums[i]|`, we inspect the sign of `nums[v - 1]`. If `nums[v - 1]` is positive, we negate it (`nums[v - 1] = -nums[v - 1]`) to record that `v` has been seen. If `nums[v - 1]` is already negative when we arrive, `v` must have been encountered previously, so `v` is a duplicate!

## Optimal approach

1. Initialize an empty list `out` to collect duplicate values.
2. Iterate `i` from 0 to `nums.length - 1`:
   a. Let `v = abs(nums[i])` (using absolute value since earlier steps may have negated `nums[i]`).
   b. Check index `v - 1`:
      - If `nums[v - 1] < 0`: `v` was already seen, so append `v` to `out`.
      - Otherwise: negate `nums[v - 1]` (`nums[v - 1] = -nums[v - 1]`).
3. Return `out`.

Complexity:
- Time: `O(n)` because we iterate through the array of `n` elements once, performing `O(1)` sign checks and multiplications per element.
- Space: `O(1)` auxiliary space beyond the output list, using in-place sign-bit encoding.

## Code walkthrough

In the reference implementation:
- `vector<int> out;`: collects the duplicate integers discovered.
- `int v = abs(nums[i]);`: recovers the original value regardless of whether cell `i` was previously negated.
- `if (nums[v - 1] < 0) out.push_back(v);`: detects that the home slot for value `v` has already been flagged, identifying `v` as a duplicate.
- `else nums[v - 1] = -nums[v - 1];`: flips the sign of the home slot to mark `v` as visited.
- `return out;`: outputs all values that occurred twice.

## Test it out loud

- `nums = [2, 2]`:
  - `i = 0`: `v = abs(2) = 2`. Index `2 - 1 = 1`: `nums[1] = 2 > 0`, negate to `-2`. Array: `[2, -2]`.
  - `i = 1`: `v = abs(-2) = 2`. Index `2 - 1 = 1`: `nums[1] = -2 < 0`, already flagged! Append 2 to `out`.
  - Returns `[2]`.
- `nums = [1, 2, 3]`:
  - `i = 0`: `v = 1`, `nums[0]` negated to -1.
  - `i = 1`: `v = 2`, `nums[1]` negated to -2.
  - `i = 2`: `v = 3`, `nums[2]` negated to -3.
  - No negative index encountered before negation, returns `[]`.

## Follow-ups

- What if elements can appear more than twice (e.g. 3 or 4 times)?
  Negation can only distinguish between seen once vs seen multiple times; for general frequencies, we can add `n` to `nums[v - 1]` or use cyclic sort.
- How can we restore the original array after finding duplicates?
  Take the absolute value of every element: `nums[i] = abs(nums[i])` in an `O(n)` cleanup pass.

## Common mistakes

- Forgetting to take `abs(nums[i])`, which attempts to index with negative numbers and triggers segmentation faults.
- Appending `nums[i]` instead of `v` to the output, accidentally outputting negative numbers.
- Off-by-one errors mapping between 1-based values and 0-based indices (`v - 1`).
