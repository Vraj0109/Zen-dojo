## Clarify first

- Can the elements be divided into unequal subset sizes? Yes, the subsets can contain any number of elements as long as their sums are identical.
- Can elements be negative or zero? No, constraints state elements are strictly positive integers (`1 <= nums[i] <= 100`).
- What if the total sum of all elements is odd? If the sum is odd, it is impossible to partition into two equal integer halves, so return `false` immediately.
- What are the input constraints? `nums.length` is between 1 and 200, and elements are up to 100 (maximum total sum is 20,000, so `target <= 10,000`).

## Examples to say out loud

- Partitionable array: `nums = [1, 5, 11, 5]`.
  - Total sum = `1 + 5 + 11 + 5 = 22` (even). Target for each partition is `22 / 2 = 11`.
  - Subset `[1, 5, 5]` sums to 11, and remaining subset `[11]` sums to 11. Returns `true`.
- Non-partitionable array: `nums = [1, 2, 3, 5]`.
  - Total sum = `1 + 2 + 3 + 5 = 11` (odd). Impossible to split into equal integers, returns `false`.
- Single element: `nums = [100]`. Cannot be split into two non-empty groups, returns `false`.

## Brute force

A brute-force solution uses recursion to test every possible subset: for each number `x`, branch into either including `x` in the first subset or excluding it. This explores all `2^n` subsets. For `n = 200`, `2^{200}` is completely intractable and results in a time limit exceeded error.

## The key observation

The problem is equivalent to the 0/1 Knapsack Problem (Subset Sum): can we pick a subset of numbers that sums to exactly `target = total / 2`? If such a subset exists, the remaining elements automatically sum to `total / 2`. We can maintain a boolean reachability array `reach` where `reach[s]` indicates whether sum `s` is achievable. By iterating backwards from `target` down to `x` for each item, each number is used at most once.

## Optimal approach

1. Calculate `total = sum(nums)`.
2. If `total % 2 != 0`, return `false`.
3. Set `target = total / 2`.
4. Allocate a boolean array `reach` of size `target + 1` with `reach[0] = true` and all other entries `false`.
5. For each number `x` in `nums`:
   - For `s` from `target` down to `x`:
     - If `reach[s - x]` is true, set `reach[s] = true`.
6. Return `reach[target]`.

Complexity:
- Time: `O(n * total)` (specifically `O(n * target)`), bounded by `200 * 10,000 = 2 \times 10^6` operations, which executes in a few milliseconds.
- Space: `O(total)` (specifically `O(target)`), using a 1D boolean array of size at most 10,001.

## Code walkthrough

In the reference implementation:
- `int total = accumulate(nums.begin(), nums.end(), 0);`: calculates total array sum.
- `if (total % 2 != 0) return false;`: eliminates impossible odd sums immediately.
- `vector<char> reach(target + 1, 0); reach[0] = 1;`: sets base case that a sum of 0 is always achievable with an empty set.
- `for (int s = target; s >= x; s--)`: iterates backward to prevent the current number `x` from contributing multiple times (0/1 knapsack invariant).
- `if (reach[s - x]) reach[s] = 1;`: marks sum `s` as reachable if remainder `s - x` was previously formed.
- `return reach[target];`: returns whether the exact target sum was attained.

## Test it out loud

- `nums = [1, 2, 5]`:
  - `total = 8`, `target = 4`. `reach[0] = true`.
  - `x = 1`: `reach[1] = true`.
  - `x = 2`: `reach[3] = true`, `reach[2] = true`.
  - `x = 5`: `x > target (5 > 4)`, loop does not execute.
  - `reach[4]` is false, returns `false`.
- `nums = [1, 5, 11, 5]`:
  - `total = 22`, `target = 11`.
  - After processing 1, 5, 11, 5, `reach[11]` becomes true (via `reach[6] + 5` where `6 = 1 + 5`). Returns `true`.

## Follow-ups

- How would you optimize the constant factor in C++?
  Use `std::bitset<10001> reach; reach[0] = 1;` and perform `reach |= (reach << x)` for each `x`, achieving a 64x speedup via bitwise operations.
- What if numbers can be negative?
  Subset sum with negative numbers requires shifting the DP array index by the minimum possible sum or using a hash set.

## Common mistakes

- Iterating `s` forward from `x` to `target`, which treats the problem as unbounded knapsack and uses the same number multiple times.
- Forgetting the odd total parity check, attempting to find a non-integer half.
- Using full 2D DP matrix of size `n \times target` when 1D backward iteration achieves `O(target)` space.
