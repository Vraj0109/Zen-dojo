## Clarify first

- What format is the input given in? (A flattened list of busy intervals `[start, end]` across all employees).
- What defines "free time"? (Any finite time period during which *no* employee is working, meaning common free time for all employees).
- Do infinite boundaries $(-\infty, \text{first\_start})$ or $(\text{last\_end}, \infty)$ count? (No, only finite intervals between scheduled work count).
- Can consecutive busy intervals touch without creating free time? (Yes, if one ends at 3 and another begins at 3, there is zero gap, so no free time interval is created).
- Should output intervals be sorted? (Yes, in increasing order of start time).

## Examples to say out loud

- Two overlapping clusters: `intervals = [[1, 2], [5, 6], [1, 3], [4, 10]]`. Merging busy intervals gives `[1, 3]` and `[4, 10]`. The gap between 3 and 4 is free for everyone, returning `[[3, 4]]`.
- Continuous back-to-back work: `intervals = [[1, 2], [2, 3], [3, 4]]`. The busy blocks touch continuously from 1 to 4 with no gaps, returning `[]`.
- Complete coverage across intervals: `intervals = [[1, 10], [2, 5], [6, 8]]`. All smaller intervals fall completely inside `[1, 10]`, leaving no finite free gaps; returns `[]`.

## Brute force

A naive brute force discretizes time into minute/second buckets or events, marks all timestamps where any employee is busy, and then scans for uncolored gaps between the minimum and maximum working times. With coordinates up to $10^8$, creating a bucket array takes $O(\max(\text{end})) \approx 10^8$ space and time, leading to Memory Limit Exceeded.

## The key observation

We only care about intervals where *everyone* is free, which is precisely the complement of the union of all busy intervals. If we treat all intervals as a single collection and sort them by start time, we can merge overlapping and touching intervals into consolidated busy blocks. Any gap between the end of the previous merged block and the start of the next merged block represents positive-length common free time.

## Optimal approach

1. Check for empty input; return an empty list if there are no intervals.
2. Sort all intervals by their start times in ascending order (break ties by end time).
3. Initialize `curEnd = intervals[0][1]` representing the furthest end time of the current continuous busy period, and an empty result list `res`.
4. Iterate through `intervals` starting from index 1:
   - If `intervals[i][0] > curEnd`:
     - The current interval starts strictly after `curEnd`, revealing a gap where nobody is working.
     - Add `[curEnd, intervals[i][0]]` to `res`.
     - Update `curEnd = intervals[i][1]`.
   - Otherwise (`intervals[i][0] <= curEnd`):
     - The interval overlaps or touches the current busy period.
     - Extend the active busy period: `curEnd = max(curEnd, intervals[i][1])`.
5. Return `res`.

Complexity:
- Time: `O(n log n)` where $n$ is the total number of intervals across all employees, dominated by the sorting step. The subsequent linear scan runs in $O(n)$.
- Space: `O(n)` auxiliary space for sorting and storing the output intervals.

## Code walkthrough

In the reference implementation:
- `sort(intervals.begin(), intervals.end(), ...);`: orders all employee commitments chronologically.
- `int curEnd = intervals[0][1];`: anchors the boundary of active employee commitments.
- `if (intervals[i][0] > curEnd)`: detects an empty scheduling window between consecutive busy blocks.
- `res.push_back({curEnd, intervals[i][0]});`: records the finite gap as common free time.
- `curEnd = max(curEnd, intervals[i][1]);`: absorbs overlapping shifts into the ongoing block.

## Test it out loud

- Disjoint non-overlapping shifts: `[[1, 3], [5, 7], [9, 11]]`.
  - Merged: `[1, 3]`, `[5, 7]`, `[9, 11]`.
  - Gaps between `3 -> 5` and `7 -> 9` recorded, returning `[[3, 5], [7, 9]]`.
- One large encompassing shift: `[[10, 20], [30, 40], [15, 25], [26, 29]]`.
  - Sorted: `[10, 20], [15, 25], [26, 29], [30, 40]`.
  - `[10, 20]` merges with `[15, 25]` into `[10, 25]`.
  - Gap `[25, 26]` added; `curEnd` becomes 29.
  - Gap `[29, 30]` added; `curEnd` becomes 40.
  - Output: `[[25, 26], [29, 30]]`.
- Single interval: `[[1, 5]]`. No subsequent intervals; loop does not run, returns `[]`.

## Follow-ups

- What if each employee's schedule is already sorted individually in the input?
  Use a min-heap (k-way merge) of size $K$ (number of employees). Repeatedly extract the earliest interval across all employees in $O(n \log K)$ time and $O(K)$ space.
- How to handle dynamic additions of employee shifts?
  Maintain intervals in an interval tree or balanced BST (e.g. `std::set`), finding and splitting free gaps dynamically in $O(\log n)$ per update.
- What if we need at least $K$ employees free simultaneously instead of all?
  Convert into a line-sweep event counter: $+1$ when an employee becomes busy, $-1$ when they finish. A window is valid whenever `busy_count <= total_employees - K`.

## Common mistakes

- Treating touching intervals (e.g., `[1, 2]` and `[2, 3]`) as generating a gap `[2, 2]`; free time must have strictly positive length (`start < end`).
- Forgetting `curEnd = max(curEnd, intervals[i][1])`, which fails when a shorter interval is completely nested within a longer preceding interval.
- Attempting to track employee identities, which is redundant since free time requires zero employees working.
