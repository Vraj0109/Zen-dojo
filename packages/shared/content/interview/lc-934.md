## Clarify first

- How many islands exist in the grid? (The problem guarantees exactly two 4-directionally connected islands).
- What values represent land and water? (`1` represents land, `0` represents water).
- What are the dimensions of the grid? (`n x n` where $2 \le n \le 100$).
- Can bridges connect diagonally? (No, connectivity is 4-directional: horizontal and vertical).
- What constitutes the length of the bridge? (The minimum number of `0` cells that must be inverted to `1` to link the two islands).

## Examples to say out loud

- Two adjacent islands separated by 1 water cell: `grid = [[0, 1], [1, 0]]`. Island 1 is at `(0, 1)`, island 2 is at `(1, 0)`. Flipping either `(0, 0)` or `(1, 1)` connects them; answer is 1.
- Distant islands: `grid = [[1, 0, 0], [0, 0, 0], [0, 0, 1]]`. Expanding from `(0, 0)` reaches `(0, 1)` (step 1), `(0, 2)` and `(1, 1)` (step 2), and neighbor `(2, 2)` (step 3); minimum flips is 3.

## Brute force

A naive brute force identifies all coordinate pairs `(r1, c1)` in the first island and `(r2, c2)` in the second island, then computes the Manhattan distance between each pair: $|r1 - r2| + |c1 - c2| - 1$. Finding components takes $O(n^2)$, but checking all pairs takes $O(K_1 \cdot K_2)$ which can be $O(n^4)$ in the worst case (e.g. spiral or comb-shaped islands). While Manhattan distance works for unobstructed straight-line paths, in grids with non-convex shapes, a multi-source wave search is required.

## The key observation

The problem asks for the shortest path in an unweighted grid from any cell in Island 1 to any cell in Island 2. We can first locate Island 1 using DFS and repaint all its cells with a distinct marker (e.g., `2`) to distinguish them from Island 2 (`1`). Then, by enqueueing all Island 1 cells as simultaneous sources into a multi-source BFS queue, we expand outward layer-by-layer into water (`0`). The first time an expansion step touches an unvisited land cell (`1`), the number of expansion layers is guaranteed to be the minimal bridge length.

## Optimal approach

1. Iterate over the grid to locate the first cell with `grid[r][c] == 1`.
2. Run DFS from this cell to discover all cells of the first island:
   - Mark visited cells as `2` to avoid mixing with Island 2.
   - Push each discovered cell into a FIFO queue `q`.
   - Once DFS finishes, break out of the initial search loops.
3. Initialize `steps = 0`.
4. While `q` is not empty:
   - For each cell in the current BFS layer (current queue size):
     - Pop `(r, c)`.
     - Check its 4 cardinal neighbors `(nr, nc)`:
       - If out of bounds or already visited (`grid[nr][nc] == 2`), continue.
       - If `grid[nr][nc] == 1`, we have reached the second island; return `steps`.
       - If `grid[nr][nc] == 0`, mark `grid[nr][nc] = 2` and push `(nr, nc)` to `q`.
   - Increment `steps` by 1.
5. Return -1 if no bridge is found (unreachable given problem constraints).

Complexity:
- Time: `O(n^2)` because every cell is visited at most twice (once during DFS/initial scan and once during BFS expansion).
- Space: `O(n^2)` for the BFS queue and recursion call stack in the worst case.

## Code walkthrough

In the reference implementation:
- `dfs(grid, r, c, q)`: labels Island 1 cells as `2` and inserts each into queue `q`.
- `found = true`: breaks out of the nested loop as soon as Island 1 is fully traversed.
- `int sz = q.size(); while (sz--)`: processes one BFS distance layer at a time.
- `if (grid[nr][nc] == 1) return steps;`: terminates immediately when the boundary of Island 2 is reached.
- `grid[nr][nc] = 2; q.push({nr, nc});`: marks water as visited when enqueuing, preventing redundant queue entries.

## Test it out loud

- Islands touching corners: `[[1, 0], [0, 1]]`. Island 1 at `(0, 0)` is marked `2`. Queue has `(0, 0)`. At `steps = 0`, neighbors `(0, 1)` and `(1, 0)` are water, pushed to queue. At `steps = 1`, expanding `(0, 1)` sees neighbor `(1, 1) == 1`, returning 1.
- Concentric islands: Outer ring of 1s, ring of 0s, inner 1. Island 1 DFS covers outer ring; BFS expands inward across the moat in 1 step, reaching inner island.
- Long thin grid: Islands at opposite ends expand level by level until meeting the second island in $n - 2$ steps.

## Follow-ups

- What if there are more than two islands and we want to connect all of them?
  This becomes a Minimum Spanning Tree (MST) problem where edge weights are shortest bridges between pairs of components.
- Can we bidirectional BFS?
  Yes, BFS can expand from both islands simultaneously, meeting in the middle to roughly halve the explored search area.
- What if flipping certain cells has different terrain costs?
  Replace the BFS queue with Dijkstra's algorithm using a min-heap or 0-1 BFS with a deque.

## Common mistakes

- Not using layer-by-layer (level-order) BFS, causing step counts to increment incorrectly per cell instead of per wave.
- Marking cells as visited when popping from the queue rather than when pushing, leading to queue blowup and exponential redundant pushes.
- Forgetting to stop the initial scan after finding Island 1, accidentally marking both islands with `2`.
