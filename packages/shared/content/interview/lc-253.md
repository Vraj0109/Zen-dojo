## Clarify first

- What does each interval represent? (`[start, end]` represents a meeting where $start < end$).
- Are interval endpoints inclusive or exclusive? (Standard interview convention: a meeting ending at time $t$ frees the room so another meeting can start at time $t$ without overlap).
- Can the input list be empty? (Constraints state $1 \le intervals.length \le 10^4$).
- Can intervals arrive out of order? (Yes, the input is unsorted).
- What is the range of times? ($0 \le start_i < end_i \le 10^6$).

## Examples to say out loud

- Adjacent non-overlapping meetings: `[[1, 5], [5, 10]]`. First meeting finishes at 5, second meeting begins at 5. Since meeting 1 frees the room at 5, meeting 2 can reuse it; requires only 1 room.
- Completely nested overlapping meetings: `[[1, 10], [2, 9], [3, 8], [4, 7]]`. At time 4, all 4 meetings are ongoing simultaneously; requires 4 rooms.
- Staggered meetings: `[[0, 30], [5, 10], [15, 20]]`. `[0, 30]` occupies room 1. At 5, `[5, 10]` takes room 2. At 10, room 2 is freed. At 15, `[15, 20]` reuses room 2. Max simultaneous meetings is 2.

## Brute force

A naive approach checks every possible time unit $t$ across all intervals and counts how many meetings are active at time $t$, returning the maximum count. Since times range up to $10^6$, this takes $O(T \cdot n)$ time. Alternatively, comparing every interval against all other intervals to find maximal cliques takes $O(n^2)$, which is too slow for $n = 10^4$.

## The key observation

The minimum number of conference rooms needed equals the maximum number of concurrent meetings at any single point in time. Each meeting start is an event that increments the active room count by 1, and each meeting end is an event that decrements the active room count by 1. We do not need to track which specific meeting occupies which room; we only need to track timestamps. By separating and sorting start times and end times independently, a two-pointer scan simulates chronological time progression.

## Optimal approach

1. Extract all start times into an array `starts` and all end times into an array `ends`.
2. Sort `starts` and `ends` in ascending order.
3. Initialize `rooms = 0` and pointer `endIdx = 0`.
4. Iterate `i` through each `start` time in `starts`:
   - If `starts[i] < ends[endIdx]`: a new meeting begins before the earliest ongoing meeting has concluded. We must allocate an additional room (`rooms++`).
   - Otherwise (`starts[i] >= ends[endIdx]`): the earliest meeting has ended and its room can be repurposed. Advance `endIdx++` without incrementing `rooms`.
5. Return `rooms`.

Complexity:
- Time: `O(n log n)` to sort the `starts` and `ends` arrays of length $n$, followed by a linear $O(n)$ two-pointer scan.
- Space: `O(n)` auxiliary space to store the two arrays of size $n$.

## Code walkthrough

In the reference implementation:
- `starts[i] = intervals[i][0]; ends[i] = intervals[i][1];`: disassociates starts from ends since identity does not matter for room capacity counting.
- `sort(starts.begin(), starts.end()); sort(ends.begin(), ends.end());`: creates sorted timelines of room demands and releases.
- `if (starts[i] < ends[endIdx]) rooms++;`: handles room demand spike.
- `else endIdx++;`: pairs the incoming start with a released room without increasing total room allocation.

## Test it out loud

- Single meeting: `[[1, 100]]`. `starts = [1], ends = [100]`. `1 < 100` triggers `rooms = 1`. Returns 1.
- Consecutive non-overlapping: `[[1, 2], [3, 4], [5, 6]]`. `starts = [1, 3, 5], ends = [2, 4, 6]`.
  - `i=0`: `1 < 2` -> `rooms = 1`.
  - `i=1`: `3 >= 2` -> `endIdx = 1`.
  - `i=2`: `5 >= 4` -> `endIdx = 2`.
  - Final `rooms = 1`.
- Back-to-back: `[[1, 5], [5, 10]]`. `starts = [1, 5], ends = [5, 10]`. At `i=1`, `5 >= 5` triggers reuse, returning 1.

## Follow-ups

- What if we need to return which room each meeting is assigned to?
  Sort intervals by start time and use a min-heap storing pairs `(end_time, room_id)`. When an interval starts, pop the heap if `top.end_time <= start`, reuse its `room_id`, and push the new end time.
- How does the min-heap approach compare to the two-pointer approach?
  Min-heap also takes $O(n \log n)$ time and $O(n)$ space. Two pointers has lower constant factor overhead because it uses contiguous vector sorting instead of repeated heap rebalancing.
- Can we solve it using difference array / line sweep?
  Yes, map events to `+1` (start) and `-1` (end), sorting events by timestamp with ends processed before starts when times tie.

## Common mistakes

- Treating `start == end` as an overlap: meeting ending at 5 frees the room for a meeting starting at 5 (`start < end` condition is strictly less).
- Trying to sort intervals by end time or start time without a min-heap, which loses track of multiple parallel room availability.
- Over-allocating memory by using a bucket array of size $10^6$ when $n$ is only $10^4$.
