## Clarify first
- Are all node values distinct? Yes, all node values in the binary tree are unique.
- Are `p` and `q` guaranteed to exist in the tree? Yes, `p != q` and both are guaranteed to be present.
- Can a node be considered a descendant of itself? Yes, if `p` is an ancestor of `q`, then `p` is their lowest common ancestor.
- How large can the tree be? Up to 100,000 nodes, with values between -10^9 and 10^9.

## Examples to say out loud
- Standard split: Tree with root 3, left child 5, right child 1. Target nodes `p = 5`, `q = 1`.
  - Node 5 is in the left subtree and node 1 is in the right subtree. The lowest common ancestor is 3.
- One node is ancestor of the other: Root 3, left subtree contains 5, which in turn has child 4. `p = 5`, `q = 4`.
  - Node 5 is the ancestor of 4, so the lowest common ancestor is 5.
- Minimal tree: Root 1 with child 2. `p = 1, q = 2`. The LCA is 1.

## Brute force
A brute force approach finds the path from the root to `p` using DFS and records the sequence of nodes in a list `pathP`. Similarly, it finds the path from the root to `q` and records `pathQ`. It then iterates through both paths simultaneously from the root until the paths diverge; the last matching node is the LCA. This takes O(n) time and O(h) space to store both path vectors. We can find the LCA directly in a single bottom-up post-order DFS traversal without explicitly storing path vectors.

## The key observation
In a bottom-up traversal:
- If a subtree contains neither `p` nor `q`, the search in that subtree returns null.
- If a subtree contains either `p` or `q`, it returns a pointer to that found node.
- At any given node, if both the left recursive call and right recursive call return non-null pointers, `p` and `q` are located in different subtrees of this node. Hence, this node is their lowest common ancestor.
- If only one child call returns non-null, both targets (or the single target found so far) reside in that child's subtree, so we propagate that non-null result upward.

## Optimal approach
1. Define a recursive helper `go(node, p, q)`:
   - If `node` is null, return null.
   - If `node->val == p` or `node->val == q`, return `node` immediately.
   - Recurse on left child: `left = go(node->left, p, q)`.
   - Recurse on right child: `right = go(node->right, p, q)`.
   - If both `left` and `right` are non-null: `node` is the split point; return `node`.
   - Otherwise, return `left` if `left` is non-null, else return `right`.
2. The root call returns the LCA node. Return its value.

Complexity:
- Time complexity: O(n) where n is the number of nodes, as each node is visited at most once in the DFS traversal.
- Space complexity: O(h) where h is the tree height, corresponding to the recursion call stack (O(log n) for a balanced tree, O(n) worst-case for a skewed tree).

## Code walkthrough
- `if (!node) return nullptr`: Base case for reaching empty leaves.
- `if (node->val == p || node->val == q) return node`: Base case identifying either target. If one target is a parent of the other, returning early correctly bubbling this parent upward.
- `TreeNode* l = go(node->left, p, q)` and `TreeNode* r = go(node->right, p, q)`: Searches both subtrees.
- `if (l && r) return node`: Identifies the divergence point where targets are in separate branches.
- `return l ? l : r`: Passes the found target upward when targets are located on one side.

## Test it out loud
- Test tree `[1, 2, 3]` with `p = 2, q = 3`:
  - At root 1: calls `go(2)` which returns node 2 immediately.
  - Calls `go(3)` which returns node 3 immediately.
  - Both `l` and `r` are non-null at root 1; returns node 1. Value is 1. Correct.
- Test tree `[1, 2]` with `p = 1, q = 2`:
  - Root 1 matches `p = 1` immediately and returns node 1 without checking children.
  - Node 1 is returned as LCA. Correct because 1 is ancestor of 2.

## Follow-ups
- What if `p` or `q` might not exist in the tree? The current code could return `p` even if `q` is absent. To handle potential missing nodes, we must either check that both nodes exist initially or return a counter/struct indicating how many target nodes were found.
- How would you solve this if nodes had parent pointers? Trace ancestors of `p` into a hash set, then walk up from `q` until encountering an ancestor already in the set.

## Common mistakes
- Not handling the case where `p` is an ancestor of `q`, attempting to search below `p` when returning `p` directly already yields the correct answer.
- Assuming the tree is a Binary Search Tree (BST) and trying to compare keys against root values to choose a single branch.
