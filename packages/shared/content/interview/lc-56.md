## Clarify first

- Do intervals that merely touch at a single point count as overlapping? Yes, `[1, 4]` and `[4, 5]` overlap and must be merged into `[1, 5]`.
- Are the input intervals guaranteed to be sorted initially? No, the input can arrive in arbitrary order.
- In what order should the output intervals be returned? The output must be sorted by their start time.
- What are the constraints on the input size? Array length is between 1 and 10,000, with coordinates between 0 and 10,000.

## Examples to say out loud

- Classic overlapping chain: `intervals = [[1, 3], [2, 6], [8, 10], [15, 18]]`.
  - Intervals `[1, 3]` and `[2, 6]` overlap because `2 <= 3`. They merge into `[1, max(3, 6)] = [1, 6]`.
  - Interval `[8, 10]` does not overlap with `[1, 6]` (`8 > 6`), so it starts a new block.
  - Interval `[15, 18]` does not overlap with `[8, 10]`, starting another block.
  - Result: `[[1, 6], [8, 10], [15, 18]]`.
- Completely contained interval: `intervals = [[1, 4], [2, 3]]`. `[2, 3]` is fully absorbed into `[1, 4]`, yielding `[[1, 4]]`.
- Touching boundaries: `intervals = [[1, 4], [4, 5]]`. Touching at 4 results in `[[1, 5]]`.

## Brute force

A brute-force solution maintains a set of intervals and repeatedly scans all pairs `(A, B)` to check if they overlap. If an overlap is found, it removes `A` and `B` and replaces them with their union `[min(A.start, B.start), max(A.end, B.end)]`. This pairwise scanning continues until no overlapping pair exists. In the worst case, this requires `O(n^2)` time and is complicated to implement correctly without order.

## The key observation

If we sort intervals by their start coordinates, any interval can only overlap with the immediately preceding interval in our merged sequence. Once the next interval starts strictly after the current merged interval ends, the current interval is complete and will never overlap with any subsequent intervals.

## Optimal approach

1. Sort the list of intervals ascending by their start values `intervals[i][0]`.
2. Initialize an empty list of merged intervals `out`.
3. Iterate through each interval `iv` in the sorted array:
   a. If `out` is not empty and `iv[0] <= out.back()[1]` (current interval starts before or at the end of the last merged interval):
      - Extend the last interval's end: `out.back()[1] = max(out.back()[1], iv[1])`.
   b. Otherwise:
      - Append `iv` as a new interval in `out`.
4. Return `out`.

Complexity:
- Time: `O(n log n)` due to sorting the `n` intervals, followed by an `O(n)` single-pass linear merge.
- Space: `O(n)` memory to store the sorted array and output results.

## Code walkthrough

In the reference implementation:
- `sort(intervals.begin(), intervals.end());`: sorts intervals primarily by `start`, secondarily by `end`.
- `vector<vector<int>> out;`: collects the disjoint consolidated intervals.
- `if (!out.empty() && iv[0] <= out.back()[1])`: detects an overlap between the active interval and the latest merged range.
- `out.back()[1] = max(out.back()[1], iv[1]);`: merges by expanding the upper bound (protecting against shorter swallowed intervals).
- `else out.push_back(iv);`: creates a new non-overlapping range.

## Test it out loud

- `intervals = [[1, 4], [0, 4]]`:
  - After sorting: `[[0, 4], [1, 4]]`.
  - Add `[0, 4]` to `out`.
  - Next `[1, 4]`: `1 <= 4`, merge by taking `max(4, 4) = 4`. Output: `[[0, 4]]`.
- `intervals = [[1, 4], [2, 3]]`:
  - Sorted: `[[1, 4], [2, 3]]`.
  - Add `[1, 4]`.
  - Next `[2, 3]`: `2 <= 4`, merge with `max(4, 3) = 4`. Output: `[[1, 4]]`.
- `intervals = [[1, 2], [3, 4]]`:
  - Sorted: `[[1, 2], [3, 4]]`.
  - Add `[1, 2]`. Next is `[3, 4]`: `3 > 2`, no overlap. Add `[3, 4]`. Output: `[[1, 2], [3, 4]]`.

## Follow-ups

- How would you handle inserting a new interval into an already sorted list of non-overlapping intervals (Insert Interval, LeetCode 57)?
  We can do it in `O(n)` time without full sorting by appending intervals before the insertion point, merging overlapping intervals with the new interval, and appending remaining intervals.
- How would you find the total length of covered points?
  After merging into disjoint intervals, sum `iv[1] - iv[0]` across all intervals in `out`.

## Common mistakes

- Merging without taking `max(out.back()[1], iv[1])`, which mistakenly shrinks a longer interval if a shorter swallowed interval comes next (e.g. `[1, 10]` followed by `[2, 3]`).
- Forgetting to sort intervals before processing.
- Missing the boundary condition where `start == previous_end`, incorrectly treating adjacent touching intervals as non-overlapping.
