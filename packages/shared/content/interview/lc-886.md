## Clarify first
- How are people and dislikes defined? `n` people numbered 1 to n, and pairs `[a, b]` meaning person `a` and person `b` cannot be in the same group.
- Can either group be empty? Yes, either group can be empty (e.g., if there are no dislikes).
- What should be returned? Return true if people can be partitioned into two mutually non-conflicting groups, false otherwise.
- Can dislikes form multiple disconnected components? Yes, the conflict graph may have multiple disconnected components.

## Examples to say out loud
- Successful split: `n = 4, dislikes = [[1, 2], [1, 3], [2, 4]]`.
  - Person 1 dislikes 2 and 3: place 1 in Group Red, place 2 and 3 in Group Blue.
  - Person 2 dislikes 4: since 2 is Blue, place 4 in Group Red.
  - Groups `{1, 4}` (Red) and `{2, 3}` (Blue) satisfy all constraints. Output: true.
- Conflict / Odd cycle: `n = 3, dislikes = [[1, 2], [1, 3], [2, 3]]`.
  - Mutually disliking triangle. At least two people must end up in the same group. Output: false.

## Brute force
A brute force approach tests all `2^n` possible binary group assignments for the n individuals. For each assignment, it verifies whether any pair `[a, b]` in `dislikes` shares the same group. For `n = 2000`, `2^2000` is impossible. We can frame this as a 2-coloring problem on an undirected graph and solve it in O(n + E) time.

## The key observation
Model the dislike pairs as edges in an undirected graph where people are vertices.
Dividing people into two groups such that no two adjacent vertices share a group is the definition of graph 2-coloring (testing if the graph is bipartite).
If the graph contains an odd cycle of dislikes, it is impossible to partition into two groups; otherwise, a valid bipartition always exists. We can traverse and color each connected component using BFS or DFS.

## Optimal approach
1. Build an adjacency list `g` of size `n + 1`. For each dislike `[u, v]`, add undirected edges: `g[u].push_back(v)` and `g[v].push_back(u)`.
2. Initialize an array `color` of size `n + 1` filled with -1 (unvisited).
3. Loop through each person `s` from 1 to `n`:
   - If `color[s] != -1`: already colored; continue.
   - Set `color[s] = 0` and enqueue `s` into a BFS queue `q`.
   - While `q` is not empty:
     - Dequeue `u`.
     - For each neighbor `v` in `g[u]`:
       - If `color[v] == -1`: assign `color[v] = color[u] ^ 1` and push `v` into `q`.
       - Else if `color[v] == color[u]`: conflict found; return false.
4. If all components are validly 2-colored, return true.

Complexity:
- Time complexity: O(n + E) where n is the number of people and E is the number of dislike pairs. Each person and dislike edge is processed a constant number of times.
- Space complexity: O(n + E) auxiliary space for the adjacency list graph, color array, and BFS queue.

## Code walkthrough
- `vector<vector<int>> g(n + 1)`: Builds undirected graph representation for 1-indexed vertices.
- `vector<int> color(n + 1, -1)`: Stores group assignments (0 for Group A, 1 for Group B).
- `for (int s = 1; s <= n; s++)`: Iterates through all vertices to cover disconnected social circles.
- `color[v] = color[u] ^ 1`: Alternates group assignment across the conflict edge.
- `if (color[v] == color[u]) return false`: Triggers immediate failure on finding two conflicting people assigned to the same group.

## Test it out loud
- Test `n = 1, dislikes = []`:
  - Person 1 has no dislikes; loop completes and returns true. Correct.
- Test `n = 2, dislikes = [[1, 2]]`:
  - Person 1 colored 0; Person 2 colored 1. No conflicts; returns true. Correct.
- Test 5-person odd cycle `[[1,2],[2,3],[3,4],[4,5],[1,5]]`:
  - 1 -> 0, 2 -> 1, 3 -> 0, 4 -> 1, 5 -> 0.
  - When inspecting edge `[1, 5]`: `color[1] == color[5] == 0`. Conflict detected; returns false. Correct.

## Follow-ups
- Can this be solved using Disjoint Set Union (DSU)? Yes, using virtual nodes or union-find with parity: for each edge `(u, v)`, unite `u` with `v + n` and `v` with `u + n`. If `find(u) == find(v)`, a conflict exists.
- How would you reconstruct the actual two group rosters? After coloring completes successfully, collect all nodes with `color[i] == 0` into Group 1 and all with `color[i] == 1` into Group 2.

## Common mistakes
- Forgetting that vertex indices are 1-based, leading to array indexing errors if allocating size `n` instead of `n + 1`.
- Not iterating across all vertices from 1 to `n`, missing disconnected components.
- Adding directed edges instead of undirected edges for mutual dislikes.
