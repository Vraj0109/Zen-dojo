## Clarify first

- Is the input array already sorted? Yes, `nums` is sorted in non-decreasing order.
- Should we do this in-place without allocating a second full array? Yes, in-place deduplication is expected, using constant extra memory.
- What should be the state of the array after the operation? The unique elements must appear in the prefix of the array in their original sorted order.
- What if the array has length 0 or 1? An array of length 0 or 1 already has no duplicate pairs, so it remains unchanged.

## Examples to say out loud

- Array with consecutive duplicates: `nums = [1, 1, 2]`.
  - First unique element is 1 (index 0).
  - Next element 1 is a duplicate (skip).
  - Next element 2 is distinct (write to index 1).
  - Prefix with distinct elements: `[1, 2]`.
- Multiple duplicates: `nums = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]`.
  - Prefix becomes `[0, 1, 2, 3, 4]`.
  - 5 unique elements.
- Single element: `nums = [5]`. Returns `[5]`.

## Brute force

A brute-force solution iterates through `nums` and pushes every unseen element into a hash set or a new dynamic array. While this takes `O(n)` time, allocating extra data structures requires `O(n)` auxiliary memory, which ignores the vital invariant that `nums` is **already sorted**. In a low-level systems or coding interview, modifying the array in-place is the expected solution.

## The key observation

Because the array is sorted, all identical elements are clustered consecutively. We can use a two-pointer approach: a fast reader pointer `x` scanning through every element of `nums`, and a slow writer pointer `w` pointing to the next available position for a unique value. A value `x` is unique if either `w == 0` (the first element is always kept) or `nums[w - 1] != x` (the current value differs from the most recently kept unique value).

## Optimal approach

1. Initialize a write pointer `w = 0`.
2. Iterate through each value `x` in `nums`:
   - If `w == 0` or `nums[w - 1] != x`:
     - Assign `nums[w] = x`.
     - Advance `w++`.
3. Resize or slice the array to length `w` (or return `w` depending on interface requirements).
4. Return `nums`.

Complexity:
- Time: `O(n)` because we iterate through the array of length `n` in a single pass, performing at most one assignment per element.
- Space: `O(1)` auxiliary space as all modifications happen in-place within the array.

## Code walkthrough

In the reference implementation:
- `int w = 0;`: tracks the boundary of the unique prefix.
- `for (int x : nums)`: reads every element sequentially.
- `if (w == 0 || nums[w - 1] != x)`: checks whether `x` is the very first element or introduces a new distinct value.
- `nums[w++] = x;`: writes the unique value into the compact prefix and increments the writer.
- `nums.resize(w);`: trims excess elements beyond the unique prefix.
- `return nums;`: returns the deduplicated array.

## Test it out loud

- `nums = [1, 1, 2]`:
  - `x = 1`: `w == 0` -> `nums[0] = 1`, `w = 1`.
  - `x = 1`: `nums[w - 1] == 1 == x` (duplicate, ignored).
  - `x = 2`: `nums[w - 1] == 1 != 2` -> `nums[1] = 2`, `w = 2`.
  - Resize to `w = 2`. Result: `[1, 2]`.
- `nums = [1, 1, 1, 1]`:
  - First element kept: `nums[0] = 1, w = 1`. All subsequent 1s ignored.
  - Result: `[1]`.
- `nums = [-3, -3, -2, 0, 0, 7]`:
  - Distinct sequence: `-3, -2, 0, 7`. Returns `[-3, -2, 0, 7]`.

## Follow-ups

- What if duplicates are allowed at most twice (LeetCode 80: Remove Duplicates from Sorted Array II)?
  Compare against `w - 2`: write `x` if `w < 2 || nums[w - 2] != x`.
- What if the array is unsorted?
  In-place deduplication on an unsorted array requires sorting first in `O(n log n)` time or using `O(n)` extra space with a hash set.

## Common mistakes

- Comparing `nums[i]` with `nums[i + 1]` instead of comparing with the last written value `nums[w - 1]`, which can cause out-of-bounds errors on the final element.
- Using an auxiliary hash set when the array is already sorted, wasting `O(n)` memory.
- Forgetting that the first element must always be kept (`w == 0`).
