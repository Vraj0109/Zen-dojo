## Clarify first
- Can candidates contain duplicate numbers? Yes, the candidate list can contain duplicates.
- How many times can each number in the list be used? Each element in the candidate array may be used at most once per combination.
- Can combinations be returned in any order? Yes, any order of combinations is accepted.
- What if target cannot be formed? Return an empty list `[]`.

## Examples to say out loud
- Consider `candidates = [10, 1, 2, 7, 6, 1, 5]`, `target = 8`:
  - Sorted: `[1, 1, 2, 5, 6, 7, 10]`.
  - Combinations adding to 8:
    - `1 + 1 + 6 = 8`
    - `1 + 2 + 5 = 8`
    - `1 + 7 = 8`
    - `2 + 6 = 8`
  - Output: `[[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]`.
  - Notice duplicate `1` from different starting branches does not produce duplicate `[1, 7]`.

## Brute force
A brute force approach enumerates all `2^n` subsets of candidates, sums the elements of each subset, filters those that equal `target`, sorts each matching combination, and removes duplicate lists using a hash set. With n up to 100, `2^100` subsets cannot be exhaustively generated. We can prune the search space heavily by sorting the array and pruning branches where candidate values exceed the remaining target sum.

## The key observation
Sorting candidates upfront provides two major optimizations:
1. Pruning by value: If `candidates[i] > remaining_target`, then because the array is sorted, all subsequent candidates `candidates[j]` (`j >= i`) will also exceed `remaining_target`. We can immediately `break` out of the loop at this level.
2. Duplicate elimination: If `candidates[i] == candidates[i - 1]` and `i > start`, this candidate has already been explored as the first choice at the current combination slot. Skipping it with `continue` prevents duplicate combinations from being generated.

## Optimal approach
1. Sort `candidates` in non-decreasing order.
2. Define a recursive backtracking function `go(start, rem)`:
   - If `rem == 0`: we have found a valid combination; add a copy of `cur` to `out` and return.
   - For `i` from `start` to `candidates.size() - 1`:
     - If `candidates[i] > rem`: break immediately (further numbers are even larger).
     - If `i > start` and `candidates[i] == candidates[i - 1]`: continue (skip duplicate choice at this level).
     - Add `candidates[i]` to `cur`.
     - Recurse: `go(i + 1, rem - candidates[i])` (advance index to `i + 1` since each number is used at most once).
     - Backtrack: remove `candidates[i]` from `cur`.
3. Call `go(0, target)` and return `out`.

Complexity:
- Time complexity: Exponential in the worst case, O(2^n) combinations to explore; pruning keeps typical inputs small.
- Space complexity: O(target) recursion stack depth and current combination storage (bounded by the maximum number of candidates that can sum to target).

## Code walkthrough
- `sort(candidates.begin(), candidates.end())`: Facilitates early loop termination and duplicate sibling pruning.
- `if (rem == 0) { out.push_back(cur); return; }`: Base case triggered when running sum reaches exact target.
- `if (a[i] > rem) break`: Prunes search tree completely for all remaining candidates in the loop.
- `if (i > start && a[i] == a[i - 1]) continue`: Skips repeated values at the same decision level.
- `go(a, i + 1, rem - a[i], cur, out)`: Advances to `i + 1` ensuring each element is used at most once.

## Test it out loud
- Test `candidates = [2, 2, 2], target = 4`:
  - Starts with first 2, needs 2. Next picks second 2, needs 0. Found `[2, 2]`.
  - At level 1, third 2 has `i = 2 > start (1)` and `a[2] == a[1]`: skipped.
  - At level 0, second 2 and third 2 skipped (`i > 0 && a[i] == a[i-1]`).
  - Output: `[[2, 2]]`. Correct.
- Test `candidates = [1], target = 2`:
  - `a[0] = 1 < 2`, picks 1, needs 1. Next start is 1, loop finishes. Returns `[]`. Correct.

## Follow-ups
- How does Combination Sum II differ from Combination Sum I? In Combination Sum I, elements are distinct and can be reused unlimited times (recurse with `i` instead of `i + 1`). In Combination Sum II, elements have duplicates and can only be used once (recurse with `i + 1` and skip duplicates with `i > start && a[i] == a[i - 1]`).
- Could we solve this with 0/1 Knapsack DP? If we only needed the count or feasibility of reaching target, DP would take O(n * target). When enumerating all concrete combination paths, backtracking is optimal.

## Common mistakes
- Using `continue` instead of `break` when `candidates[i] > rem`, missing the opportunity to prune all subsequent larger candidates.
- Recursing with `go(i, ...)` instead of `go(i + 1, ...)`, accidentally allowing the same candidate to be reused multiple times.
- Using `i > 0` instead of `i > start` for duplicate elimination, which blocks picking multiple copies of the same value across different positions.
