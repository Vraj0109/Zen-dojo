## Clarify first
- What does the problem ask for? The minimum number of edges in a walk that visits every vertex in the connected undirected graph at least once.
- Can we start and end at any vertex? Yes, you can choose any starting vertex and terminate at any vertex.
- Can edges and vertices be visited multiple times? Yes, revisiting vertices and traversing edges repeatedly is explicitly permitted.
- How large is n? Very small: `1 <= n <= 12`.

## Examples to say out loud
- Star graph with 4 nodes: `[[1,2,3],[0],[0],[0]]`.
  - Node 0 is connected to 1, 2, and 3.
  - A shortest walk visiting all nodes: `1 -> 0 -> 2 -> 0 -> 3`.
  - Total edges traversed: 4. Output: 4.
- Single node `[[[]]]`: 0 edges needed to visit all nodes. Output: 0.
- Triangle `[[1,2],[0,2],[0,1]]`:
  - Path `0 -> 1 -> 2` visits all 3 nodes using 2 edges. Output: 2.

## Brute force
A brute force approach enumerates permutations of all n nodes to decide an ordering in which they are first visited, then runs all-pairs shortest paths between consecutive nodes in the permutation. With `n = 12`, `12! = 4.79 * 10^8` permutations is too slow to evaluate all combinations. Because `n <= 12`, the set of visited nodes can be represented compactly as a 12-bit integer bitmask.

## The key observation
A state in this graph walk is completely characterized by a pair:
`(u, mask)`
where:
- `u` is the current vertex (`0 <= u < n`).
- `mask` is a bitmask of length n where the `i`-th bit is 1 if vertex `i` has been visited at least once on this walk, and 0 otherwise.
Total number of states is `n * 2^n`. For `n = 12`, `12 * 4096 = 49,152` states.
Because each step across an edge adds 1 to the walk length, finding the shortest walk visiting all nodes is an unweighted shortest path problem on this state graph.
By seeding a multi-source BFS with all possible starting nodes `(i, 1 << i)` at distance 0, the first time any state with a full bitmask `(1 << n) - 1` is popped, its distance is guaranteed to be the minimum walk length.

## Optimal approach
1. Let `full = (1 << n) - 1`.
2. Initialize a 2D distance array `dist` of dimensions `n x (1 << n)` filled with -1.
3. Initialize a queue `q` holding pairs `{node, mask}`.
4. For each node `i` from 0 to `n - 1`:
   - Set `dist[i][1 << i] = 0`.
   - Push `{i, 1 << i}` into `q`.
5. While `q` is not empty:
   - Pop `{u, mask}`.
   - If `mask == full`, return `dist[u][mask]`.
   - For each neighbor `v` in `graph[u]`:
     - Compute new mask: `nm = mask | (1 << v)`.
     - If `dist[v][nm] == -1`:
       - `dist[v][nm] = dist[u][mask] + 1`.
       - Push `{v, nm}` into `q`.
6. Return 0.

Complexity:
- Time complexity: O(2^n * n * deg) where `deg` is average vertex degree. There are `n * 2^n` states, and each state transitions along at most n edges, taking roughly `12 * 4096 * 12` operations.
- Space complexity: O(2^n * n) auxiliary space for the `dist` array and the BFS queue.

## Code walkthrough
- `int full = (1 << n) - 1`: Target bitmask where all n bits are set to 1.
- Multi-source initialization: Enqueues `{i, 1 << i}` for all `i`, allowing the search to start from the globally optimal starting node.
- `if (mask == full) return dist[u][mask]`: Earliest arrival at full coverage guarantees minimum edges traversed.
- `int nm = mask | (1 << v)`: Transitions to neighbor `v` and marks `v` as visited in the bitmask.
- `if (dist[v][nm] == -1)`: Standard BFS visited check on state pair `(node, mask)`.

## Test it out loud
- Test single node `[[]]`:
  - `n = 1, full = 1`.
  - Queue starts with `{0, 1}` at `dist = 0`.
  - Popped `{0, 1}`, `mask == full` immediately. Returns 0. Correct.
- Test 2 connected nodes `[[1], [0]]`:
  - Enqueue `{0, 1}` and `{1, 2}`.
  - From `{0, 1}`, neighbor 1 produces `{1, 3}` at `dist = 1`.
  - `{1, 3}` has `mask == 3 == full`. Returns 1. Correct.

## Follow-ups
- Can this be solved using Dynamic Programming without a queue? Yes, Floyd-Warshall precalculates all-pairs shortest paths, followed by TSP (Traveling Salesperson Problem) bitmask DP `dp(mask, u)`. However, multi-source BFS avoids precomputing all pairs and solves it in a single pass.
- Why is multi-source BFS valid here? Because every edge has equal weight 1 and starting at any node incurs 0 initial cost.

## Common mistakes
- Tracking only `visited[u]` instead of `visited[u][mask]`, preventing nodes from being revisited as part of valid walks.
- Running separate BFS searches for each starting node instead of multi-source BFS, repeating work across states.
- Off-by-one bitshift errors with `1 << n`.
