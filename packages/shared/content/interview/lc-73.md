## Clarify first
- When a cell is 0, does setting its row and column to 0 cause subsequent rows or columns to turn zero as well? No, only the original zeros dictate which rows and columns must be cleared.
- Can values in the matrix be negative, zero, or positive? Yes, values range across standard 32-bit signed integers.
- Can we return a new matrix or modify in place? The transformation should modify the matrix in place.
- What are the dimensions? Rows and columns are between 1 and 200.

## Examples to say out loud
- Standard case:
  ```
  [1, 1, 1]
  [1, 0, 1]
  [1, 1, 1]
  ```
  Zero is at (1, 1). Row 1 and column 1 become 0. Output:
  ```
  [1, 0, 1]
  [0, 0, 0]
  [1, 0, 1]
  ```
- Boundary case: A 1x1 matrix `[[5]]` remains `[[5]]`, while `[[0]]` remains `[[0]]`.
- Multiple zeros in different rows/columns:
  ```
  [0, 1, 2, 0]
  [3, 4, 5, 2]
  [1, 3, 1, 5]
  ```
  Zeros at (0, 0) and (0, 3). Row 0, column 0, and column 3 all zero out.

## Brute force
A naive approach creates a full copy of the matrix of size `r x c`. For every zero found in the original matrix, it iterates across the entire corresponding row and column in the copy and sets cells to zero. This takes O(r * c * (r + c)) time and O(r * c) space. We can optimize by recording which rows and columns require zeroing during a single scan.

## The key observation
A cell `(i, j)` should become 0 if and only if row `i` originally contained at least one 0, or column `j` originally contained at least one 0. We do not need to keep track of every individual zero coordinate; tracking boolean flags for whether row `i` contains a zero and whether column `j` contains a zero is sufficient.

## Optimal approach
1. Allocate two boolean arrays: `row` of size `r` initialized to false, and `col` of size `c` initialized to false.
2. First pass: iterate over every cell `(i, j)` in the matrix. If `matrix[i][j] == 0`, set `row[i] = true` and `col[j] = true`.
3. Second pass: iterate over every cell `(i, j)`. If either `row[i]` or `col[j]` is true, assign `matrix[i][j] = 0`.
4. Return the updated matrix.

Complexity:
- Time complexity: O(r * c) since each cell is inspected once in the first pass and updated once in the second pass.
- Space complexity: O(r + c) auxiliary space for the two boolean tracking arrays.

## Code walkthrough
- `vector<bool> row(r, false), col(c, false)`: Tracks which rows and columns need zeroing.
- First nested loop: Scans `a[i][j] == 0` and records flags `row[i] = col[j] = true`.
- Second nested loop: If `row[i] || col[j]` evaluates to true, overwrites `a[i][j] = 0`.
- Returns the modified matrix `a`.

## Test it out loud
- Test `[[1, 1, 1], [1, 0, 1], [1, 1, 1]]`:
  - `row = [false, true, false]`, `col = [false, true, false]`.
  - Cells at `i = 1` or `j = 1` are set to 0. Correct.
- Test `[[0, 0], [0, 0]]`:
  - `row = [true, true]`, `col = [true, true]`.
  - All cells remain 0. Correct.

## Follow-ups
- How can we reduce auxiliary space to O(1)? Use the first row and first column of the matrix itself as the marker arrays, with two boolean variables tracking whether row 0 and column 0 originally contained zeros before overwriting them.
- In what order should we update the matrix in the O(1) space variant? Update the inner matrix from bottom-up or right-to-left first, then finally update the first row and first column based on their dedicated boolean flags.

## Common mistakes
- Mutating cells to 0 immediately while still scanning, which introduces cascade zeros across the rest of the matrix.
- In the O(1) space optimization, updating the first row or first column before scanning the rest of the inner matrix.
