## Clarify first
- Can the exponent `n` be negative? Yes, negative exponents mean `1 / (x^(-n))`.
- Can `x` be 0 when `n <= 0`? The constraints guarantee either `x != 0` or `n > 0`, avoiding division by zero.
- How large can `n` be? `-2^31 <= n <= 2^31 - 1`. Note that `-(-2^31)` overflows a standard 32-bit signed integer.
- What precision is expected? Standard double precision floating-point arithmetic.

## Examples to say out loud
- Consider `x = 2.0, n = 10`:
  - `10` in binary is `1010_2`.
  - `2^10 = (2^2) * (2^8) = 4 * 256 = 1024`.
- Consider `x = 2.0, n = -2`:
  - Compute positive power `2^2 = 4.0`.
  - Invert due to negative exponent: `1.0 / 4.0 = 0.25`.
- Consider `x = 5.0, n = 0`:
  - Any number to power 0 equals `1.0`.

## Brute force
Multiplying `x` by itself `|n|` times in a linear loop takes `O(|n|)` time. For `n = 2^31 - 1 ≈ 2 * 10^9`, this will result in Time Limit Exceeded. We need binary exponentiation.

## The key observation
We can compute powers using repeated squaring:
- If `n` is even: `x^n = (x^2)^(n / 2)`.
- If `n` is odd: `x^n = x * (x^2)^((n - 1) / 2)`.
Each iteration halves the exponent, reducing the problem to `O(log |n|)` multiplications. Using a 64-bit integer avoids 32-bit integer overflow when negating `-2^31`.

## Optimal approach
1. Store `n` into a 64-bit integer `e`.
2. Check if `e < 0`. If negative, record `neg = true` and set `e = -e`.
3. Initialize `result = 1.0` and `base = x`.
4. While `e > 0`:
   - If the lowest bit of `e` is 1 (`e & 1`), multiply `result *= base`.
   - Square the base: `base *= base`.
   - Shift `e` right by 1: `e >>= 1`.
5. If `neg` is true, return `1.0 / result`; otherwise return `result`.

Complexity:
- Time: `O(log |n|)` time because `e` is halved in each iteration (at most 32 iterations).
- Space: `O(1)` auxiliary space.

## Code walkthrough
- `long long e = n;` safely widens the 32-bit signed integer to 64 bits.
- `if (neg) e = -e;` cleanly handles `n = -2147483648` without negative overflow.
- `while (e > 0)` runs repeated squaring:
  - `if (e & 1) result *= base;` incorporates the current power of two if present in the binary representation of `e`.
  - `base *= base;` squares the base for the next higher bit.
  - `e >>= 1;` moves to the next binary digit.
- `return neg ? 1.0 / result : result;` applies reciprocation if the original exponent was negative.

## Test it out loud
- Test `x = 5.0, n = 0`: While loop doesn't execute; returns `1.0`.
- Test `x = 0.0, n = 5`: `result` is initially 1, multiplies by 0, remains 0.
- Test `x = -1.0, n = 2147483647`: Exponent is odd, returns `-1.0`.
- Test `x = -1.0, n = -2147483648`: Widens to `long long`, negates safely to `+2147483648`, exponent is even, returns `1.0`.
- Test `x = 2.1, n = 3`: Multiplies `2.1 * 4.41 = 9.261`. Correct.

## Follow-ups
- How does modular exponentiation differ from this?
  - Every multiplication operation is taken modulo `M`.
- Can this approach be extended to matrix multiplication?
  - Yes, matrix exponentiation uses the identical algorithm to find `M^n` in `O(d^3 log n)` time.

## Common mistakes
- Attempting `-n` on a 32-bit signed integer when `n = -2^31`, causing undefined behavior or integer overflow.
- Using recursive formulation without memoization or tail recursion, which uses `O(log n)` call stack frames instead of `O(1)` iterative space.
