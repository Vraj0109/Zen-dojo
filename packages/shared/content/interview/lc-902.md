## Clarify first
- What digits can be used? An array of sorted distinct digit strings from `"1"` to `"9"` (the digit '0' is not in `digits`).
- Can digits be used multiple times? Yes, each digit can be used as many times as desired.
- What are we counting? All positive integers formed using only the given digits that are less than or equal to `n`.
- How large can n be? Up to 1,000,000,000 (up to 10 digits in length).

## Examples to say out loud
- Consider `digits = ["1","3","5","7"]`, `n = 100`:
  - 1-digit numbers: 4 numbers (`1, 3, 5, 7`).
  - 2-digit numbers: each of the 2 positions can use any of the 4 digits: `4^2 = 16` numbers.
  - 3-digit numbers `<= 100`: none, since smallest 3-digit number from digits is `111 > 100`.
  - Total = `4 + 16 = 20`. Output: 20.
- Single digit: `digits = ["7"]`, `n = 8`.
  - Only `7` is `<= 8`. Output: 1.

## Brute force
A brute force approach iterates through every integer `x` from 1 to `n`, checks if all digits of `x` belong to the allowed `digits` set, and increments a counter. With `n` up to `10^9`, iterating through 1 billion numbers takes several seconds and times out. By counting numbers combinatorially by length and prefix matching (Digit DP), we can solve it in O(L * d) time, where `L <= 10` is the number of digits in `n`.

## The key observation
We split the count into two disjoint categories:
1. Numbers with fewer digits than `n`:
   - If `n` has length `L`, any number of length `len < L` formed using the `d` allowed digits is automatically smaller than `n`.
   - For each length `len` from 1 to `L - 1`, there are exactly `d^len` valid numbers.
2. Numbers with the exact same length `L` as `n`:
   - Compare digit-by-digit from left to right (most significant to least significant):
   - At position `i`, let the corresponding digit in `n` be `s[i]`:
     - Any allowed digit strictly smaller than `s[i]` can be placed here, and all remaining `L - i - 1` positions can be filled arbitrarily in `d^(L - i - 1)` ways.
     - If `s[i]` itself is in `digits`, we can match it and continue to position `i + 1`.
     - If `s[i]` is not in `digits`, we cannot match `s[i]` exactly, so no further numbers of length `L` can be formed; we break immediately.
   - If all `L` digits matched, `n` itself is formed using allowed digits; add 1.

## Optimal approach
1. Convert `n` to string `s` of length `L`. Let `d = digits.size()`.
2. Initialize `total = 0`.
3. Count all shorter numbers:
   - For `len` from 1 to `L - 1`: add `d^len` to `total`.
4. Walk digits of `n` from `i = 0` to `L - 1`:
   - Count how many allowed digits in `digits` are `< s[i]` (`below`).
   - Check if any allowed digit equals `s[i]` (`same`).
   - Add `below * (d^(L - i - 1))` to `total`.
   - If `!same`: we cannot continue matching prefix of `n`; return `total`.
5. If loop completes, `n` itself is composed of allowed digits: return `total + 1`.

Complexity:
- Time complexity: O(L * d) where L is the number of decimal digits in n (`L <= 10`) and d is the size of `digits` (`d <= 9`). This takes at most 90 operations.
- Space complexity: O(L) to store the string representation of `n`.

## Code walkthrough
- `for (int len = 1; len < L; len++) { p *= d; total += p; }`: Tally of all valid numbers with length strictly less than `L`.
- `for (auto& dg : digits)`: Counts `below` (< s[i]) and checks for equality `same` (== s[i]).
- `total += below * rest`: Multiplies choices for smaller digits by combinations of free suffix digits.
- `if (!same) return (int)total`: Prunes search immediately if prefix match is impossible.
- `return (int)(total + 1)`: Accounts for `n` itself if loop matches all `L` positions.

## Test it out loud
- Test `digits = ["1", "2"], n = 22`:
  - `L = 2, d = 2`.
  - Length 1: `d^1 = 2` (`1, 2`).
  - Length 2:
    - `i = 0` ('2'): `below = 1` ('1'). `below * 2^1 = 2` (`11, 12`). `same = true` ('2').
    - `i = 1` ('2'): `below = 1` ('1'). `below * 2^0 = 1` (`21`). `same = true` ('2').
  - Loop completes: add 1 for 22.
  - `total = 2 + 2 + 1 + 1 = 6` (`1, 2, 11, 12, 21, 22`). Output: 6. Correct.
- Test `digits = ["5"], n = 4`:
  - `L = 1, d = 1`. Length 0: no shorter lengths.
  - `i = 0` ('4'): allowed digit '5' is not < '4' (`below = 0`) and not == '4' (`same = false`).
  - Returns `total = 0`. Correct.

## Follow-ups
- How does this generalize to counting numbers in range `[L, R]`? Compute `count(R) - count(L - 1)`.
- What if the digit '0' were allowed? Leading zeros require care: when building numbers with length `L`, the first digit cannot be 0, and shorter lengths must handle 0 without leading padding.

## Common mistakes
- Forgetting to count numbers with fewer digits than `n`.
- Continuing the prefix walk after encountering a digit not present in `digits`.
- Forgetting to add 1 when `n` itself is formed entirely from allowed digits.
