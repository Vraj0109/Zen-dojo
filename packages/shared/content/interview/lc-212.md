## Clarify first

- Can the same cell on the board be used multiple times for a single word? (No, each cell can be used at most once per word).
- Can the same cell be reused across different words? (Yes, separate words can traverse through the same cells).
- What character set does the board and words contain? (All lowercase English letters `'a'` through `'z'`).
- Can the words list contain duplicates, and should the returned result contain duplicates? (All words in the input list are unique; the result must contain each found word at most once).
- What are the dimensions of the board and max word length? (`m, n <= 12`, word length up to 10).

## Examples to say out loud

- Word found: `board = [["a", "b"], ["c", "d"]]`, `words = ["ab", "ac", "bd", "ca"]`. Starting DFS from `'a'`, neighbors `'b'` and `'c'` form `"ab"` and `"ac"`. All 4 words are formed and returned.
- Word cannot reuse cells: `board = [["a", "b"], ["c", "d"]]`, `words = ["abcb"]`. Traversing `a -> b -> c` requires returning to `'b'`, which is already visited on the current path, so `"abcb"` cannot be formed.
- No matching prefixes: If words start with letters not present on the board, DFS aborts at depth 0 immediately.

## Brute force

A naive brute force runs LeetCode 79 (Word Search) individually for each word in `words`. For each word of length $L$, we search from all $m \times n$ cells with up to $4^L$ branching. Across $W$ words, the total time complexity would be $O(W \cdot m \cdot n \cdot 4^L)$. With $W = 30,000$, this results in massive redundant grid traversals for shared prefixes like `"sea"`, `"seat"`, and `"seats"`.

## The key observation

Instead of searching the board once per word, search the board once for all words simultaneously using a Trie (prefix tree). Inserting all words into a Trie allows the board traversal to follow matching prefixes. If the current sequence of cells does not form a valid prefix in the Trie, we prune the search branch immediately. Furthermore, storing the complete word at terminal Trie nodes avoids reconstructing strings during backtracking.

## Optimal approach

1. Build a Trie from all strings in `words`. Store the complete word string at each terminal leaf node (or a flag).
2. For each cell `(r, c)` on the $m \times n$ board:
   - Initiate a recursive DFS with cell `(r, c)` and Trie `root`.
3. In `dfs(board, r, c, node)`:
   - Check boundaries: if `r` or `c` is out of bounds, return.
   - Read cell character `ch = board[r][c]`. If `board[r][c] == "#"` (visited) or `node` has no child for `ch`, return immediately.
   - Advance `node = node->children[ch - 'a']`.
   - If `node` contains a completed word:
     - Add the word to the results list.
     - Clear the word in the node (`node->word = ""`) so the same word is not added multiple times from different paths.
   - Mark the cell as visited: `board[r][c] = "#"`.
   - Recurse in all four cardinal directions `(r+1, c)`, `(r-1, c)`, `(r, c+1)`, `(r, c-1)` with `node`.
   - Backtrack: restore `board[r][c] = ch`.
4. Return the accumulated list of unique words.

Complexity:
- Time: `O(m * n * 4^L + W * L)` where $W$ is the number of words and $L$ is the maximum length of a word ($L \le 10$). Building the Trie takes $O(W \cdot L)$, and grid DFS explores at most $4^L$ depth from each of the $m \cdot n$ cells, heavily constrained by Trie branches.
- Space: `O(W * L)` auxiliary space for the Trie nodes, plus $O(L)$ for the recursion call stack.

## Code walkthrough

In the reference implementation:
- `struct TrieNode`: holds `children[26]` and a `string word`.
- `insertWord(w)`: builds the prefix tree, setting `cur->word = w` at the ending node.
- `if (!node->children[idx]) return;`: terminates grid exploration instantly when no dictionary word shares this prefix.
- `result.push_back(nextNode->word); nextNode->word = "";`: captures found word and de-duplicates future paths in `O(1)`.
- `b[r][c] = "#"; ... b[r][c] = cell;`: marks cell in-place to prevent cell reuse during active word path, then backtracks.

## Test it out loud

- Single character board: `[["a"]]`, `words = ["a"]`. Explores `(0, 0)`, matches `'a'` at root, adds `"a"`, restores board, returns `["a"]`.
- Prefix overlap: `["oath", "oa"]`. DFS reaches `'a'`, adds `"oa"`, continues deeper along `'t'` and `'h'`, adds `"oath"`. Both recorded without redundant searches.
- Disjoint characters: Dictionary words start with `'z'`, but board contains only `'a'` through `'e'`. All root child lookups fail at depth 1, running in `O(m * n)`.

## Follow-ups

- How can we further optimize the Trie during search?
  Implement Trie pruning (leaf removal): when a leaf node matches and has no remaining children, remove it from its parent. This prevents re-traversing exhausted prefixes.
- What if the board is very large (e.g. 1000x1000) and words are short?
  Index starting letters of words and only launch DFS from cells whose character matches the first letter of at least one word.
- What if diagonal movements are allowed?
  Expand direction array from 4 to 8 directions; the Trie pruning structure remains identical.

## Common mistakes

- Inserting words found into a hash set or forgetting to clear `node->word = ""`, causing duplicate entries when multiple paths form the same word.
- Forgetting to unmark visited cells during backtracking, corrupting subsequent searches from neighboring starting points.
- Allocating a fresh string on every recursive DFS step instead of storing the target word at Trie nodes.
