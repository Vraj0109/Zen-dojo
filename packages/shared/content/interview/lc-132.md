## Clarify first
- What defines a valid palindrome partitioning? Dividing string `s` into contiguous substrings where each substring reads the same forwards and backwards.
- What are we minimizing? The total number of cuts. If the string is already a palindrome, 0 cuts are needed.
- What characters appear in the string? Only lowercase English letters.
- What is the maximum string length? `1 <= s.length <= 2000`.

## Examples to say out loud
- Consider `s = "aab"`:
  - Cut as `"aa" | "b"`. Both `"aa"` and `"b"` are palindromes.
  - Number of cuts: 1. Output: 1.
- Already a palindrome: `s = "aba"`.
  - 0 cuts needed. Output: 0.
- All distinct letters: `s = "abc"`.
  - Cut as `"a" | "b" | "c"`.
  - Number of cuts: 2. Output: 2.

## Brute force
A brute force approach tests all `2^(n - 1)` possible cut locations using backtracking, checks if all generated pieces are palindromes, and finds the minimum cut count. For `n = 2000`, checking `2^1999` partitions is impossible. By breaking the problem into subproblems using 1D Dynamic Programming with an O(1) palindrome lookup table, we can solve it in O(n^2) time.

## The key observation
Let `cut[j]` be the minimum number of cuts needed to partition the prefix `s[0..j]`.
- If the entire prefix `s[0..j]` is a palindrome, then `cut[j] = 0`.
- Otherwise, we can consider every possible last palindromic cut `s[i..j]` where `1 <= i <= j`.
  If `s[i..j]` is a palindrome, then a valid partition can be formed by taking the best partition of prefix `s[0..i-1]` and adding 1 cut:
  `cut[j] = min(cut[j], cut[i - 1] + 1)`.
To check whether `s[i..j]` is a palindrome in O(1) time, we precompute a 2D boolean table `pal[i][j]` using interval DP:
`pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i + 1][j - 1])`.

## Optimal approach
1. Precompute palindrome table `pal`:
   - Allocate `n x n` boolean array `pal` initialized to false.
   - For `i` from `n - 1` down to 0:
     - For `j` from `i` to `n - 1`:
       - `pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i + 1][j - 1])`.
2. Allocate array `cut` of size `n`.
3. For `j` from 0 to `n - 1`:
   - If `pal[0][j]` is true:
     - `cut[j] = 0`.
   - Else:
     - Initialize `cut[j] = j` (worst case: cut every character).
     - For `i` from 1 to `j`:
       - If `pal[i][j]` is true:
         - `cut[j] = min(cut[j], cut[i - 1] + 1)`.
4. Return `cut[n - 1]`.

Complexity:
- Time complexity: O(n^2) because filling the `pal` table takes O(n^2) and evaluating `cut[j]` takes O(j) per index, summing to O(n^2).
- Space complexity: O(n^2) auxiliary space for the `pal` boolean table and O(n) for the `cut` array.

## Code walkthrough
- `pal[i][j] = s[i] == s[j] && (j - i < 2 || pal[i + 1][j - 1])`: Bottom-up DP filling palindrome substring truth values.
- `if (pal[0][j]) { cut[j] = 0; continue; }`: Zero cuts needed when prefix `s[0..j]` is already a palindrome.
- `cut[j] = j`: Sets worst-case upper bound (each single letter separated by a cut).
- `for (int i = 1; i <= j; i++) if (pal[i][j]) cut[j] = min(cut[j], cut[i - 1] + 1)`: Explores all valid final palindromic segments ending at `j`.
- Returns `cut[n - 1]`.

## Test it out loud
- Test `s = "aab"`:
  - `j = 0` ('a'): `pal[0][0] = true`, `cut[0] = 0`.
  - `j = 1` ("aa"): `pal[0][1] = true`, `cut[1] = 0`.
  - `j = 2` ("aab"): `pal[0][2] = false`.
    - `i = 1`: `s[1..2] = "ab"`, `pal[1][2] = false`.
    - `i = 2`: `s[2..2] = "b"`, `pal[2][2] = true`. `cut[2] = min(2, cut[1] + 1) = 0 + 1 = 1`.
  - Returns `cut[2] = 1`. Correct.
- Test `s = "aba"`:
  - `pal[0][2]` is true, `cut[2] = 0`. Correct.

## Follow-ups
- Can space complexity be reduced to O(n)? Yes, by expanding around centers (like Manacher's algorithm) to find palindromic substrings and updating `cut[j]` directly on the fly, eliminating the O(n^2) palindrome matrix and using only O(n) space.
- How does this relate to Palindrome Partitioning I? Palindrome Partitioning I requires generating all possible partitions (exponential output), whereas Part II only computes the minimal cut count (polynomial time).

## Common mistakes
- Initializing `cut[j]` without considering `pal[0][j] == true`, requiring clumsy boundary sentinels for `cut[-1]`.
- Using an O(n) two-pointer check inside the inner loop, degrading time complexity from O(n^2) to O(n^3).
- Loop bounds errors when checking `cut[i - 1]`.
