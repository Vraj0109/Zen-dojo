## Clarify first
- Are all words guaranteed to have the same length? Yes, all words in `wordList` and the `beginWord` have identical length L.
- Must intermediate words exist in the dictionary? Yes, all intermediate words and the `endWord` must be present in `wordList`. `beginWord` does not have to be in `wordList`.
- What should be returned if `endWord` is not in `wordList` or no transformation path exists? Return 0.
- How is ladder length counted? It counts the total number of words in the transformation sequence, including both `beginWord` and `endWord`.

## Examples to say out loud
- Standard case: `beginWord = "hit"`, `endWord = "cog"`, `wordList = ["hot","dot","dog","lot","log","cog"]`.
  - Path: `hit -> hot -> dot -> dog -> cog`.
  - Total words in sequence: 5. Return 5.
- Impossible target: `beginWord = "hit"`, `endWord = "cog"`, `wordList = ["hot","dot","dog","lot","log"]`.
  - `"cog"` is not in `wordList`. Return 0.
- Immediate 1-step transformation: `beginWord = "hit"`, `endWord = "hot"`, `wordList = ["hot"]`.
  - Path: `hit -> hot`. Return 2.

## Brute force
A naive approach treats each word as a graph node and builds an explicit adjacency list by comparing every pair of words in `wordList` (plus `beginWord`). Comparing all pairs takes O(N^2 * L) time. For N = 5000, N^2 is 2.5 * 10^7 string comparisons, which is slow. We can instead generate valid neighbor words on the fly in O(L * 26) per word and check presence against a hash set.

## The key observation
Since every edge has uniform weight 1 (transforming exactly one letter), the shortest transformation sequence corresponds directly to the shortest path in an unweighted graph, which is optimally solved with Breadth-First Search (BFS).
Instead of comparing against all N words, for a word of length L we try mutating each of its L characters to the 26 lowercase English letters ('a' through 'z'). This yields `26 * L` candidate words. Testing each candidate against an `unordered_set` of available dictionary words takes O(L) time. Whenever a word is visited, removing it from the hash set prevents duplicate visits and acts as an in-place visited set.

## Optimal approach
1. Insert all words from `wordList` into an `unordered_set` named `dict`.
2. If `endWord` is not present in `dict`, return 0 immediately.
3. Initialize a BFS queue `q` holding pairs of `(current_word, current_distance)`.
4. Push `{beginWord, 1}` into `q` and erase `beginWord` from `dict` if present.
5. While `q` is not empty:
   - Pop `(w, d)`.
   - If `w == endWord`, return `d`.
   - For each character position `i` from 0 to `L - 1`:
     - Save the original character `orig = w[i]`.
     - For `c` from 'a' to 'z':
       - If `c == orig`, continue.
       - Set `w[i] = c`.
       - If `dict.count(w)`: erase `w` from `dict` and push `{w, d + 1}` into `q`.
     - Restore `w[i] = orig`.
6. If the queue is exhausted without reaching `endWord`, return 0.

Complexity:
- Time complexity: O(N * L * 26) where N is the number of words in `wordList` and L is the length of each word. Each word is pushed to the queue at most once and generates 26 * L neighboring candidates.
- Space complexity: O(N * L) auxiliary space to store dictionary words in the hash set and BFS queue.

## Code walkthrough
- `if (!dict.count(endWord)) return 0`: Early exit if destination is unreachable.
- `q.push({beginWord, 1})`: Starts BFS from `beginWord` with distance 1.
- `for (size_t i = 0; i < w.size(); i++) ... for (char c = 'a'; c <= 'z'; c++)`: Generates all one-character substitutions on the fly.
- `dict.erase(w)`: Removes queued word immediately, eliminating the need for a separate visited set.
- `if (w == endWord) return d`: Returns the shortest path length as soon as the target word is popped.

## Test it out loud
- Test `begin = "a", end = "c", list = ["a", "b", "c"]`:
  - `q = [("a", 1)]`.
  - Mutate 'a' -> 'c' (matches dictionary). `dict.erase("c")`, `q.push({ "c", 2 })`.
  - Pop `"c"`, returns 2. Correct.
- Test `begin = "hot", end = "dog", list = ["hot", "dog"]`:
  - Mutate "hot": "dot" is not in list, "hog" is not in list.
  - Queue empties; returns 0. Correct.

## Follow-ups
- How can search time be reduced further for large word sets? Bidirectional BFS: start two simultaneous searches from `beginWord` and `endWord`, always expanding the smaller frontier. This cuts the branching search tree exponentially.
- What if we need to return all shortest transformation sequences (Word Ladder II)? Run BFS to build level-by-level predecessor parent pointers, followed by DFS backtracking from `endWord` back to `beginWord`.

## Common mistakes
- Comparing all word pairs to build an adjacency graph upfront, which incurs unnecessary O(N^2 * L) overhead.
- Not erasing words from the dictionary or not marking visited upon pushing into the queue, which causes cycles and exponential queue growth.
- Returning the number of transformations (edges) rather than the number of words (edges + 1).
