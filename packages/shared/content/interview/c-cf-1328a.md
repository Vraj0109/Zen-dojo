## Clarify first
- What are the inputs? We are given two positive integers, `a` and `b`. In the problem setting there can be multiple test cases `t`.
- What operation can we perform? In one step, we can increase `a` by 1.
- What is the goal? Find the minimum number of moves needed to make `a` divisible by `b`.
- What are the constraints on `a` and `b`? Both are between 1 and 10^9, and `t` can be up to 10^4.
- Can `a` already be divisible by `b`? Yes, in which case the answer is 0.

## Examples to say out loud
- Consider `a = 10` and `b = 4`. The remainder of `10` divided by `4` is `2`. To reach the next multiple of `4` (which is `12`), we need `4 - 2 = 2` increments. The answer is `2`.
- Consider `a = 13` and `b = 7`. The remainder is `13 % 7 = 6`. Moves needed: `7 - 6 = 1`.
- Edge case: `a = 10` and `b = 5`. Since `10 % 5 == 0`, `a` is already divisible by `b`, so the answer is `0`.

## Brute force
A direct simulation would use a `while (a % b != 0)` loop, incrementing `a` by 1 and counting each step. However, if `a = 1` and `b = 10^9`, this loop will execute `10^9 - 1` times. Across 10^4 test cases, this would take ~10^13 operations, which immediately causes Time Limit Exceeded. We need an O(1) arithmetic formula per test query.

## The key observation
Modulo arithmetic directly tells us how far `a` is past the previous multiple of `b`. Specifically, `rem = a % b` is the excess beyond that multiple. If `rem == 0`, `a` is already a multiple, so 0 moves are needed; otherwise, the distance to the next multiple of `b` is exactly `b - rem`.

## Optimal approach
1. Compute the remainder `rem = a % b`.
2. If `rem == 0`, return `0`.
3. Otherwise, return `b - rem`. Alternatively, the unified expression `(b - (a % b)) % b` works in all cases without branching.
4. Process each test case in O(1) time.

Complexity:
- Time complexity: O(1) per test case, or O(t) total for `t` queries, which runs in milliseconds.
- Space complexity: O(1) auxiliary space as only basic integer variables are used.

## Code walkthrough
- `rem = a % b`: Computes how many units `a` exceeds the nearest multiple of `b` below it.
- `if (rem == 0) return 0`: Handles the exact multiple boundary condition.
- `return b - rem`: Returns the steps needed to advance to the upper multiple.

## Test it out loud
- `a = 10, b = 4`: `10 % 4 = 2`. Not 0, so returns `4 - 2 = 2`. Correct.
- `a = 10, b = 5`: `10 % 5 = 0`. Returns `0`. Correct.
- `a = 1, b = 100`: `1 % 100 = 1`. Returns `100 - 1 = 99`. Correct.
- `a = 100, b = 1`: `100 % 1 = 0`. Returns `0`. Correct.

## Follow-ups
- What if `a` and `b` can be negative? In C++/Java, `%` preserves the sign of the dividend. We would need to normalize modulo arithmetic to obtain standard Euclidean remainder before subtracting.

## Common mistakes
- Using a loop to increment `a` one by one, exceeding the time limit.
- Returning `b - rem` when `rem == 0`, incorrectly answering `b` instead of `0`.
