## Clarify first

- Does an arrow shot at position `x` burst a balloon that touches `x` at its endpoint? Yes, an arrow at `x` bursts any balloon where `xstart <= x <= xend`.
- Can multiple balloons overlap at the same point? Yes, a single arrow shot at position `x` bursts all balloons whose horizontal spans cover `x`.
- Can coordinates be negative or large? Yes, coordinates span the full 32-bit signed integer range (`-2^31` to `2^31 - 1`).
- What are the constraints on array length? `points.length` is between 1 and 100,000.

## Examples to say out loud

- Multi-overlap chain: `points = [[10, 16], [2, 8], [1, 6], [7, 12]]`.
  - Balloons `[1, 6]` and `[2, 8]` can be burst by 1 arrow at `x = 6`.
  - Balloons `[7, 12]` and `[10, 16]` can be burst by 1 arrow at `x = 10` (or 11, 12).
  - Minimum arrows needed = 2.
- Completely disjoint balloons: `points = [[1, 2], [3, 4], [5, 6], [7, 8]]`. No two balloons share a coordinate, so 4 arrows are required.
- Touching boundaries: `points = [[1, 2], [2, 3]]`. An arrow shot at `x = 2` bursts both balloons, so 1 arrow is needed.

## Brute force

A brute-force strategy evaluates all subsets of shooting coordinates to cover all intervals (Set Cover Problem). Testing all coordinate positions or combinations of points takes exponential time, which is completely impossible for `n = 100,000`.

## The key observation

To maximize the number of balloons hit by a single arrow, consider the balloon that finishes earliest (smallest `xend`). To burst this balloon, an arrow **must** be shot at some position `<= xend`. To maximize the chance of bursting other overlapping balloons simultaneously, the best greedy choice is to shoot the arrow at the latest possible valid moment: **exactly at `xend`**.
Any balloon whose `xstart <= xend` will be burst by this arrow. The remaining unburst balloons form the exact same subproblem.

## Optimal approach

1. Sort the balloons in ascending order of their end coordinate: `points[i][1]`.
2. Initialize `arrows = 1`, and set `pos = points[0][1]` (the position of the first arrow, placed at the end of the first balloon).
3. For each balloon `p` in the sorted list:
   - If `p[0] > pos`:
     - The current arrow cannot reach balloon `p`.
     - We must shoot a new arrow: increment `arrows++`.
     - Update the arrow position to this balloon's end: `pos = p[1]`.
4. Return `arrows`.

Complexity:
- Time: `O(n log n)` because we sort `n` intervals, followed by an `O(n)` single-pass linear sweep.
- Space: `O(1)` auxiliary space beyond the sorting buffer.

## Code walkthrough

In the reference implementation:
- `sort(points.begin(), points.end(), [](auto& a, auto& b) { return a[1] < b[1]; });`: orders balloons by right boundary (avoiding integer subtraction overflow).
- `int arrows = 1; long long pos = points[0][1];`: shoots the first arrow at the earliest right boundary using 64-bit precision to prevent overflow.
- `for (auto& p : points) if (p[0] > pos)`: identifies when a balloon starts strictly past the active arrow position.
- `{ arrows++; pos = p[1]; }`: commits a new arrow at the next unburst balloon's right endpoint.
- `return arrows;`: returns the minimum arrow count.

## Test it out loud

- `points = [[1, 2], [2, 3]]`:
  - Sorted: `[1, 2]`, `[2, 3]`.
  - Arrow 1 at `pos = 2`.
  - Second balloon has `p[0] = 2 <= 2`, covered by arrow 1!
  - Return `arrows = 1`.
- `points = [[1, 2], [3, 4]]`:
  - Arrow 1 at `pos = 2`.
  - Second balloon has `p[0] = 3 > 2`, triggers arrow 2 at `pos = 4`.
  - Return `arrows = 2`.

## Follow-ups

- Why is sorting by end coordinate better than sorting by start coordinate?
  Sorting by end coordinate allows fixing the arrow position at `p[1]` permanently for all compatible intervals; sorting by start requires dynamically tracking `min(end)` across overlaps.
- How does this relate to Non-overlapping Intervals (LeetCode 435)?
  The minimum arrows required equals the maximum number of mutually non-overlapping intervals (Activity Selection Problem).

## Common mistakes

- Using subtraction `a[1] - b[1]` in the sorting comparator, which causes integer overflow when coordinates are near `INT_MIN` and `INT_MAX` (use `<` comparator instead).
- Treating touching balloons as non-overlapping (e.g. `p[0] >= pos` instead of `p[0] > pos`).
- Starting `arrows = 0` and adding conditionally, which can miss the final arrow.
