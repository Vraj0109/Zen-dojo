## Clarify first

- How is the probability of picking index $i$ calculated? (The probability of picking index $i$ is exactly $w[i] / \sum w$).
- Are weights guaranteed to be strictly positive? (Yes, $1 \le w[i] \le 100,000$).
- Can the total weight exceed a 32-bit signed integer? (With $10,000$ weights up to $100,000$, max total sum is $10^4 \times 10^5 = 10^9$, which fits comfortably in a standard signed 32-bit integer).
- What is the return value of `pickIndex()`? (An integer index $i \in [0, w.length - 1]$ chosen according to the weight distribution).
- What are the query bounds? ($w.length \le 10,000$, with at most $10,000$ calls to `pickIndex()`).

## Examples to say out loud

- Two weights: `w = [1, 3]`.
  - Total weight is $1 + 3 = 4$.
  - Index 0 has weight 1 ($25\%$ probability).
  - Index 1 has weight 3 ($75\%$ probability).
  - Prefix sums are `[1, 4]`. Generating random integer in $[1, 4]$: 1 maps to index 0; 2, 3, 4 map to index 1.
- Equal weights: `w = [2, 2, 2]`. Total weight 6. Each index gets range of length 2, resulting in an exact uniform $1/3$ probability each.

## Brute force

A naive approach expands the weight array by duplicating each index $i$ exactly $w[i]$ times into a large array of size $S = \sum w$ (e.g. `[0, 1, 1, 1]`). Then `pickIndex()` simply chooses a random uniform index from $[0, S - 1]$ in $O(1)$. However, if weights sum to $10^9$, allocating an array of size $10^9$ requires 4 GB+ of memory, causing Memory Limit Exceeded during initialization.
Another naive approach generates a random number and linearly scans through weights in $O(n)$ time per pick, which is too slow for 10,000 calls.

## The key observation

Think of the weights as contiguous disjoint segments laid end-to-end on a 1D number line from $1$ to $totalSum = \sum w$.
- Index 0 occupies range $[1, w[0]]$.
- Index 1 occupies range $[w[0] + 1, w[0] + w[1]]$.
- Index $i$ occupies range $[\text{prefix}[i-1] + 1, \text{prefix}[i]]$.
The length of index $i$'s segment is exactly $w[i]$, so a uniformly chosen random integer in $[1, totalSum]$ falls into index $i$'s interval with probability $w[i] / totalSum$.
Because the prefix sums are strictly increasing, we can locate the interval containing the random number using **binary search** (`std::lower_bound` / `bisect_left`) in $O(\log n)$ time.

## Optimal approach

1. Constructor `Solution(w)`:
   - Create a prefix sum array `prefix`.
   - Iterate through `w`, accumulating the running sum and appending it to `prefix`.
   - The total sum is `prefix.back()`.
2. Operation `pickIndex()`:
   - Generate a random integer `val` uniformly in the range $[1, \text{totalSum}]$: `val = (rand() % totalSum) + 1`.
   - Perform binary search (`lower_bound`) on `prefix` to find the smallest index where `prefix[idx] >= val`.
   - Return `idx`.

Complexity:
- Time: Constructor takes $O(n)$ time to build prefix sums. Each call to `pickIndex()` takes $O(\log n)$ time for the binary search.
- Space: $O(n)$ auxiliary space to store the prefix sums of length $n$.

## Code walkthrough

In the reference implementation:
- `prefix.push_back(sum);`: accumulates cumulative upper boundaries for each index's weight window.
- `int total = prefix.back();`: retrieves the total combined weight.
- `int val = (rand() % total) + 1;`: samples a 1-indexed random point uniformly across $[1, total]$.
- `return lower_bound(prefix.begin(), prefix.end(), val) - prefix.begin();`: finds the first prefix sum $\ge val$ in $O(\log n)$.

## Test it out loud

- Single element: `w = [10]`. `prefix = [10]`, `total = 10`. Random values in $[1, 10]$ all have `lower_bound` at index 0. Returns 0 with $100\%$ probability.
- Two distinct weights: `w = [1, 3]`. `prefix = [1, 4]`.
  - If random value is 1: `lower_bound` returns index 0 ($25\%$).
  - If random value is 2, 3, or 4: `lower_bound` returns index 1 ($75\%$).
- Large weights: `w = [100000]`. Prefix sum safely stays within integer range, returns 0.

## Follow-ups

- How to achieve $O(1)$ pick time?
  Use **Walker's Alias Method** (Vose's algorithm), which precomputes an alias table in $O(n)$ time and samples any discrete distribution in strictly $O(1)$ time.
- What if weights are updated dynamically?
  Use a Binary Indexed Tree (Fenwick Tree) or Segment Tree: updating a weight takes $O(\log n)$, and binary lifting on the Fenwick tree allows sampling in $O(\log n)$.
- What if `rand()` has insufficient resolution for large sums?
  Standard `rand()` in C++ has `RAND_MAX = 32767` on some platforms; use `std::mt19937` with `std::uniform_int_distribution<int>(1, total)` for proper 32-bit random precision.

## Common mistakes

- Generating random values in $[0, total - 1]$ instead of $[1, total]$ when using `lower_bound`: offset mismatch can shift probabilities into the wrong index buckets.
- Using 0-indexed prefix sums where `prefix[0] = 0`, leading to off-by-one errors in the returned index.
- Memory explosion by expanding weights into an explicit element array.
