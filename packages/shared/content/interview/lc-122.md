## Clarify first

- Can we hold multiple shares at once? No, you can hold at most one share at any time (you must sell your current share before buying again).
- Can we buy and sell on the same day? Yes, selling and buying on the same day is permitted, but yields no net change in holding.
- Is there any transaction fee or cooldown period? No fees and no cooldown restrictions in this problem.
- What if prices are monotonically decreasing? No profitable trade can be made, so the maximum profit is 0.

## Examples to say out loud

- Continuous ascent: `prices = [1, 2, 3, 4, 5]`.
  - Buying at 1 and selling at 5 yields `5 - 1 = 4`.
  - This is identical to summing daily gains: `(2 - 1) + (3 - 2) + (4 - 3) + (5 - 4) = 1 + 1 + 1 + 1 = 4`.
- Volatile prices: `prices = [7, 1, 5, 3, 6, 4]`.
  - Buy at 1, sell at 5: profit = 4.
  - Buy at 3, sell at 6: profit = 3.
  - Total profit = `4 + 3 = 7`.
- Monotonically falling: `prices = [7, 6, 4, 3, 1]`. Profit is 0.

## Brute force

A brute-force backtracking approach evaluates every possible sequence of buy, sell, and hold actions for every day. Because there are 2 states on each day (holding or not holding) over `n` days, the decision tree generates `O(2^n)` combinations. For `n = 30,000`, this is computationally impossible.

## The key observation

Any multi-day profitable trade from day `i` to day `j` can be decomposed into a sum of consecutive daily gains: `prices[j] - prices[i] = \sum_{k=i}^{j-1} (prices[k + 1] - prices[k])`. To maximize total profit when unlimited transactions are allowed, we can greedily capture every single positive daily price difference `prices[i] - prices[i - 1] > 0`. If a daily difference is negative, we simply do not hold the stock over that day.

## Optimal approach

1. Initialize `profit = 0`.
2. Iterate `i` from 1 to `prices.length - 1`:
   - If `prices[i] > prices[i - 1]`:
     - Add `prices[i] - prices[i - 1]` to `profit`.
3. Return `profit`.

Complexity:
- Time: `O(n)` because we iterate through the array of length `n` in a single pass with `O(1)` operations per step.
- Space: `O(1)` auxiliary space as we only store one running scalar integer.

## Code walkthrough

In the reference implementation:
- `int profit = 0;`: initializes the cumulative profit accumulator.
- `for (size_t i = 1; i < prices.size(); i++)`: scans day-over-day transitions from day 1 onward.
- `if (prices[i] > prices[i - 1]) profit += prices[i] - prices[i - 1];`: captures every upward slope in the price curve without holding during downward movements.
- `return profit;`: outputs the maximum total profit earned.

## Test it out loud

- `prices = [7, 1, 5, 3, 6, 4]`:
  - `i = 1`: `1 < 7`, no gain.
  - `i = 2`: `5 > 1`, gain `5 - 1 = 4`. `profit = 4`.
  - `i = 3`: `3 < 5`, no gain.
  - `i = 4`: `6 > 3`, gain `6 - 3 = 3`. `profit = 4 + 3 = 7`.
  - `i = 5`: `4 < 6`, no gain.
  - Total profit is 7.
- `prices = [1]`: loop does not execute, returns 0.

## Follow-ups

- What if there is a transaction fee `fee` per trade (LeetCode 714)?
  Maintain two state machine DP variables: `hold = max(hold, cash - price)` and `cash = max(cash, hold + price - fee)`.
- What if there is a 1-day cooldown after selling (LeetCode 309)?
  Maintain three state variables: `hold`, `sold`, and `rest`.
- What if transactions are capped at `k` trades (LeetCode 188)?
  Use dynamic programming with `k` buy/sell state pairs in `O(n * k)` time.

## Common mistakes

- Trying to find local valleys and peaks explicitly with complex pointer logic, which introduces index boundary bugs when simple day-over-day accumulation achieves the exact same result.
- Conflating this with single-transaction stock trading (LeetCode 121), which only permits one buy and one sell.
- Accumulating negative differences during downturns.
