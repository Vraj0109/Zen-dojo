## Clarify first

- What operations are allowed? Three character-level operations: insert, delete, or replace.
- Do all operations have the same cost? Yes, each operation has a unit cost of 1.
- Can one or both strings be empty? Yes, lengths range from 0 to 500. Transforming an empty string into a string of length `m` costs `m` insertions.
- Are characters case-sensitive? Yes, lowercase English letters are specified.

## Examples to say out loud

- Classic replacement and deletion: `word1 = "horse"`, `word2 = "ros"`.
  - Replace `'h'` with `'r'`: `"rorse"`.
  - Delete `'r'`: `"rose"`.
  - Delete `'e'`: `"ros"`.
  - Total minimum operations = 3.
- Insertion and replacement: `word1 = "intention"`, `word2 = "execution"`. Minimum operations = 5.
- One string empty: `word1 = ""`, `word2 = "a"`. 1 insertion needed, returns 1.
- Identical strings: `word1 = "abc"`, `word2 = "abc"`. 0 operations, returns 0.

## Brute force

A brute-force recursive formulation starts at the end of both strings `(i, j)`. If characters match, recurse on `(i - 1, j - 1)`. If they differ, branch into 3 recursive calls: insert `(i, j - 1)`, delete `(i - 1, j)`, and replace `(i - 1, j - 1)`, adding 1 to the minimum. The branching factor is 3, leading to `O(3^{\max(n, m)})` exponential time, which times out for lengths beyond 15.

## The key observation

Let `dp[i][j]` be the minimum edit distance between prefixes `word1[0..i-1]` and `word2[0..j-1]`.
- If `word1[i - 1] == word2[j - 1]`, no new edit is needed: `dp[i][j] = dp[i - 1][j - 1]`.
- If they differ, we take 1 plus the minimum of the three possible operations:
  - Replace: `dp[i - 1][j - 1]`
  - Delete from `word1`: `dp[i - 1][j]`
  - Insert into `word1` (match `word2[j - 1]`): `dp[i][j - 1]`
Hence `dp[i][j] = 1 + min({dp[i - 1][j - 1], dp[i - 1][j], dp[i][j - 1]})`.

## Optimal approach

1. Let `n = word1.length()` and `m = word2.length()`.
2. Allocate a 2D array `dp` of size `(n + 1) \times (m + 1)`.
3. Base cases:
   - For `i` from 0 to `n`: `dp[i][0] = i` (deleting `i` characters).
   - For `j` from 0 to `m`: `dp[0][j] = j` (inserting `j` characters).
4. Iterate `i` from 1 to `n`:
   - Iterate `j` from 1 to `m`:
     - If `word1[i - 1] == word2[j - 1]`:
       - `dp[i][j] = dp[i - 1][j - 1]`.
     - Else:
       - `dp[i][j] = 1 + min({dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]})`.
5. Return `dp[n][m]`.

Complexity:
- Time: `O(n * m)` because every state in the `(n + 1) \times (m + 1)` table is computed in `O(1)` time.
- Space: `O(n * m)` auxiliary space for the DP table (can be optimized to `O(min(n, m))` using rolling rows).

## Code walkthrough

In the reference implementation:
- `for (int i = 0; i <= n; i++) dp[i][0] = i;`: represents the cost of deleting all characters to reach an empty string.
- `for (int j = 0; j <= m; j++) dp[0][j] = j;`: represents the cost of inserting all characters from an empty source.
- `if (word1[i - 1] == word2[j - 1]) dp[i][j] = dp[i - 1][j - 1];`: copies previous diagonal cost when characters match.
- `else dp[i][j] = 1 + min({dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]});`: evaluates the minimum cost among deletion, insertion, and replacement.
- `return dp[n][m];`: returns total edit distance.

## Test it out loud

- `word1 = "ab", word2 = "b"`:
  - Row 0: `[0, 1]`
  - Row 1 (`'a'`): `j = 1 ('b')` -> mismatch -> `1 + min(dp[0][1], dp[1][0], dp[0][0]) = 1 + min(1, 1, 0) = 1` (replace `'a'` with `'b'`). Row 1: `[1, 1]`.
  - Row 2 (`'b'`): `j = 1 ('b')` -> match -> `dp[1][0] = 1` (delete `'a'`). Row 2: `[2, 1]`.
  - Result: `dp[2][1] = 1`.
- `word1 = "", word2 = ""`: returns `dp[0][0] = 0`.

## Follow-ups

- How would you reconstruct the actual sequence of operations?
  Trace backward from `(n, m)` to `(0, 0)`: check which neighbor produced `dp[i][j]` (diagonal match, replace, delete, or insert) and output the corresponding action.
- What if operations had different costs (e.g. insert cost 2, delete cost 3)?
  Multiply respective transitions by their specific costs in the `min()` function.

## Common mistakes

- Forgetting base case initialization for `dp[i][0] = i` and `dp[0][j] = j`.
- Confusing insertion with deletion transitions (e.g. `dp[i][j - 1]` is insertion, `dp[i - 1][j]` is deletion).
- Forgetting to subtract 1 when indexing into strings: `word1[i - 1]` vs `dp[i]`.
