## Clarify first

- Can a string from `strs` be used more than once? No, this is a 0/1 Knapsack problem; each string can be selected at most once.
- What should be maximized? Maximize the **number of strings** in the subset (each string has value 1).
- What are the capacity constraints? At most `m` zeros and at most `n` ones across all chosen strings combined.
- What are the input size bounds? `strs.length <= 600`, string lengths `<= 100`, and `m, n <= 100`.

## Examples to say out loud

- Multi-choice budget: `strs = ["10", "0001", "111001", "1", "0"]`, `m = 5`, `n = 3`.
  - String costs `(zeros, ones)`:
    - `"10"`: (1, 1)
    - `"0001"`: (3, 1)
    - `"111001"`: (2, 4) — exceeds `n = 3`, cannot pick.
    - `"1"`: (0, 1)
    - `"0"`: (1, 0)
  - Selecting `"10"`, `"0001"`, `"1"`, and `"0"` uses `1 + 3 + 0 + 1 = 5` zeros and `1 + 1 + 1 + 0 = 3` ones.
  - Total strings selected = 4.
- Infeasible constraint: `strs = ["10", "0", "1"]`, `m = 1`, `n = 1`.
  - Can pick `"10"` (size 1) or `["0", "1"]` (size 2). Max strings = 2.
- Out of capacity: `strs = ["1"]`, `m = 1`, `n = 0`. Needs one 1 but budget has 0 ones, returns 0.

## Brute force

A brute-force solution evaluates all `2^L` subsets of strings, where `L = strs.length`. For each subset, check if the total zeros `<= m` and total ones `<= n`, keeping track of the maximum subset size. For `L = 600`, exploring `2^{600}` subsets is completely intractable and results in a time limit exceeded error.

## The key observation

This problem is a **two-dimensional 0/1 Knapsack Problem**. Each string acts as an item with value 1 and dual costs: weight in zeros `z` and weight in ones `o`.
Let `dp[i][j]` be the maximum number of strings that can be selected using at most `i` zeros and `j` ones.
For each item with cost `(z, o)`:
`dp[i][j] = \max(dp[i][j], dp[i - z][j - o] + 1)`.
To ensure each string is used at most once (0/1 constraint) without allocating a 3D table, we iterate both dimensions `i` and `j` **backwards** from `m` down to `z` and from `n` down to `o`.

## Optimal approach

1. Allocate a 2D DP array `dp` of size `(m + 1) \times (n + 1)` initialized to zeros.
2. For each string `s` in `strs`:
   a. Count the number of zeros `z` and ones `o` in `s`.
   b. Iterate `i` from `m` down to `z`:
      - Iterate `j` from `n` down to `o`:
        - `dp[i][j] = max(dp[i][j], dp[i - z][j - o] + 1)`.
3. Return `dp[m][n]`.

Complexity:
- Time: `O(L * m * n)` where `L` is `strs.length`. For `L = 600` and `m, n = 100`, total operations are `600 \times 100 \times 100 = 6 \times 10^6`, which executes in a few milliseconds.
- Space: `O(m * n)` auxiliary space for the 2D DP table of size `101 \times 101`.

## Code walkthrough

In the reference implementation:
- `vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));`: establishes the dual-capacity budget table.
- `int z = count(s.begin(), s.end(), '0'), o = (int)s.size() - z;`: calculates the two-dimensional cost of string `s`.
- `for (int i = m; i >= z; i--)`: loops backwards across the zero capacity to enforce 0/1 item usage.
- `for (int j = n; j >= o; j--)`: loops backwards across the one capacity.
- `dp[i][j] = max(dp[i][j], dp[i - z][j - o] + 1);`: includes string `s` if it improves upon the previous subset count for budget `(i, j)`.
- `return dp[m][n];`: extracts the maximum count supported by the full budget `(m, n)`.

## Test it out loud

- `strs = ["10", "0", "1"], m = 1, n = 1`:
  - `s = "10"`: `z = 1, o = 1`. `dp[1][1] = 1`.
  - `s = "0"`: `z = 1, o = 0`.
    - `i = 1, j = 1`: `dp[1][1] = max(dp[1][1], dp[0][1] + 1) = max(1, 1) = 1`.
    - `i = 1, j = 0`: `dp[1][0] = max(0, dp[0][0] + 1) = 1`.
  - `s = "1"`: `z = 0, o = 1`.
    - `i = 1, j = 1`: `dp[1][1] = max(dp[1][1], dp[1][0] + 1) = max(1, 1 + 1) = 2`.
    - `i = 0, j = 1`: `dp[0][1] = 1`.
  - Result: `dp[1][1] = 2` (selecting `"0"` and `"1"`).

## Follow-ups

- What if each string had an associated positive score or value other than 1?
  Replace `+ 1` with `+ value` in the state transition: `dp[i][j] = max(dp[i][j], dp[i - z][j - o] + value)`.
- What if an unlimited supply of each string was available?
  Iterate `i` forward from `z` to `m` and `j` forward from `o` to `n`.

## Common mistakes

- Iterating `i` or `j` in the forward direction, which allows a single string to be selected multiple times.
- Creating a 3D table `dp[L][m][n]`, which uses `O(L * m * n)` extra memory and is unnecessary when backward 2D iteration suffices.
- Forgetting that a string can contain 0 zeros or 0 ones (requiring loops to run down to `z` and `o`, not strictly `> 0`).
