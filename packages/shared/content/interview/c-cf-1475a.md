## Clarify first

- What is an odd divisor? (An integer $x$ such that $n$ divides evenly by $x$, $x > 1$, and $x \pmod 2 \ne 0$).
- What should be returned? (A boolean `true` if $n$ has at least one odd divisor strictly greater than 1, otherwise `false`).
- What is the range of $n$? ($2 \le n \le 10^{14}$).
- Can $n$ be prime? (Yes, if $n$ is an odd prime like 3, its divisor is 3, so return `true`; if $n = 2$, its only divisors are 1 and 2, neither of which is an odd number $> 1$, so return `false`).
- Does $n$ fit in standard integer types? (With $n \le 10^{14}$, it requires a 64-bit integer type like `long long` in C++ or `long` in Java).

## Examples to say out loud

- Composite with odd divisor: `n = 6`. Divisors of 6 are 1, 2, 3, 6. The odd divisor greater than 1 is 3. Output is `true`.
- Power of two: `n = 4`. Divisors of 4 are 1, 2, 4. All divisors greater than 1 are even. Output is `false`.
- Odd prime: `n = 3`. 3 is odd and divides 3. Output is `true`.
- Large power of two: `n = 1024`. $1024 = 2^{10}$. Only divisors are powers of two ($1, 2, 4, 8, \dots, 1024$). None $> 1$ is odd. Output is `false`.

## Brute force

A brute-force trial division tests all odd numbers $d = 3, 5, 7, \dots \le \sqrt{n}$ to check if $n \bmod d == 0$. If any divides $n$, return `true`. If no odd divisor up to $\sqrt{n}$ divides $n$, we check if $n$ itself is odd. In the worst case where $n$ is a power of 2 or prime near $10^{14}$, trial division takes up to $\sqrt{10^{14}} = 10^7$ iterations. While feasible, trial division is completely unnecessary because powers of two can be identified in $O(1)$ operations.

## The key observation

Every positive integer $n$ can be uniquely factored into:
$$n = 2^e \times m$$
where $e \ge 0$ is the exponent of 2, and $m$ is an odd integer.
- If $m > 1$, then $m$ is an odd divisor of $n$ strictly greater than 1.
- If $m = 1$, then $n = 2^e$, meaning $n$ is an exact power of two. The only divisors of a power of two are $2^0, 2^1, 2^2, \dots, 2^e$, none of which are odd except 1.
Therefore, $n$ has an odd divisor greater than 1 if and only if $n$ is NOT a power of two. In binary representation, a positive number is a power of two if and only if it has exactly one set bit: $(n \ \& \ (n - 1)) == 0$.

## Optimal approach

1. Check whether $n$ is a power of two using the classic bitwise identity:
   `is_power_of_two = (n & (n - 1)) == 0`.
2. If $n$ is a power of two, return `false`.
3. Otherwise, return `true` (`(n & (n - 1)) != 0`).

Complexity:
- Time: `O(1)` as it executes a single bitwise AND operation and comparison.
- Space: `O(1)` auxiliary space for scalar registers.

## Code walkthrough

In the reference implementation:
- `n & (n - 1)`: clears the lowest set bit of $n$. If $n$ is a power of two (having only a single 1 bit in binary), the result is exactly 0.
- `return (n & (n - 1)) != 0;`: returns `true` whenever $n$ contains more than one set bit (which implies an odd factor exists), and `false` when $n$ is an exact power of two.

## Test it out loud

- `n = 2`:
  - Binary `10`. `2 & 1 = 0`. Returns `false`.
- `n = 3`:
  - Binary `11`. `3 & 2 = 2 != 0`. Returns `true`.
- `n = 4`:
  - Binary `100`. `4 & 3 = 0`. Returns `false`.
- `n = 6`:
  - Binary `110`. `6 & 5 = 4 != 0`. Returns `true`.
- `n = 1024`:
  - Power of two ($2^{10}$). `1024 & 1023 = 0`. Returns `false`.

## Follow-ups

- What if we are asked to find the actual smallest odd divisor $> 1$?
  Divide $n$ by 2 repeatedly until it becomes odd (`n >>= __builtin_ctzll(n)`). Then run trial division on the resulting odd number starting at 3 up to $\sqrt{m}$ to find its smallest prime factor.
- How does `(n & (n - 1))` work mechanically in hardware?
  Subtracting 1 from $n$ flips the lowest set bit and all trailing zeros after it. Performing bitwise AND with the original $n$ clears this lowest set bit while keeping all higher bits unchanged.

## Common mistakes

- Using 32-bit signed integers for $n$: $n$ can be up to $10^{14}$, which overflows 32-bit `int` ($2 \times 10^9$) and yields incorrect bitwise results.
- Operator precedence errors: writing `n & (n - 1) != 0` without parentheses, because `!=` has higher precedence than `&` in C++ and Java (`n & ((n - 1) != 0)`). Parenthesizing as `(n & (n - 1)) != 0` is required.
- Dividing out factors of 2 in an unneeded while loop instead of the $O(1)$ bitwise test.
