## Clarify first
- How is the cost of connecting two points defined? Manhattan distance: `|x1 - x2| + |y1 - y2|`.
- What are we constructing? A minimum spanning tree (MST) that connects all n points with exactly n - 1 edges at the minimum possible total Manhattan distance.
- Can points have duplicate coordinates? Constraints state all points are distinct.
- How large can n be? Up to 1000 points.

## Examples to say out loud
- Consider `points = [[0,0],[2,2],[3,10],[5,2],[7,0]]`:
  - Distance between `(0,0)` and `(2,2)` is `2 + 2 = 4`.
  - Distance between `(2,2)` and `(5,2)` is `3 + 0 = 3`.
  - Distance between `(5,2)` and `(7,0)` is `2 + 2 = 4`.
  - Distance between `(2,2)` and `(3,10)` is `1 + 8 = 9`.
  - Total minimum connection cost: `4 + 3 + 4 + 9 = 20`.
- Single point `[[0, 0]]`: Total cost is 0 since 0 edges are needed.

## Brute force
A brute force approach considers all spanning trees across n vertices and finds the one with minimal sum. By Cayley's formula, there are `n^(n - 2)` spanning trees in a complete graph, which is astronomical. Kruskal's algorithm generates all `n * (n - 1) / 2` edges, sorts them in O(n^2 log n) time, and applies DSU. However, because the graph is completely dense (every point connects to every other point), Prim's algorithm without a binary heap achieves strictly O(n^2) time with lower memory overhead.

## The key observation
Since any two points can be connected, the underlying graph is a complete graph with `V = n` vertices and `E = O(n^2)` edges.
- Kruskal's algorithm requires generating and sorting `O(n^2)` edges, which takes O(n^2 log n) time and O(n^2) space.
- Dense Prim's algorithm maintains an array `best[i]` storing the minimum distance from vertex `i` to the growing spanning tree. In each of the n iterations, it linearly scans `best` to find the closest unvisited vertex, adds it to the tree, and relaxes all other vertices in O(n) time.
This achieves optimal O(n^2) time and requires only O(n) auxiliary space.

## Optimal approach
1. Initialize an array `best` of size `n` with infinity (`LLONG_MAX`), and a boolean array `in` of size `n` with false.
2. Set `best[0] = 0` to start the tree at point 0, and initialize `total = 0`.
3. Loop `it` from 0 to `n - 1`:
   - Find the unvisited vertex `u` with the smallest `best[u]`:
     - Scan `i` from 0 to `n - 1`: if `!in[i]` and `(u == -1 || best[i] < best[u])`, set `u = i`.
   - Mark `in[u] = true`.
   - Add `best[u]` to `total`.
   - For each vertex `v` from 0 to `n - 1`:
     - If `!in[v]`:
       - Compute Manhattan distance `d = |x_u - x_v| + |y_u - y_v|`.
       - Update `best[v] = min(best[v], d)`.
4. Return `total`.

Complexity:
- Time complexity: O(n^2) because finding the minimum takes O(n) per iteration and updating neighbors takes O(n) per iteration, repeated n times.
- Space complexity: O(n) auxiliary space for the `best` distance array and `in` inclusion flags.

## Code walkthrough
- `vector<long long> best(n, LLONG_MAX); best[0] = 0`: Distances to the tree.
- `vector<bool> in(n, false)`: Tracks whether a point has been included in the MST.
- Outer loop runs `n` times: Each round selects the nearest external vertex `u`.
- `total += best[u]`: Accumulates the minimum edge weight connecting `u` to the tree.
- Inner relaxation loop: Updates `best[v]` for all remaining external nodes with respect to newly added node `u`.

## Test it out loud
- Test single point `[[0, 0]]`:
  - `best[0] = 0`.
  - Iteration 0: `u = 0`, `in[0] = true`, `total = 0`. Loop ends. Returns 0. Correct.
- Test two points `[[0, 0], [1, 1]]`:
  - `best = [0, INF]`.
  - Round 1: picks 0, adds 0. Relaxes point 1 with `d = |0-1| + |0-1| = 2`. `best[1] = 2`.
  - Round 2: picks 1, adds 2. Total = 2. Returns 2. Correct.

## Follow-ups
- Why is dense Prim faster than heap-based Prim here? A heap-based Prim runs in O(E log V) = O(n^2 log n) and requires storing edges in memory. On dense graphs where E = O(V^2), array-based Prim runs in O(V^2) with virtually no memory overhead.
- What if points were 1-dimensional? Sorting points by x-coordinate and connecting adjacent points solves it in O(n log n).

## Common mistakes
- Creating an explicit edge list of size `n * (n - 1) / 2`, which risks memory limits and incurs sorting overhead.
- Integer overflow when calculating Manhattan distances between points with coordinates near 1,000,000 (best practice is using 64-bit integers).
- Not resetting `u = -1` before finding the minimum unvisited vertex in each round.
