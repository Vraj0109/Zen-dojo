## Clarify first

- Can `nums` be empty? Constraints indicate length is between 1 and 30,000.
- How many times does each element appear? Exactly one element appears once; every other element appears exactly twice.
- What are the time and space complexity requirements? The problem explicitly requires `O(n)` linear time and `O(1)` constant extra memory.
- Can numbers be negative? Yes, values range from -30,000 to 30,000.

## Examples to say out loud

- Standard array: `nums = [2, 2, 1]`. The 2s cancel out, leaving 1. Result is 1.
- Multiple pairs: `nums = [4, 1, 2, 1, 2]`. 1s pair up and cancel, 2s pair up and cancel, leaving 4. Result is 4.
- Single element: `nums = [1]`. Has no pairs, returns 1.

## Brute force

A brute-force solution uses a hash map or hash set to count the frequencies of each element, then iterates through the map to find the key with count 1. While this takes `O(n)` time, the hash map consumes `O(n)` auxiliary space, violating the strict `O(1)` memory constraint. Alternatively, sorting the array takes `O(n log n)` time and `O(1)` space, which fails the `O(n)` time requirement.

## The key observation

The bitwise XOR operator (`^`) satisfies three fundamental mathematical properties:
1. **Self-inverse:** `x ^ x = 0` (any number XORed with itself cancels to zero).
2. **Identity:** `x ^ 0 = x` (any number XORed with zero remains unchanged).
3. **Commutativity and Associativity:** `a ^ b ^ c = a ^ c ^ b` (the order of operations does not alter the result).
If we compute the cumulative XOR of every number in the array, all duplicate pairs will cancel each other out to 0: `(x_1 ^ x_1) ^ (x_2 ^ x_2) ^ \dots ^ single = 0 ^ 0 ^ \dots ^ single = single`.

## Optimal approach

1. Initialize `r = 0`.
2. Iterate through each number `x` in `nums`:
   - Compute `r = r ^ x`.
3. Return `r`.

Complexity:
- Time: `O(n)` because we iterate through the list of `n` numbers once, performing a single bitwise XOR operation per element.
- Space: `O(1)` auxiliary space as we only maintain one integer variable `r`.

## Code walkthrough

In the reference implementation:
- `int r = 0;`: initializes the XOR accumulator to the identity element 0.
- `for (int x : nums) r ^= x;`: processes each number in the array, cancelling out identical pairs.
- `return r;`: yields the unique surviving unpaired integer.

## Test it out loud

- `nums = [4, 1, 2, 1, 2]`:
  - `r = 0 ^ 4 = 4`.
  - `r = 4 ^ 1`.
  - `r = (4 ^ 1) ^ 2`.
  - `r = (4 ^ 1 ^ 2) ^ 1 = 4 ^ 2 ^ (1 ^ 1) = 4 ^ 2 ^ 0 = 4 ^ 2`.
  - `r = (4 ^ 2) ^ 2 = 4 ^ (2 ^ 2) = 4 ^ 0 = 4`.
  - Output is 4.
- `nums = [1]`: `r = 0 ^ 1 = 1`. Output is 1.

## Follow-ups

- What if every element appears three times except one that appears once (Single Number II, LeetCode 137)?
  XOR cancels modulo 2; for modulo 3, sum the bits at each position modulo 3, or maintain two bitmasks (`ones` and `twos`) in `O(n)` time and `O(1)` space.
- What if exactly two elements appear once and all others appear twice (Single Number III, LeetCode 260)?
  XOR all elements to get `a ^ b`, find the lowest set bit to partition the array into two groups, and XOR each group separately.

## Common mistakes

- Using an `O(n)` auxiliary hash map or sorting in `O(n log n)` when the problem requires `O(n)` time and `O(1)` space.
- Initializing `r` with something other than 0 (e.g. 1).
- Assuming XOR arithmetic works for frequencies other than multiples of 2.
