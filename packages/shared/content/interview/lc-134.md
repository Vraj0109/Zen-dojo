## Clarify first

- Is the road strictly circular and traversed in a single direction? Yes, traveling from station `i` to `(i + 1) % n`.
- What if the total gas available across all stations is less than the total cost? It is mathematically impossible to complete a full circuit, so return -1.
- Is the valid starting station guaranteed to be unique if one exists? Yes, the problem guarantees that if a solution exists, it is unique.
- Can your tank capacity hold unlimited fuel? Yes, the car's fuel tank has no maximum capacity limit.

## Examples to say out loud

- Complete circuit: `gas = [1, 2, 3, 4, 5]`, `cost = [3, 4, 5, 1, 2]`.
  - Differences `gas[i] - cost[i]` are `[-2, -2, -2, +3, +3]`.
  - Total sum is `(-6) + 6 = 0 >= 0`, so a solution exists.
  - Starting at station 3 (index 3):
    - Depart 3: tank = `0 + 4 - 1 = 3`.
    - Depart 4: tank = `3 + 5 - 2 = 6`.
    - Depart 0: tank = `6 + 1 - 3 = 4`.
    - Depart 1: tank = `4 + 2 - 4 = 2`.
    - Depart 2: tank = `2 + 3 - 5 = 0`.
    - Returns index 3.
- Insufficient total fuel: `gas = [2, 3, 4]`, `cost = [3, 4, 3]`. Total gas is 9, total cost is 10. `9 < 10`, returns -1.

## Brute force

A brute-force solution simulates a full circuit from every candidate starting index `s` from 0 to `n - 1`. For each candidate `s`, step through up to `n` stations, adding `gas[i]` and subtracting `cost[i]`. If the running tank dips below 0, abandon candidate `s` and test `s + 1`. In the worst case, simulating `n` steps for `n` candidates takes `O(n^2)` time. With `n = 100,000`, `10^{10}` operations times out.

## The key observation

Two key mathematical insights unlock linear time:
1. If the sum of all `gas[i]` is at least the sum of all `cost[i]` (`\sum (gas[i] - cost[i]) \ge 0`), a valid starting station is guaranteed to exist.
2. If starting at station `A` allows you to reach station `B`, but the fuel tank runs dry trying to reach `B + 1`, then **no station between `A` and `B` can possibly be a valid start**. Why? Because arriving at any intermediate station `k \in [A, B]` with remaining non-negative fuel from `A` still led to a deficit at `B + 1`; starting at `k` with an empty tank can only perform strictly worse. Therefore, we can greedily skip all stations up to `B` and restart our search from `B + 1`.

## Optimal approach

1. Initialize `total = 0` (overall gas balance), `tank = 0` (current fuel from active candidate start), and `start = 0` (candidate starting index).
2. Iterate `i` from 0 to `gas.length - 1`:
   a. Compute net fuel difference `diff = gas[i] - cost[i]`.
   b. Add `diff` to `total`.
   c. Add `diff` to `tank`.
   d. If `tank < 0`:
      - We cannot reach `i + 1` from `start` or any intermediate station.
      - Reset `start = i + 1`.
      - Reset `tank = 0`.
3. If `total < 0`, return -1; otherwise, return `start`.

Complexity:
- Time: `O(n)` because we iterate through the `n` stations once in a single forward pass.
- Space: `O(1)` auxiliary space since only scalar counters are maintained.

## Code walkthrough

In the reference implementation:
- `int total = 0, tank = 0, start = 0;`: tracks overall feasibility, current run fuel balance, and candidate start index.
- `int diff = gas[i] - cost[i]; total += diff; tank += diff;`: updates both the global ledger and local trip tank.
- `if (tank < 0) { start = i + 1; tank = 0; }`: resets search frontier to the next station when the current candidate run fails.
- `return total < 0 ? -1 : start;`: returns -1 if global gas is deficient, or the uniquely surviving start index.

## Test it out loud

- `gas = [5], cost = [4]`:
  - `diff = 5 - 4 = 1`. `total = 1`, `tank = 1 >= 0`. `start = 0`. Returns 0.
- `gas = [1, 2], cost = [2, 1]`:
  - `i = 0`: `diff = 1 - 2 = -1`. `total = -1`, `tank = -1 < 0`. `start` becomes 1, `tank = 0`.
  - `i = 1`: `diff = 2 - 1 = +1`. `total = 0`, `tank = 1`.
  - `total = 0 >= 0`, returns `start = 1`.

## Follow-ups

- Why is a second wrap-around pass from `start` back to `n - 1` unnecessary?
  Because `total >= 0` proves that the surplus accumulated from `start` to `n - 1` is mathematically sufficient to cover the known deficit accumulated from index 0 up to `start - 1`.
- How does this relate to Kadane's algorithm?
  Both maintain a running sum and reset the starting anchor to `i + 1` whenever the running sum becomes negative.

## Common mistakes

- Simulating full circular paths using nested loops, leading to `O(n^2)` time complexity.
- Forgetting to check the global sum `total < 0`, incorrectly returning `start` when no valid circuit is possible.
- Resetting `start = start + 1` instead of jumping directly to `i + 1`, failing to capitalize on the elimination proof.
