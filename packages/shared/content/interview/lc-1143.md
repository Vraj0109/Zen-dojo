## Clarify first

- What is the difference between a substring and a subsequence? A substring is contiguous, whereas a subsequence maintains relative order but elements do not need to be adjacent.
- What if there is no common subsequence? Return 0.
- Do both strings contain only lowercase English letters? Yes, constraints state only lowercase English characters appear.
- What are the length limits? Both strings have lengths between 1 and 1,000.

## Examples to say out loud

- Interleaved match: `text1 = "abcde"`, `text2 = "ace"`.
  - Characters `'a'`, `'c'`, and `'e'` appear in order in both strings.
  - Longest common subsequence is `"ace"`, length is 3.
- Complete match: `text1 = "abc"`, `text2 = "abc"`. Length is 3.
- No characters in common: `text1 = "abc"`, `text2 = "def"`. Length is 0.
- Equal length with gaps: `text1 = "oxcpqrsvwf"`, `text2 = "shmtulqrypy"`. Common characters `'q'` and `'r'` give length 2.

## Brute force

A brute-force solution generates all subsequences of `text1` and checks if each is a subsequence of `text2`. A string of length `n` has `2^n` subsequences. For `n = 1,000`, `2^{1,000}` is unimaginably large and completely impossible to compute.

## The key observation

Let `dp[i][j]` represent the LCS length between prefixes `text1[0..i-1]` and `text2[0..j-1]`. When comparing the current characters `text1[i - 1]` and `text2[j - 1]`: if they match, they can extend the best solution for both shorter prefixes by 1 (`dp[i - 1][j - 1] + 1`). If they do not match, the optimal LCS must come from dropping the character from either `text1` or `text2`: `max(dp[i - 1][j], dp[i][j - 1])`.

## Optimal approach

1. Let `n = text1.length()` and `m = text2.length()`.
2. Allocate a 2D table `dp` of size `(n + 1) \times (m + 1)` filled with zeros.
3. Iterate `i` from 1 to `n`:
   - Iterate `j` from 1 to `m`:
     - If `text1[i - 1] == text2[j - 1]`:
       - `dp[i][j] = dp[i - 1][j - 1] + 1`.
     - Else:
       - `dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])`.
4. Return `dp[n][m]`.

Complexity:
- Time: `O(n * m)` because every cell in the `(n + 1) \times (m + 1)` table is computed once with `O(1)` operations.
- Space: `O(n * m)` auxiliary space for the DP table (can be optimized to `O(min(n, m))` using two rolling rows).

## Code walkthrough

In the reference implementation:
- `vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));`: sets up the DP matrix where row 0 and col 0 represent base comparisons against an empty prefix.
- `if (text1[i - 1] == text2[j - 1]) dp[i][j] = dp[i - 1][j - 1] + 1;`: consumes matching characters from both strings simultaneously.
- `else dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);`: resolves mismatches by retaining the best result from discarding a character from either string.
- `return dp[n][m];`: yields the final LCS length of the full strings.

## Test it out loud

- `text1 = "abc", text2 = "ac"`:
  - `i = 1 ('a')`: matches `'a'` at `j = 1` -> `dp[1][1] = 1`, `dp[1][2] = 1`.
  - `i = 2 ('b')`: no matches -> row 2 is `[0, 1, 1]`.
  - `i = 3 ('c')`: at `j = 2 ('c')`, matches -> `dp[2][1] + 1 = 1 + 1 = 2`.
  - Result: `dp[3][2] = 2`.
- `text1 = "a", text2 = "b"`: no character matches, `dp[1][1] = 0`. Returns 0.

## Follow-ups

- How would you print the actual LCS string rather than just its length?
  Backtrack from `(n, m)`: if `text1[i - 1] == text2[j - 1]`, prepend the character to the result and move to `(i - 1, j - 1)`; else move to whichever of `(i - 1, j)` or `(i, j - 1)` has the larger DP value.
- How can we optimize space to `O(min(n, m))`?
  Maintain only the previous and current row of length `min(n, m)`.

## Common mistakes

- Indexing off-by-one by confusing 1-indexed DP dimensions with 0-indexed string character positions (`text1[i - 1]` vs `dp[i]`).
- Forgetting that subsequences preserve order, unlike anagrams or bag-of-characters matching.
- Trying a greedy matching approach, which fails on cases like `"ab"` and `"ba"`.
