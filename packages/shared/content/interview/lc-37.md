## Clarify first

- Is the board guaranteed to be exactly 9x9? (Yes, standard 9x9 Sudoku grid).
- Is there always a valid solution, and is it unique? (Yes, the problem guarantees exactly one valid solution).
- What character represents an empty cell? (A period character `"."`).
- Can we modify the board in-place or do we return a new grid? (Modify the board in-place and return it).
- What values are valid for filled cells? (Digits `'1'` through `'9'`).

## Examples to say out loud

- Single missing cell: If 80 of the 81 cells are already filled, the single missing cell in row `r` and column `c` has only one digit from 1 to 9 not already present in its row, column, or 3x3 box. We identify it immediately and place it.
- Branching cell: An empty cell with candidates `{2, 7}`. We try placing `'2'`. If downstream cells lead to a conflict where some empty cell has 0 valid candidates, we backtrack, undo the `'2'`, and try `'7'`.

## Brute force

A naive brute-force generates all possible assignments of digits 1 through 9 for all empty cells without any validation until the end. With up to 81 empty cells, there are $9^{81}$ configurations. Checking validity after filling the entire board takes `O(81)` per configuration, leading to astronomical and infeasible running time.

## The key observation

Sudoku is a exact-cover constraint satisfaction problem. Instead of guessing blindly, we enforce three constraints concurrently: no duplicate digits in any row, column, or 3x3 block. By maintaining bitmasks for used digits in each row, column, and subgrid, candidate validation takes `O(1)` bitwise operations. Backtracking immediately prunes branches whenever a digit violates any constraint.

## Optimal approach

1. Pre-process the initial board to populate three bitmask arrays of length 9: `rowMask`, `colMask`, and `boxMask`. For each already placed digit `d`, set the bit `1 << d` in the corresponding masks.
2. Define a recursive backtracking function `solve(board)`:
   a. Scan the board for the next empty cell `board[r][c] == "."`.
   b. Calculate its sub-box index: `bIdx = (r / 3) * 3 + (c / 3)`.
   c. Iterate through candidate digits `d` from 1 to 9:
      - Form mask bit `1 << d`.
      - If `bit` is already set in `rowMask[r]`, `colMask[c]`, or `boxMask[bIdx]`, skip it.
      - Place `d` at `board[r][c]`, mark `bit` in all three masks.
      - Recursively call `solve(board)`. If it returns `true`, propagate `true` upward immediately.
      - Backtrack: reset `board[r][c] = "."` and unset `bit` from all three masks.
   d. If all digits 1-9 fail for this empty cell, return `false`.
3. If no empty cell is found during the scan, the puzzle is solved; return `true`.

Complexity:
- Time: `O(9^m)` in the worst case where `m` is the number of empty cells ($m \le 81$), though heavily pruned by bitmask constraints to run in milliseconds.
- Space: `O(m)` auxiliary space for the recursion stack plus `O(1)` for fixed 9-element bitmask arrays.

## Code walkthrough

In the reference implementation:
- `rowMask[9]`, `colMask[9]`, `boxMask[9]`: track digit presence using bit positions 1 through 9.
- `int bIdx = (r / 3) * 3 + (c / 3);`: maps coordinates `(r, c)` to its 3x3 box index from 0 to 8.
- `if ((rowMask[r] & bit) || (colMask[c] & bit) || (boxMask[bIdx] & bit)) continue;`: validates candidate `d` in `O(1)` bitwise operations.
- `rowMask[r] |= bit; ... b[r][c] = to_string(d);`: places candidate and updates constraints.
- `if (solve(b)) return true;`: early exit upon finding the unique solution.
- `b[r][c] = "."; rowMask[r] &= ~bit; ...`: cleans up state upon dead end.

## Test it out loud

- Board with 1 empty cell: Bitmasks identify the only missing digit; loop tries candidate, succeeds on first attempt, returns `true`.
- Board requiring deep backtracking: Candidate choices that seem valid locally fail several levels deeper; recursion unwinds and explores alternative branches until valid configuration is reached.
- Box boundary index check: Cell `(2, 2)` maps to box 0, while `(2, 3)` maps to box 1, ensuring subgrid constraints isolate correctly across boundaries.

## Follow-ups

- How to speed up search on harder puzzles?
  Use the Minimum Remaining Values (MRV) heuristic: select the empty cell with the fewest available candidate digits first to fail early and minimize branching.
- How does Algorithm X / Dancing Links (DLX) compare?
  Donald Knuth's DLX represents Sudoku as an exact cover matrix with 324 columns and 729 rows, achieving maximum theoretical backtracking speed.
- What if multiple solutions exist and we need to count them?
  Remove the early exit `return true;`, increment a counter when all cells are filled, and stop if counter exceeds a target threshold.

## Common mistakes

- 1-based vs 0-based digit shifting: shifting `1 << d` when `d` is 1 to 9 requires either size-10 masks or shifting `1 << (d - 1)`.
- Forgetting to reset the cell back to `"."` or unmask bits when a recursive path fails.
- Incorrect box index calculation: forgetting integer division precedence or using `(r % 3) * 3 + (c % 3)`.
