## Clarify first

- Can individual strings be empty? (Yes, string lengths range from 0 to 100).
- What character set do the strings contain? (Only lowercase English letters 'a' through 'z').
- Can the input array have duplicates of the exact same word? (Yes, duplicates are identical anagrams and belong in the same group).
- Does the order of output groups or strings inside groups matter? (No, any group order and string order is accepted).
- What are the scale limits on the number of strings and their lengths? (Up to 10,000 strings, each at most 100 characters long).

## Examples to say out loud

- Standard set: `strs = ["eat", "tea", "tan", "ate", "nat", "bat"]`.
  - Words "eat", "tea", "ate" share letter counts: one 'a', one 'e', one 't'. They form `["eat", "tea", "ate"]`.
  - Words "tan" and "nat" share one 'a', one 'n', one 't'. They form `["tan", "nat"]`.
  - Word "bat" has one 'a', one 'b', one 't'. It forms `["bat"]`.
- Empty strings: `strs = ["", ""]`. Both have length 0, share empty character counts, and form `[["", ""]]`.
- Single character strings: `strs = ["a", "b", "a"]`. Forms `[["a", "a"], ["b"]]`.

## Brute force

A brute-force strategy compares every string with all others. For each unvisited string `s`, scan all other strings `t` and check if `t` is an anagram of `s` (for example, by building frequency tables of size 26 in `O(k)` time). Group all matches together and mark them as collected. With `n` strings, comparing pairs takes `O(n^2 * k)` time. With `n = 10,000`, `n^2 * k` is `10^10` operations, which is completely unfeasible.

## The key observation

Two strings are anagrams if and only if they share the exact same character frequency signature. If we compute a canonical representation for each word—such as a tuple or formatted string representing the 26 character counts—all anagrams map to the exact same key. We can group all words in a hash table by this canonical signature in a single pass.

## Optimal approach

1. Create a hash map `groups` mapping a signature string or tuple to a list of original words.
2. For each string `s` in `strs`:
   a. Build an array of length 26 counting occurrences of each letter `'a'` through `'z'`.
   b. Convert this count array into a canonical string key (e.g., delimited counts `#1#0#0...`).
   c. Append `s` to `groups[key]`.
3. Collect and return all value lists from `groups`.

Complexity:
- Time: `O(n * k)` where `n` is the number of strings and `k` is the maximum string length. Counting letters takes `O(k)` per word and serialization of 26 counts takes `O(26) = O(1)`. This is strictly faster than sorting each word which takes `O(n * k log k)`.
- Space: `O(n * k)` auxiliary space to store all `n` words of length `k` and their signatures in the hash map.

## Code walkthrough

In reference solutions, words are often sorted to produce keys (`sort(key.begin(), key.end())`), running in `O(n * k log k)` time. In an interview, we explain both:
- `for (const string& s : strs)`: iterates through each word once.
- Counting representation: `int count[26] = {0};` populated by `count[c - 'a']++` for each character `c` in `s`.
- `string key`: serialized count array or sorted string used as index in `unordered_map<string, vector<string>> groups;`.
- `groups[key].push_back(s);`: places the word into its anagram bucket in average `O(1)` time.
- Return the vectors stored in `groups`.

## Test it out loud

- `strs = ["ab", "ba"]`:
  - "ab" produces counts `a:1, b:1`. Group key is created with `["ab"]`.
  - "ba" produces counts `a:1, b:1`. Key matches, word appended to get `["ab", "ba"]`.
- `strs = [""]`:
  - All 26 counts are zero. Stored in group `[[""]]`.
- `strs = ["aab", "aba", "baa", "abb"]`:
  - First three have `a:2, b:1`, forming group `["aab", "aba", "baa"]`.
  - Last word has `a:1, b:2`, forming group `["abb"]`.

## Follow-ups

- What if strings contain arbitrary Unicode characters or large alphabets?
  Sorting words (`O(n * k log k)`) becomes cleaner than fixed 26-element arrays, or a sparse frequency map / tuple can be used.
- What if the dataset is too huge to fit into memory?
  Stream through words, write `(signature, word)` records to disk, and use an external merge sort or distributed MapReduce grouped by signature.
- What if `k` is very large (long documents)?
  Computing 26-integer count signatures in `O(k)` is far superior to `O(k log k)` sorting.

## Common mistakes

- Relying on simple ASCII sum or product hashes without full counts; character sums collide easily (e.g., "ac" and "bb" have identical sums 196).
- Creating un-delimited count strings: counts 1 and 11 can clash with 11 and 1 if numbers are concatenated without separators.
- Sorting the input list of words rather than sorting the characters within each word.
