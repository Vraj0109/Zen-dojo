## Clarify first

- Can the root node be null? Yes, 0 nodes is possible; return an empty list `[]`.
- In what format should the result be returned? A list of lists, where each sub-list contains node values on that level ordered left to right.
- What are the tree size bounds? Between 0 and 2,000 nodes.
- Can values be negative? Yes, values range from -1,000 to 1,000.

## Examples to say out loud

- Multi-level tree: `root = [3, 9, 20, null, null, 15, 7]`.
  - Level 0: `[3]`.
  - Level 1: `[9, 20]`.
  - Level 2: `[15, 7]`.
  - Returned structure: `[[3], [9, 20], [15, 7]]`.
- Single node tree: `root = [1]`. Level 0 is `[1]`, returns `[[1]]`.
- Empty tree: `root = []`. Returns `[]`.

## Brute force

A brute-force strategy computes the total height `h` of the tree, and then for every level `d` from 0 to `h - 1`, calls a recursive function that prints nodes at depth `d`. Because every level re-traverses from the root down to depth `d`, this approach takes `O(n * h)` time, which degrades to `O(n^2)` for skewed trees.

## The key observation

A queue processes nodes in First-In, First-Out (FIFO) order. By capturing the queue's size at the beginning of each iteration, we delineate the exact boundary of the current tree level. All nodes currently in the queue belong to this level, and any children pushed during the level's processing belong to the next level.

## Optimal approach

1. If `root == null`, return an empty list.
2. Initialize a queue with `root` and an empty list `out` to store level lists.
3. While the queue is not empty:
   a. Let `n = queue.size()`.
   b. Allocate a temporary list `level` for the current tier.
   c. Loop `n` times:
      i. Dequeue node `x`.
      ii. Append `x.val` to `level`.
      iii. If `x.left` exists, enqueue `x.left`.
      iv. If `x.right` exists, enqueue `x.right`.
   d. Append `level` to `out`.
4. Return `out`.

Complexity:
- Time: `O(n)` because every node is enqueued and dequeued exactly once.
- Space: `O(w)` auxiliary queue memory, where `w` is the maximum width of the tree (`w <= n / 2` for a complete binary tree).

## Code walkthrough

In the reference implementation:
- `if (!root) return out;`: handles null trees immediately.
- `queue<TreeNode*> q; q.push(root);`: initiates BFS from the root.
- `int n = (int)q.size();`: snapshots the exact node count residing at the active level.
- `for (int i = 0; i < n; i++)`: processes only nodes belonging to this level.
- `if (x->left) q.push(x->left); if (x->right) q.push(x->right);`: schedules next level's children into the queue.
- `out.push_back(level);`: saves the completed tier.

## Test it out loud

- `root = [1, 2, 3, null, 4, null, 5]`:
  - Level 0: queue has `[1]`. Size is 1. Pop 1, push left 2 and right 3. Level 0 is `[1]`.
  - Level 1: queue has `[2, 3]`. Size is 2. Pop 2, push right 4. Pop 3, push right 5. Level 1 is `[2, 3]`.
  - Level 2: queue has `[4, 5]`. Size is 2. Pop 4 (no children). Pop 5 (no children). Level 2 is `[4, 5]`.
  - Queue is empty, returns `[[1], [2, 3], [4, 5]]`.
- `root = []`:
  - Root is null, returns `[]`.

## Follow-ups

- How would you implement zigzag (spiral) level order traversal (LeetCode 103)?
  Alternate reversing the level array, or use a deque to push and pop from alternating ends based on level depth.
- Can this be solved using DFS?
  Yes, pass current depth as a parameter; if `depth == out.size()`, append a new list to `out`, then append `node.val` to `out[depth]`.

## Common mistakes

- Recomputing `q.size()` dynamically inside the `for` loop condition (`i < q.size()`), which causes newly pushed children to be processed on the current level.
- Failing to check if `root == null` before accessing children or pushing into the queue.
- Enqueueing null children, which requires null checks upon dequeueing.
