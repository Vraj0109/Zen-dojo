## Clarify first
- How are course indices indexed in the input? Courses are 1-indexed from 1 to n, while array `time` is 0-indexed (course `i` takes `time[i - 1]` months).
- Can multiple courses be taken in parallel? Yes, any number of courses can be taken simultaneously as soon as all their respective prerequisites are completed.
- Are cycles possible in the relations? No, constraints guarantee the dependency graph is a directed acyclic graph (DAG).
- What should be returned? The minimum total time needed to complete all n courses.

## Examples to say out loud
- Consider `n = 3`, `relations = [[1, 3], [2, 3]]`, `time = [3, 2, 5]`:
  - Courses 1 and 2 have no prerequisites and can run concurrently from month 0.
  - Course 1 finishes at month 3; course 2 finishes at month 2.
  - Course 3 requires both 1 and 2, so it cannot start until month `max(3, 2) = 3`.
  - Course 3 finishes at month `3 + 5 = 8`.
  - Total minimum time is 8.
- Independent courses: `n = 3`, `relations = []`, `time = [4, 9, 2]`.
  - All three run in parallel from month 0. Total time is `max(4, 9, 2) = 9`.

## Brute force
A naive approach might try simulating time month by month, tracking active courses and remaining durations. However, since course times can reach 10,000 and dependencies chain together, time-stepping simulation is needlessly slow and complex. Alternatively, finding paths by running DFS from every single course to calculate completion times incurs redundant subproblem evaluations without memoization.

## The key observation
Since the courses and prerequisites form a DAG, the minimum time to complete all courses is the length of the longest path in the DAG, where node weights represent course completion times.
For any course `c`, its earliest possible start time `start[c]` is determined by the latest finish time among all of its prerequisites:
`start[c] = max(finish[p])` for all prerequisite courses `p` of `c`.
Its finish time is simply `finish[c] = start[c] + time[c]`.
Processing courses in topological order guarantees that when a course is evaluated, the finish times of all its prerequisites have already been finalized.

## Optimal approach
1. Build an adjacency list `g` of size `n + 1` and track in-degrees `indeg`. For each relation `[a, b]`, add edge `a -> b` and increment `indeg[b]`.
2. Initialize an array `start` of size `n + 1` with 0s.
3. Enqueue all courses `i` with `indeg[i] == 0` into a FIFO queue `q`.
4. Initialize `best = 0`.
5. While `q` is not empty:
   - Dequeue course `u`.
   - Calculate its finish time: `fin = start[u] + time[u - 1]`.
   - Update `best = max(best, fin)`.
   - For each dependent course `v` in `g[u]`:
     - Update its earliest start time: `start[v] = max(start[v], fin)`.
     - Decrement `indeg[v]`.
     - If `indeg[v] == 0`, enqueue `v`.
6. Return `best`.

Complexity:
- Time complexity: O(n + E) where n is the number of courses and E is the number of prerequisite relations. Kahn's algorithm processes every node and edge exactly once.
- Space complexity: O(n + E) auxiliary space for the graph representation, in-degree array, start time array, and queue.

## Code walkthrough
- `vector<int> indeg(n + 1, 0), start(n + 1, 0)`: Tracks prerequisites and earliest unlocked starting month for 1-indexed courses.
- `int fin = start[u] + time[u - 1]`: Computes completion time for course `u` taking 0-indexed `time` into account.
- `best = max(best, fin)`: Records the latest finish time across all courses.
- `start[v] = max(start[v], fin)`: Relaxes the start time of dependent child courses based on prerequisite finish times.
- `if (--indeg[v] == 0) q.push(v)`: Enqueues child node once all its prerequisites have finalized.

## Test it out loud
- Test `n = 1, relations = [], time = [7]`:
  - `indeg[1] = 0`, `q = [1]`.
  - `fin = 0 + 7 = 7`, `best = 7`. Returns 7. Correct.
- Test chain `n = 3, relations = [[1, 2], [2, 3]], time = [1, 2, 3]`:
  - Course 1 finishes at 1. Updates `start[2] = 1`.
  - Course 2 finishes at `1 + 2 = 3`. Updates `start[3] = 3`.
  - Course 3 finishes at `3 + 3 = 6`. `best = 6`. Returns 6. Correct.

## Follow-ups
- Can this be solved with DFS and memoization? Yes, a recursive post-order DFS computing `memo[u] = time[u - 1] + max(dfs(v) for v in g[u])` yields the exact same O(n + E) time.
- What if there was a constraint on the maximum number of courses that could be taken in parallel (k courses at a time)? That changes the problem to Parallel Courses II, which requires bitmask dynamic programming and is NP-hard in general.

## Common mistakes
- Off-by-one errors with 1-based indexing for courses versus 0-based indexing for the `time` array (`time[u - 1]`).
- Taking the sum of prerequisite times instead of the maximum, ignoring that prerequisites can run in parallel.
- Overwriting `start[v]` instead of taking the maximum across multiple prerequisite completions (`start[v] = max(start[v], fin)`).
