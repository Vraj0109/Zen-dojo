## Clarify first

- What is a "happy prefix"? A non-empty proper prefix of string `s` that is also a suffix of `s`.
- What does "proper" mean? It cannot be the entire string `s` itself (length must be strictly less than `s.length`).
- What should be returned if no such prefix exists? Return the empty string `""`.
- What characters appear in `s`? Lowercase English letters only, with length up to 100,000.

## Examples to say out loud

- Single character overlap: `s = "level"`.
  - Prefix `"l"` matches suffix `"l"`.
  - Length is 1, returns `"l"`.
- Multi-character overlap: `s = "ababab"`.
  - Proper prefixes that are suffixes: `"ab"` (length 2), `"abab"` (length 4).
  - Longest is `"abab"`.
- Repeating characters: `s = "aaaa"`.
  - Length 3 prefix `"aaa"` matches suffix `"aaa"`. Returns `"aaa"`.
- No overlap: `s = "abc"`. No proper prefix equals a suffix, returns `""`.

## Brute force

A brute-force solution checks every prefix length `len` from `n - 1` down to 1. For each `len`, compare substring `s[0..len-1]` with suffix `s[n-len..n-1]`. Because comparing two substrings of length `len` takes `O(len)` time, testing all `n - 1` lengths takes `O(n^2)` time. With `n = 100,000`, `10^{10}` character comparisons will time out.

## The key observation

The problem asks for the longest proper prefix of `s` that is also a suffix of `s`. This is precisely what the **Knuth-Morris-Pratt (KMP) prefix function** (commonly denoted as `pi` or `fail` table) computes! For any string `s`, `pi[n - 1]` gives the length of the longest proper prefix of `s[0..n-1]` that is also a suffix of `s[0..n-1]`. Computing the KMP prefix table takes linear `O(n)` time.

## Optimal approach

1. Let `n = s.length()`.
2. Allocate an array `pi` of size `n` initialized to 0.
3. Iterate `i` from 1 to `n - 1`:
   a. Initialize candidate length `k = pi[i - 1]`.
   b. While `k > 0` and `s[i] != s[k]`:
      - Fall back to the next shorter valid prefix: `k = pi[k - 1]`.
   c. If `s[i] == s[k]`:
      - Extend the match: `k++`.
   d. Record `pi[i] = k`.
4. The length of the longest happy prefix is `len = pi[n - 1]`.
5. Return the substring `s.substr(0, len)`.

Complexity:
- Time: `O(n)` because computing the KMP `pi` array processes each character in amortized `O(1)` time (the pointer `k` increases by at most 1 per step, so it decrements at most `n` times in total).
- Space: `O(n)` auxiliary space to store the prefix function array `pi`.

## Code walkthrough

In the reference implementation:
- `vector<int> pi(n, 0);`: stores the length of the longest proper prefix that is also a suffix for each prefix `s[0..i]`.
- `int k = pi[i - 1];`: seeds candidate match length from the immediately preceding character.
- `while (k > 0 && s[i] != s[k]) k = pi[k - 1];`: jumps back through the failure chain when the extending character mismatches.
- `if (s[i] == s[k]) k++; pi[i] = k;`: extends the prefix-suffix match length upon character equality.
- `return s.substr(0, pi[n - 1]);`: extracts the happy prefix using the final computed length.

## Test it out loud

- `s = "level"`:
  - `i = 1 ('e')`: `s[1] != s[0]`, `pi[1] = 0`.
  - `i = 2 ('v')`: `pi[2] = 0`.
  - `i = 3 ('e')`: `pi[3] = 0`.
  - `i = 4 ('l')`: `s[4] == s[0] ('l')`, `k = 1`, `pi[4] = 1`.
  - Returns `s.substr(0, 1) = "l"`.
- `s = "ababab"`:
  - `pi` array becomes `[0, 0, 1, 2, 3, 4]`.
  - `pi[5] = 4`, returns `s.substr(0, 4) = "abab"`.
- `s = "abc"`: `pi[2] = 0`, returns `""`.

## Follow-ups

- Can this be solved using polynomial rolling hashes (Rabin-Karp)?
  Yes, compute rolling prefix hash and rolling suffix hash in `O(n)` time, though hash collisions must be guarded against with double hashing or verification.
- How does this relate to finding the period of a repeating string (LeetCode 459: Repeated Substring Pattern)?
  A string has a repeating period if `pi[n - 1] > 0` and `n % (n - pi[n - 1]) == 0`.

## Common mistakes

- Off-by-one errors in KMP transition: writing `k = pi[k]` instead of `k = pi[k - 1]`.
- Returning the entire string `s` when all characters match (e.g. `"aaaa"` must return `"aaa"`, not `"aaaa"`), which is naturally prevented because the loop only runs up to `n - 1`.
- Using naive quadratic string slicing and comparisons.
