## Clarify first

- Can the robot move diagonally or backward? No, valid moves are strictly right and down.
- Are there any obstacles in the grid? No obstacles in this version; all cells are passable.
- What if `m = 1` or `n = 1`? There is only a single straight-line path (all rights or all downs), so return 1.
- What are the dimensions and answer constraints? `m` and `n` are between 1 and 100, and the total path count fits within a 32-bit signed integer.

## Examples to say out loud

- Rectangular grid: `m = 3, n = 7`.
  - Robot must make `m - 1 = 2` down moves and `n - 1 = 6` right moves (total 8 moves).
  - Number of distinct path combinations is 28.
- Small grid: `m = 3, n = 2`.
  - The paths are: Down-Down-Right, Down-Right-Down, Right-Down-Down. Total is 3.
- Single cell edge case: `m = 1, n = 1`. Start is already destination, returns 1.

## Brute force

A brute-force recursive function branches into two calls at each cell `(r, c)`: `paths(r, c) = paths(r + 1, c) + paths(r, c + 1)`. Since each cell branches twice until reaching the boundary, the depth of the recursion tree is `(m - 1) + (n - 1)`. Without caching, this executes `O(2^{m + n})` operations, which quickly times out for `m = 20, n = 20`.

## The key observation

To arrive at any cell `(r, c)`, the robot must have arrived from either the cell directly above `(r - 1, c)` or the cell directly to the left `(r, c - 1)`. By the addition rule of independent choices, `dp[r][c] = dp[r - 1][c] + dp[r][c - 1]`. Because computing any row only requires the current row and the row above, we can compress the 2D table into a single 1D rolling array of size `n`.

## Optimal approach

1. Allocate a 1D array `dp` of size `n` initialized to 1 (representing the first row where every cell has exactly 1 incoming path).
2. For each row `r` from 1 to `m - 1`:
   - For each column `c` from 1 to `n - 1`:
     - Update `dp[c] = dp[c] + dp[c - 1]` (where `dp[c]` on the right-hand side represents the value from the cell above, and `dp[c - 1]` represents the value from the left).
3. Return `dp[n - 1]`.

Complexity:
- Time: `O(m * n)` because we process each of the `m * n` grid cells with constant-time addition.
- Space: `O(n)` auxiliary space for the rolling 1D DP array of width `n`.

## Code walkthrough

In the reference implementation:
- `vector<int> dp(n, 1);`: fills the single row buffer with 1s, satisfying base cases for row 0.
- `for (int r = 1; r < m; r++)`: iterates downward across all remaining rows.
- `for (int c = 1; c < n; c++) dp[c] += dp[c - 1];`: accumulates incoming paths from the top (`dp[c]`) and from the left (`dp[c - 1]`).
- `return dp[n - 1];`: returns total paths arriving at the bottom-right corner.

## Test it out loud

- `m = 3, n = 2`:
  - Start `dp = [1, 1]`.
  - Row 1: `dp[1] += dp[0]` -> `1 + 1 = 2`. `dp` is `[1, 2]`.
  - Row 2: `dp[1] += dp[0]` -> `2 + 1 = 3`. `dp` is `[1, 3]`.
  - Return `dp[1] = 3`.
- `m = 1, n = 5`: loop does not execute; returns `dp[4] = 1`.

## Follow-ups

- Can this be computed in `O(min(m, n))` time without a DP array?
  Yes, combinatorially: total steps is `N = m + n - 2`, and we choose `k = min(m - 1, n - 1)` down moves: `binom(N, k) = \frac{N \times (N-1) \times \dots \times (N-k+1)}{k!}` computed with 64-bit integers in `O(min(m, n))` time and `O(1)` space.
- What if some cells contain obstacles (Unique Paths II, LeetCode 63)?
  Set `dp[c] = 0` whenever cell `(r, c)` contains an obstacle.

## Common mistakes

- Allocating a full `m \times n` matrix when a single rolling row of size `n` suffices.
- Integer overflow when calculating combinations `binom(m + n - 2, m - 1)` with factorial multiplication rather than iterative multiply-and-divide.
- Off-by-one errors with base boundary rows and columns.
