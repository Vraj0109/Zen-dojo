## Clarify first

- What should be computed? The sum of minimum elements over all possible contiguous subarrays of `arr`.
- Can the answer be very large? Yes, return the result modulo `1,000,000,007`.
- Can the array contain duplicate values? Yes, values can be identical, which requires careful tie-breaking so subarrays with equal minimums are counted exactly once.
- What are the constraints on array length and values? Length is between 1 and 30,000, and values are between 1 and 30,000.

## Examples to say out loud

- Small array: `arr = [3, 1, 2, 4]`.
  - Subarrays: `[3]` (3), `[1]` (1), `[2]` (2), `[4]` (4).
  - Length 2: `[3,1]` (1), `[1,2]` (1), `[2,4]` (2).
  - Length 3: `[3,1,2]` (1), `[1,2,4]` (1).
  - Length 4: `[3,1,2,4]` (1).
  - Sum: `3 + 1 + 2 + 4 + 1 + 1 + 2 + 1 + 1 + 1 = 17`.
- Single element: `arr = [5]`. Subarray `[5]` minimum is 5.
- Identical elements: `arr = [1, 1, 1]`. All 6 subarrays have minimum 1, sum = 6.

## Brute force

A brute-force solution iterates over all `n * (n + 1) / 2` contiguous subarrays, finds the minimum in each subarray, and sums them up modulo `10^9 + 7`. Generating and finding minimums for all subarrays takes `O(n^2)` time with running minimums. For `n = 30,000`, `n^2 \approx 9 \times 10^8` operations, which exceeds the time limit.

## The key observation

Instead of asking "what is the minimum of each subarray?", invert the question using the **contribution technique**: "For each element `arr[i]`, in how many contiguous subarrays is `arr[i]` the minimum element?"
Element `arr[i]` remains the minimum as long as the subarray does not extend past a smaller element to the left or a smaller element to the right. Let `left[i]` be the distance to the previous strictly smaller element, and `right[i]` be the distance to the next smaller or equal element. Then `arr[i]` is the minimum for exactly `left[i] \times right[i]` subarrays. Breaking ties strictly on one side prevents double counting duplicate minimums.

## Optimal approach

1. Let `n = arr.length` and `MOD = 10^9 + 7`.
2. Allocate arrays `left` and `right` of size `n`.
3. First pass (monotonic stack for previous strictly smaller element):
   - For `i` from 0 to `n - 1`:
     - Pop while `st.top()` has `arr[st.top()] >= arr[i]`.
     - `left[i] = st.empty() ? i + 1 : i - st.top()`.
     - Push `i`.
4. Clear stack and perform second pass (monotonic stack for next smaller-or-equal element):
   - For `i` from `n - 1` down to 0:
     - Pop while `st.top()` has `arr[st.top()] > arr[i]`.
     - `right[i] = st.empty() ? n - i : st.top() - i`.
     - Push `i`.
5. Compute total sum: for each `i`, add `(arr[i] \times left[i] \times right[i]) % MOD` to `ans`.
6. Return `ans % MOD`.

Complexity:
- Time: `O(n)` because each index is pushed and popped from the monotonic stack at most once in both passes.
- Space: `O(n)` auxiliary space to store the `left` and `right` span arrays and the stack.

## Code walkthrough

In the reference implementation:
- `left[i] = st.empty() ? i + 1 : i - st.top();`: computes the number of contiguous choices extending leftward where `arr[i]` is strictly minimum.
- `while (!st.empty() && arr[st.top()] > arr[i]) st.pop();`: rightward pass pops only strictly greater elements, breaking ties symmetrically.
- `right[i] = st.empty() ? n - i : st.top() - i;`: computes contiguous choices extending rightward.
- `long long term = (long long)arr[i] * left[i] % MOD * right[i] % MOD;`: multiplies contribution count by value modulo `10^9 + 7`.
- `total = (total + term) % MOD;`: accumulates total sum across all elements.

## Test it out loud

- `arr = [3, 1, 2, 4]`:
  - For 3: `left = 1`, `right = 1`. Subarrays = 1. Contribution = `3 * 1 = 3`.
  - For 1: `left = 2` (3, 1), `right = 3` (1, 2, 4). Subarrays = `2 * 3 = 6`. Contribution = `1 * 6 = 6`.
  - For 2: `left = 1` (2), `right = 2` (2, 4). Subarrays = `1 * 2 = 2`. Contribution = `2 * 2 = 4`.
  - For 4: `left = 1` (4), `right = 1` (4). Subarrays = 1. Contribution = `4 * 1 = 4`.
  - Total = `3 + 6 + 4 + 4 = 17`.

## Follow-ups

- How would you solve Sum of Subarray Maximums?
  The logic is dual: find previous greater and next greater-or-equal elements using a decreasing monotonic stack.
- How does this solve Sum of Subarray Ranges (LeetCode 2104)?
  Subarray range is `max - min`, so compute `sum(subarray maxes) - sum(subarray mins)`.

## Common mistakes

- Using `>=` on both left and right passes, which double counts subarrays that share duplicate minimum values (must use `>=` on one side and `>` on the other).
- Forgetting 64-bit integer casting before multiplying `arr[i] * left[i] * right[i]`, causing integer overflow before the modulo operation.
- Generating all subarrays instead of computing per-element contributions in `O(n)` time.
