## Clarify first
- Are we allowed to modify the node values directly, or must we manipulate pointers? We must reorder the nodes by updating next pointers in place without changing node values.
- How should the list be partitioned when the length is odd? The first half takes the extra node; for example, five nodes split into lengths 3 and 2.
- What if the list has only 0, 1, or 2 nodes? A list with fewer than 3 nodes requires no rearrangement; returning the original head unchanged is correct.
- Does this function return the head node or return void? In standard definitions it modifies in place, but returning the head of the reordered list is standard.

## Examples to say out loud
- Consider `1 -> 2 -> 3 -> 4`. The middle divides into `1 -> 2` and `3 -> 4`. Reversing the second half yields `4 -> 3`. Interleaving front and back gives `1 -> 4 -> 2 -> 3`.
- Edge case: `1 -> 2 -> 3 -> 4 -> 5`. Splitting gives `1 -> 2 -> 3` and `4 -> 5`. Reversing the second half gives `5 -> 4`. Merging alternately gives `1 -> 5 -> 2 -> 4 -> 3`.
- Small boundary: `1 -> 2`. Middle split yields `1` and `2`. Reversing `2` gives `2`. Merging leaves `1 -> 2`.

## Brute force
A direct approach copies all node pointers into an array or deque. Then two pointers, left starting at 0 and right at n - 1, alternate linking nodes together: `arr[left]->next = arr[right]`, then `arr[right]->next = arr[left + 1]`. While this takes O(n) time, it requires O(n) auxiliary space to store node pointers. We can improve auxiliary space to O(1) by restructuring the linked list directly.

## The key observation
The target order alternates one node from the front half and one from the back half read in reverse. Because a singly linked list cannot traverse backward, the back half must be reversed. Once the second half is reversed in place, reordering reduces to weaving two shorter singly linked lists together.

## Optimal approach
1. Find the midpoint of the linked list using slow and fast pointers. Advance slow by 1 step and fast by 2 steps until fast reaches the end. Slow stops at the end of the first half.
2. Sever the list into two halves by setting `slow->next` to null, preserving the head of the second half.
3. Reverse the second half in place using standard three-pointer iterative reversal (`prev`, `cur`, `nx`).
4. Interleave the first half and the reversed second half using two pointers `a` and `b`. In each step, save `a->next` and `b->next`, connect `a->next = b`, connect `b->next = an`, and advance `a` and `b` to their saved successors until `b` is exhausted.

Complexity:
- Time complexity: O(n) because finding the midpoint, reversing half the nodes, and weaving both halves each visit at most n nodes once.
- Space complexity: O(1) auxiliary space as only a constant number of pointer variables are maintained.

## Code walkthrough
- `slow = head, fast = head`: Advance while `fast->next && fast->next->next` so `slow` stops at the midpoint node.
- `cur = slow->next; slow->next = nullptr;`: Splits the list into two disjoint lists.
- Iterative reversal loop: While `cur` is valid, save `nx = cur->next`, flip `cur->next = prev`, shift `prev = cur`, and update `cur = nx`. `prev` becomes the new head of the reversed second half.
- Interleaving loop: While `b` is non-null, store `an = a->next` and `bn = b->next`. Rewire `a->next = b` and `b->next = an`, then step `a = an` and `b = bn`.
- Return `head`.

## Test it out loud
- Test with `[1, 2, 3, 4]`:
  - Slow ends at node 2. Second half is `3 -> 4`.
  - Reversed second half is `4 -> 3`.
  - Weave: `1 -> 4 -> 2 -> 3 -> null`. Matches expected output.
- Test with `[1, 2, 3, 4, 5]`:
  - Slow ends at node 3. Second half is `4 -> 5`.
  - Reversed second half is `5 -> 4`.
  - First step weaves 1 with 5, second weaves 2 with 4, leaving node 3 at the tail. Output `1 -> 5 -> 2 -> 4 -> 3`.
- Test with single node `[7]`: Early exit returns `[7]` immediately without modification.

## Follow-ups
- How would you verify if a linked list is a palindrome using this exact structure? Find the midpoint, reverse the second half, compare node values step-by-step from both heads, and optionally restore the second half by reversing it again.
- Can this be done recursively? Yes, recursion can unwind from the tail to match nodes with the head, but call stack frames consume O(n) memory, violating O(1) auxiliary space.

## Common mistakes
- Forgetting to terminate the first half with `slow->next = nullptr`, which creates a cycle during interleaving.
- Using incorrect loop conditions for fast/slow traversal, causing `slow` to overshoot or causing a null pointer dereference on `fast->next->next`.
- Losing track of next pointers during interleaving by overwriting `a->next` before caching `an`.
