## Clarify first
- What special characters exist in the pattern?
  - `.` matches any single character.
  - `*` matches zero or more occurrences of the preceding element.
- Does `*` match by itself? No, every `*` is guaranteed to follow a valid character or `.`.
- Must the pattern match the entire string `s`? Yes, full string matching is required.
- What are string length constraints? Both `s` and `p` have lengths up to 20, containing only lowercase letters, '.', and '*'.

## Examples to say out loud
- Star with zero occurrences: `s = "aab"`, `p = "c*a*b"`.
  - `"c*"` matches 0 'c's.
  - `"a*"` matches 2 'a's.
  - `"b"` matches 'b'. Matches fully. Output: true.
- Dot and star: `s = "ab"`, `p = ".*"`.
  - `.*` can match any arbitrary sequence of characters. Output: true.
- Star without match: `s = "aa"`, `p = "a"`. Length mismatch. Output: false.

## Brute force
A naive recursive backtracking approach attempts to branch on every `*`: either skip the `*` clause (zero occurrences) or match one character and recurse. Without memoization, repetitive subproblems cause exponential O(2^(|s| + |p|)) time, repeatedly matching the same suffixes. Dynamic programming or memoization reduces runtime to O(|s| * |p|).

## The key observation
Define subproblem `dp[i][j]` as: does suffix `s[i..]` match suffix `p[j..]`?
Let `first_match = (i < |s|) && (p[j] == s[i] || p[j] == '.')`.
Two distinct cases arise based on whether the next character in pattern `p[j + 1]` is `'*'`:
1. If `p[j + 1] == '*'`:
   - Choice A (zero occurrences): Skip `p[j]` and `p[j+1]` completely: `dp[i][j + 2]`.
   - Choice B (one or more occurrences): If `first_match` is true, consume one character from `s` while keeping the `*` pattern active: `first_match && dp[i + 1][j]`.
   - Thus, `dp[i][j] = dp[i][j + 2] || (first_match && dp[i + 1][j])`.
2. Otherwise (no `*` following):
   - We must match exactly one character: `dp[i][j] = first_match && dp[i + 1][j + 1]`.

## Optimal approach
1. Let `n = s.length()` and `m = p.length()`.
2. Allocate a 2D boolean array `dp` of size `(n + 2) x (m + 2)` initialized to false.
3. Base case: `dp[n][m] = true` (empty string matches empty pattern).
4. Iterate `i` from `n` down to 0:
   - Iterate `j` from `m - 1` down to 0:
     - Determine `first = (i < n) && (p[j] == s[i] || p[j] == '.')`.
     - If `j + 1 < m && p[j + 1] == '*'`:
       - `dp[i][j] = dp[i][j + 2] || (first && dp[i + 1][j])`.
     - Else:
       - `dp[i][j] = first && dp[i + 1][j + 1]`.
5. Return `dp[0][0]`.

Complexity:
- Time complexity: O(n * m) because there are `(n + 1) * (m + 1)` states, and each state is computed in O(1) time.
- Space complexity: O(n * m) auxiliary space for the DP table (can be optimized to O(m) space using two rows).

## Code walkthrough
- `dp[n][m] = true`: Both suffixes empty means successful match.
- Loop ranges `i` from `n` down to 0: Evaluates matching against the empty string `s[n..]` (e.g. `s = ""` matching `p = "a*b*"`).
- `bool first = i < n && (p[j] == s[i] || p[j] == '.')`: Validates whether the head character can align.
- `dp[i][j + 2]`: Bypasses the starred character (matching 0 times).
- `first && dp[i + 1][j]`: Consumes `s[i]` and stays at `p[j]` to allow matching multiple consecutive identical characters.
- Returns `dp[0][0]`.

## Test it out loud
- Test `s = "aa", p = "a*"`:
  - `i = 2, j = 0` (empty `s` vs `"a*"`): `first = false`. `dp[2][0] = dp[2][2] (true) || false = true`.
  - `i = 1, j = 0` ('a' vs `"a*"`): `first = true`. `dp[1][0] = dp[1][2] (false) || (true && dp[2][0] (true)) = true`.
  - `i = 0, j = 0` ("aa" vs `"a*"`): `first = true`. `dp[0][0] = dp[0][2] (false) || (true && dp[1][0] (true)) = true`.
  - Returns true. Correct.
- Test `s = "ab", p = ".*"`:
  - `.*` can consume 'a', then 'b', then terminate. Returns true. Correct.

## Follow-ups
- How does Wildcard Matching (LeetCode 44) differ? In Wildcard Matching, `*` stands alone and matches any sequence of characters directly, whereas in regex matching, `*` repeats the single preceding character.
- Can we reconstruct the matched transitions? Backtrack through the DP table from `dp[0][0]` to `dp[n][m]` following the valid transitions.

## Common mistakes
- Not running the `i` loop down to 0 (including `i = n`), which fails to match empty prefixes against patterns like `"a*b*c*"`.
- Confusing the roles of `dp[i + 1][j]` (consuming one char from `s`) and `dp[i][j + 2]` (skipping the `*` pattern).
- Forgetting that `.` can also be repeated by `*` (`.*`).
