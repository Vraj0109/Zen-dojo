## Clarify first
- What are the conditions for a valid pair? Two distinct indices `i` and `j` such that `|i - j| <= indexDiff` and `|nums[i] - nums[j]| <= valueDiff`.
- Can `valueDiff` be negative? Absolute differences are non-negative, so if `valueDiff < 0`, return false immediately.
- Can values overflow 32-bit integers during subtraction? Yes, `nums[i]` ranges from `-10^9` to `10^9`, so `nums[i] - nums[j]` can exceed `2 * 10^9`. We must use 64-bit arithmetic.
- What if `indexDiff >= nums.length`? Any pair within the entire array is index-valid.

## Examples to say out loud
- Consider `nums = [1, 2, 3, 1], indexDiff = 3, valueDiff = 0`:
  - `nums[0] = 1` and `nums[3] = 1`.
  - Index difference `|3 - 0| = 3 <= 3`. Value difference `|1 - 1| = 0 <= 0`.
  - Return true.
- Consider `nums = [1, 5, 9, 1, 5, 9], indexDiff = 2, valueDiff = 3`:
  - Windows of size 3: `[1, 5, 9]`, differences are at least 4.
  - Return false.

## Brute force
A brute-force double loop checks every pair `(i, j)` where `1 <= j - i <= indexDiff`. In the worst case where `indexDiff = n`, this checks `O(n^2)` pairs. For `n = 100000`, `n^2 = 10^10`, which times out. We need a faster approach using a sliding window.

## The key observation
We maintain a sliding window of the last `indexDiff` elements. For each incoming element `x = nums[i]`, we need to determine whether the window contains any number `y` satisfying `x - valueDiff <= y <= x + valueDiff`. In an ordered balanced binary search tree (like `std::set`), finding the smallest element `>= x - valueDiff` is a `lower_bound` query. If that candidate exists and is `<= x + valueDiff`, we have found a valid pair.

## Optimal approach
1. If `valueDiff < 0` or `indexDiff <= 0`, return false.
2. Initialize an ordered set `window` storing 64-bit integers.
3. For each index `i` from `0` to `n - 1`:
   - Query `window.lower_bound((long long)nums[i] - valueDiff)`.
   - If the iterator is not at the end and its value is `<= (long long)nums[i] + valueDiff`, return true.
   - Insert `nums[i]` into `window`.
   - If `i >= indexDiff`, remove `nums[i - indexDiff]` from `window` to keep the window size bounded by `indexDiff`.
4. If no pair is found, return false.

Complexity:
- Time: `O(n log k)` where `k = indexDiff`, because each element is inserted, queried, and erased in an ordered tree of size at most `k`.
- Space: `O(k)` space to hold at most `k` elements in the ordered set.

## Code walkthrough
- `set<long long> window;` maintains elements within the sliding index window in sorted order.
- `auto it = window.lower_bound((long long)nums[i] - valueDiff);` locates the first element in the window with value at least `nums[i] - valueDiff`.
- `if (it != window.end() && *it <= (long long)nums[i] + valueDiff) return true;` confirms whether that smallest candidate also falls below the upper ceiling.
- `window.insert(nums[i]);` registers the current number.
- `if (i >= indexDiff) window.erase(nums[i - indexDiff]);` evicts the element falling outside the sliding window.

## Test it out loud
- Test adjacent duplicates `nums = [1, 1], indexDiff = 1, valueDiff = 0`: Returns true immediately at `i = 1`.
- Test values close enough `nums = [1, 2], indexDiff = 1, valueDiff = 1`: `|1 - 2| = 1 <= 1`, returns true.
- Test values exceeding bound `nums = [1, 2], indexDiff = 1, valueDiff = 0`: Difference 1 > 0, returns false.
- Test large 32-bit values `nums = [-1000000000, 1000000000], indexDiff = 2, valueDiff = 1000000000`: Difference is `2 * 10^9 > 10^9`, returns false.
- Test with `valueDiff = 2000000000`: Difference fits within bound, returns true.

## Follow-ups
- Can this be solved in `O(n)` linear time?
  - Yes, using bucket sort / bucket hashing where each bucket has width `valueDiff + 1`. Each bucket holds at most 1 number, and we only inspect the current bucket and adjacent buckets `b - 1` and `b + 1`.
- Why might someone choose the ordered set approach in an interview?
  - It is standard and straightforward without needing floor division handling for negative integers.

## Common mistakes
- Integer overflow when calculating `nums[i] - valueDiff` or `nums[i] + valueDiff` with signed 32-bit types.
- Evicting elements prematurely or using the wrong eviction index in the sliding window.
