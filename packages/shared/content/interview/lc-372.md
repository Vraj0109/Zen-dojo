## Clarify first
- What modulus should we use? Modulo 1337.
- How is exponent `b` represented? As an array of decimal digits representing a huge non-negative integer.
- How large can `b` be? Up to 2000 digits long, meaning `b` can be on the order of `10^2000`.
- Are there leading zeros in `b`? The constraints state `b` has no leading zeros.

## Examples to say out loud
- Consider `a = 2, b = [3]`:
  - `2^3 = 8`.
  - `8 mod 1337 = 8`.
- Consider `a = 2, b = [1, 0]`:
  - `2^10 = 1024`.
  - `1024 mod 1337 = 1024`.
- Consider `a = 1, b = [4, 3, 3, 8, 5, 2]`:
  - Any power of 1 is 1. Result is 1.

## Brute force
Attempting to convert the digit array `b` into a native integer will overflow even 64-bit and 128-bit integer types, as `b` has up to 2000 digits. Using arbitrary-precision arithmetic without modular reduction during exponentiation would consume astronomical memory and time. We must process the digits sequentially using mathematical properties of modular exponentiation.

## The key observation
If an integer `b` is represented as its previous digits `b'` followed by the last digit `d`, then `b = 10 * b' + d`.
Therefore, `a^b = a^(10 * b' + d) = (a^b')^10 * a^d`.
By processing the array from left to right like Horner's method, if `result` holds the value of `a^(b_prefix) mod 1337`, processing the next digit `d` transforms `result` to `(result^10 * a^d) mod 1337`.

## Optimal approach
1. Implement a helper function `pw(base, e)` that computes `(base^e) mod 1337` using binary exponentiation in `O(log e)` time.
2. Initialize `result = 1`.
3. Reduce `a = a % 1337`.
4. Iterate through each digit `d` in array `b`:
   - Update `result = (pw(result, 10) * pw(a, d)) % 1337`.
5. Return `result` as an integer.

Complexity:
- Time: `O(len(b) * log 10)` which simplifies to `O(len(b))` because each digit requires raising to power 10 and power `d <= 9`, taking a constant number of multiplications.
- Space: `O(1)` auxiliary space.

## Code walkthrough
- `long long pw(long long base, int e)` performs modular repeated squaring:
  - Takes `base %= 1337;` to prevent multiplication overflow.
  - While `e > 0`, if `e & 1`, multiplies `r = (r * base) % 1337`.
  - Squares `base = (base * base) % 1337` and shifts `e >>= 1`.
- `superPow` loops over digits:
  - `for (int d : b)`:
    - Calculates `pw(result, 10)` to shift the existing exponent by one decimal place.
    - Multiplies by `pw(a, d)` to add the contribution of the new digit `d`.
    - Modulates by 1337 at each step.

## Test it out loud
- Test single digit `a = 2, b = [1]`: Returns 2.
- Test `a = 3, b = [2]`: Returns 9.
- Test `a = 7, b = [1, 0, 0]`:
  - Digit 1: `result = pw(1, 10) * pw(7, 1) = 7`.
  - Digit 0: `result = pw(7, 10) * pw(7, 0) = 7^10 mod 1337`.
  - Digit 0: `result = pw(7^10, 10) * 1 = 7^100 mod 1337 = 574`.
- Test `a = 2147483647, b = [2, 0, 0, 0]`: Initial modulo handles large `a`, output matches 407.

## Follow-ups
- Could we use Euler's Totient Theorem here?
  - Yes: `1337 = 7 * 191`, both prime. `phi(1337) = 6 * 190 = 1140`. If `gcd(a, 1337) == 1`, we could reduce the entire exponent `b mod 1140`. However, when `gcd(a, 1337) > 1`, handling the coprimality edge case is tricky, making the digit-by-digit approach simpler and cleaner.

## Common mistakes
- Forgetting to take `a % 1337` initially, which can lead to intermediate overflow before the first multiplication.
- Trying to assemble `b` into a 64-bit integer instead of streaming digit by digit.
