## Clarify first

- Do we need to land exactly on the last index, or can we jump past it? Landing on or jumping past the last index counts as reaching it.
- Can `nums[i]` be 0? Yes, 0 means you cannot jump forward from that position.
- Are we asked for the minimum jumps or just reachability? Only boolean reachability: return `true` if the last index is reachable, `false` otherwise.
- What if the array has length 1? You start on the last index already, so return `true`.

## Examples to say out loud

- Reachable example: `nums = [2, 3, 1, 1, 4]`.
  - Start at index 0: can reach up to index `0 + 2 = 2`.
  - From index 1: can reach up to index `1 + 3 = 4`, which is the last index. Returns `true`.
- Trapped by zero: `nums = [3, 2, 1, 0, 4]`.
  - Index 0 reaches up to 3.
  - Index 1 reaches up to `1 + 2 = 3`.
  - Index 2 reaches up to `2 + 1 = 3`.
  - All paths funnel into index 3 where `nums[3] = 0`. The frontier cannot extend past 3, so index 4 is unreachable. Returns `false`.
- Single element: `nums = [0]`. Already at the last index, returns `true`.

## Brute force

A brute-force recursive or dynamic programming solution computes `canReach(i)` by checking whether any jump `j \in [1, nums[i]]` can reach an index from which the end is reachable. With memoization, each state `i` checks up to `nums[i]` transitions, taking `O(n^2)` time in the worst case. For `n = 10,000`, this takes `10^8` operations, which is slower than necessary.

## The key observation

You do not need to choose a specific jump length: jumping is monotonic in coverage. If you can reach index `k`, you can also reach any index `j < k` by simply taking shorter jumps. Therefore, you only need to track the single scalar `farthest`: the maximum index reachable from any position visited so far. If you ever arrive at an index `i > farthest`, you are stuck and can never proceed.

## Optimal approach

1. Let `n = nums.length`, and initialize `farthest = 0`.
2. Iterate `i` from 0 to `n - 1`:
   a. If `i > farthest`: you cannot reach the current index, return `false`.
   b. Update `farthest = max(farthest, i + nums[i])`.
   c. If `farthest >= n - 1`: the target is reached, return `true` immediately.
3. Return `true` (unreached early return handles single-element arrays).

Complexity:
- Time: `O(n)` because we iterate through the array of length `n` at most once, performing `O(1)` arithmetic per step.
- Space: `O(1)` auxiliary space as we only maintain two scalar integer variables.

## Code walkthrough

In the reference implementation:
- `int farthest = 0, n = (int)nums.size();`: initializes the maximum reachable frontier.
- `if (i > farthest) return false;`: detects when the current index lies beyond the reach of all previous jump options.
- `farthest = max(farthest, i + nums[i]);`: expands the reachable horizon based on the jump capability at index `i`.
- `if (farthest >= n - 1) return true;`: exits early as soon as the last position is covered.

## Test it out loud

- `nums = [1, 0]`:
  - `i = 0`: `farthest = max(0, 0 + 1) = 1 >= 1`. Return `true`.
- `nums = [0, 1]`:
  - `i = 0`: `farthest = max(0, 0 + 0) = 0`.
  - `i = 1`: `i (1) > farthest (0)`, return `false`.
- `nums = [2, 0, 0]`:
  - `i = 0`: `farthest = 2 >= 2`. Return `true`.

## Follow-ups

- What if we need the minimum number of jumps to reach the end (Jump Game II, LeetCode 45)?
  Use a BFS-style level frontier: track `curEnd` and increment jumps whenever the loop index `i` reaches `curEnd`.
- What if negative jumps or directed jumps to specific values are allowed?
  Model as a general graph and find shortest path using standard BFS.

## Common mistakes

- Writing an `O(n^2)` dynamic programming solution when a greedy single-variable frontier solves it in `O(n)` time.
- Forgetting the early exit when `i > farthest`, causing the loop to falsely assume index `i` is reachable.
- Failing on single element arrays like `[0]`, where the answer should be `true` (since the start is already at the destination).
