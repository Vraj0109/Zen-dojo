## Clarify first
- What should be returned if no valid rearrangement exists? Return the empty string `""`.
- What characters does string `s` contain? Only lowercase English letters `'a'` through `'z'`.
- If multiple valid rearrangements exist, which one should we return? The lexicographically smallest one.
- Is it possible for length `n` to be 1? Yes, a string of length 1 is already valid.

## Examples to say out loud
- Consider `s = "aab"`:
  - Frequencies: `a: 2, b: 1`, length is 3. Max frequency is 2 <= `(3 + 1) / 2 = 2`.
  - First position: trying `'a'`, remaining `a: 1, b: 1`, feasible.
  - Second position: cannot use `'a'` (same as previous), so try `'b'`. Remaining `a: 1`, feasible.
  - Third position: use `'a'`. Result is `"aba"`.
- Consider `s = "aaab"`:
  - Frequencies: `a: 3, b: 1`, length is 4. Max frequency is 3 > `(4 + 1) / 2 = 2`.
  - It is impossible to place three `'a'` characters without placing two adjacent to each other. Return `""`.

## Brute force
Generating all permutations and checking adjacent characters would take `O(n!)` time, which is completely infeasible for `n = 500`. We need a greedy approach that construct the string character by character.

## The key observation
A rearrangement is possible if and only if the most frequent character appears at most `(rem + 1) / 2` times, where `rem` is the remaining number of slots. To ensure the result is lexicographically smallest, at each index we iterate over characters from `'a'` to `'z'`. For each candidate character that is distinct from the immediately preceding character, we check whether decrementing its count leaves a feasible configuration for the remaining `rem - 1` positions. Additionally, because the chosen character cannot immediately follow itself, its remaining count in the next step cannot exceed `(rem - 1) / 2`.

## Optimal approach
1. Count the frequency of each character in `s` using an array `cnt` of size 26.
2. Define a feasibility check `feasible(cnt, rem, last)`:
   - If `rem == 0`, return true.
   - If any character has frequency greater than `(rem + 1) / 2`, return false.
   - If `last >= 0` and `cnt[last] > rem / 2`, return false (since `last` cannot occupy the very next slot).
   - Otherwise, return true.
3. Check if the initial configuration `feasible(cnt, n, -1)` is valid. If not, return `""`.
4. Construct the string index by index for `pos` from `0` to `n - 1`:
   - Iterate candidate character `c` from 0 to 25 (`'a'` to `'z'`).
   - If `cnt[c] == 0` or `c == last`, continue.
   - Temporarily decrement `cnt[c]`.
   - If `feasible(cnt, n - pos - 1, c)` is true, append `c` to the output, update `last = c`, and break to the next position.
   - Otherwise, restore `cnt[c]` and try the next candidate.
5. Return the constructed string.

Complexity:
- Time: `O(26 * 26 * n)` where at each of the `n` positions we check up to 26 characters, each evaluating a 26-element array. This is strictly `O(n)` linear time in practice.
- Space: `O(26)` extra space for the character count array.

## Code walkthrough
- `feasible(cnt, rem, last)` validates that the maximum frequency in `cnt` is at most `(rem + 1) / 2` and `cnt[last] <= rem / 2`.
- Outer loop `for (int pos = 0; pos < n; pos++)` determines characters one by one.
- Inner loop `for (int c = 0; c < 26; c++)` searches for the smallest viable letter.
- Decrementing `cnt[c]--` and testing `feasible` guarantees that choosing `c` does not lead to a dead end.
- Appending `c` and updating `last = c` ensures no two consecutive characters are identical.

## Test it out loud
- Test single character `s = "a"`: `n = 1`, `a` has count 1 <= 1, returns `"a"`.
- Test impossible pair `s = "aa"`: `cnt[a] = 2 > (2 + 1) / 2 = 1`, returns `""`.
- Test already alternating `s = "ab"`: outputs `"ab"`.
- Test tie-breaking for lexicographical order `s = "aabb"`:
  - Pos 0: picks `'a'`, `cnt` becomes `a: 1, b: 2`. Feasible because max count 2 <= `(3 + 1) / 2 = 2`.
  - Pos 1: cannot pick `'a'`; picks `'b'`, `cnt` becomes `a: 1, b: 1`.
  - Pos 2: picks `'a'`, `cnt` becomes `a: 0, b: 1`.
  - Pos 3: picks `'b'`. Output is `"abab"`.

## Follow-ups
- What if any valid reorganization is accepted rather than the lexicographically smallest?
  - A max-heap of character frequencies can pair the two most frequent characters greedily in `O(n log 26)`.
- What if the forbidden condition is that no two identical characters appear within distance `k`?
  - Maintain a queue of size `k` to delay re-inserting consumed characters into the candidate pool.

## Common mistakes
- Forgetting that the character chosen at step `pos` cannot be chosen at step `pos + 1`, which requires checking `cnt[last] <= rem / 2`.
- Not verifying feasibility before making greedy decisions, leading to backtracking or impossible states.
