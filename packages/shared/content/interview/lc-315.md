## Clarify first

- Are we counting elements that appear to the right of `i`, or anywhere in the array? Strictly elements to the right of `i` (indices `j > i` where `nums[j] < nums[i]`).
- Do duplicate smaller elements count separately? Yes, if an element appears twice to the right and is smaller, both instances count toward `ans[i]`.
- Can values in `nums` be negative? Yes, values range from -10,000 to 10,000.
- What are the array constraints? Length is between 1 and 100,000.

## Examples to say out loud

- Standard array: `nums = [5, 2, 6, 1]`.
  - For 5: to its right are 2 and 1 (2 smaller). Count = 2.
  - For 2: to its right is 1 (1 smaller). Count = 1.
  - For 6: to its right is 1 (1 smaller). Count = 1.
  - For 1: nothing to its right. Count = 0.
  - Result: `[2, 1, 1, 0]`.
- Reverse sorted array: `nums = [-1, -1]`. Elements to the right are equal (not strictly smaller), result is `[0, 0]`.
- Strictly decreasing: `nums = [3, 2, 1]`. Result: `[2, 1, 0]`.

## Brute force

A brute-force solution uses two nested loops: for each index `i`, scan every index `j > i` and count how many times `nums[j] < nums[i]`. For an array of length `n`, this requires `n * (n - 1) / 2` comparisons, which takes `O(n^2)` time. With `n = 100,000`, this takes `5 \times 10^9` operations and results in a time limit exceeded error.

## The key observation

If we process the array from **right to left**, any element encountered has already seen all elements that sit to its right. At index `i`, the question becomes: "How many numbers currently inserted are strictly smaller than `nums[i]`?"
By shifting the value range `[-10,000, 10,000]` by `+10,001` so that all coordinates are positive, we can maintain frequency counts in a Binary Indexed Tree (Fenwick Tree). Querying `sum(nums[i] - 1)` answers the count in `O(\log V)` time, and updating `add(nums[i])` takes `O(\log V)` time.

## Optimal approach

1. Offset all numbers by `OFF = 10001` so that values map to positive indices in range `[1, 20002]`.
2. Initialize a Fenwick tree (Binary Indexed Tree) `bit` of size `V = 20003` with all zeros.
3. Allocate an answer array `ans` of size `n`.
4. Traverse `nums` from right to left (`i` from `n - 1` down to 0):
   a. Let `p = nums[i] + OFF`.
   b. Query the Fenwick tree for the frequency of elements strictly smaller than `p`: `ans[i] = query(p - 1)`.
   c. Insert the current element into the Fenwick tree: `add(p)`.
5. Return `ans`.

Complexity:
- Time: `O(n log V)` where `n` is `nums.length` and `V = 20001` is the value span. For `n = 100,000`, `\log V \approx 15`, requiring roughly `1.5 \times 10^6` operations.
- Space: `O(V)` auxiliary space for the Fenwick tree array of size 20,003 (plus `O(n)` output array).

## Code walkthrough

In the reference implementation:
- `const int OFF = 10001, V = 20003;`: defines value domain offset to accommodate negative inputs.
- `auto add = ...`: standard point-update in a Fenwick tree using bit manipulation `i += i & -i`.
- `auto sum = ...`: computes prefix sum in logarithmic time using `i -= i & -i`.
- `for (int i = (int)nums.size() - 1; i >= 0; i--)`: right-to-left traversal ensures only future elements reside in the data structure.
- `ans[i] = sum(p - 1); add(p);`: records strictly smaller count before adding the current element.

## Test it out loud

- `nums = [5, 2, 6, 1]`:
  - `i = 3 (1)`: `sum(1 - 1) = sum(0) = 0`. `ans[3] = 0`. Add 1.
  - `i = 2 (6)`: `sum(6 - 1) = sum(5)` (contains 1) = 1. `ans[2] = 1`. Add 6.
  - `i = 1 (2)`: `sum(2 - 1) = sum(1)` (contains 1) = 1. `ans[1] = 1`. Add 2.
  - `i = 0 (5)`: `sum(5 - 1) = sum(4)` (contains 1 and 2) = 2. `ans[0] = 2`. Add 5.
  - Output is `[2, 1, 1, 0]`.
- `nums = [-1]`: `ans[0] = 0`. Output `[0]`.

## Follow-ups

- How would you solve this if the value range was arbitrary (e.g. up to `10^9`)?
  Coordinate compress the values to rank indices `[0, n - 1]` in `O(n log n)` time, then use a Fenwick tree of size `n`, achieving `O(n log n)` time and `O(n)` space.
- Can this be solved using modified Merge Sort?
  Yes, track original indices and during the merge step, when an element from the right half is placed before an element from the left half, count how many right elements jump past the left element.

## Common mistakes

- Querying `sum(p)` instead of `sum(p - 1)`, which mistakenly includes equal elements and violates strictly smaller.
- Traversing left to right instead of right to left, which counts smaller elements before self rather than after self.
- Forgetting to shift negative numbers, causing negative index access into the Fenwick tree.
