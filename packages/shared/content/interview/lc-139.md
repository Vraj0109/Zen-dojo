## Clarify first

- Can dictionary words be reused multiple times? (Yes, words can be used an arbitrary number of times).
- Does the entire string $s$ have to be matched? (Yes, the complete string from start to finish must be segmented).
- What character set is used? (Only lowercase English letters for both $s$ and dictionary words).
- What are the length bounds? ($1 \le s.length \le 300$, $1 \le wordDict.length \le 1000$, and max word length $k \le 20$).
- Can the dictionary contain duplicate words? (Constraints specify all words in `wordDict` are unique).

## Examples to say out loud

- Simple segmentation: `s = "leetcode"`, `wordDict = ["leet", "code"]`. Prefix `"leet"` matches, followed by `"code"`, covering the whole string; returns `true`.
- Repeated words: `s = "applepenapple"`, `wordDict = ["apple", "pen"]`. Segments into `"apple"` + `"pen"` + `"apple"`; returns `true`.
- Partial dead end: `s = "catsandog"`, `wordDict = ["cats", "dog", "sand", "and", "cat"]`. Prefix can be `"cat"` + `"sand"`, leaving `"og"` (not in dictionary), or `"cats"` + `"and"`, leaving `"og"`. No full segmentation exists; returns `false`.

## Brute force

A naive recursive approach tests every dictionary word against the current prefix of $s$. If a word matches, it slices off the prefix and recurses on the remaining suffix. In the worst case (e.g. $s = \text{"aaaa...b"}$ with `wordDict = ["a", "aa", "aaa", ...]`), there are $2^n$ possible partition boundaries. Without memoization, exploring all partitions takes $O(2^n)$ exponential time, causing Time Limit Exceeded.

## The key observation

The decision at index $i$ depends only on whether the prefix $s[0..j-1]$ can be validly segmented, and whether the remaining substring $s[j..i-1]$ is a dictionary word. This exhibits optimal substructure with overlapping subproblems. Define a 1D boolean array `dp` of size $n + 1$, where `dp[i]` is `true` if the prefix of length $i$ can be segmented into dictionary words. Then:
$dp[i] = \bigvee_{0 \le j < i} (dp[j] \land (s[j..i-1] \in wordDict))$.
By checking only split points where $dp[j]$ is already `true`, we avoid redundant exploration.

## Optimal approach

1. Insert all strings from `wordDict` into a hash set `dict` for $O(1)$ average string lookups.
2. Let $n = s.length()$. Allocate a boolean array `dp` of size $n + 1$ initialized to `false`.
3. Set base case `dp[0] = true` (an empty prefix of length 0 is trivially valid).
4. For $i$ from 1 to $n$:
   - For $j$ from 0 to $i - 1$:
     - If `dp[j]` is `true` and the substring $s[j..i-1]$ exists in `dict`:
       - Set `dp[i] = true`.
       - Break out of the inner loop early (one valid segmentation for length $i$ suffices).
5. Return `dp[n]`.

Complexity:
- Time: `O(n^2 * k)` where $n$ is string length ($n \le 300$) and $k$ is the maximum word length ($k \le 20$). There are $O(n^2)$ state transitions, each extracting a substring of length at most $k$ and performing a hash lookup. With $k \le 20$, limiting $i - j \le k$ further reduces time to $O(n \cdot k^2)$.
- Space: `O(n + W * k)` auxiliary space for the `dp` array of size $n + 1$ and the hash set storing $W$ dictionary words.

## Code walkthrough

In the reference implementation:
- `unordered_set<string> dict(wordDict.begin(), wordDict.end());`: stores dictionary for $O(1)$ lookup.
- `vector<bool> dp(n + 1, false); dp[0] = true;`: 1-indexed DP where `dp[i]` corresponds to prefix of length $i$.
- `if (dp[j] && dict.count(s.substr(j, i - j)))`: checks if prefix up to $j$ is valid AND remaining chunk is a known word.
- `dp[i] = true; break;`: early termination upon discovering any valid partition for length $i$.
- `return dp[n];`: answers whether the full string of length $n$ is segmentable.

## Test it out loud

- Single character matching: `s = "a"`, `wordDict = ["a"]`. $n = 1$. $j = 0$: $dp[0]$ is true and `"a"` is in dict $\to dp[1] = true$. Returns `true`.
- Single character mismatch: `s = "a"`, `wordDict = ["b"]`. $dp[1]$ remains false, returns `false`.
- Overlapping choices: `s = "cars"`, `wordDict = ["car", "ca", "rs"]`.
  - At $i = 2$: `"ca"` matches $\to dp[2] = true$.
  - At $i = 3$: `"car"` matches $\to dp[3] = true$.
  - At $i = 4$: $j = 2$ has $dp[2] == true$ and $s[2..3] = \text{"rs"} \in dict \to dp[4] = true$.
  - Returns `true`.

## Follow-ups

- How to optimize when $k$ (max word length) is small ($k \le 20$)?
  Restrict the inner loop to $j$ from $\max(0, i - k)$ to $i - 1$, reducing time from $O(n^2)$ to $O(n \cdot k)$.
- What if we need to return all valid sentences (LeetCode 140 - Word Break II)?
  Use DFS with memoization or backpointers on the DP array, building paths only from valid `dp[j]` states.
- How can a Trie optimize dictionary lookups?
  Insert words into a Trie (optionally in reverse); traversing the Trie matches prefixes without repeated substring allocations.

## Common mistakes

- Indexing confusion: confusing string 0-indexed character positions with the 1-indexed DP state lengths.
- Slicing length vs end index in substrings: in C++, `substr(start, length)` takes length $i - j$, whereas in Java and Python `substring(start, end)` takes end index $i$.
- Forgetting `break` after setting `dp[i] = true`, doing unnecessary substring extractions.
