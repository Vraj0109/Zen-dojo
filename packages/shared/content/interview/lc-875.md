## Clarify first

- What happens if a pile has fewer than `k` bananas? Koko finishes the entire pile in that hour and eats nothing else for the rest of the hour.
- Can `h` be less than `piles.length`? No, since Koko can eat from at most one pile per hour, `h >= piles.length` is guaranteed for a solution to exist.
- What are the input constraints? `piles.length` is up to 10,000, `h` is between `piles.length` and `10^9`, and pile values can reach `10^9`.
- Does Koko need to finish all bananas within `h` hours? Yes, find the minimum integer speed `k >= 1` such that total hours spent is `<= h`.

## Examples to say out loud

- Standard search: `piles = [3, 6, 7, 11]`, `h = 8`.
  - At speed `k = 4`: hours needed are `ceil(3/4) + ceil(6/4) + ceil(7/4) + ceil(11/4) = 1 + 2 + 2 + 3 = 8 <= 8`.
  - At speed `k = 3`: hours needed are `1 + 2 + 3 + 4 = 10 > 8`.
  - Minimum eating speed is 4.
- High capacity requirement: `piles = [30, 11, 23, 4, 20]`, `h = 5`. Since `h == piles.length`, Koko must finish each pile in exactly 1 hour, so `k = max(piles) = 30`.
- Single giant pile: `piles = [1000000000]`, `h = 2`. Speed `k = 500000000`.

## Brute force

A brute-force solution tries speeds sequentially starting from `k = 1, 2, 3, ...` up to `max(piles)`. For each candidate `k`, it sums `ceil(pile / k)` over all piles and compares the total to `h`. In the worst case where `max(piles) = 10^9`, checking every candidate speed takes `O(n * max(piles))` time, requiring up to `10^{13}` operations, which is completely unfeasible.

## The key observation

The total time spent eating is a monotonically non-increasing function of the speed `k`: increasing `k` never increases the hours required. The feasibility function `canEatAll(k) <= h` produces a monotonic boolean predicate of the form `false, false, ..., true, true`. This structure allows us to binary search for the first valid speed `k` in the range `[1, max(piles)]`.

## Optimal approach

1. Set search range: `lo = 1` and `hi = max(piles)`.
2. While `lo < hi`:
   a. Compute candidate speed `mid = lo + (hi - lo) / 2`.
   b. Compute total hours needed: sum `(p + mid - 1) / mid` for each pile `p` in `piles`. Use 64-bit integers to prevent overflow.
   c. If total hours `<= h`: speed `mid` is feasible; narrow search to `hi = mid`.
   d. Otherwise: speed `mid` is too slow; set `lo = mid + 1`.
3. Return `lo`.

Complexity:
- Time: `O(n log(max pile))` because the binary search runs `log(max pile)` rounds (at most 30 iterations for `10^9`), and each round computes the hours in `O(n)` time.
- Space: `O(1)` auxiliary space as we only store scalar loop variables.

## Code walkthrough

In the reference implementation:
- `int lo = 1, hi = *max_element(piles.begin(), piles.end());`: initializes the search interval between the minimum conceivable speed and the guaranteed feasible upper bound.
- `int mid = lo + (hi - lo) / 2;`: avoids integer overflow when computing midpoint.
- `long long hours = 0; for (int p : piles) hours += (p + mid - 1) / mid;`: calculates ceiling division `ceil(p / mid)` in integer arithmetic with 64-bit accumulation.
- `if (hours <= h) hi = mid; else lo = mid + 1;`: preserves the smallest feasible speed on the right boundary.
- `return lo;`: terminates with the optimal minimal eating speed.

## Test it out loud

- `piles = [1], h = 1`: `lo = 1, hi = 1`. Loop terminates immediately, returns 1.
- `piles = [2, 2], h = 4`:
  - `lo = 1, hi = 2`.
  - `mid = 1`: `hours = ceil(2/1) + ceil(2/1) = 4 <= 4`. `hi = 1`.
  - Loop terminates, returns 1.
- `piles = [30, 11, 23, 4, 20], h = 6`:
  - `lo = 1, hi = 30`.
  - Eventually converges on `mid = 23`: hours = `2 + 1 + 1 + 1 + 1 = 6 <= 6`, whereas `mid = 22` gives 7 hours. Returns 23.

## Common mistakes

- Using 32-bit signed integers for the `hours` accumulator, leading to integer overflow when `piles.length` and pile values are large and candidate `mid` is small.
- Implementing ceiling division with floating point arithmetic (`ceil((double)p / mid)`), which introduces precision errors on large inputs.
- Setting `lo = 0`, causing division by zero when calculating `ceil(p / mid)`.
