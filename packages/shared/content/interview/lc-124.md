## Clarify first
- What defines a path in this problem? A sequence of nodes where each adjacent pair is connected by an edge, visiting each node at most once.
- Does the path need to pass through the root node? No, the path can start and end at any node in the tree.
- Can node values be negative? Yes, values range from -1000 to 1000.
- Can the path be empty? No, the path must contain at least one node.

## Examples to say out loud
- Simple positive tree: Root 1 with children 2 and 3 (`[1, 2, 3]`).
  - Path `2 -> 1 -> 3` gives sum `2 + 1 + 3 = 6`.
- Tree with negative root: `[-10, 9, 20, null, null, 15, 7]`.
  - Subtree at 20 has path `15 -> 20 -> 7` with sum `42`.
  - Extending this path through root `-10` and left child `9` would lower the sum (`42 - 10 + 9 = 41`), so the max path sum is 42.
- All negative nodes: `[-3]`.
  - Best path is the single node itself with sum `-3`.

## Brute force
A brute force approach considers every pair of nodes `(u, v)` in the tree, finds the unique simple path connecting `u` and `v`, and computes its sum. For n nodes, there are O(n^2) paths, each taking up to O(n) time to compute, giving O(n^3) time. Precomputing LCA allows path sums in O(1), reducing brute force to O(n^2). However, dynamic programming on trees via post-order DFS solves this in linear O(n) time.

## The key observation
Every non-empty path in a binary tree has a unique "highest" node (the node with the minimum depth on that path). That node acts as the peak or turning point.
For any node acting as the peak:
- The path consists of the node itself, plus optionally an extending path downward into its left child, plus optionally an extending path downward into its right child.
- If a child's downward path sum is negative, it is strictly optimal to prune that branch (take 0).
- When a node returns its contribution up to its parent, it can only extend along at most ONE downward arm (either left or right), because a valid path cannot branch into two children when continuing upward.

## Optimal approach
1. Maintain a global variable `best` initialized to negative infinity (`INT_MIN`).
2. Define a recursive helper function `gain(node)`:
   - If `node` is null, return 0.
   - Compute max positive gain from left child: `l = max(0, gain(node->left))`.
   - Compute max positive gain from right child: `r = max(0, gain(node->right))`.
   - The best path where `node` is the highest turning point has sum `node->val + l + r`. Update `best = max(best, node->val + l + r)`.
   - Return to parent the maximum single-arm contribution: `node->val + max(l, r)`.
3. Call `gain(root)` and return `best`.

Complexity:
- Time complexity: O(n) because every node in the binary tree is visited exactly once.
- Space complexity: O(h) where h is the tree height, representing the recursion stack (O(log n) for balanced trees, O(n) worst-case).

## Code walkthrough
- `int best = INT_MIN`: Ensures all-negative trees correctly select the single largest negative node.
- `int l = max(0, gain(n->left))` and `int r = max(0, gain(n->right))`: Prunes negative subtree gains by clamping to 0.
- `best = max(best, n->val + l + r)`: Updates the global maximum with a potential arch path through the current node.
- `return n->val + max(l, r)`: Returns the max straight downward branch usable by the parent call.

## Test it out loud
- Test `[-3]`:
  - `gain(-3)`: `l = 0, r = 0`.
  - `best = max(INT_MIN, -3 + 0 + 0) = -3`.
  - Returns `-3`. Output is -3. Correct.
- Test `[1, 2, 3]`:
  - `gain(2)` returns 2, `best` becomes 2.
  - `gain(3)` returns 3, `best` becomes 3.
  - At root 1: `l = 2, r = 3`. `best = max(3, 1 + 2 + 3) = 6`.
  - Returns `1 + max(2, 3) = 4`. Final answer is 6. Correct.

## Follow-ups
- How would you reconstruct the actual path of nodes producing the maximum sum? Return or record child choices during DFS, and when `best` is updated, trace the nodes down the left and right paths that achieved `l` and `r`.
- What if the path was constrained to have at most k edges? This turns into tree DP where each node tracks state vectors indexed by path length from 1 to k.

## Common mistakes
- Returning `n->val + l + r` to the parent instead of `n->val + max(l, r)`, which creates an invalid branching tree rather than a simple path.
- Initializing `best = 0`, which fails on trees where all node values are negative.
- Forgetting to clamp negative gains to 0 with `max(0, ...)`.
