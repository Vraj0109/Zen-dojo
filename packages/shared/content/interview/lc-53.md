## Clarify first

- Can the subarray be empty? No, the problem specifies a contiguous block of at least one element.
- Can all elements in `nums` be negative? Yes, constraints allow values from -10,000 to 10,000. In an all-negative array, the answer is the largest single negative number.
- What if there are multiple subarrays with the maximum sum? Returning the maximum sum value is all that is required, not the subarray boundaries.
- What is the size range of `nums`? Between 1 and 100,000 integers.

## Examples to say out loud

- Mixed positive and negative values: `nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]`. The subarray `[4, -1, 2, 1]` produces the maximum contiguous sum of 6.
- All negative values: `nums = [-3, -2, -1]`. The best single-element choice is `[-1]`, returning sum -1.
- Single element: `nums = [1]`. The only non-empty contiguous choice is `[1]`, returning 1.

## Brute force

A brute-force solution checks all possible subarrays `nums[i..j]` where `i <= j`. By iterating through all pairs and computing their sums, there are `O(n^2)` possible subarrays. Summing each subarray takes between `O(n^3)` without prefix sums and `O(n^2)` with running sums. For `n = 100,000`, an `O(n^2)` algorithm requires `10^{10}` operations, causing a time limit exceeded error.

## The key observation

For any element `nums[i]`, a subarray ending at index `i` either extends the optimal subarray ending at `i - 1`, or starts fresh at `nums[i]`. If the running sum ending at `i - 1` is negative, adding it to `nums[i]` will strictly decrease the sum, so it is always better to discard the previous sum and start a new subarray at `nums[i]`.

## Optimal approach

1. Initialize `cur = nums[0]` to represent the maximum subarray sum ending at the current index, and `best = nums[0]` for the overall maximum sum.
2. Iterate from index 1 to `nums.length - 1`:
   a. Update `cur = max(nums[i], cur + nums[i])`.
   b. Update `best = max(best, cur)`.
3. Return `best`.

Complexity:
- Time: `O(n)` because we iterate through the list of `n` elements in a single pass with `O(1)` operations per step.
- Space: `O(1)` auxiliary space since we only store two integer variables.

## Code walkthrough

In the reference implementation:
- `int cur = nums[0], best = nums[0];`: initialises both the running subarray sum and the global answer to the first element, handling all-negative inputs correctly.
- `for (size_t i = 1; i < nums.size(); i++)`: iterates sequentially through the remainder of the array.
- `cur = max(nums[i], cur + nums[i]);`: decides whether to extend the previous subarray or start a new one at `nums[i]`.
- `best = max(best, cur);`: captures the peak subarray sum found across all possible ending positions.
- `return best;`: returns the maximum contiguous sum found.

## Test it out loud

- `nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]`:
  - Start: `cur = -2`, `best = -2`.
  - `i = 1 (1)`: `cur = max(1, -1) = 1`, `best = 1`.
  - `i = 2 (-3)`: `cur = max(-3, -2) = -2`, `best = 1`.
  - `i = 3 (4)`: `cur = max(4, 2) = 4`, `best = 4`.
  - `i = 4 (-1)`: `cur = max(-1, 3) = 3`, `best = 4`.
  - `i = 5 (2)`: `cur = max(2, 5) = 5`, `best = 5`.
  - `i = 6 (1)`: `cur = max(1, 6) = 6`, `best = 6`.
  - `i = 7 (-5)`: `cur = max(-5, 1) = 1`, `best = 6`.
  - `i = 8 (4)`: `cur = max(4, 5) = 5`, `best = 6`.
  - Output is 6.
- `nums = [-3, -2, -1]`:
  - Start: `cur = -3`, `best = -3`.
  - `i = 1 (-2)`: `cur = max(-2, -5) = -2`, `best = -2`.
  - `i = 2 (-1)`: `cur = max(-1, -3) = -1`, `best = -1`.
  - Output is -1.

## Follow-ups

- How would you return the actual subarray indices rather than just the sum?
  Maintain tracking variables for the current subarray's start index, and update recorded `best_start` and `best_end` whenever `best` is updated.
- Can this problem be solved using Divide and Conquer?
  Yes, divide the array into left and right halves in `O(n log n)` time by computing the maximum of left, right, and cross-boundary subarrays.
- What if the array is circular (LeetCode 918)?
  Find both maximum subarray sum via Kadane and minimum subarray sum; the answer is `max(max_sum, total_sum - min_sum)` unless all elements are negative.

## Common mistakes

- Initializing `best = 0` instead of `nums[0]`, which fails when all numbers in `nums` are negative by incorrectly returning 0.
- Resetting `cur` to 0 after negative elements instead of comparing `cur + nums[i]` against `nums[i]`.
- Conflating contiguous subarrays with non-contiguous subsequences.
