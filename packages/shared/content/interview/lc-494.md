## Clarify first

- Can elements of `nums` be 0? Yes, elements can be 0 (`0 <= nums[i] <= 1,000`). Each zero doubles the number of ways since `+0` and `-0` both produce identical sums.
- Can `target` be negative? Yes, `target` is between -1,000 and 1,000.
- What if `|target| > sum(nums)`? It is impossible to achieve `target` even if all numbers are given the same sign, so return 0.
- What are the constraints on array length and sum? `nums.length` is up to 20, and `sum(nums) <= 1,000`.

## Examples to say out loud

- Repeated ones: `nums = [1, 1, 1, 1, 1]`, `target = 3`.
  - We can assign four `+` signs and one `-` sign (5 choose 1 ways).
  - Total ways = 5.
- Zero handling: `nums = [0, 0, 0, 0, 0, 0, 0, 0, 1]`, `target = 1`.
  - The eight zeros can each be `+` or `-` (2^8 = 256 combinations), while 1 must be `+`.
  - Total ways = 256.
- Out of reach: `nums = [1]`, `target = 2`. `sum(nums) = 1 < 2`, return 0.

## Brute force

A brute-force recursive solution generates all `2^n` assignments of `+` and `-` signs across the array. For each assignment, compute the sum and check if it matches `target`. For `n = 20`, `2^{20} \approx 10^6` operations, which barely passes within time limits but is unscalable.

## The key observation

Let `P` be the sum of numbers assigned a `+` sign, and `N` be the sum of numbers assigned a `-` sign.
We know:
1. `P - N = target`
2. `P + N = total`
Adding the two equations yields `2P = total + target \implies P = (total + target) / 2`.
Thus, the problem reduces to: **How many subsets of `nums` sum up to exactly `P`?**
If `total + target < 0` or `(total + target) % 2 != 0`, no integer subset can satisfy the equation, so return 0 immediately. Otherwise, this is standard 0/1 Subset Sum counting.

## Optimal approach

1. Calculate `total = sum(nums)`.
2. Check impossibility: If `abs(target) > total` or `(total + target) % 2 != 0`, return 0.
3. Compute required subset sum: `need = (total + target) / 2`.
4. Allocate a 1D DP array `dp` of size `need + 1` filled with zeros, with base case `dp[0] = 1`.
5. For each number `x` in `nums`:
   - For `s` from `need` down to `x`:
     - `dp[s] += dp[s - x]`.
6. Return `dp[need]`.

Complexity:
- Time: `O(n * \text{sum})` because the outer loop runs `n` times and the inner loop checks up to `need <= \text{sum}` states.
- Space: `O(\text{sum})` auxiliary space for the 1D combination count array.

## Code walkthrough

In the reference implementation:
- `int total = accumulate(nums.begin(), nums.end(), 0);`: computes total sum of the array.
- `if (abs(target) > total || (total + target) % 2) return 0;`: rules out targets beyond reach or with incompatible parity.
- `int need = (total + target) / 2;`: solves for the positive subset target sum.
- `vector<int> dp(need + 1, 0); dp[0] = 1;`: represents base case where an empty subset produces sum 0.
- `for (int s = need; s >= x; s--) dp[s] += dp[s - x];`: counts subset combinations using 0/1 knapsack backward iteration.
- `return dp[need];`: outputs total sign configurations yielding `target`.

## Test it out loud

- `nums = [1, 1], target = 0`:
  - `total = 2`, `need = (2 + 0) / 2 = 1`.
  - `dp` starts `[1, 0]`.
  - `x = 1`: `dp[1] += dp[0] = 1`. Array: `[1, 1]`.
  - `x = 1`: `dp[1] += dp[0] = 1 + 1 = 2`. Array: `[1, 2]`.
  - Return `dp[1] = 2` (`+1-1` and `-1+1`).
- `nums = [2, 1], target = 2`:
  - `total = 3`, `(3 + 2) % 2 = 1 != 0`, returns 0.

## Follow-ups

- Why does backward iteration correctly handle zeros in `nums`?
  For `x = 0`, the loop checks `s` down to 0: at `s = 0`, `dp[0] += dp[0 - 0] = dp[0] + dp[0]`, which doubles `dp[0]`, exactly matching the two choices (`+0` and `-0`).
- How would you solve this if `nums[i]` was floating point?
  Floating point subset sums require meet-in-the-middle bidirectional search.

## Common mistakes

- Forgetting `abs(target) > total`, which can result in a negative `need` index and segmentation faults.
- Iterating `s` forward from `x` to `need`, which mistakenly allows elements to be used an unlimited number of times.
- Missing the parity check `(total + target) % 2 != 0`.
