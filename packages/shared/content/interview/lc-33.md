## Clarify first

- Are all elements in `nums` distinct? Yes, constraints explicitly state all values are distinct.
- What if the target is not present in the array? Return -1.
- Can the rotation count be zero (i.e., array is normally sorted)? Yes, standard sorted arrays are a valid zero-rotation case.
- What is the required time complexity? The problem requires `O(log n)` time complexity.

## Examples to say out loud

- Target in right half: `nums = [4, 5, 6, 7, 0, 1, 2]`, `target = 0`.
  - Midpoint is `nums[3] = 7`.
  - Left half `[4, 5, 6, 7]` is sorted since `4 <= 7`. Target 0 is not in `[4, 7]`, so search right half `[0, 1, 2]`.
  - Target 0 is found at index 4.
- Target not found: `nums = [4, 5, 6, 7, 0, 1, 2]`, `target = 3`. Return -1.
- Single element found: `nums = [1]`, `target = 1`. Midpoint matches target, return 0.
- Two elements edge case: `nums = [3, 1]`, `target = 1`. Returns index 1.

## Brute force

A brute-force linear scan iterates through each index `i` from 0 to `n - 1`, comparing `nums[i]` with `target`. While simple and correct, it requires `O(n)` time, which violates the strict `O(log n)` time limit constraint.

## The key observation

When an array sorted in ascending order is rotated at an unknown pivot, splitting it at any index `mid` divides it into two halves such that at least one of the two halves is guaranteed to be normally sorted. We can determine which half is sorted by checking if `nums[lo] <= nums[mid]`. Once identified, we simply check whether `target` falls within the known bounds of that sorted half; if it does, we narrow our search to that half, otherwise we search the opposite half.

## Optimal approach

1. Initialize two pointers: `lo = 0` and `hi = nums.length - 1`.
2. While `lo <= hi`:
   a. Compute `mid = lo + (hi - lo) / 2`.
   b. If `nums[mid] == target`, return `mid`.
   c. If `nums[lo] <= nums[mid]` (left half is sorted):
      - If `nums[lo] <= target && target < nums[mid]`, search left: `hi = mid - 1`.
      - Otherwise, search right: `lo = mid + 1`.
   d. Otherwise (right half is sorted, `nums[mid] < nums[hi]`):
      - If `nums[mid] < target && target <= nums[hi]`, search right: `lo = mid + 1`.
      - Otherwise, search left: `hi = mid - 1`.
3. If the loop ends without finding target, return -1.

Complexity:
- Time: `O(log n)` because each comparison discards half of the remaining search space.
- Space: `O(1)` auxiliary space since only index pointers are maintained.

## Code walkthrough

In the reference implementation:
- `int lo = 0, hi = (int)nums.size() - 1;`: sets search boundaries covering the full array.
- `int mid = lo + (hi - lo) / 2;`: avoids integer overflow when calculating midpoint.
- `if (nums[mid] == target) return mid;`: checks for an immediate match.
- `if (nums[lo] <= nums[mid])`: identifies that the left segment is monotonically increasing.
- `if (nums[lo] <= target && target < nums[mid]) hi = mid - 1; else lo = mid + 1;`: chooses between the sorted range and the unsorted remainder.
- `return -1;`: returns failure indicator if boundaries cross without matching.

## Test it out loud

- `nums = [3, 1], target = 1`:
  - `lo = 0, hi = 1`. `mid = 0`, `nums[0] = 3`.
  - `nums[lo] <= nums[mid]` (`3 <= 3`) is true. Left half sorted.
  - Check target in left: `3 <= 1 && 1 < 3` is false.
  - Set `lo = mid + 1 = 1`.
  - Next iteration: `lo = 1, hi = 1`. `mid = 1`, `nums[1] = 1 == target`. Return 1.
- `nums = [5, 1, 3], target = 5`:
  - `lo = 0, hi = 2`. `mid = 1`, `nums[1] = 1`.
  - `nums[0] <= nums[1]` (`5 <= 1`) is false -> right half `[1, 3]` is sorted.
  - Target 5 in right half `(1 < 5 && 5 <= 3)` is false.
  - Move to left half: `hi = mid - 1 = 0`.
  - `mid = 0`, `nums[0] = 5 == target`. Return 0.

## Follow-ups

- What if duplicate elements are allowed (Search in Rotated Sorted Array II, LeetCode 81)?
  When `nums[lo] == nums[mid] == nums[hi]`, we cannot determine which half is sorted; increment `lo` and decrement `hi`, degrading worst-case time complexity to `O(n)`.
- How would you find the minimum element or rotation pivot index (Find Minimum in Rotated Sorted Array, LeetCode 153)?
  Compare `nums[mid]` with `nums[hi]`: if `nums[mid] > nums[hi]`, the pivot lies strictly to the right (`lo = mid + 1`), else `hi = mid`.

## Common mistakes

- Using `<` instead of `<=` when comparing `nums[lo] <= nums[mid]`, causing two-element arrays like `[3, 1]` to misidentify the sorted half.
- Forgetting strict vs inclusive bounds when checking if target lies within the sorted half (e.g., using `target <= nums[mid]` instead of `target < nums[mid]` after having already verified `nums[mid] != target`).
- Trying to first find the pivot in a separate pass and then do standard binary search, which takes more code and introduces additional edge cases.
