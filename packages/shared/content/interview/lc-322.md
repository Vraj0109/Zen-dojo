## Clarify first

- Can each coin be used an unlimited number of times? Yes, an infinite supply of each coin denomination is available.
- What if it is impossible to form the exact target amount? Return -1.
- What should be returned if `amount == 0`? Return 0, since 0 coins are needed.
- What are the constraints on amount and coins? `amount` is between 0 and 10,000, and `coins.length` is between 1 and 12. Coin values are positive integers.

## Examples to say out loud

- Standard case where greedy would fail: `coins = [1, 3, 4]`, `amount = 6`.
  - A greedy approach picks 4, then two 1s, using 3 coins (`4 + 1 + 1`).
  - The optimal choice is two 3s (`3 + 3 = 6`), using only 2 coins. Returns 2.
- Clean combination: `coins = [1, 2, 5]`, `amount = 11`. `5 + 5 + 1 = 11` using 3 coins. Returns 3.
- Impossible combination: `coins = [2]`, `amount = 3`. No combination of even numbers can sum to an odd number. Returns -1.
- Zero amount: `amount = 0`. Returns 0.

## Brute force

A brute-force solution tries all possible combinations of coins using recursion: at amount `a`, branch on each coin `c <= a` by calling `coinChange(a - c) + 1`. This forms a tree of branching factor up to 12 and depth up to `amount`, giving `O(|coins|^{amount})` exponential time complexity. For `amount = 10,000`, this causes immediate call stack overflow and timeout.

## The key observation

The problem possesses optimal substructure and overlapping subproblems: to make amount `a`, the final coin placed could be any coin `c` from the denomination set. If coin `c` is chosen, the remainder `a - c` must have been made using the fewest possible coins. Therefore, `fewest[a] = 1 + min_{c <= a} fewest[a - c]`.

## Optimal approach

1. Initialize an array `fewest` of size `amount + 1` filled with sentinel value `amount + 1` (representing infinity, since using all 1-cent coins requires at most `amount` coins).
2. Set base case `fewest[0] = 0`.
3. Loop `a` from 1 to `amount`:
   a. For each coin `c` in `coins`:
      i. If `c <= a`: `fewest[a] = min(fewest[a], fewest[a - c] + 1)`.
4. If `fewest[amount] > amount`, return -1; otherwise return `fewest[amount]`.

Complexity:
- Time: `O(amount * |coins|)` because the outer loop runs `amount` times and the inner loop checks each of the `|coins|` denominations.
- Space: `O(amount)` auxiliary space for the dynamic programming table.

## Code walkthrough

In the reference implementation:
- `vector<int> fewest(amount + 1, amount + 1);`: initializes DP array with an unreachable upper bound.
- `fewest[0] = 0;`: establishes that zero coins are required for zero amount.
- `for (int a = 1; a <= amount; a++)`: iterates upward through every sub-amount.
- `if (c <= a) fewest[a] = min(fewest[a], fewest[a - c] + 1);`: transitions the optimal subproblem result when coin `c` is used.
- `return fewest[amount] > amount ? -1 : fewest[amount];`: verifies whether a valid combination was reachable.

## Test it out loud

- `coins = [2], amount = 3`:
  - `fewest[0] = 0`, `fewest[1] = 4`, `fewest[2] = 1`, `fewest[3] = 4`.
  - `fewest[3] = 4 > 3`, returns -1.
- `coins = [1, 2, 5], amount = 5`:
  - `fewest[1] = 1 (1)`
  - `fewest[2] = min(fewest[1]+1, fewest[0]+1) = 1 (2)`
  - `fewest[3] = min(fewest[2]+1, fewest[1]+1) = 2`
  - `fewest[4] = min(fewest[3]+1, fewest[2]+1) = 2`
  - `fewest[5] = min(fewest[4]+1, fewest[3]+1, fewest[0]+1) = 1 (5)`
  - Output is 1.

## Follow-ups

- How would you count the total number of combinations that make the amount (Coin Change II, LeetCode 518)?
  Loop over coins in the outer loop and amounts in the inner loop: `dp[a] += dp[a - c]` to avoid permutations and count unique combinations.
- How would you reconstruct the actual coins used?
  Store `parent_coin[a] = c` whenever `fewest[a]` is updated, then backtrack from `amount` to 0.

## Common mistakes

- Trying a greedy strategy (sorting coins descending and taking the largest), which fails on denominations like `[1, 3, 4]` for amount 6.
- Initializing the DP array with `INT_MAX`, which leads to integer overflow when evaluating `INT_MAX + 1`.
- Forgetting that `c <= a` must be checked before accessing `fewest[a - c]`, causing out-of-bounds memory access or underflow.
