## Clarify first
- What does a camera monitor? A camera placed on a node monitors the node itself, its direct parent, and all of its immediate children.
- What are we minimizing? The total number of cameras required so that every node in the binary tree is monitored.
- What do node values signify? All node values are 0; only the tree topology matters.
- Can a leaf hold a camera? Yes, but placing a camera on a leaf is generally suboptimal compared to placing it on the leaf's parent.

## Examples to say out loud
- Consider tree `[0, 0, null, 0, 0]`:
  - Root 0 has left child 0, which has two children 0 and 0.
  - Placing a camera on the left child monitors the root, the left child itself, and both leaves.
  - Total cameras: 1.
- Straight chain of 3 nodes: `[0, null, 0, null, 0]`.
  - Placing a camera on the middle node monitors all 3 nodes.
  - Total cameras: 1.
- Single node `[0]`: Needs 1 camera on the root itself. Total cameras: 1.

## Brute force
A brute force approach considers all `2^n` subsets of nodes to place cameras, checks whether each subset monitors all nodes, and finds the smallest valid subset. For n up to 1000, `2^1000` is impossible. Tree DP or bottom-up greedy post-order traversal allows solving this in linear O(n) time.

## The key observation
We make decisions greedily from the leaves up to the root:
- A leaf node should NEVER hold a camera if possible. Placing the camera on the leaf's parent covers the leaf, the parent, the parent's other child, and the parent's parent, which strictly dominates placing the camera on the leaf itself.
- We classify each node into one of three states during a post-order traversal:
  - State 0: Node is NOT covered by any camera.
  - State 1: Node HAS a camera placed on it.
  - State 2: Node is COVERED (monitored) by a camera on one of its children, but has no camera itself.
Null nodes are treated as State 2 (covered, no camera needed).
Transitions at node `u`:
1. If either child is State 0 (uncovered), `u` MUST place a camera: increment camera count, return State 1.
2. Else if either child is State 1 (has a camera), `u` is now covered for free: return State 2.
3. Else (both children are State 2, meaning covered without cameras), `u` is not covered by any child: return State 0 (deferring coverage to `u`'s parent).
Finally, if the root returns State 0, it has no parent to cover it, so we must add one extra camera at the root.

## Optimal approach
1. Initialize a counter `cameras = 0`.
2. Define recursive helper `go(node)` returning the state of `node`:
   - If `node` is null, return 2 (covered).
   - Recurse on children: `l = go(node->left)`, `r = go(node->right)`.
   - If `l == 0 || r == 0`:
     - At least one child is uncovered; place camera here:
     - `cameras++`, return 1.
   - If `l == 1 || r == 1`:
     - Covered by a child's camera; return 2.
   - Return 0 (uncovered, waiting for parent).
3. If `go(root) == 0`:
   - Root remains uncovered; `cameras++`.
4. Return `cameras`.

Complexity:
- Time complexity: O(n) because each node in the tree is visited exactly once in post-order.
- Space complexity: O(h) where h is the tree height, corresponding to the recursion call stack (O(log n) balanced, O(n) worst-case).

## Code walkthrough
- `if (!n) return 2`: Empty leaves are considered covered so that real leaves evaluate to State 0.
- `if (l == 0 || r == 0) { cameras++; return 1; }`: Forces parent of an uncovered child to place a camera.
- `if (l == 1 || r == 1) return 2`: Recognizes coverage from a child camera.
- `return 0`: Defers placing a camera to the ancestor.
- `if (go(root) == 0) cameras++`: Covers the root if it ended in State 0.

## Test it out loud
- Test single node `[0]`:
  - `go(0)`: left null (2), right null (2). Neither is 0, neither is 1. Returns 0.
  - Root returned 0. `cameras++`. Returns 1. Correct.
- Test `[0, 0, 0]` (root with 2 children):
  - Left child returns 0; right child returns 0.
  - At root: `l == 0 || r == 0` is true. `cameras` becomes 1, returns 1.
  - Root returned 1. Returns 1. Correct.

## Follow-ups
- How does this relate to Vertex Cover or Dominating Set? Minimum camera cover is the Minimum Dominating Set problem on trees, which is NP-hard on general graphs but solvable in linear time on trees using post-order tree DP.
- How would full Tree DP look without greedy state definitions? Each node computes three values: `dp[u][0]` (u has camera), `dp[u][1]` (u covered by child), `dp[u][2]` (u not covered).

## Common mistakes
- Treating null nodes as uncovered (State 0), which incorrectly forces cameras onto all leaves.
- Forgetting to check if the root node itself remains uncovered after the DFS finishes.
- Placing cameras on leaves instead of greedily pushing camera placement to parents.
