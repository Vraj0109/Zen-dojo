## Clarify first
- What range of numbers are we considering? All integers x such that `0 <= x < 10^n`.
- What property must each number satisfy? All of its decimal digits must be strictly distinct (unique).
- What is the value of n? `0 <= n <= 8`.
- What should be returned for n = 0? The range `0 <= x < 1` contains only the number 0, which has unique digits, so return 1.

## Examples to say out loud
- For `n = 0`: Range is `[0, 1)`, only `0`. Output: 1.
- For `n = 1`: Range is `[0, 10)`. All numbers `0, 1, 2, ..., 9` have unique digits. Output: 10.
- For `n = 2`: Range is `[0, 100)`. There are 100 numbers total. The numbers with duplicate digits are `11, 22, 33, 44, 55, 66, 77, 88, 99` (9 numbers).
  Unique count: `100 - 9 = 91`. Output: 91.

## Brute force
A brute force approach iterates through every integer from 0 to `10^n - 1`, extracts each number's digits into a set or frequency array, and counts numbers where no digit repeats. For `n = 8`, checking 100,000,000 numbers is slow and unnecessary. Using basic combinatorics and digit counting gives an exact closed-form product in O(n) time.

## The key observation
We can count unique-digit numbers by grouping them according to their number of digits `k`:
- For `k = 1`: the single-digit numbers `0` through `9` contribute 10 numbers.
- For `k >= 2`:
  - The leading (first) digit can be any digit from 1 to 9 (9 choices, cannot be 0).
  - The second digit can be any digit from 0 to 9 except the first digit (9 choices).
  - The third digit can be any digit except the first two (8 choices).
  - The `k`-th digit has `(11 - k)` choices.
  - Total numbers of length `k` with unique digits: `9 * 9 * 8 * 7 * ... * (11 - k)`.
For any `n >= 10`, by the Pigeonhole Principle, no number with 11 or more digits can have unique decimal digits. Thus, we only sum up to `min(n, 10)`.

## Optimal approach
1. If `n == 0`, return 1.
2. Initialize `total = 10` (accounting for all 1-digit numbers `0..9`).
3. Maintain running product `cur = 9` and available choices `avail = 9`.
4. For `k` from 2 to `min(n, 10)`:
   - Multiply `cur` by `avail`: `cur *= avail`.
   - Decrement `avail` by 1.
   - Add `cur` to `total`.
5. Return `total`.

Complexity:
- Time complexity: O(n) (at most 10 iterations) running in O(1) constant time.
- Space complexity: O(1) auxiliary space as only a few primitive integer accumulators are maintained.

## Code walkthrough
- `if (n == 0) return 1`: Handles edge case for empty range `[0, 1)`.
- `int total = 10`: Seeds base count with all single-digit numbers `0..9`.
- `for (int k = 2; k <= min(n, 10); k++)`: Accumulates permutations for lengths 2 up to n.
- `cur *= avail; avail--; total += cur`: Multiplies available remaining digits and adds unique-digit numbers of length `k`.
- Returns `total`.

## Test it out loud
- Test `n = 1`: Returns `10` immediately. Correct.
- Test `n = 2`:
  - `total = 10`.
  - `k = 2`: `cur = 9 * 9 = 81`, `avail = 8`, `total = 10 + 81 = 91`. Returns 91. Correct.
- Test `n = 3`:
  - `k = 3`: `cur = 81 * 8 = 648`, `total = 91 + 648 = 739`. Returns 739. Correct.

## Follow-ups
- What if we needed to count unique-digit numbers `<= N` for an arbitrary non-power-of-ten N? We would use full Digit DP tracking `(index, mask_of_used_digits, is_less, is_started)`.
- What happens if n > 10? Since there are only 10 decimal digits (0-9), any number with 11 or more digits must repeat at least one digit, so the answer caps at `n = 10`.

## Common mistakes
- Allowing the leading digit to be 0 for multi-digit numbers, which double counts numbers of shorter lengths.
- Forgetting to include the number 0 itself in the final count.
- Not capping the loop at `min(n, 10)`, which would lead to multiplying by negative numbers when `k > 10`.
