## Clarify first

- What language does the alphabet come from? (Lowercase English letters `'a'` through `'z'`).
- How is the lexicographical order defined? (Given two words, find the first position where they differ; the character from the first word precedes the character from the second word).
- What should be returned if the ordering is invalid or impossible? (Return an empty string `""`).
- When is the ordering invalid? (If there is a cycle like $a < b < a$, or if an earlier word is strictly longer than a later word while having that later word as a prefix, e.g. `["abc", "ab"]`).
- If multiple valid topological orders exist, which should be returned? (The lexicographically smallest valid topological order, requiring a min-heap priority queue).

## Examples to say out loud

- Normal order: `words = ["wrt", "wrf", "er", "ett", "rftt"]`.
  - Comparing `"wrt"` and `"wrf"` yields $t \to f$.
  - `"wrf"` and `"er"` yields $w \to e$.
  - `"er"` and `"ett"` yields $r \to t$.
  - `"ett"` and `"rftt"` yields $e \to r$.
  - Topological sort gives `"wertf"`.
- Prefix violation: `words = ["abc", "ab"]`. `"abc"` appears before `"ab"`, which violates standard dictionary rules where shorter prefixes come first. Return `""`.
- Direct cycle: `words = ["z", "x", "z"]`. Implies $z < x$ and $x < z$, forming a cycle. Return `""`.

## Brute force

A naive approach attempts all $26!$ permutations of the English alphabet, testing whether each permutation orders the entire list of words correctly. With $26! \approx 4 \times 10^{26}$, this is computationally impossible. Even attempting DFS with unmemoized cycle detection across all pairs is inefficient and difficult to tie-break lexicographically.

## The key observation

The dictionary order constraints can be represented as a Directed Acyclic Graph (DAG) whose vertices are the unique characters present in `words`. Comparing adjacent pairs of words `words[i]` and `words[i+1]` gives the only direct constraints: at the first index where characters differ, say $c_1 \ne c_2$, we must have a directed edge $c_1 \to c_2$. To satisfy the tie-breaking rule ("lexicographically smallest valid topological order"), we perform Kahn's algorithm using a min-heap priority queue instead of a FIFO queue.

## Optimal approach

1. Collect all distinct characters that appear in any word into a set `allChars`.
2. Initialize an adjacency list `adj` and an `inDegree` map initialized to 0 for every character in `allChars`.
3. Compare each adjacent pair of words `words[i]` and `words[i+1]`:
   - Let $w_1 = words[i]$ and $w_2 = words[i+1]$.
   - If $|w_1| > |w_2|$ and $w_1$ starts with $w_2$, the ordering is impossible; return `""`.
   - Find the first index $j$ where $w_1[j] \ne w_2[j]$:
     - If directed edge $w_1[j] \to w_2[j]$ has not been recorded, insert it into `adj` and increment `inDegree[w2[j]]`.
     - Break immediately after the first difference (subsequent characters give no ordering information).
4. Insert all characters with `inDegree[c] == 0` into a min-heap priority queue `pq`.
5. While `pq` is not empty:
   - Extract the smallest character $u$ and append it to result string `order`.
   - For each neighbor $v$ of $u$ in `adj`:
     - Decrement `inDegree[v]`.
     - If `inDegree[v] == 0`, push $v$ into `pq`.
6. If `order.length() < allChars.size()`, a cycle prevented full traversal; return `""`. Otherwise, return `order`.

Complexity:
- Time: `O(C + U \log U)` where $C$ is the total number of characters across all words, and $U \le 26$ is the number of unique letters. Comparing adjacent words takes $O(C)$, and Kahn's algorithm with a min-heap processes at most 26 nodes and edges taking $O(U \log U)$ time.
- Space: `O(U + E)` auxiliary space where $U \le 26$ and $E \le U^2$ to store the adjacency list, in-degrees, and priority queue.

## Code walkthrough

In the reference implementation:
- `allChars`: gathers all participating letters so isolated characters are included in the sort.
- `if (w1.size() > w2.size() && w1.compare(0, w2.size(), w2) == 0) return "";`: detects prefix violations like `["abc", "ab"]`.
- `break;`: halts comparison of two words immediately upon finding the first differing character.
- `priority_queue<char, vector<char>, greater<char>> pq;`: ensures the lexicographically smallest character is processed first among available roots.
- `if (order.size() < allChars.size()) return "";`: detects directed cycles where some characters never reached an in-degree of 0.

## Test it out loud

- Single character words: `words = ["z"]`. Graph has node `z` with in-degree 0. Min-heap extracts `'z'`. Returns `"z"`.
- Independent letters: `words = ["zy", "zx"]`. Differences give $y \to x$. Letter $z$ has no dependencies. Roots are `'y'` and `'z'`. Min-heap pops `'y'`, then `'x'` becomes root; `'x'` is popped before `'z'`. Output is `"yxz"`.
- Disjoint words: `words = ["a", "b", "ca", "cc"]`. Yields $a \to b$ and $a \to c$. Heap pops `'a'`, unlocking `'b'` and `'c'`. Heap pops `'b'`, then `'c'`. Output is `"abc"`.

## Follow-ups

- What if words contain characters outside ASCII English?
  Use generic hash maps with unicode code points instead of fixed 26-character lookups.
- Why only compare adjacent words and not all pairs $(i, j)$?
  Lexicographical ordering is transitive: if $w_i < w_{i+1}$ holds for all adjacent pairs, then $w_i < w_j$ holds for all $i < j$.
- How to detect multiple valid orders if we didn't require lexicographical minimum?
  Standard Kahn's algorithm with a regular queue suffices; if the queue ever holds $> 1$ elements, multiple orders exist.

## Common mistakes

- Comparing characters beyond the first differing position in two adjacent words; subsequent characters do not determine relative character order.
- Missing the prefix violation case (`["apple", "app"]`), which has no differing character but is inherently invalid.
- Forgetting to include characters that appear in words but have zero incoming and outgoing edges.
