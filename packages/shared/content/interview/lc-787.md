## Clarify first
- What does k represent? `k` is the maximum number of intermediate stops allowed, which corresponds to at most `k + 1` flights (edges).
- Are edge weights strictly positive? Yes, `price >= 1`.
- What should be returned if no route reaches `dst` within `k` stops? Return -1.
- Why does standard Dijkstra fail on this problem? A cheaper flight sequence might use more than `k` stops and prune a slightly more expensive route that uses fewer stops.

## Examples to say out loud
- Consider `n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2`:
  - If `k = 1`: we can stop at city 1. Flight `0 -> 1 -> 2` costs `100 + 100 = 200` with 1 stop. Output: 200.
  - If `k = 0`: 0 stops allowed (direct flight only). Direct flight `0 -> 2` costs 500. Output: 500.
- Unreachable case: `flights = [[0,1,1],[1,2,1]], src = 0, dst = 2, k = 0`. Path needs 2 flights (1 stop), but `k = 0`. Output: -1.

## Brute force
A brute force approach uses backtracking DFS to explore all possible simple paths from `src` to `dst`, terminating any path that exceeds `k + 1` edges. In the worst case, dense graphs have O(n!) paths, leading to time limit exceeded. Standard Dijkstra with state `(price, city, stops)` works, but Bellman-Ford offers a simpler and optimal approach tailored to bounded-hop shortest paths.

## The key observation
The problem asks for the minimum weight path using at most `k + 1` edges.
The Bellman-Ford algorithm is specifically designed around edge-count rounds: round `r` computes the shortest distance from the source using at most `r` edges.
By running exactly `k + 1` rounds of edge relaxations and ensuring that each round relaxes edges using only the distance values from the previous round (by taking a snapshot of `dist`), we strictly prevent a path from using more than one edge per round.

## Optimal approach
1. Initialize an array `dist` of size `n` with a large sentinel value `INF` (e.g. 10^9), setting `dist[src] = 0`.
2. Run a loop for `round` from 0 to `k`:
   - Create a copy of the current distances: `next = dist`.
   - For each flight `[u, v, price]` in `flights`:
     - If `dist[u] < INF`:
       - Relax the edge: `next[v] = min(next[v], dist[u] + price)`.
   - Update `dist = next`.
3. Return `dist[dst] >= INF ? -1 : dist[dst]`.

Complexity:
- Time complexity: O(k * E) where E is the number of flights and k is the number of allowed stops. We execute `k + 1` rounds, scanning all E edges in each round.
- Space complexity: O(n) auxiliary space to store the distance array and its temporary copy across n cities.

## Code walkthrough
- `vector<int> dist(n, INF); dist[src] = 0`: Establishes initial prices from source.
- `vector<int> next = dist`: Freezes distances from round `r - 1` so that relaxations in the current round only chain off paths of length `<= r - 1`.
- `if (dist[u] < INF) next[f[1]] = min(next[f[1]], dist[u] + f[2])`: Relaxes flight from `u` to `v` based on previous snapshot.
- `dist = next`: Commits distances for paths with at most `round + 1` flights.
- `return dist[dst] >= INF ? -1 : dist[dst]`: Checks whether `dst` was reachable within the stop limit.

## Test it out loud
- Test `n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 0`:
  - `dist = [0, INF, INF]`.
  - Round 0 (1 flight):
    - From 0 to 1: `next[1] = 100`.
    - From 0 to 2: `next[2] = 500`.
    - `dist` becomes `[0, 100, 500]`.
  - Loop terminates (round 0 done).
  - Returns `dist[2] = 500`. Correct.
- Test `k = 1`:
  - Round 1 (2 flights):
    - From 1 to 2: `next[2] = min(500, 100 + 100) = 200`.
    - `dist` becomes `[0, 100, 200]`.
  - Returns `dist[2] = 200`. Correct.

## Follow-ups
- Can we solve this with BFS? Yes, a queue-based BFS tracking `(city, cost)` with level-by-level processing for `k + 1` steps (SPFA variant) achieves the same complexity and prunes inactive nodes.
- How can we modify Dijkstra for this? Priority queue stores `(cost, city, stops)`. To avoid infinite states, prune if `stops > k + 1` or if we have previously visited `city` with fewer stops and lower cost.

## Common mistakes
- Relaxing edges directly in `dist` without making a copy `next = dist`, which allows multiple flights to be chained in a single round.
- Allowing standard Dijkstra to overwrite node distances globally without tracking the number of stops used.
- Setting `round <= k` when 0 stops corresponds to 1 edge (requiring 1 iteration).
