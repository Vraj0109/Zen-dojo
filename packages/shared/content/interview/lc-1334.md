## Clarify first
- How are cities connected? By undirected weighted edges `[from, to, weight]`.
- What is `distanceThreshold`? The maximum shortest-path distance for a city to be considered reachable.
- What should be returned? The city index that can reach the fewest other cities within `distanceThreshold`.
- How are ties broken? If multiple cities reach the same minimum number of neighbors, return the city with the greatest numerical index.

## Examples to say out loud
- Consider `n = 4, edges = [[0,1,3],[1,2,1],[1,3,4],[2,3,1]], distanceThreshold = 4`:
  - Distances from 0: to 1 is 3, to 2 is 4, to 3 is 5 (via 1->2->3 is `3+1+1=5`). Reachable: {1, 2} (count 2).
  - Distances from 1: to 0 is 3, to 2 is 1, to 3 is 2. Reachable: {0, 2, 3} (count 3).
  - Distances from 2: to 1 is 1, to 3 is 1, to 0 is 4. Reachable: {0, 1, 3} (count 3).
  - Distances from 3: to 2 is 1, to 1 is 2, to 0 is 5. Reachable: {1, 2} (count 2).
  - Cities 0 and 3 tie with 2 reachable cities. We choose the larger index: 3. Output: 3.

## Brute force
A brute force approach runs Dijkstra's algorithm from each of the n cities independently. For each city, Dijkstra finds shortest paths to all other cities in O(E log V) time. Across all n cities, this takes O(V * E log V) time. Since `n <= 100`, the graph is dense (E up to `n * (n - 1) / 2`), and finding all-pairs shortest paths via Floyd-Warshall takes O(n^3) time with minimal code overhead and excellent cache locality.

## The key observation
We need the shortest distance between every pair of cities `(i, j)`.
Because n is very small (`n <= 100`), the Floyd-Warshall algorithm computes all-pairs shortest paths in three compact nested loops in O(n^3) time.
Let `d[i][j]` be the shortest distance between `i` and `j`. For every intermediate city `k`, we update:
`d[i][j] = min(d[i][j], d[i][k] + d[k][j])`.
After filling the distance matrix, we simply count how many cities `j != i` satisfy `d[i][j] <= distanceThreshold` for each city `i`, and pick the city with the minimum count, breaking ties with `cnt <= bestCount` (which naturally favors larger indices).

## Optimal approach
1. Allocate an `n x n` 2D array `d` initialized to a large value `INF` (e.g. 10^15 using 64-bit integers to prevent addition overflow).
2. For each `i` from 0 to `n - 1`, set `d[i][i] = 0`.
3. For each undirected edge `[u, v, w]`, set `d[u][v] = w` and `d[v][u] = w`.
4. Run Floyd-Warshall:
   - For `k` from 0 to `n - 1`:
     - For `i` from 0 to `n - 1`:
       - For `j` from 0 to `n - 1`:
         - `d[i][j] = min(d[i][j], d[i][k] + d[k][j])`.
5. Iterate `i` from 0 to `n - 1`:
   - Count `cnt` of `j` where `i != j` and `d[i][j] <= distanceThreshold`.
   - If `cnt <= bestCount`: update `bestCount = cnt` and `best = i`.
6. Return `best`.

Complexity:
- Time complexity: O(n^3) for the three nested loops of Floyd-Warshall, which takes roughly 10^6 operations for n = 100.
- Space complexity: O(n^2) auxiliary space for the n x n distance matrix.

## Code walkthrough
- `const long long INF = 1e15`: Uses 64-bit integers so adding `d[i][k] + d[k][j]` never overflows.
- Symmetric edge assignment: `d[e[0]][e[1]] = d[e[1]][e[0]] = e[2]`.
- Triple loop with `k` outermost: Standard Floyd-Warshall DP formulation.
- `if (cnt <= bestCount) { bestCount = cnt; best = i; }`: The `<=` condition ensures ties are automatically broken in favor of the larger city index `i`.

## Test it out loud
- Test `n = 2, edges = [[0, 1, 5]], threshold = 4`:
  - `d[0][1] = 5 > 4`.
  - Both cities reach 0 neighbors within threshold.
  - Count for 0 is 0 (`best = 0`). Count for 1 is 0 (`cnt <= bestCount` updates `best = 1`).
  - Returns 1. Correct.
- Test `n = 2, edges = [[0, 1, 5]], threshold = 5`:
  - `d[0][1] = 5 <= 5`. Both reach 1 neighbor.
  - Returns larger index 1. Correct.

## Follow-ups
- Could we run n Dijkstra searches instead? Yes, n Dijkstra runs with a binary heap take O(n * (E log n + n)), which is theoretically faster for sparse graphs (O(n * E log n)). For dense graphs where E is close to n^2, Floyd-Warshall has a much lower constant factor.
- How would negative weight edges affect this? Floyd-Warshall handles negative weights naturally as long as there are no negative weight cycles (which can be detected by checking if `d[i][i] < 0`).

## Common mistakes
- Placing `k` in the innermost loop instead of the outermost loop, which breaks the dynamic programming invariant.
- 32-bit integer overflow when adding `INT_MAX + INT_MAX`.
- Failing to break ties in favor of the larger index.
