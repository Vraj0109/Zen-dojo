## Clarify first

- Can we move diagonally? (No, only 4 cardinal directions: up, down, left, right).
- Does the path need to be strictly increasing? (Yes, each subsequent cell in the path must have a strictly greater value than the previous cell).
- Can the path wrap around boundaries? (No, movement outside matrix boundaries is disallowed).
- What are the matrix dimensions? ($1 \le m, n \le 200$).
- Can cell values be negative? (Constraints state $0 \le matrix[i][j] \le 2^{31} - 1$).

## Examples to say out loud

- Example with branches: `matrix = [[9, 9, 4], [6, 6, 8], [2, 1, 1]]`. Longest increasing path is $1 \to 2 \to 6 \to 9$, giving length 4.
- Spiral / snake pattern: `matrix = [[7, 8, 9], [6, 1, 2], [5, 4, 3]]`. The path travels $1 \to 2 \to 3 \to 4 \to 5 \to 6 \to 7 \to 8 \to 9$, visiting all 9 cells with length 9.
- Single cell: `matrix = [[1]]`. No neighbors can be visited; length is 1.

## Brute force

A naive brute force starts a DFS from each of the $m \times n$ cells. At each step, it explores all 4 directions with strictly larger numbers without caching results. In the worst case (e.g. A matrix with strictly increasing values everywhere), the number of paths is exponential in the grid area: $O(4^{m \cdot n})$. Even for small grids, unmemoized DFS causes massive redundant path recalculations and severe Time Limit Exceeded.

## The key observation

Because every step along a path must strictly increase in value ($matrix[nr][nc] > matrix[r][c]$), it is impossible to return to a previously visited cell on the same path. Therefore, the grid graph contains **zero directed cycles**: it is a Directed Acyclic Graph (DAG). On a DAG, the longest path starting from any cell $(r, c)$ is unique and immutable. We can compute and cache it in a 2D table `memo[r][c]`. Any time a subsequent path reaches $(r, c)$, it returns `memo[r][c]` in $O(1)$ time.

## Optimal approach

1. Let $m = matrix.length$ and $n = matrix[0].length$.
2. Create a 2D memoization table `memo[m][n]` initialized to 0.
3. Define a recursive function `dfs(r, c)`:
   - If `memo[r][c] != 0`, return `memo[r][c]`.
   - Initialize `best = 1` (a path consisting only of the current cell).
   - For each of the 4 cardinal directions $(dr, dc)$:
     - Let $nr = r + dr, nc = c + dc$.
     - If $(nr, nc)$ is inside the grid bounds and $matrix[nr][nc] > matrix[r][c]$:
       - Update `best = max(best, 1 + dfs(nr, nc))`.
   - Store and return `memo[r][c] = best`.
4. Initialize `ans = 0`. Iterate $r$ from 0 to $m - 1$ and $c$ from 0 to $n - 1$:
   - Update `ans = max(ans, dfs(r, c))`.
5. Return `ans`.

Complexity:
- Time: `O(m * n)` because each cell $(r, c)$ is computed via DFS at most once and cached; subsequent lookups are $O(1)$. Each cell evaluates 4 neighbors, totaling $4 \cdot m \cdot n$ operations.
- Space: `O(m * n)` auxiliary space for the `memo` table and recursion call stack (which is bounded by the longest path length $\le m \cdot n$).

## Code walkthrough

In the reference implementation:
- `memo[201][201]`: stores the longest increasing path starting at each cell, initialized to 0.
- `if (memo[r][c] != 0) return memo[r][c];`: memoized return avoids recomputing overlapping subpaths.
- `if (... mat[nr][nc] > mat[r][c])`: strictly enforces the increasing condition, preventing cycles and invalid transitions.
- `best = max(best, 1 + dfs(mat, nr, nc));`: Bellman-Ford / DAG longest path recurrence.
- `ans = max(ans, dfs(matrix, r, c));`: finds the global maximum over all possible starting positions.

## Test it out loud

- Single row: `matrix = [[1, 2, 3, 4]]`. DFS from 0 computes $1 + \text{dfs}(1) = 1 + 1 + \text{dfs}(2) = \dots = 4$. Returns 4.
- All equal elements: `matrix = [[2, 2], [2, 2]]`. Neighbor condition `mat[nr][nc] > mat[r][c]` is never satisfied for any cell. Every cell has path length 1. Returns 1.
- Decreasing sequence: `matrix = [[5], [4], [3], [2], [1]]`. Starting at cell `(4, 0)` (value 1) walks upward to 5, returning 5.

## Follow-ups

- Can we solve this iteratively with topological sort (Kahn's algorithm)?
  Yes, compute out-degrees for every cell (count of neighbors with strictly greater value). Enqueue all cells with out-degree 0 (local peaks), peel layers backward decrementing degrees, and count levels.
- How to return the actual cells on the longest path?
  Track the successor cell $(nr, nc)$ that achieved `best` in a companion `next_cell` table, then reconstruct the path by walking from the maximal cell.
- What if paths could be non-decreasing ($\ge$ instead of $>$)?
  Plateaus of equal values would create cycles, requiring strongly connected component (SCC / Tarjan's) compression before longest path calculation.

## Common mistakes

- Using a separate `visited` array: because the graph is strictly increasing, cycles are mathematically impossible, so a visited boolean set is unnecessary and can incorrectly block alternate paths.
- Forgetting memoization: without caching, the algorithm degenerates to exponential $O(4^{m \cdot n})$ brute force.
- Missing boundary checks before accessing `matrix[nr][nc]`.
