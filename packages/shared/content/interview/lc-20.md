## Clarify first

- What characters can appear in the string? Only the six bracket characters `()[]{}`.
- Can the input string be empty? The constraints specify length is between 1 and 10,000.
- Does an odd length string immediately fail? Yes, every opening bracket must pair with a closing bracket.
- What defines validity? Opening brackets must be closed by the matching closing bracket in the exact reverse order of opening (most recent opener closed first).

## Examples to say out loud

- Standard balanced case: `s = "{[]}"`. We see `{` and push it, see `[` and push it. Next is `]`, matching the top `[`, so we pop. Then `}` matches `{`, so we pop. String ends and stack is empty, return true.
- Interleaved mismatch: `s = "([)]"`. We push `(`, push `[`. Next is `)`. The top is `[`, which does not match `)`. We return false immediately.
- Premature closing edge case: `s = ")"`. The stack is empty when encountering a closing bracket, return false.
- Unclosed opener edge case: `s = "(()"`. After scanning, the stack still contains `(`, return false.

## Brute force

A brute-force strategy repeatedly searches for adjacent matching pairs `"()"`, `"[]"`, or `"{}"` in the string and deletes them until no pairs remain. If the resulting string is empty, it is valid; otherwise invalid. In each round, scanning and creating a new string takes `O(n)` time, and there can be up to `n / 2` rounds, taking `O(n^2)` time. We can improve upon this because we only ever need to match against the most recently opened bracket.

## The key observation

Brackets satisfy a Last-In, First-Out (LIFO) property: the most recently opened bracket must be the first one to be closed. A stack data structure perfectly maintains this invariant in linear time by buffering open brackets and matching each closing bracket against the stack top.

## Optimal approach

1. If the string length is odd, immediately return false.
2. Initialize an empty stack of characters.
3. Traverse each character `c` in `s`:
   a. If `c` is an opening bracket (`'('`, `'{'`, `'['`), push it onto the stack.
   b. Otherwise, `c` is a closing bracket. If the stack is empty, return false.
   c. Pop the top bracket from the stack and check whether it matches `c`. If it does not match, return false.
4. After traversing all characters, return true if the stack is empty, false otherwise.

Complexity:
- Time: `O(n)` because we process each of the `n` characters exactly once with `O(1)` stack operations.
- Space: `O(n)` auxiliary space to store open brackets in the stack in the worst case (e.g., all openers `((((`).

## Code walkthrough

In the reference implementation:
- `vector<char> st;`: acts as the LIFO stack to store opening brackets.
- `if (c == '(' || c == '{' || c == '[') st.push_back(c);`: pushes any opener.
- `if (st.empty()) return false;`: guards against closing brackets when no opener exists.
- `char o = st.back(); st.pop_back();`: retrieves and removes the most recent opener.
- `if ((c == ')' && o != '(') || ... ) return false;`: verifies kind match.
- `return st.empty();`: ensures no dangling unclosed openers remain.

## Test it out loud

- `s = "()[]{}"`:
  - `i = 0`: push `(`, `i = 1`: pop and match with `)`, stack empty.
  - `i = 2`: push `[`, `i = 3`: pop and match with `]`, stack empty.
  - `i = 4`: push `{`, `i = 5`: pop and match with `}`, stack empty.
  - End of string, stack is empty, return true.
- `s = "(]"`:
  - `i = 0`: push `(`.
  - `i = 1`: closing `]`, popped opener is `(`, mismatch, return false.
- `s = "{"`:
  - `i = 0`: push `{`.
  - Loop ends, stack has 1 element, `st.empty()` is false, return false.

## Follow-ups

- What if there are other characters in the string, like numbers or algebraic operators?
  Ignore non-bracket characters and only push or match when encountering bracket characters.
- Could you optimize space if there was only one type of bracket (e.g. only parentheses)?
  Yes, use an integer counter tracking open bracket count in `O(1)` space; if it drops below zero return false, and check counter is zero at end.

## Common mistakes

- Forgetting to check if the stack is empty before popping when a closing bracket is met, causing runtime exceptions.
- Returning true immediately after loop ends without checking `st.empty()`, incorrectly returning true for inputs like `"("`.
- Using a simple counter instead of a stack when multiple bracket types are present, failing to detect improper nesting like `"([)]"`.
