## Clarify first

- How many elements appear once? Exactly two elements appear once; every other element appears exactly twice.
- In what order should the two elements be returned? The answer can be returned in any order.
- Can numbers be negative? Yes, values span the full 32-bit signed integer range from `-2^31` to `2^31 - 1`.
- What are the time and space constraints? Must run in `O(n)` linear time and `O(1)` constant auxiliary space.

## Examples to say out loud

- Mixed array: `nums = [1, 2, 1, 3, 2, 5]`.
  - Pairs: 1 and 2 cancel out.
  - Singles: 3 and 5.
  - Return `[3, 5]` (or `[5, 3]`).
- Two elements only: `nums = [-1, 0]`. Both are singles, return `[-1, 0]`.
- Extreme values: `nums = [0, 1]`. Return `[0, 1]`.

## Brute force

A brute-force solution counts element frequencies using a hash map or hash set. After a linear scan, any element with a count of 1 is appended to the result. While this runs in `O(n)` time, the hash map consumes `O(n)` auxiliary memory, which violates the strict `O(1)` space requirement. Alternatively, sorting takes `O(n log n)` time, which violates the `O(n)` time requirement.

## The key observation

Let `a` and `b` be the two unique single numbers.
If we compute the cumulative XOR of all numbers in the array, all duplicate pairs cancel out, leaving:
`x = a ^ b`.
Because `a \neq b`, `x \neq 0`, which means there must be at least one bit where `a` and `b` differ (where that bit is 1 in `x`).
We can isolate any set bit of `x`—conveniently the lowest set bit using `bit = x & -x`.
This bit acts as a discriminator:
1. `a` has this bit set and `b` does not (or vice versa).
2. For every duplicate pair in `nums`, both copies will fall into the exact same group (either both have the bit set, or both do not).
Thus, partitioning the entire array into two groups based on whether this bit is set splits `a` and `b` into separate groups, and XORing each group independently reveals `a` and `b` in `O(1)` space!

## Optimal approach

1. Compute the cumulative XOR of all numbers in `nums`: `long long x = 0; for (int v : nums) x ^= v;`.
2. Isolate the lowest set bit of `x`: `long long bit = x & -x` (using 64-bit integer arithmetic to prevent overflow when `x = INT_MIN`).
3. Initialize `a = 0` and `b = 0`.
4. Iterate through `nums`:
   - If `v & bit` is non-zero, XOR `v` into `a`: `a ^= v`.
   - Otherwise, XOR `v` into `b`: `b ^= v`.
5. Return `{a, b}`.

Complexity:
- Time: `O(n)` because we iterate through the array of `n` elements twice, performing constant-time bitwise operations per element.
- Space: `O(1)` auxiliary space since only a few scalar variables are maintained.

## Code walkthrough

In the reference implementation:
- `long long x = 0; for (int v : nums) x ^= v;`: combines all values; duplicate pairs cancel to zero, leaving `x = a ^ b`.
- `long long bit = x & -x;`: extracts the least significant 1-bit where `a` and `b` differ. 64-bit type avoids signed integer negation overflow on `INT_MIN`.
- `for (int v : nums)`: second pass partitioning elements into two distinct streams.
- `if ((long long)v & bit) a ^= v; else b ^= v;`: cancels duplicate pairs within each partition, isolating `a` in one accumulator and `b` in the other.
- `return {a, b};`: returns the two single numbers.

## Test it out loud

- `nums = [1, 2, 1, 3, 2, 5]`:
  - `x = 1 ^ 2 ^ 1 ^ 3 ^ 2 ^ 5 = 3 ^ 5 = (011)_2 ^ (101)_2 = (110)_2 = 6`.
  - Lowest set bit of 6 (`110_2`) is `bit = 2` (`010_2`).
  - Partition by bit 1:
    - Group with bit set: `2, 2, 3` -> `2 ^ 2 ^ 3 = 3`.
    - Group without bit set: `1, 1, 5` -> `1 ^ 1 ^ 5 = 5`.
  - Return `[3, 5]`.
- `nums = [0, 1]`:
  - `x = 0 ^ 1 = 1`. `bit = 1`.
  - Group with bit 0 set: `1`.
  - Group without bit 0 set: `0`.
  - Return `[1, 0]`.

## Follow-ups

- What if `x = INT_MIN` (`-2147483648`)?
  In 32-bit signed integers, `-x` causes signed integer overflow because `2147483648` exceeds `INT_MAX`. Computing `x & -x` in `long long` (or unsigned integer) prevents undefined behavior.
- How does this generalize to finding two missing numbers from `1` to `n`?
  XOR the array with numbers `1` to `n`, isolating the two missing numbers in identical fashion.

## Common mistakes

- Computing `x & -x` in standard 32-bit signed `int`, which causes integer overflow when `x = -2^31`.
- Forgetting operator precedence: `&` has lower precedence than `==` and `!=` in C++, so `(v & bit) != 0` requires parentheses.
- Using `O(n)` extra space with a hash set instead of the bit partition technique.
