## Clarify first

- Can houses have 0 money? Yes, money values range from 0 to 400.
- Does robbing houses at distance 2 trigger the alarm? No, the constraint only prohibits robbing two immediately adjacent houses.
- Can we skip two or more houses consecutively? Yes, if skipping multiple houses leads to a greater total, it is entirely valid.
- What is the size of the street? Between 1 and 100 houses.

## Examples to say out loud

- Alternating houses: `nums = [1, 2, 3, 1]`.
  - Rob house 0 and 2: `1 + 3 = 4`.
  - Rob house 1 and 3: `2 + 1 = 3`.
  - Maximum robbed amount is 4.
- Larger selection: `nums = [2, 7, 9, 3, 1]`.
  - Optimal selection is house 0, 2, and 4: `2 + 9 + 1 = 12`.
- Single house: `nums = [5]`. Rob house 0, result is 5.
- Two houses: `nums = [1, 2]`. Best is `max(1, 2) = 2`.

## Brute force

A brute-force recursive approach starts at house 0 and for every house `i`, branches into two decisions: rob house `i` and jump to `i + 2`, or skip house `i` and advance to `i + 1`. This creates a binary decision tree of height `n`, taking `O(2^n)` exponential time. For `n = 100`, `2^{100}` operations is astronomical.

## The key observation

At each house `i`, the maximum loot depends only on the optimal answers for earlier houses: either we skip house `i` (achieving `dp[i - 1]`), or we rob house `i` (achieving `nums[i] + dp[i - 2]`). Therefore, the state recurrence is `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])`. Because `dp[i]` depends strictly on the two immediately preceding values, we do not need a full array; two scalar variables suffice.

## Optimal approach

1. Initialize two variables `prev2 = 0` (best profit up to two houses ago) and `prev1 = 0` (best profit up to the previous house).
2. For each house value `x` in `nums`:
   a. Compute `cur = max(prev1, prev2 + x)`.
   b. Shift states: `prev2 = prev1`, `prev1 = cur`.
3. Return `prev1`.

Complexity:
- Time: `O(n)` because we iterate through the list of `n` houses once, doing constant work per house.
- Space: `O(1)` auxiliary space since only two variables are maintained.

## Code walkthrough

In the reference implementation:
- `int prev2 = 0, prev1 = 0;`: represents base cases for an empty prefix and 0-house profits.
- `for (int x : nums)`: iterates over the cash values of each house.
- `int cur = max(prev1, prev2 + x);`: chooses between skipping house `x` (keeping `prev1`) and robbing house `x` (adding `x` to `prev2`).
- `prev2 = prev1; prev1 = cur;`: advances the two-step sliding window.
- `return prev1;`: yields the maximum achievable loot across all houses.

## Test it out loud

- `nums = [2, 1, 1, 2]`:
  - `x = 2`: `cur = max(0, 0 + 2) = 2`, `prev2 = 0`, `prev1 = 2`.
  - `x = 1`: `cur = max(2, 0 + 1) = 2`, `prev2 = 2`, `prev1 = 2`.
  - `x = 1`: `cur = max(2, 2 + 1) = 3`, `prev2 = 2`, `prev1 = 3`.
  - `x = 2`: `cur = max(3, 2 + 2) = 4`, `prev2 = 3`, `prev1 = 4`.
  - Return 4 (robbing first and last house).
- `nums = [5]`:
  - `x = 5`: `cur = max(0, 0 + 5) = 5`, `prev1 = 5`.
  - Return 5.

## Follow-ups

- What if the houses are arranged in a circle (House Robber II, LeetCode 213)?
  The first and last houses are adjacent. Run the linear robber algorithm twice: once on `nums[0..n-2]` and once on `nums[1..n-1]`, taking the maximum of the two runs.
- What if houses are arranged in a binary tree (House Robber III, LeetCode 337)?
  Use tree DP returning `(robbed, skipped)` from post-order DFS.

## Common mistakes

- Allocating an `O(n)` DP table when only the previous two states are needed for computation.
- Mistakenly assuming a greedy alternating strategy (e.g. sum of even indices vs sum of odd indices) works; for example, `[2, 1, 1, 2]` requires robbing indices 0 and 3, which neither even nor odd parity captures.
- Index out of bounds when looking back 2 steps without proper base case initialization.
