## Clarify first

- How is the tree structured and rooted? (Nodes are numbered $0$ to $n - 1$, rooted at node 0 with `parent[0] == -1`).
- What defines the $k$-th ancestor? (The node reached by moving $k$ edges up the direct path towards the root).
- What should be returned if no such ancestor exists (e.g. stepping past the root)? (Return -1).
- What are the scale and performance requirements? ($n \le 50,000$ and up to $50,000$ queries).
- Can $k$ be larger than $n$? (Constraints state $1 \le k \le n$).

## Examples to say out loud

- Tree with branches: $n = 7$, `parent = [-1, 0, 0, 1, 1, 2, 2]`. Query `[3, 1]` gives parent 1; query `[5, 2]` goes $5 \to 2 \to 0$, giving 0; query `[6, 3]` goes $6 \to 2 \to 0 \to \text{out}$, giving -1.
- Line graph: $0 \to 1 \to 2 \to 3 \to 4$. `[4, 2]` gives 2, `[4, 4]` reaches root 0, `[4, 5]` exceeds tree depth, returning -1.
- Root node query: Node 0 has no parent (`parent[0] = -1`), so any query on node 0 with $k \ge 1$ returns -1.

## Brute force

A naive approach traverses up the parent pointers one step at a time: starting at `node`, set `node = parent[node]` repeatedly $k$ times or until reaching -1. While this uses $O(1)$ extra space, each query can take $O(k) = O(n)$ time on a degenerate skewed tree. For $50,000$ queries and $n = 50,000$, total time is $O(q \cdot n) \approx 2.5 \times 10^9$ operations, resulting in Time Limit Exceeded.

## The key observation

Any positive integer $k$ can be uniquely expressed in binary as a sum of powers of two (e.g., $13 = 8 + 4 + 1$). Instead of stepping by 1, precompute jumps of size $2^j$ using **binary lifting**. Let `up[node][j]` be the $2^j$-th ancestor of `node`. Because $2^j = 2^{j-1} + 2^{j-1}$, we have the recurrence:
`up[node][j] = up[ up[node][j-1] ][j-1]`.
Since $n \le 50,000$, $\log_2(50000) < 16$, so $LOG = 17$ powers of two suffice. Every query is answered in $O(\log k)$ jumps by checking the set bits of $k$.

## Optimal approach

1. Set $LOG = 17$ (since $2^{16} = 65,536 > n$).
2. Allocate a 2D table `up[n][LOG]` initialized to -1.
3. Base jumps of length $2^0 = 1$: for each node $i \in [0, n - 1]$, `up[i][0] = parent[i]`.
4. Fill table using DP:
   - For $j$ from 1 to $LOG - 1$:
     - For $i$ from 0 to $n - 1$:
       - If `up[i][j - 1] != -1`:
         - `up[i][j] = up[ up[i][j - 1] ][ j - 1 ]`.
5. For each query `[node, k]`:
   - Iterate $j$ from 0 to $LOG - 1$:
     - If the $j$-th bit of $k$ is set (`(k >> j) & 1`):
       - Jump: `node = up[node][j]`.
       - If `node == -1`, break early.
   - Record `node` into the answer list.
6. Return the accumulated results.

Complexity:
- Time: Preprocessing takes $O(n \log n)$ time. Each of the $q$ queries takes $O(\log k)$ time, yielding $O((n + q) \log n)$ overall time.
- Space: `O(n log n)` auxiliary space for the `up` table ($50,000 \times 17 \approx 8.5 \times 10^5$ integers, taking under 4 MB).

## Code walkthrough

In the reference implementation:
- `int LOG = 17;`: covers maximum possible tree depth up to 50,000.
- `up[i][0] = parent[i];`: initializes power $2^0 = 1$ ancestors.
- `up[i][j] = up[up[i][j - 1]][j - 1];`: composes two $2^{j-1}$ jumps into a $2^j$ jump.
- `if ((k >> j) & 1)`: tests bit $j$ of $k$ to execute the corresponding power-of-two jump.
- `if (node == -1) break;`: halts immediately once an ancestor query leaves the root.

## Test it out loud

- Single node tree: $n = 1$, `parent = [-1]`, query `[0, 1]`. `up[0][0] = -1`. Jump sets `node = -1`, breaks, returns `[-1]`.
- Star graph: Center 0, children 1, 2, 3. `[1, 1]` gives 0. `[1, 2]` tries jump past 0, yielding -1.
- Deep line: $n = 4$, path $0 \to 1 \to 2 \to 3$. Query `[3, 3]`: binary $3 = 2^0 + 2^1$. Jumps $2^0$ to 2, then $2^1$ to 0. Correctly returns 0.

## Follow-ups

- How does binary lifting help compute Lowest Common Ancestor (LCA)?
  First lift the deeper node so both nodes are at the same depth. Then lift both simultaneously in decreasing powers of two until their parents coincide.
- Can we answer tree path aggregate queries (e.g., max edge weight on path)?
  Yes, store a companion table `maxWeight[node][j]` storing the maximum edge weight across the $2^j$ ancestors.
- How does offline Euler tour + RMQ compare for LCA?
  Euler tour + Sparse Table allows $O(n \log n)$ preprocessing and true $O(1)$ query time for LCA, though it does not directly answer $k$-th ancestor queries.

## Common mistakes

- Outer loop iterating over nodes and inner loop over powers: `up[up[i][j - 1]][j - 1]` requires that all nodes have computed jump $j - 1$ before any node computes jump $j$. The outer loop must iterate over $j$.
- Not stopping when `node` reaches -1, leading to out-of-bounds indexing like `up[-1][j]`.
- Choosing $LOG$ too small (e.g. $LOG = 16$ with $2^{15} = 32768 < 50000$).
