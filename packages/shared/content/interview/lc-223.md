## Clarify first
- Are rectangles aligned with the coordinate axes? Yes, sides are parallel to the x and y axes.
- How are rectangles represented? By bottom-left `(x1, y1)` and top-right `(x2, y2)` coordinates.
- Can coordinates be negative? Yes, coordinates range between `-10000` and `10000`.
- What if the rectangles do not overlap? The total area is simply the sum of the two individual rectangle areas.

## Examples to say out loud
- Consider `A = [-3, 0, 3, 4]` and `B = [0, -1, 9, 2]`:
  - Area of A: `(3 - (-3)) * (4 - 0) = 6 * 4 = 24`.
  - Area of B: `(9 - 0) * (2 - (-1)) = 9 * 3 = 27`.
  - Overlap in x: `[max(-3, 0), min(3, 9)] = [0, 3]`, width = 3.
  - Overlap in y: `[max(0, -1), min(4, 2)] = [0, 2]`, height = 2.
  - Overlap area: `3 * 2 = 6`.
  - Total area: `24 + 27 - 6 = 45`.
- Consider two identical rectangles `[-2, -2, 2, 2]` and `[-2, -2, 2, 2]`:
  - Area A = 16, Area B = 16, Overlap = 16. Total = 16.

## Brute force
Because this is a closed-form geometric calculation, brute force pixel-by-pixel counting or 2D grid simulation would be unnecessarily slow (`O(W * H)`) and memory intensive. The direct analytical formula using inclusion-exclusion provides the exact answer in constant time.

## The key observation
By the principle of inclusion-exclusion:
`Total Area = Area(A) + Area(B) - Area(A ∩ B)`.
Because the rectangles are axis-aligned, their intersection (if non-empty) is also an axis-aligned rectangle. The intersection's x-span is `[max(ax1, bx1), min(ax2, bx2)]` and y-span is `[max(ay1, by1), min(ay2, by2)]`. If the upper bound is less than the lower bound along either axis, the intersection width or height is 0 (no overlap).

## Optimal approach
1. Compute area of rectangle A: `areaA = (ax2 - ax1) * (ay2 - ay1)`.
2. Compute area of rectangle B: `areaB = (bx2 - bx1) * (by2 - by1)`.
3. Compute the overlap width: `w = max(0, min(ax2, bx2) - max(ax1, bx1))`.
4. Compute the overlap height: `h = max(0, min(ay2, by2) - max(ay1, by1))`.
5. Compute overlap area: `overlap = w * h`.
6. Return `areaA + areaB - overlap`.

Complexity:
- Time: `O(1)` time since it involves a constant number of arithmetic operations.
- Space: `O(1)` space using a few local 64-bit integer variables.

## Code walkthrough
- `long long a = (long long)(ax2 - ax1) * (ay2 - ay1);` computes area A safely with 64-bit integers.
- `long long b = (long long)(bx2 - bx1) * (by2 - by1);` computes area B.
- `min(ax2, bx2) - max(ax1, bx1)` finds the projected overlap along the x-axis. Using `max(0, ...)` clamps negative lengths (when rectangles are disjoint) to 0.
- `min(ay2, by2) - max(ay1, by1)` computes the projected overlap along the y-axis, clamped to 0.
- `return (int)(a + b - w * h);` subtracts the double-counted intersection area.

## Test it out loud
- Test disjoint rectangles `[0, 0, 1, 1]` and `[2, 2, 3, 3]`:
  - Overlap width = `max(0, min(1, 3) - max(0, 2)) = max(0, -1) = 0`.
  - Overlap = 0. Total area = `1 + 1 - 0 = 2`.
- Test touching boundaries `[0, 0, 2, 2]` and `[2, 0, 4, 2]`:
  - Overlap width = `min(2, 4) - max(0, 2) = 2 - 2 = 0`.
  - Overlap = 0. Total area = `4 + 4 = 8`.
- Test one containing the other `[0, 0, 4, 4]` and `[1, 1, 2, 2]`:
  - Area A = 16, Area B = 1, Overlap = 1. Total = `16 + 1 - 1 = 16`.
- Test extreme range `[-10000, -10000, 10000, 10000]`:
  - Area is `20000 * 20000 = 4 * 10^8`. Sum is `8 * 10^8`, fitting within a signed 32-bit integer.

## Follow-ups
- How would we extend this to `k` overlapping rectangles?
  - For `k` rectangles, sweeping line algorithms combined with interval trees or segment trees calculate total union area in `O(k log k)` time.
- What if rectangles are rotated at arbitrary angles?
  - Use polygon clipping (Sutherland-Hodgman algorithm) to find polygon intersection and Shoelace formula for area.

## Common mistakes
- Forgetting to clamp negative intersection spans to 0 with `max(0, ...)`, which would incorrectly add artificial negative areas when rectangles are completely separated.
- 32-bit integer overflow during coordinate subtraction and multiplication if coordinates reach `20000`.
