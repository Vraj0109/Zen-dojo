## Clarify first

- What operations must be supported? (`insert(val)`, `remove(val)`, and `getRandom()`).
- What should `insert` and `remove` return? (`insert` returns `true` if added, `false` if already present; `remove` returns `true` if removed, `false` if not present).
- What does `getRandom()` return? (Returns an element from the current set uniformly at random, each with probability $1/N$).
- What are the time complexity requirements? (All three operations must run in $O(1)$ average time).
- What are the value constraints? ($-10^9 \le val \le 10^9$; up to 200,000 total calls).

## Examples to say out loud

- Basic lifecycle:
  - `insert(1)` $\implies$ returns `true` (set holds `{1}`).
  - `remove(2)` $\implies$ returns `false` (2 is not present).
  - `insert(2)` $\implies$ returns `true` (set holds `{1, 2}`).
  - `getRandom()` $\implies$ returns 1 or 2 with equal $50\%$ probability.
  - `remove(1)` $\implies$ returns `true` (set holds `{2}`).
  - `getRandom()` $\implies$ returns 2 with $100\%$ probability.

## Brute force

Using a standard hash set (`std::unordered_set`), `insert` and `remove` both run in $O(1)$ time, but `getRandom()` cannot be done in $O(1)$ because hash sets do not support random-access indexing. Iterating through a hash set to a random index takes $O(n)$ time.
Conversely, using a standard array (`std::vector`), `getRandom()` is $O(1)$ via random index access, and `insert` is $O(1)$ via append, but `remove` takes $O(n)$ time because searching for the element and shifting remaining elements left takes linear time.

## The key observation

We can combine both data structures:
1. A **dynamic array (vector)** stores the elements contiguously so `getRandom()` can pick a random index in $[0, \text{size} - 1]$ in $O(1)$.
2. A **hash map** stores `val -> index in array`, allowing $O(1)$ existence checks and location lookups.
To achieve $O(1)$ removal from an array without shifting all subsequent elements, **swap the element to be removed with the last element of the array**, update the swapped element's index in the hash map, and pop the last element from the array in $O(1)$.

## Optimal approach

1. Maintain:
   - `vector<int> items`: stores values contiguously.
   - `unordered_map<int, int> where`: maps `val` to its index in `items`.
2. Operation `insert(val)`:
   - If `val` is already in `where`, return `false`.
   - Record `where[val] = items.size()`.
   - Append `items.push_back(val)`.
   - Return `true`.
3. Operation `remove(val)`:
   - If `val` is not in `where`, return `false`.
   - Let `idx = where[val]` and `last = items.back()`.
   - Copy `last` into `items[idx]`.
   - Update `where[last] = idx`.
   - Call `items.pop_back()` and `where.erase(val)`.
   - Return `true`.
4. Operation `getRandom()`:
   - Pick a random index: `items[rand() % items.size()]`.
   - Return that element.

Complexity:
- Time: $O(1)$ average time for `insert`, `remove`, and `getRandom`. Array appends, pops, and index lookups are $O(1)$, and hash map operations take $O(1)$ average time.
- Space: $O(n)$ auxiliary space to store $n$ elements in both the array and the hash map.

## Code walkthrough

In the reference implementation:
- `vector<int> items; unordered_map<int, int> where;`: pairs array indexing with hash map lookup.
- `items[it->second] = last; where[last] = it->second;`: moves the last element into the deleted slot and updates its index pointer.
- `items.pop_back(); where.erase(val);`: removes the tail element in $O(1)$ with no shifting.
- `return items[rand() % items.size()];`: generates a uniformly random selection over contiguous indices in $O(1)$.

## Test it out loud

- Removing the last element itself: If `val == last`, setting `items[idx] = last` and `where[last] = idx` followed by `where.erase(val)` correctly removes `val` without leaving an orphaned or invalid map entry.
- Re-inserting a previously removed element: Element is cleanly appended to the end with its fresh index.
- Negative numbers and zero: `val` values like `-10^9`, `0`, `10^9` are handled natively by the hash map without offset shifts.

## Follow-ups

- What if duplicate elements are allowed? (LeetCode 381 - Insert Delete GetRandom O(1) - Duplicates allowed):
  Instead of mapping to a single index, map each value to a hash set of indices (`unordered_map<int, unordered_set<int>> where`).
- Why is updating `where[last]` before `where.erase(val)` important?
  If the element being removed happens to be the last element in the array (`idx == items.size() - 1`), updating `where[last]` first and then erasing `val` ensures `val` is properly deleted from the map.
- How to make this thread-safe?
  Use a mutex or read-write lock (`std::shared_mutex`) wrapping the class methods, or lock-free concurrent structures.

## Common mistakes

- Removing from the vector using `items.erase(items.begin() + idx)`, which takes $O(n)$ time due to shifting elements.
- Forgetting to update the index of `last` in the hash map when swapping with the deleted element.
- Bugs when the element to be removed is already the last element: if map updates are done in the wrong order, the deleted element can be accidentally re-inserted into the map.
