## Clarify first

- What should be returned if the input graph is empty (null node pointer)? (Return `nullptr`).
- What defines a deep copy? (Every node and its list of neighbor edges must be completely newly instantiated; no cloned node should point to any node in the original graph).
- Can the graph contain cycles or self-loops? (Undirected edges inherently form 2-cycles between neighbors; there are no self-loops, but cycles must be handled to prevent infinite recursion).
- Are node values guaranteed to be unique? (Yes, $1 \le Node.val \le 100$, unique per node).
- Is the graph guaranteed to be connected? (Yes, all nodes can be reached from the given starting node).

## Examples to say out loud

- 4-node cycle: `1 - 2 - 3 - 4 - 1`. Cloning node 1 explores neighbor 2, which explores 3, which explores 4, which links back to cloned node 1 without re-allocating.
- Single node without neighbors: `Node(1)` with empty `neighbors`. Clones a single node `Node(1)` with empty `neighbors`.
- Empty input: `node == nullptr` returns `nullptr`.

## Brute force

A naive traversal without memoizing cloned nodes attempts to create a new node and recursively clone all its neighbors. Because the graph is undirected and contains cycles, this causes infinite recursion and stack overflow as node 1 attempts to clone neighbor 2, which attempts to clone neighbor 1, endlessly.

## The key observation

The primary challenge in deep-cloning an arbitrary graph is handling cycles and shared vertices.
We use a **hash map** mapping original node pointers to newly created cloned node pointers (`original -> clone`):
1. The hash map serves dual purposes: it prevents duplicate node allocations and acts as a `visited` set to terminate recursive cycles.
2. Before traversing neighbors of a node, create the clone and immediately register it in the hash map.
3. When inspecting neighbors, if a neighbor is already in the map, reuse its existing clone pointer directly instead of recursing.

## Optimal approach

1. If `node == nullptr`, return `nullptr`.
2. Maintain a global or passed hash map `copies: unordered_map<Node*, Node*>`.
3. In `cloneGraph(node)`:
   - If `node == nullptr`, return `nullptr`.
   - If `copies.count(node)`, the node has already been created; return `copies[node]`.
   - Create a new node `copy = new Node(node->val)`.
   - Register the clone immediately: `copies[node] = copy`.
   - For each `neighbor` in `node->neighbors`:
     - Append `cloneGraph(neighbor)` to `copy->neighbors`.
   - Return `copy`.

Complexity:
- Time: $O(V + E)$ where $V$ is the number of vertices ($V \le 100$) and $E$ is the number of undirected edges. Each vertex is created once and its adjacency list is traversed once.
- Space: $O(V)$ auxiliary space for the `copies` hash map and the recursion stack (bounded by the number of vertices $V$).

## Code walkthrough

In the reference implementation:
- `unordered_map<Node*, Node*> copies;`: maps original node addresses to their deep-copy counterparts.
- `if (copies.find(node) != copies.end()) return copies[node];`: cycle detection and memoization base case.
- `Node* copy = new Node(node->val); copies[node] = copy;`: registers the cloned node BEFORE exploring its neighbors to resolve cyclical references.
- `copy->neighbors.push_back(cloneGraph(neighbor));`: recursively deep-clones adjacent connections.

## Test it out loud

- Two connected nodes: `1 - 2`.
  - Call on 1: creates clone 1. Calls on 2.
  - Call on 2: creates clone 2. Neighbor 1 is already in `copies`, returns clone 1.
  - Clone 2's neighbors list gets `[clone 1]`.
  - Clone 1's neighbors list gets `[clone 2]`.
  - Returns `clone 1`.
- Graph with 3-node triangle: `1-2-3-1`. Clones nodes once and correctly completes the cyclic adjacency triangle.
- Null input: `nullptr` returns `nullptr` immediately.

## Follow-ups

- Can we solve this using BFS instead of DFS?
  Yes, push the starting node onto a queue, clone it, and map it. While the queue is not empty, pop a node, and for each neighbor, create its clone if not in map, enqueue it, and wire the neighbor edge.
- What if node values are not unique?
  Because the hash map keys are memory addresses (`Node*`) rather than integer values, identical values in different nodes are handled correctly without collision.
- What if the graph is disconnected (multiple components)?
  Iterate over an array of all node references, launching BFS/DFS whenever an unvisited node is encountered.

## Common mistakes

- Registering `copies[node] = copy` AFTER the neighbor recursion loop: this causes infinite recursion because cycles loop back to `node` before it is recorded in the map.
- Shallow copying neighbor lists (`copy->neighbors = node->neighbors`), which leaves cloned nodes pointing to original graph objects.
- Forgetting to handle `nullptr` input, leading to null pointer dereference.
