## Clarify first

- Can the matrix have different numbers of rows and columns (non-square)? Yes, `m` rows and `n` columns, where `1 <= m, n <= 10`.
- What is the direction of the spiral? Clockwise: start along the top row left-to-right, down the right column, back along the bottom row right-to-left, and up the left column bottom-to-top, repeating inward.
- Does the return array count as auxiliary space? As standard in interview settings, the returned output array does not count toward auxiliary space complexity.
- What if there is only 1 row or 1 column? The traversal should visit the single line and terminate cleanly without duplicate visits.

## Examples to say out loud

- Square matrix: `matrix = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]`.
  - Top row: 1, 2, 3.
  - Right col: 6, 9.
  - Bottom row: 8, 7.
  - Left col: 4.
  - Center: 5.
  - Result: `[1, 2, 3, 6, 9, 8, 7, 4, 5]`.
- Rectangular matrix with 3 rows and 4 columns: visits the outer ring of 10 elements, then the inner 2 elements.
- Single row edge case: `matrix = [[1, 2, 3]]`. Visited once as `[1, 2, 3]`.

## Brute force

A simulation approach tracks current position `(r, c)` and direction `(dr, dc)`, accompanied by an `m \times n` boolean `visited` array. Whenever advancing into an already-visited cell or boundary, turn right 90 degrees. While this runs in `O(m * n)` time, it requires an `O(m * n)` visited table and complex state checking. We can eliminate the visited table by using four shrinking boundaries.

## The key observation

The matrix can be peeled layer by layer like an onion. By maintaining four boundary pointers (`top`, `bottom`, `left`, `right`), each complete spiral cycle traverses the perimeter of the active rectangle and then shrinks the boundaries inward (`top++`, `right--`, `bottom--`, `left++`). To handle remaining single rows or columns correctly, we check `top <= bottom` before traversing the bottom row and `left <= right` before traversing the left column.

## Optimal approach

1. Initialize four boundaries: `top = 0`, `bottom = m - 1`, `left = 0`, `right = n - 1`.
2. Initialize an empty output list `out`.
3. While `top <= bottom` and `left <= right`:
   a. Traverse top row: for `c` from `left` to `right`, append `matrix[top][c]`. Increment `top`.
   b. Traverse right column: for `r` from `top` to `bottom`, append `matrix[r][right]`. Decrement `right`.
   c. If `top <= bottom`:
      - Traverse bottom row: for `c` from `right` down to `left`, append `matrix[bottom][c]`. Decrement `bottom`.
   d. If `left <= right`:
      - Traverse left column: for `r` from `bottom` down to `top`, append `matrix[r][left]`. Increment `left`.
4. Return `out`.

Complexity:
- Time: `O(m * n)` because each of the `m * n` cells in the matrix is visited exactly once.
- Space: `O(1)` auxiliary space beyond the output list, since only four boundary integer pointers are maintained.

## Code walkthrough

In the reference implementation:
- `int top = 0, bottom = (int)matrix.size() - 1, left = 0, right = (int)matrix[0].size() - 1;`: establishes the perimeter coordinates.
- `for (int c = left; c <= right; c++) out.push_back(matrix[top][c]); top++;`: scans across the active top row and pushes the ceiling down.
- `for (int r = top; r <= bottom; r++) out.push_back(matrix[r][right]); right--;`: scans down the active right wall and pulls the right boundary in.
- `if (top <= bottom)`: guards against duplicate processing when the remaining area has collapsed to a single row.
- `if (left <= right)`: guards against duplicate processing when the remaining area has collapsed to a single column.

## Test it out loud

- `matrix = [[1, 2], [3, 4]]`:
  - `top = 0, bottom = 1, left = 0, right = 1`.
  - Top row: 1, 2. `top = 1`.
  - Right col: 4. `right = 0`.
  - `top <= bottom` (`1 <= 1`) true: Bottom row: 3. `bottom = 0`.
  - `left <= right` (`0 <= 0`) true: Left col: empty since `bottom (0) < top (1)`. `left = 1`.
  - Loop condition `top <= bottom` (`1 <= 0`) fails. Result: `[1, 2, 4, 3]`.
- `matrix = [[1], [2]]`:
  - Top row: 1. `top = 1`.
  - Right col: 2. `right = -1`.
  - Bottom row guard: `top <= bottom` (`1 <= 1`) true, `c` from -1 to 0 (empty loop). `bottom = 0`.
  - Left col guard: `left <= right` (`0 <= -1`) false, skipped.
  - Loop ends. Result: `[1, 2]`.

## Follow-ups

- How would you generate a spiral matrix given integer `n` (Spiral Matrix II, LeetCode 59)?
  Follow the same 4-boundary traversal, filling an empty `n \times n` grid with incrementing numbers `1` to `n^2`.
- What if the matrix is too large to fit in memory and streaming?
  Process block-by-block by calculating the coordinates mathematically using layer rings.

## Common mistakes

- Omitting the `if (top <= bottom)` and `if (left <= right)` boundary checks, causing single-row or single-column matrices to traverse the same elements twice.
- Updating boundary variables before the corresponding row/column traversal completes.
- Off-by-one errors with index bounds when walking backwards along bottom or left edges.
