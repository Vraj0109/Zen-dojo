## Clarify first

- Is the input `intervals` list already sorted? Yes, it is guaranteed to be sorted by start time in ascending order.
- Are the existing intervals in `intervals` disjoint (non-overlapping)? Yes, they are already non-overlapping.
- Can `intervals` be empty? Yes, if `intervals` is empty, return `[newInterval]`.
- Do touching intervals count as overlapping? Yes, intervals that touch at an endpoint (like `[1, 5]` and `[5, 7]`) overlap and must merge into `[1, 7]`.
- What are the constraints on length? `intervals.length` is between 0 and 10,000, with coordinates between 0 and 100,000.

## Examples to say out loud

- Insertion with overlap: `intervals = [[1, 3], [6, 9]]`, `newInterval = [2, 5]`.
  - `[1, 3]` overlaps with `[2, 5]` -> merges into `[1, 5]`.
  - `[6, 9]` starts strictly after 5 -> added as is.
  - Result: `[[1, 5], [6, 9]]`.
- Spanning multiple intervals: `intervals = [[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]]`, `newInterval = [4, 8]`.
  - Intervals `[3, 5]`, `[6, 7]`, and `[8, 10]` overlap with `[4, 8]`.
  - Merged interval becomes `[min(3, 4), max(10, 8)] = [3, 10]`.
  - Result: `[[1, 2], [3, 10], [12, 16]]`.
- Disjoint insertion: `intervals = [[1, 5]]`, `newInterval = [6, 8]`. Result: `[[1, 5], [6, 8]]`.
- Empty intervals edge case: `intervals = []`, `newInterval = [5, 7]`. Result: `[[5, 7]]`.

## Brute force

A brute-force solution appends `newInterval` to the end of `intervals`, calls a general interval sorting function (`sort` by start time), and then runs the standard Merge Intervals algorithm (LeetCode 56). Sorting `n + 1` intervals takes `O(n log n)` time. This ignores the vital invariant that the original `intervals` array is **already sorted and disjoint**, which allows a single linear `O(n)` scan.

## The key observation

Because the existing intervals are already sorted and non-overlapping, any insertion partitions the timeline into three distinct, sequential phases:
1. **Left phase (strictly before):** Copy all intervals that end strictly before `newInterval` starts (`intervals[i].end < newInterval.start`).
2. **Overlap phase (merging):** While intervals start before or at the moment `newInterval` ends (`intervals[i].start <= newInterval.end`), merge each overlapping interval into `newInterval` by updating `newInterval = [min(newInterval.start, intervals[i].start), max(newInterval.end, intervals[i].end)]`. Then append `newInterval` to the output.
3. **Right phase (strictly after):** Copy all remaining intervals that start strictly after the merged interval.

## Optimal approach

1. Initialize an empty list of intervals `out`, and index `i = 0`.
2. Let `n = intervals.length`.
3. Phase 1: While `i < n && intervals[i][1] < newInterval[0]`:
   - Append `intervals[i]` to `out`.
   - Increment `i`.
4. Phase 2: While `i < n && intervals[i][0] <= newInterval[1]`:
   - `newInterval[0] = min(newInterval[0], intervals[i][0])`.
   - `newInterval[1] = max(newInterval[1], intervals[i][1])`.
   - Increment `i`.
   - Append `newInterval` to `out`.
5. Phase 3: While `i < n`:
   - Append `intervals[i]` to `out`.
   - Increment `i`.
6. Return `out`.

Complexity:
- Time: `O(n)` because we iterate through the list of `n` intervals in a single pass using pointer `i`.
- Space: `O(n)` auxiliary space to construct and return the merged output list.

## Code walkthrough

In the reference implementation:
- `while (i < n && intervals[i][1] < newInterval[0]) out.push_back(intervals[i++]);`: collects all preceding intervals that finish before the new interval begins.
- `while (i < n && intervals[i][0] <= newInterval[1])`: identifies all intervals overlapping with the active expanded interval.
- `newInterval[0] = min(newInterval[0], intervals[i][0]); newInterval[1] = max(newInterval[1], intervals[i][1]);`: continually stretches `newInterval` to absorb all overlapping segments.
- `out.push_back(newInterval);`: commits the combined merged interval to the output.
- `while (i < n) out.push_back(intervals[i++]);`: appends all trailing intervals without modification.

## Test it out loud

- `intervals = [[1, 5]], newInterval = [2, 3]`:
  - `i = 0`: `intervals[0][1] (5) < 2` is false.
  - Overlap check: `intervals[0][0] (1) <= 3` is true.
  - `newInterval = [min(2, 1), max(3, 5)] = [1, 5]`. `i` becomes 1.
  - Append `[1, 5]`.
  - Phase 3: `i == n`, no remaining intervals. Output is `[[1, 5]]`.
- `intervals = [[1, 5]], newInterval = [5, 7]`:
  - Touching at 5 triggers overlap: `intervals[0][0] (1) <= 7`.
  - Merges into `[1, 7]`. Output is `[[1, 7]]`.

## Follow-ups

- What if the intervals were not sorted originally?
  Sort first in `O(n log n)` time and apply the LeetCode 56 general merge algorithm.
- Can we perform binary search to find the insertion point?
  We can binary search the start and end indices of overlapping intervals in `O(log n)` time, but constructing the output array still requires `O(n)` time due to array shifting.

## Common mistakes

- Re-sorting the array in `O(n log n)` instead of utilizing the pre-sorted property in `O(n)` time.
- Missing the touching boundary condition where `intervals[i].start == newInterval.end` (e.g. `[1, 5]` and `[5, 7]`).
- Appending `newInterval` inside the overlap loop instead of once after the overlap loop finishes.
