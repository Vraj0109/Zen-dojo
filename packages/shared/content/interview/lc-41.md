## Clarify first

- What is the definition of the smallest positive integer? The positive integers start from 1, so the sequence of interest is 1, 2, 3, 4, ...
- Can the input contain negative numbers, zeros, or duplicates? Yes, elements can span the full 32-bit integer range.
- Are we allowed to modify the input array in-place? Yes, in-place rearrangement is explicitly permitted to achieve `O(1)` auxiliary space.
- What are the time and space constraints? The algorithm must strictly run in `O(n)` time and `O(1)` extra space.

## Examples to say out loud

- Normal missing middle: `nums = [3, 4, -1, 1]`.
  - The positive integers present are 1, 3, 4. The smallest missing positive is 2.
- Consecutive sequence from 1: `nums = [1, 2, 0]`. Positive integers present are 1 and 2. The smallest missing is 3.
- All large numbers: `nums = [7, 8, 9, 11, 12]`. None of the numbers from 1 to 5 exist, so the smallest missing is 1.
- All negatives: `nums = [-1, -2]`. Smallest positive is 1.

## Brute force

A brute-force approach inserts all elements of `nums` into a hash set, then queries 1, 2, 3, ... in an increasing loop until finding the first integer not present in the set. While this takes `O(n)` time, the hash set requires `O(n)` auxiliary space. Alternatively, sorting the array takes `O(n log n)` time and `O(1)` or `O(log n)` space, which fails the `O(n)` time requirement.

## The key observation

For an array of length `n`, the smallest missing positive integer must lie in the range `[1, n + 1]`. If the array contains all integers from `1` to `n`, the answer is `n + 1`; otherwise, at least one integer between `1` and `n` is missing. We can use the array itself as a direct-address hash table: every valid number `v \in [1, n]` belongs at index `v - 1`. By cyclically swapping each number to its home index, we can organize valid numbers in-place in linear time.

## Optimal approach

1. Let `n = nums.length`.
2. Iterate `i` from 0 to `n - 1`:
   - While `nums[i]` is in the valid range `[1, n]` and is not already at its correct destination (`nums[nums[i] - 1] != nums[i]`):
     - Swap `nums[i]` with `nums[nums[i] - 1]`.
3. Perform a second linear pass over the array from `i = 0` to `n - 1`:
   - If `nums[i] != i + 1`, return `i + 1` immediately.
4. If all positions `0` to `n - 1` contain their matching numbers `1` to `n`, return `n + 1`.

Complexity:
- Time: `O(n)` because each swap places at least one number in its correct home position; an element is swapped at most `n` times across the entire loop.
- Space: `O(1)` auxiliary space as all swaps occur directly within the input array.

## Code walkthrough

In the reference implementation:
- `while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i])`: checks if the current number is a positive candidate in range that is not yet at its destination index.
- `swap(nums[i], nums[nums[i] - 1]);`: places `nums[i]` at its intended home index while pulling a new candidate to index `i`.
- `nums[nums[i] - 1] != nums[i]`: avoids infinite loops when encountering duplicate values.
- `if (nums[i] != i + 1) return i + 1;`: identifies the first gap in the expected `1, 2, ..., n` sequence.
- `return n + 1;`: default answer when the array contains a complete sequence of `1` through `n`.

## Test it out loud

- `nums = [3, 4, -1, 1]`, `n = 4`:
  - `i = 0 (3)`: swap with `nums[2] (-1)`. Array: `[-1, 4, 3, 1]`. `-1` not in `1..4`, advance `i`.
  - `i = 1 (4)`: swap with `nums[3] (1)`. Array: `[-1, 1, 3, 4]`. Now `nums[1] = 1`, swap with `nums[0] (-1)`. Array: `[1, -1, 3, 4]`. Now `nums[1] = -1`, advance `i`.
  - `i = 2 (3)`: already in place (`nums[2] == 3`), advance `i`.
  - `i = 3 (4)`: already in place, advance `i`.
  - Second pass: `nums[0] = 1 (ok)`, `nums[1] = -1 != 2`. Returns 2.
- `nums = [1]`: second pass finds `nums[0] == 1`, returns `n + 1 = 2`.

## Follow-ups

- What if the input array is strictly read-only?
  Without extra space, it is impossible to solve in `O(n)` time and `O(1)` space; one can use binary search on the range `[1, n]` with counting in `O(n log n)` time and `O(1)` space.
- How does this relate to finding all missing numbers or duplicate numbers (LeetCode 442, 448)?
  Both use the cyclic sort / index-as-hash technique over the range `1..n`.

## Common mistakes

- Using an `if` statement instead of a `while` loop during the placement phase, which leaves the incoming swapped element uninspected.
- Swapping when `nums[i] == nums[nums[i] - 1]`, creating an infinite loop on duplicate numbers like `[1, 1]`.
- Forgetting that valid target numbers can be `n` (which belongs at index `n - 1`).
