## Clarify first

- Must the serialized format match LeetCode's level-order format exactly? (No, as clarified in the problem statement, any string format is valid as long as `deserialize(serialize(root))` reconstructs an identical tree).
- What node values are possible? ($-1000 \le Node.val \le 1000$; negative numbers and zeros are possible).
- Can the tree be empty? (Yes, $0 \le n \le 10,000$; an empty tree has `root == nullptr`).
- What should be used to represent null pointers? (A distinct sentinel character, such as `'#'` or `"null"`).
- What delimiter should separate tokens? (Commas `','` or spaces, ensuring multi-digit and negative numbers parse cleanly).

## Examples to say out loud

- General binary tree: `[1, 2, 3, null, null, 4, 5]`.
  - In pre-order traversal: visit root 1, left child 2 (both children null `#,#`), right child 3 with left 4 (`4,#,#`) and right 5 (`5,#,#`).
  - Serialized string: `"1,2,#,#,3,4,#,#,5,#,#"`.
  - Deserialization processes tokens sequentially in pre-order, reconstructing the identical tree structure.
- Empty tree: `root == nullptr` serializes to `"#"`. Deserializing `"#" ` returns `nullptr`.
- Skewed tree (linked list): `1 -> 2 -> 3`. Serialized as `"1,2,3,#,#,#,#"`.

## Brute force

A naive approach attempts to serialize without recording null pointers, storing only an in-order or pre-order array of values. However, a single traversal sequence cannot uniquely reconstruct a general binary tree (e.g. `[1, 2]` could have 2 as left child or right child). Attempting to store both pre-order and in-order traversals requires $O(n^2)$ tree reconstructions or breaks down when nodes contain duplicate values.

## The key observation

If we record **null pointers explicitly** using a sentinel token like `'#'`, then a single **pre-order traversal (DFS)** uniquely identifies both the values and the complete shape of any binary tree, even with duplicate values!
In pre-order (root, left, right):
- The first token is always the current subtree's root.
- The next tokens recursively construct the left subtree.
- When the left subtree finishes (hitting `#` on its leaves), the subsequent tokens immediately construct the right subtree.
This allows both serialization and deserialization to run in a single linear pass.

## Optimal approach

1. `serialize(root)`:
   - If `root == nullptr`, return `"#"`.
   - Otherwise, return `to_string(root->val) + "," + serialize(root->left) + "," + serialize(root->right)`.
2. `deserialize(data)`:
   - Tokenize the string by splitting on commas `','` (or using `stringstream` in C++).
   - Define a recursive helper `decode(tokens, index)`:
     - Read the next token.
     - If the token is `"#"`, return `nullptr`.
     - Otherwise, parse the integer value and construct `node = new TreeNode(val)`.
     - Recursively assign `node->left = decode(tokens, index)`.
     - Recursively assign `node->right = decode(tokens, index)`.
     - Return `node`.
   - Return `decode(tokens, 0)`.

Complexity:
- Time: $O(n)$ time for both serialization and deserialization. Each node is visited once during the pre-order traversal, and each token is processed once during reconstruction.
- Space: $O(n)$ auxiliary space to store the serialized string buffer, token list, and recursion stack (depth bounded by tree height $O(h) \le O(n)$).

## Code walkthrough

In the reference implementation:
- `if (!root) return "#";`: captures null leaf pointers explicitly as sentinel tokens.
- `to_string(root->val) + "," + serialize(root->left) + ...`: recursively constructs pre-order token stream.
- `stringstream ss(data);`: stream tokenizer reading tokens separated by commas.
- `if (item == "#") return nullptr;`: base case of deserialization matching null pointers.
- `TreeNode* node = new TreeNode(stoi(item)); node->left = decode(ss); node->right = decode(ss);`: recursive structural rebuilding matching pre-order serialization order.

## Test it out loud

- Empty tree: `serialize(nullptr)` returns `"#"`. `deserialize("#")` reads `"#"`, returns `nullptr`.
- Single node: `serialize(new TreeNode(1))` returns `"1,#,#"`.
  - `decode` reads `1`, creates node.
  - Left child reads `#` $\to nullptr$.
  - Right child reads `#` $\to nullptr$.
  - Returns `node(1)`.
- Asymmetric tree: `[1, null, 2]`. Serialized as `"1,#,2,#,#"`. Left child correctly becomes null, right child creates node 2.

## Follow-ups

- How to do this using BFS (level-order) traversal?
  Use a queue for both serialization and deserialization (similar to LeetCode test formatting). For BFS, enqueue children of every popped node; during decode, link left and right children from the token stream in pairs.
- How to serialize an N-ary tree?
  Include the child count or an end-of-children marker (e.g. `val, childCount, ...`).
- How can we minimize string size / bandwidth?
  Use binary serialization: pack integers into 4 bytes (or variable-length LEB128), and use a bitmask for null child flags rather than ASCII strings.

## Common mistakes

- Missing delimiters between numbers: serializing `1` and `23` without commas as `"123"` cannot be differentiated from `12` and `3`.
- Forgetting to handle negative numbers (e.g. `-100`), which contain minus signs.
- Passing index by value in deserialization instead of reference or iterator, causing children to re-read already consumed tokens.
