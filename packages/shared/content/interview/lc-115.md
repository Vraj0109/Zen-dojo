## Clarify first
- What defines a subsequence? A string formed by deleting zero or more characters from `s` without reordering the remaining characters.
- What if identical letters exist at different positions in `s`? Each distinct combination of deletion indices counts as a separate subsequence even if the resulting strings look identical.
- Can `s` or `t` be empty? Strings have length between 1 and 1000.
- Does the answer fit in standard integer ranges? Yes, constraints guarantee the final answer fits in a 32-bit signed integer (though intermediate counts during summation can exceed 32-bit limits, so 64-bit integer tracking is recommended).

## Examples to say out loud
- Consider `s = "rabbbit"`, `t = "rabbit"`:
  - `s` has three 'b's at indices 2, 3, and 4.
  - Deleting index 2 gives `"rabbit"`.
  - Deleting index 3 gives `"rabbit"`.
  - Deleting index 4 gives `"rabbit"`.
  - Total ways: 3.
- Example 2: `s = "babgbag"`, `t = "bag"`. Total ways: 5.
- Impossible match: `s = "a"`, `t = "b"`. Total ways: 0.

## Brute force
A brute force approach generates all `2^|s|` subsequences of `s` and counts how many match `t`. For `|s| = 1000`, `2^1000` is impossible. We can exploit the optimal substructure of string alignment using two-string Dynamic Programming.

## The key observation
Let `f(i, j)` be the number of distinct subsequences of `s[0..i-1]` that equal `t[0..j-1]`.
When inspecting characters `s[i - 1]` and `t[j - 1]`:
1. We can always choose to skip character `s[i - 1]`. The number of ways to form `t[0..j-1]` without using `s[i - 1]` is `f(i - 1, j)`.
2. In addition, if `s[i - 1] == t[j - 1]`, we can also choose to match `s[i - 1]` with `t[j - 1]`. The number of ways using this match is `f(i - 1, j - 1)`.
Therefore:
- If `s[i - 1] == t[j - 1]`: `f(i, j) = f(i - 1, j) + f(i - 1, j - 1)`.
- If `s[i - 1] != t[j - 1]`: `f(i, j) = f(i - 1, j)`.
Because `f(i, j)` only depends on the current and previous values of the inner index `j`, we can compress the 2D table into a 1D array of size `|t| + 1` by updating `j` in descending order.

## Optimal approach
1. Let `m = t.length()`.
2. Allocate a 1D array `dp` of size `m + 1` using 64-bit unsigned integers (`unsigned long long` or `long`), initialized to 0.
3. Base case: `dp[0] = 1` (the empty target string `t[0..0]` is formed in exactly 1 way from any prefix of `s`).
4. For each character `c` in `s`:
   - Iterate `j` from `m` down to 1:
     - If `t[j - 1] == c`:
       - `dp[j] += dp[j - 1]`.
5. Return `(int)dp[m]`.

Complexity:
- Time complexity: O(|s| * |t|) because for each of the |s| characters, we iterate through the |t| target positions with an O(1) transition.
- Space complexity: O(|t|) auxiliary space for the compressed 1D DP table.

## Code walkthrough
- `vector<unsigned long long> dp(m + 1, 0); dp[0] = 1`: Uses 64-bit unsigned integers to avoid 32-bit overflow on intermediate values before the final result.
- `for (char c : s)`: Streams characters of `s` one by one.
- `for (int j = m; j >= 1; j--)`: Loops backward so `dp[j - 1]` contains the count before encountering character `c`.
- `if (t[j - 1] == c) dp[j] += dp[j - 1]`: Adds the ways that match character `c` with `t[j - 1]`.
- Returns `(int)dp[m]`.

## Test it out loud
- Test `s = "aab", t = "ab"`:
  - `m = 2`. `dp = [1, 0, 0]`.
  - Char 'a' (1st): `dp[1] += dp[0]` -> `dp = [1, 1, 0]`.
  - Char 'a' (2nd): `dp[1] += dp[0]` -> `dp = [1, 2, 0]`.
  - Char 'b': `dp[2] += dp[1]` -> `dp = [1, 2, 2]`.
  - Returns `dp[2] = 2` (subsequences `s[0,2]` and `s[1,2]`). Correct.
- Test `s = "a", t = "b"`:
  - No character match; `dp[1]` stays 0. Returns 0. Correct.

## Follow-ups
- Why must the inner loop run in descending order? Because `dp[j]` depends on `dp[j - 1]` from the previous step. Running forward would use the newly updated value of `dp[j - 1]`, erroneously matching the same character `c` multiple times.
- How would you modify this to find the shortest common supersequence? That problem tracks lengths rather than counting paths, solved by minimizing lengths in O(|s| * |t|).

## Common mistakes
- Running the `j` loop from 1 up to `m`, which allows a single character from `s` to be reused repeatedly across multiple positions of `t`.
- Using 32-bit signed integers for DP accumulators, triggering runtime overflow on intermediate test cases before the final result is bounded.
- Forgetting to initialize `dp[0] = 1`.
