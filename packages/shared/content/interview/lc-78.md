## Clarify first

- Are all elements in `nums` unique? (Yes, the problem statement guarantees all elements in `nums` are unique).
- Can the input array be empty? (Constraints state $1 \le nums.length \le 10$, though handling an empty array should return `[[]]`).
- In what order should the subsets be returned? (Any order is acceptable).
- Does the power set include the empty set and the full set? (Yes, both the empty subset `[]` and `nums` itself are valid subsets).
- What are the element value ranges? ($-10 \le nums[i] \le 10$).

## Examples to say out loud

- Standard array of 3 elements: `nums = [1, 2, 3]`. Length is 3, producing $2^3 = 8$ subsets: `[[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]`.
- Single element: `nums = [0]`. $2^1 = 2$ subsets: `[[]]` and `[[0]]`.
- Negative elements: `nums = [-1, 3]`. Subsets: `[[], [-1], [3], [-1, 3]]`.

## Brute force

Because the goal is to produce the complete power set of all $2^n$ subsets, every valid algorithm must construct all $2^n$ subsets. However, an inefficient approach might generate duplicate permutations (e.g. `[1, 2]` and `[2, 1]`) and use a hash set or sorting on each subset to filter duplicates, adding unnecessary $O(n \log n)$ per subset and high hash table overhead.

## The key observation

For each of the $n$ elements in `nums`, there are independently exactly 2 choices: either include it in the subset or exclude it. This mapping matches the binary numbers from $0$ to $2^n - 1$. If we represent each subset by an integer bitmask `mask` in $[0, 2^n - 1]$, the $i$-th bit of `mask` (`mask & (1 << i)`) determines whether `nums[i]` is included. Because $n \le 10$, $2^{10} = 1024$, which can be enumerated in a single loop without recursion.

## Optimal approach

1. Let $n = nums.size()$. The total number of subsets is $2^n$ (`total = 1 << n`).
2. Allocate a result list `res` and reserve capacity for $2^n$ vectors.
3. Iterate `mask` from 0 to $2^n - 1$:
   - Initialize an empty list `cur`.
   - Iterate index $i$ from 0 to $n - 1$:
     - If the $i$-th bit is set in `mask` (`mask & (1 << i)`):
       - Append `nums[i]` to `cur`.
   - Append `cur` to `res`.
4. Return `res`.

Complexity:
- Time: `O(n * 2^n)` because there are $2^n$ subsets, and building each subset takes $O(n)$ bit checks and copies. For $n = 10$, $10 \times 1024 \approx 10^4$ operations, completing in less than 1 millisecond.
- Space: `O(n * 2^n)` auxiliary space required to store all $2^n$ subsets in the return structure.

## Code walkthrough

In the reference implementation:
- `int total = 1 << n;`: computes $2^n$ via bit shift.
- `res.reserve(total);`: avoids multiple vector reallocations during power set generation.
- `for (int mask = 0; mask < total; mask++)`: systematically visits every binary configuration from `00...0` to `11...1`.
- `if (mask & (1 << i)) cur.push_back(nums[i]);`: inspects whether element $i$ belongs to the current subset.
- `res.push_back(cur);`: collects the completed subset.

## Test it out loud

- Empty array: `nums = []`. $n = 0 \implies total = 1$. `mask = 0` yields `cur = []`, returning `[[]]`.
- Single element: `nums = [1]`. $n = 1$.
  - `mask = 0`: `[]`.
  - `mask = 1`: `[1]`.
  - Output: `[[], [1]]`.
- Two elements: `nums = [1, 2]`. $n = 2$.
  - `mask = 0` (`00`): `[]`.
  - `mask = 1` (`01`): `[1]`.
  - `mask = 2` (`10`): `[2]`.
  - `mask = 3` (`11`): `[1, 2]`.
  - Output: `[[], [1], [2], [1, 2]]`.

## Follow-ups

- What if `nums` contains duplicate elements (LeetCode 90 - Subsets II)?
  Sort `nums` first. In recursive backtracking, skip identical adjacent elements when choosing not to pick the first one (`if (i > start && nums[i] == nums[i-1]) continue;`).
- How does the recursive backtracking approach compare to bit manipulation?
  Recursive backtracking takes the exact same $O(n \cdot 2^n)$ time, but uses $O(n)$ recursion stack and naturally generates subsets in lexicographical / tree order.
- How can we generate subsets in Gray code order (only one element added/removed per step)?
  Iterate using the Gray code formula $g(i) = i \oplus (i >> 1)$, which flips exactly one bit between consecutive subsets.

## Common mistakes

- Shifting by 32 bits or more if $n \ge 32$: with $n \le 10$, standard 32-bit `1 << n` is safe, but for larger $n$, `1LL << n` is required.
- Confusing subset (combination of elements in any order) with contiguous subarray (which has only $O(n^2)$ possibilities).
- Creating duplicate subsets when trying to build subsets by permuting indices.
