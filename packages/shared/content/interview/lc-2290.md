## Clarify first
- What do grid values represent? 0 represents an empty cell; 1 represents an obstacle.
- How are obstacles cleared? Walking into an obstacle removes it, incurring a cost of 1. Walking into an empty cell incurs a cost of 0.
- What are start and end points? Start at `(0, 0)` and end at `(rows - 1, cols - 1)`. Both cells are guaranteed to be 0 (empty).
- What movements are permitted? 4 cardinal directions (up, down, left, right).

## Examples to say out loud
- Consider 3x3 grid:
  ```
  [0, 1, 1]
  [1, 1, 0]
  [1, 1, 0]
  ```
  - Path `(0,0) -> (0,1) -> (0,2) -> (1,2) -> (2,2)` requires removing obstacles at `(0,1)` and `(0,2)`. Cost = 2.
  - Any path requires removing at least 2 obstacles. Output: 2.
- Obstacle-free path: If an unblocked path of 0s connects start to finish, output is 0.
- 1x2 grid `[[0, 0]]`: Cost is 0.

## Brute force
A standard BFS does not work directly because edges have different weights (0 or 1). Running Dijkstra's algorithm with a min-heap priority queue finds the shortest path in O(V log V) time, where `V = rows * cols`. With `rows * cols` up to 100,000, Dijkstra takes O(V log V) operations. However, because edge weights are strictly binary (either 0 or 1), 0-1 BFS using a double-ended queue achieves strictly linear O(V) time.

## The key observation
In a graph where all edge weights are either 0 or 1, a double-ended queue (deque) can maintain nodes in monotonically non-decreasing order of distance:
- If moving to an adjacent neighbor costs 0 (empty cell), the neighbor has the exact same distance as the current cell. We push it to the FRONT of the deque so it is processed immediately at the current distance level.
- If moving to an adjacent neighbor costs 1 (obstacle), the neighbor has distance `current + 1`. We push it to the BACK of the deque to be processed in the next distance wave.
This guarantees each cell is dequeued in optimal distance order without the logarithmic overhead of a binary heap.

## Optimal approach
1. Allocate a 2D distance array `dist` of size `r x c` initialized to infinity (`INT_MAX`), setting `dist[0][0] = 0`.
2. Initialize a deque `dq` of coordinate pairs and push `{0, 0}` to the back.
3. While `dq` is not empty:
   - Pop `{x, y}` from the front of `dq`.
   - If `{x, y}` is the bottom-right corner `(r - 1, c - 1)`, return `dist[x][y]`.
   - For each of the 4 cardinal neighbors `(nx, ny)`:
     - Check boundaries: `0 <= nx < r` and `0 <= ny < c`.
     - Let edge weight `w = grid[nx][ny]`.
     - If `dist[x][y] + w < dist[nx][ny]`:
       - Update `dist[nx][ny] = dist[x][y] + w`.
       - If `w == 0`, push `{nx, ny}` to the front of `dq`.
       - Else (`w == 1`), push `{nx, ny}` to the back of `dq`.
4. Return `dist[r - 1][c - 1]`.

Complexity:
- Time complexity: O(rows * columns) because each cell is pushed and popped from the deque at most a constant number of times.
- Space complexity: O(rows * columns) auxiliary space for the distance matrix and the deque.

## Code walkthrough
- `vector<vector<int>> dist(r, vector<int>(c, INT_MAX)); dist[0][0] = 0`: Tracks minimum obstacles removed to reach each cell.
- `deque<pair<int, int>> dq`: Double-ended queue for 0-1 BFS.
- `int w = grid[nx][ny]`: 0 if empty, 1 if obstacle.
- `if (w == 0) dq.push_front({nx, ny}); else dq.push_back({nx, ny})`: Enforces distance monotonicity in O(1) time per edge.
- Returns `dist[r - 1][c - 1]`.

## Test it out loud
- Test `[[0, 1], [1, 0]]`:
  - `dist[0][0] = 0`, `dq = [(0, 0)]`.
  - Pop `(0, 0)`.
    - Neighbor `(0, 1)` has `w = 1`, `dist = 1`, push back.
    - Neighbor `(1, 0)` has `w = 1`, `dist = 1`, push back.
  - Pop `(0, 1)`.
    - Neighbor `(1, 1)` has `w = 0`, `dist = 1 + 0 = 1`, push FRONT.
  - Next pop is `(1, 1)`. Target reached with distance 1. Returns 1. Correct.
- Test `[[0, 0]]`:
  - Pop `(0, 0)`. Target `(0, 1)` reached with weight 0. Returns 0. Correct.

## Follow-ups
- How does 0-1 BFS relate to Dijkstra? 0-1 BFS is a special case of Dial's algorithm (Dijkstra with buckets). When edge weights are bounded by small integer W, Dial's algorithm runs in O(V * W + E) using an array of buckets.
- What if grid cells cost arbitrary non-negative weights? Then standard Dijkstra with a priority queue is required.

## Common mistakes
- Pushing weight-0 edges to the back of the queue, breaking the monotonic distance order and degrading to non-optimal paths.
- Re-visiting cells without checking if `dist[x][y] + w < dist[nx][ny]`.
- Forgetting that the starting cell itself might be an obstacle in generic variants (though here guaranteed 0).
