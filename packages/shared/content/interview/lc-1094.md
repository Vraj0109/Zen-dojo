## Clarify first

- In what direction does the car travel? The car drives strictly east along a straight road (increasing kilometer coordinates).
- When passengers get off at kilometer `to`, are their seats immediately available for passengers getting on at `to`? Yes, passengers exit at kilometer `to` before or at the same moment new passengers enter.
- What if the car's passenger load at any point strictly exceeds `capacity`? Return `false`.
- What are the coordinate and capacity bounds? Kilometer coordinates `from` and `to` are between 0 and 1,000, `trips.length <= 1,000`, and `capacity <= 100,000`.

## Examples to say out loud

- Feasible overlapping trips: `trips = [[2, 1, 5], [3, 3, 7]]`, `capacity = 5`.
  - At km 1: +2 passengers (load = 2 <= 5).
  - At km 3: +3 passengers (load = 5 <= 5).
  - At km 5: -2 passengers (load = 3 <= 5).
  - At km 7: -3 passengers (load = 0 <= 5).
  - Max load never exceeds capacity, returns `true`.
- Over capacity at overlap: `trips = [[2, 1, 5], [3, 3, 7]]`, `capacity = 4`.
  - Between km 3 and 5, load is 5 > 4. Returns `false`.
- Drop-off and pick-up at same location: `trips = [[2, 1, 5], [3, 5, 7]]`, `capacity = 3`.
  - At km 5, 2 passengers leave and 3 enter. Load never exceeds 3, returns `true`.

## Brute force

A brute-force solution maintains an array representing the road coordinates. For every trip `[num, from, to]`, loop `km` from `from` to `to - 1` and add `num` to each coordinate's current occupancy. If any coordinate exceeds `capacity`, return `false`. For `n` trips spanning distances up to `K = 1,000`, this takes `O(n * K)` time. While acceptable for small constraints, it performs redundant interval updates when a difference array does it in constant time per trip.

## The key observation

The passenger count only changes at discrete drop-off and pick-up points. Instead of updating every kilometer in the interval `[from, to - 1]`, we record the delta changes: `+num` at `from` (passengers board) and `-num` at `to` (passengers alight). A single prefix sum sweep across the coordinate timeline computes the active passenger load at every point in time.

## Optimal approach

1. Allocate a difference array `diff` of size 1,002 (since max coordinate is 1,000) filled with zeros.
2. For each trip `[num, from, to]` in `trips`:
   a. Add `num` to `diff[from]`.
   b. Subtract `num` from `diff[to]`.
3. Initialize `load = 0`.
4. Sweep `km` from 0 to 1,000:
   a. Add `diff[km]` to `load`.
   b. If `load > capacity`, return `false` immediately.
5. Return `true`.

Complexity:
- Time: `O(n + K)` where `n` is `trips.length` and `K = 1001` is the maximum coordinate span.
- Space: `O(K)` auxiliary space for the fixed difference array.

## Code walkthrough

In the reference implementation:
- `vector<int> diff(1002, 0);`: creates the discrete difference array covering all possible kilometer markers.
- `for (auto& t : trips) { diff[t[1]] += t[0]; diff[t[2]] -= t[0]; }`: marks passenger entry at `t[1]` and exit at `t[2]`.
- `int load = 0;`: tracks the running sum of passengers currently seated in the vehicle.
- `for (int d : diff) { load += d; if (load > capacity) return false; }`: simulates vehicle progress along the highway, failing if load exceeds limit.
- `return true;`: confirms all trips were completed within capacity.

## Test it out loud

- `trips = [[2, 1, 5], [3, 5, 7]], capacity = 3`:
  - `diff[1] = +2`, `diff[5] = -2 + 3 = +1`, `diff[7] = -3`.
  - At km 1: `load = 2 <= 3`.
  - At km 5: `load = 2 + 1 = 3 <= 3`.
  - At km 7: `load = 3 - 3 = 0 <= 3`.
  - Returns `true`.
- `trips = [[5, 0, 1]], capacity = 4`:
  - At km 0: `load = 5 > 4`, returns `false`.

## Follow-ups

- What if the kilometer coordinates can be up to `10^9`?
  Use a sorted map (`std::map<int, int>`) or an array of event pairs `(coordinate, delta)` sorted by coordinate, achieving `O(n log n)` time and `O(n)` space (Meeting Rooms II pattern).
- What if trips are served in multiple directions?
  Split trips into eastbound and westbound groups and evaluate each separately.

## Common mistakes

- Subtracting passengers at `to + 1` instead of `to`, which erroneously assumes passengers occupy seats until kilometer `to + 1`.
- Allocating array size smaller than 1,001, triggering index out of bounds.
- Sorting events incorrectly when pick-ups and drop-offs happen at the same location (drop-offs must be processed before or simultaneously with pick-ups).
