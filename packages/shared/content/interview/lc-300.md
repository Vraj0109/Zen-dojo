## Clarify first

- Does "strictly increasing" allow duplicate values? No, each subsequent element must be strictly greater than the previous element (`x < y`).
- Must the subsequence be contiguous? No, subsequences maintain relative order but can skip intermediate elements.
- Can values be negative? Yes, values range from -10,000 to 10,000.
- What are the constraints on array length? Length is between 1 and 2,500.

## Examples to say out loud

- Mixed sequence: `nums = [10, 9, 2, 5, 3, 7, 101, 18]`.
  - The longest strictly increasing subsequence is `[2, 3, 7, 101]` or `[2, 5, 7, 101]`, which has length 4.
- Strictly decreasing: `nums = [4, 3, 2, 1]`. Any single element forms an increasing subsequence of length 1, so result is 1.
- Identical elements: `nums = [7, 7, 7, 7]`. Cannot pick duplicates, length is 1.
- Strictly increasing: `nums = [1, 2, 3, 4]`. Length is 4.

## Brute force

A brute-force solution checks all `2^n` possible subsequences to determine which ones are strictly increasing, keeping the maximum length. This requires `O(2^n)` exponential time. Alternatively, a basic dynamic programming approach maintains `dp[i]` as the length of the LIS ending at index `i`, checking all `j < i` with `nums[j] < nums[i]`. This takes `O(n^2)` time, which works for `n = 2,500` but is suboptimal.

## The key observation

We can use patience sorting / tails array: let `tails[k]` store the smallest ending element of any increasing subsequence of length `k + 1` found so far. The `tails` array is guaranteed to remain strictly sorted in ascending order. When encountering a new number `x`, we use binary search (`std::lower_bound`) to find the first tail `>= x`. If all tails are `< x`, `x` extends the longest subsequence and is appended to `tails`; otherwise, replacing that tail with `x` creates a smaller ending value for that length without altering the overall best length.

## Optimal approach

1. Initialize an empty dynamic array `tails`.
2. For each number `x` in `nums`:
   a. Perform binary search for the first element in `tails` that is `>= x` (using `lower_bound`).
   b. If no such element exists (all elements in `tails` are strictly smaller than `x`):
      - Append `x` to `tails` (`tails.push_back(x)`).
   c. Otherwise:
      - Replace that element with `x` (`*it = x`).
3. Return the size of `tails`.

Complexity:
- Time: `O(n log n)` because we iterate through `n` numbers and perform binary search on `tails` of length at most `n` in `O(log n)` time.
- Space: `O(n)` auxiliary space to store the `tails` array.

## Code walkthrough

In the reference implementation:
- `vector<int> tails;`: holds the minimum tails for each discovered subsequence length.
- `auto it = lower_bound(tails.begin(), tails.end(), x);`: locates the first element `>= x` in logarithmic time via binary search.
- `if (it == tails.end()) tails.push_back(x);`: extends the maximum subsequence length when `x` exceeds all existing tail values.
- `else *it = x;`: tightens the ending value for a known length, making future extensions easier.
- `return (int)tails.size();`: the final length of `tails` equals the length of the LIS.

## Test it out loud

- `nums = [10, 9, 2, 5, 3, 7]`:
  - `x = 10`: `tails = [10]`.
  - `x = 9`: replace 10 -> `tails = [9]`.
  - `x = 2`: replace 9 -> `tails = [2]`.
  - `x = 5`: append 5 -> `tails = [2, 5]`.
  - `x = 3`: replace 5 -> `tails = [2, 3]`.
  - `x = 7`: append 7 -> `tails = [2, 3, 7]`.
  - Result length is 3.
- `nums = [7, 7, 7]`:
  - `x = 7`: `tails = [7]`.
  - `x = 7`: `lower_bound` finds 7, replaces 7 -> `tails = [7]`.
  - Result length is 1.

## Follow-ups

- How would you reconstruct the actual LIS sequence?
  Store parent pointers and index positions during binary search, then backtrack from the element that established the longest length.
- What if the subsequence needs to be non-decreasing (`<=`) instead of strictly increasing?
  Use `upper_bound` instead of `lower_bound` to permit equal values to extend the subsequence.
- How does Russian Doll Envelopes (LeetCode 354) relate to this?
  Sort envelopes by width ascending and height descending, then run LIS on heights.

## Common mistakes

- Using `upper_bound` instead of `lower_bound` for strictly increasing subsequences, which erroneously permits equal values to extend lengths.
- Assuming the `tails` array itself contains the actual elements of the LIS (it stores optimal tail candidates, not necessarily a valid subsequence sequence).
- Forgetting that binary search can be applied to `tails` because `tails` is monotonically increasing.
