## Clarify first

- What does circular mean? The array wraps around, so the last element `nums[n - 1]` is followed by the first element `nums[0]`.
- Can the circular subarray use the same element more than once? No, each element can be included at most once (subarray length `<= n`).
- Can the chosen subarray be empty? No, the problem specifies a non-empty contiguous subarray.
- What if all numbers in `nums` are negative? The answer must be the largest single negative element, not 0.

## Examples to say out loud

- Wrapping subarray: `nums = [5, -3, 5]`.
  - Non-wrapping contiguous maximum is 5.
  - Wrapping subarray `[5]` (end) and `[5]` (start) gives `5 + 5 = 10`. Max circular sum is 10.
- Standard non-wrapping subarray: `nums = [1, -2, 3, -2]`.
  - Max contiguous sum is `[3]` = 3.
- All negative elements: `nums = [-3, -2, -3]`.
  - Max single element is -2. Returning 0 is incorrect because the subarray must be non-empty.

## Brute force

A brute-force solution evaluates all circular contiguous subarrays: for each starting index `i` from 0 to `n - 1`, sum lengths `len` from 1 to `n` using index `(i + len - 1) % n`. There are `n^2` possible non-empty circular subarrays. Computing all running sums takes `O(n^2)` time. For `n = 30,000`, `n^2 = 9 \times 10^8` operations, which exceeds standard time limits.

## The key observation

A circular maximum subarray falls into one of two mutually exclusive cases:
1. **Non-wrapping case:** The optimal subarray resides entirely within the array without crossing the boundary. This is solved directly by standard Kadane's algorithm (`maxKadane`).
2. **Wrapping case:** The optimal subarray wraps around the boundary (it consists of a prefix and a suffix). The elements *not* included in a wrapping subarray form a contiguous non-empty middle subarray! To maximize the sum of the prefix and suffix, we must **minimize** the sum of the contiguous middle subarray. Thus, `wrappingMax = total_sum - minKadane`.
The overall answer is `max(maxKadane, total_sum - minKadane)`. The only edge case occurs when all numbers are negative: here `minKadane == total_sum`, making `total_sum - minKadane = 0` (an empty subarray, which is forbidden), so we must return `maxKadane`.

## Optimal approach

1. Initialize `total = 0`.
2. Initialize Kadane variables: `curMax = 0, best = nums[0]` for maximum subarray, and `curMin = 0, worst = nums[0]` for minimum subarray.
3. For each number `x` in `nums`:
   a. `total += x`.
   b. `curMax = max(curMax + x, x)`, `best = max(best, curMax)`.
   c. `curMin = min(curMin + x, x)`, `worst = min(worst, curMin)`.
4. If `best < 0` (all numbers in `nums` are negative):
   - Return `best`.
5. Otherwise:
   - Return `max(best, total - worst)`.

Complexity:
- Time: `O(n)` because we iterate through the array of length `n` once in a single pass.
- Space: `O(1)` auxiliary space as we only maintain scalar accumulator variables.

## Code walkthrough

In the reference implementation:
- `int total = 0, curMax = 0, best = nums[0], curMin = 0, worst = nums[0];`: tracks total sum alongside concurrent min and max Kadane states.
- `curMax = max(curMax + x, x); best = max(best, curMax);`: standard Kadane computing the best non-wrapping contiguous subarray.
- `curMin = min(curMin + x, x); worst = min(worst, curMin);`: inverted Kadane computing the smallest contiguous subarray to subtract from `total`.
- `return best < 0 ? best : max(best, total - worst);`: handles all-negative inputs correctly and returns the superior of the linear or wrapping sum.

## Test it out loud

- `nums = [5, -3, 5]`:
  - `total = 5 - 3 + 5 = 7`.
  - Max Kadane `best = 5` (or 7 if combined). Actually: `5` -> `5 + (-3) = 2` -> `2 + 5 = 7`. `best = 7`? Wait: `5 + (-3) + 5 = 7`.
  - Min Kadane `worst = -3`.
  - `total - worst = 7 - (-3) = 10` (taking `[5]` from start and `[5]` from end, omitting `-3`).
  - `max(7, 10) = 10`.
- `nums = [-3, -2, -3]`:
  - `best = -2 < 0`. All elements negative.
  - Returns `best = -2`.

## Follow-ups

- What if we doubled the array to length `2 * n`?
  A circular subarray of length `<= n` in `nums` corresponds to a subarray of length `<= n` in `nums + nums`. Using a prefix sum array and a monotonic deque to find `max(prefix[j] - prefix[i])` for `j - i <= n` solves it in `O(n)` time and `O(n)` space.
- Can we reconstruct the circular start and end indices?
  Track indices for both `best` and `worst` boundaries, choosing whichever configuration maximizes the sum.

## Common mistakes

- Missing the all-negative edge case: when all elements are negative, `total == worst`, so `total - worst = 0`, which incorrectly returns 0 instead of the maximum single negative number.
- Forgetting that circular subarrays cannot exceed length `n` (which prevents simple concatenation with standard Kadane).
- Using `O(n^2)` circular scans instead of the dual min/max Kadane insight.
