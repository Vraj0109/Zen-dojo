## Clarify first

- What is the partition rule? Every letter that appears in a piece must appear *only* in that piece (no character can appear in multiple pieces).
- What should be optimized? We want to partition into as **many pieces as possible** (maximize the number of parts).
- What format is the output? A list of integers representing the lengths of each piece in left-to-right order.
- What are the constraints? `s.length` is between 1 and 500, containing only lowercase English letters.

## Examples to say out loud

- Multi-part split: `s = "ababcbacadefegdehijhklij"`.
  - First segment: `"ababcbaca"` (length 9). Characters `a`, `b`, `c` appear only in this piece.
  - Second segment: `"defegde"` (length 7). Characters `d`, `e`, `f`, `g` appear only here.
  - Third segment: `"hijhklij"` (length 8). Characters `h`, `i`, `j`, `k`, `l` appear only here.
  - Output: `[9, 7, 8]`.
- All identical characters: `s = "aaaa"`. Only 1 part of length 4, returns `[4]`.
- Alternating overlap: `s = "eccbbbbdec"`. The character `'c'` stretches from index 1 to the end, forcing a single partition of length 10: `[10]`.

## Brute force

A brute-force strategy recursively tests all possible partition split boundaries. For every candidate partition, check whether any letter appears across multiple segments. With `n - 1` potential split points, there are `2^{n - 1}` possible partitionings. For `n = 500`, exploring `2^{499}` combinations is completely intractable.

## The key observation

If character `c` appears at index `i`, the partition containing index `i` **must** extend at least until the *last occurrence* of character `c`.
Therefore:
1. In a first pass, record `last[c]`: the last index where each character `c` appears in `s`.
2. In a second pass, maintain the active partition boundary `end = max(end, last[s[i]])`.
3. As we iterate, as soon as `i == end`, every character seen in the current window has its last occurrence within `[start, end]`. We can greedily cut the string here to maximize the number of partitions!

## Optimal approach

1. Create an array `last` of size 26 to store the rightmost index of each character `'a'` to `'z'`.
2. Iterate `i` from 0 to `s.length() - 1`: set `last[s[i] - 'a'] = i`.
3. Initialize `start = 0`, `end = 0`, and an empty result list `out`.
4. Iterate `i` from 0 to `s.length() - 1`:
   a. Update the current partition endpoint: `end = max(end, last[s[i] - 'a'])`.
   b. If `i == end`:
      - The partition is complete!
      - Append `end - start + 1` to `out`.
      - Reset `start = i + 1`.
5. Return `out`.

Complexity:
- Time: `O(n)` because we iterate through the string of length `n` exactly twice (once to record last positions, once to form partitions).
- Space: `O(1)` auxiliary space beyond the output list, since the character array has fixed size 26.

## Code walkthrough

In the reference implementation:
- `int last[26]; for (int i = 0; i < (int)s.size(); i++) last[s[i] - 'a'] = i;`: records the final occurrence index of each letter.
- `int start = 0, end = 0;`: establishes pointers tracking the beginning and required boundary of the active chunk.
- `end = max(end, last[s[i] - 'a']);`: continually expands the horizon to cover the complete span of any newly encountered character.
- `if (i == end)`: signals that all characters in the current substring have no remaining occurrences later in the string.
- `out.push_back(end - start + 1); start = i + 1;`: logs the piece length and advances to the next piece.

## Test it out loud

- `s = "abac"`:
  - `last`: `'a' -> 2`, `'b' -> 1`, `'c' -> 3`.
  - `i = 0 ('a')`: `end = max(0, 2) = 2`.
  - `i = 1 ('b')`: `end = max(2, 1) = 2`.
  - `i = 2 ('a')`: `end = max(2, 2) = 2`. `i == end (2)`! Cut: length `2 - 0 + 1 = 3`. Next `start = 3`.
  - `i = 3 ('c')`: `end = max(2, 3) = 3`. `i == end (3)`! Cut: length `3 - 3 + 1 = 1`.
  - Output: `[3, 1]`.
- `s = "aa"`: `last['a'] = 1`. At `i = 1`, cuts piece of length 2. Output `[2]`.

## Follow-ups

- How does this problem relate to Merge Intervals (LeetCode 56)?
  Each character defines an interval `[first_occurrence, last_occurrence]`. Merging all overlapping intervals yields the exact same partition boundaries.
- What if the alphabet was arbitrary Unicode?
  Use a hash map to store `last` occurrence indices; time complexity remains `O(n)`.

## Common mistakes

- Cutting as soon as a single character finishes without checking if an earlier character in the same block stretches farther.
- Forgetting to reset `start = i + 1` after making a cut, leading to cumulative lengths instead of individual segment lengths.
- Storing full intervals and sorting them `O(n log n)` when a single pass with a 26-element array achieves `O(n)` time and `O(1)` space.
