## Clarify first
- Are all numbers positive integers? Yes, `nums[i] >= 1`.
- Must every number be used in exactly one subset? Yes, the array must be partitioned into k non-empty subsets with no elements left over.
- Can subsets have different numbers of elements? Yes, the only requirement is that all k subsets have the exact same sum.
- What is the range of n and k? `1 <= k <= nums.length <= 16`.

## Examples to say out loud
- Consider `nums = [4, 3, 2, 3, 5, 2, 1]`, `k = 4`:
  - Total sum = 20. Target per subset = `20 / 4 = 5`.
  - Subsets summing to 5: `[5]`, `[4, 1]`, `[3, 2]`, `[3, 2]`.
  - All 4 subsets have sum 5. Output: true.
- Indivisible total: `nums = [1, 2, 3, 4]`, `k = 3`.
  - Total sum = 10. `10 % 3 != 0`, so impossible to divide evenly. Output: false.
- Element exceeds target: `nums = [2, 2, 2, 2, 3, 4, 5]`, `k = 4`. Total = 20, target = 5. Element 5 can only form a single subset, but remaining elements cannot all partition into 5s.

## Brute force
A naive backtracking search tries assigning each of the n numbers to one of the k buckets. There are `k^n` possible assignments. For `n = 16, k = 4`, `4^16 = 4.29 * 10^9` states, which times out without aggressive memoization and symmetry breaking. We can formulate this as a bitmask dynamic programming problem over the 2^n subsets of used elements.

## The key observation
First, check basic divisibility: let `total = sum(nums)`. If `total % k != 0` or any `nums[i] > total / k`, return false immediately. The target sum for each subset is `target = total / k`.
Represent the subset of used elements using an integer `mask` where the `i`-th bit is 1 if `nums[i]` is used.
Let `fill[mask]` be the remainder sum of the currently active partial subset formed by elements in `mask`:
- `fill[mask] == -1` means the subset `mask` cannot be partitioned into some number of complete subsets of size `target` plus one valid partial subset.
- `fill[mask] >= 0` stores `(sum of elements in mask) % target`.
If `fill[mask] >= 0` and we consider adding unused element `nums[i]`:
- If `fill[mask] + nums[i] <= target`, the new state `nm = mask | (1 << i)` is valid, with new remainder `(fill[mask] + nums[i]) % target`.
If we can reach `fill[(1 << n) - 1] == 0`, all k subsets have been successfully completed.

## Optimal approach
1. Compute `total = sum(nums)`. If `total % k != 0`, return false.
2. Let `target = total / k`. If any element `nums[i] > target`, return false.
3. Allocate an array `fill` of size `1 << n` initialized to -1.
4. Base case: `fill[0] = 0` (empty mask has 0 remainder).
5. For each `mask` from 0 to `(1 << n) - 1`:
   - If `fill[mask] < 0`: continue (unreachable state).
   - For `i` from 0 to `n - 1`:
     - If `(mask & (1 << i))` is non-zero: continue (element `i` already used).
     - If `fill[mask] + nums[i] > target`: continue (would exceed target bucket sum).
     - Let `nm = mask | (1 << i)`.
     - If `fill[nm] < 0`:
       - `fill[nm] = (fill[mask] + nums[i]) % target`.
6. Return `fill[(1 << n) - 1] == 0`.

Complexity:
- Time complexity: O(2^n * n). There are 2^n masks, and from each reachable mask we attempt to add one of the n elements. For `n = 16`, `65536 * 16 = 1.05 * 10^6` operations, executing in under 20ms.
- Space complexity: O(2^n) auxiliary space for the `fill` DP table of size `2^16 = 65,536`.

## Code walkthrough
- `if (total % k) return false; int target = total / k`: Fast early rejection for mathematically impossible splits.
- `vector<int> fill(1 << n, -1); fill[0] = 0`: Tracks the modulo target progress of the currently active group.
- `if (fill[mask] + nums[i] > target) continue`: Prunes transitions that would overflow the current target bucket.
- `fill[nm] = (fill[mask] + nums[i]) % target`: When the bucket reaches `target`, the modulo resets the remainder to 0 for the next bucket.
- `return fill[(1 << n) - 1] == 0`: Confirms all n elements are used and all buckets closed cleanly.

## Test it out loud
- Test `nums = [1, 1], k = 2`:
  - `total = 2, target = 1`.
  - `mask = 0`: `fill[0] = 0`.
    - Add 0: `mask = 1`, `fill[1] = (0 + 1) % 1 = 0`.
  - `mask = 1`: `fill[1] = 0`.
    - Add 1: `mask = 3`, `fill[3] = (0 + 1) % 1 = 0`.
  - `fill[3] == 0`. Returns true. Correct.
- Test `nums = [1, 2], k = 2`:
  - `total = 3, 3 % 2 != 0`. Returns false immediately. Correct.

## Follow-ups
- How does backtracking with sorting compare to bitmask DP? Backtracking with `nums` sorted descending and skipping identical elements can be faster on average due to extreme pruning, but has worst-case exponential time, while bitmask DP has a guaranteed O(2^n * n) runtime bound.
- What if n were larger, say n = 30? Partitioning into equal sum subsets for large n is NP-complete, requiring heuristic methods or meet-in-the-middle for small k.

## Common mistakes
- Not checking `total % k != 0` or `nums[i] > target` before starting the DP.
- Allowing `fill[mask] + nums[i]` to exceed `target`, which would conflate elements across different buckets.
- Forgetting that when remainder reaches `target`, `(fill + nums[i]) % target` resets to 0 to begin the next bucket.
