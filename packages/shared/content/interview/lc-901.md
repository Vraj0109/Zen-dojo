## Clarify first

- What does the stock span represent? (The maximum number of consecutive days ending at day $i$ going backward where the stock price was $\le prices[i]$).
- What is the span of the very first day? (Always 1, since the current day itself counts).
- What if today's price equals yesterday's price? (Equal prices count toward the span because the condition is $\le$).
- Can prices be negative or zero? (No, $1 \le prices[i] \le 10^5$).
- What is the maximum number of price quotes? (Up to $10^5$).

## Examples to say out loud

- Strictly decreasing sequence: `prices = [100, 90, 80, 70]`. Each day is lower than the previous day, so no previous days can be included. Span is 1 for every day: `[1, 1, 1, 1]`.
- Strictly increasing sequence: `prices = [31, 41, 48, 59, 79]`. Each day exceeds all prior days, so span counts all previous days plus today: `[1, 2, 3, 4, 5]`.
- Fluctuating sequence: `prices = [100, 80, 60, 70, 60, 75, 85]`. On day 6 with price 85, previous consecutive prices $\le 85$ are 80, 60, 70, 60, 75, giving span 6.

## Brute force

A naive brute force steps backward from index $i$ to index $0$ for each day, counting how many consecutive elements are $\le prices[i]$ until encountering an element strictly greater than $prices[i]$. In the worst case of non-decreasing prices (e.g. `[10, 20, 30, ...]`), comparing backwards takes $1 + 2 + \dots + n = O(n^2)$ operations. For $n = 10^5$, $10^{10}$ comparisons will trigger Time Limit Exceeded.

## The key observation

If today's price $p$ is $\ge$ yesterday's price $p_{\text{prev}}$, then any future day that spans past $p$ will automatically span past $p_{\text{prev}}$ as well. Therefore, we do not need to keep individual daily history. Instead, maintain a **strictly decreasing monotonic stack** of pairs: `(price, span)`. When a new price $p$ arrives, pop all entries with price $\le p$ from the stack and accumulate their recorded spans into today's span. Every element enters and leaves the stack at most once, achieving amortized $O(1)$ per quote.

## Optimal approach

1. Initialize an empty stack `st` holding pairs of integers `(price, span)`.
2. Initialize an empty list `res` for the daily spans.
3. For each price `p` in `prices`:
   - Initialize `span = 1` (accounting for the current day).
   - While `st` is not empty and `st.top().first <= p`:
     - Add `st.top().second` to `span`.
     - Pop the top element from `st`.
   - Push `(p, span)` onto `st`.
   - Append `span` to `res`.
4. Return `res`.

Complexity:
- Time: `O(n)` total for $n$ price quotes, amortized $O(1)$ per quote. Each price is pushed to the stack once and popped at most once.
- Space: `O(n)` auxiliary space for the monotonic stack in the worst case (monotonically decreasing prices).

## Code walkthrough

In the reference implementation:
- `stack<pair<int, int>> st;`: stores `(price, span)` pairs maintaining strictly decreasing prices from bottom to top.
- `int span = 1;`: sets base span count for current day.
- `while (!st.empty() && st.top().first <= p)`: identifies all earlier consecutive days dominated by the current price.
- `span += st.top().second; st.pop();`: compresses past history in $O(1)$ by absorbing precomputed spans.
- `st.push({p, span});`: preserves the invariant that elements remaining on the stack are strictly decreasing in price.

## Test it out loud

- Single quote: `[100]`. Stack starts empty; loop does not run. Span is 1. Stack gets `(100, 1)`, returns `[1]`.
- All equal prices: `[10, 10, 10, 10]`.
  - Day 1: `(10, 1)`.
  - Day 2: pops `(10, 1)`, span becomes $1 + 1 = 2$. Stack gets `(10, 2)`.
  - Day 3: pops `(10, 2)`, span becomes $1 + 2 = 3$.
  - Output is `[1, 2, 3, 4]`.
- Dip and recovery: `[50, 40, 30, 20, 60]`. Days 2..4 stay on stack with span 1 each. At 60, all four are popped and summed: $1 + 1 + 1 + 1 + 1 = 5$.

## Follow-ups

- How to adapt this to an online streaming interface (`next(int price)`)?
  The stateful stack is kept as a class member variable; each call to `next(price)` executes the exact same loop and returns `span` directly.
- What if we need the stock span looking forward instead of backward?
  Iterate from right to left using the identical monotonic stack logic.
- Can we store indices instead of spans?
  Yes, store the index $i$. Then `span = i - st.top()`, where `st` stores indices of elements strictly greater than current price.

## Common mistakes

- Using `<` instead of `<=` in `st.top().first <= p`, failing to absorb identical consecutive prices.
- Iterating backward through the raw array for each query rather than popping and aggregating spans.
- Forgetting to initialize `span = 1`, omitting the current day itself.
