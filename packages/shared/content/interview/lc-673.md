## Clarify first

- What should be returned? The **number** of different longest strictly increasing subsequences, not just the length.
- When are two subsequences considered different? When they use different sets of indices from `nums` (even if they contain identical values).
- What if the longest increasing subsequence has length 1? Every element is its own subsequence of length 1, so the answer is `nums.length`.
- What are the input constraints? `nums.length` is between 1 and 2,000, and values range between -1,000,000 and 1,000,000.

## Examples to say out loud

- Multiple LIS paths: `nums = [1, 3, 5, 4, 7]`.
  - Longest length is 4.
  - The two distinct subsequences of length 4 are `[1, 3, 5, 7]` and `[1, 3, 4, 7]`.
  - Output is 2.
- Identical elements: `nums = [2, 2, 2, 2, 2]`.
  - Longest length is 1.
  - There are 5 separate single-element subsequences. Output is 5.
- Strictly increasing: `nums = [1, 2, 3]`. Length is 3, exactly 1 way: `[1]`.

## Brute force

A brute-force solution generates all `2^n` subsequences, filters those that are strictly increasing, determines the maximum length among them, and counts how many reach that maximum length. For `n = 2,000`, this takes `O(2^n)` exponential time, which is completely unfeasible.

## The key observation

To count the number of longest increasing subsequences, we need to track two values for each index `i`:
1. `len[i]`: the length of the longest increasing subsequence ending at index `i`.
2. `cnt[i]`: the number of different increasing subsequences of length `len[i]` ending at index `i`.
For each earlier element `j < i` where `nums[j] < nums[i]`:
- If `len[j] + 1 > len[i]`: we found a strictly longer subsequence! Update `len[i] = len[j] + 1` and reset `cnt[i] = cnt[j]`.
- If `len[j] + 1 == len[i]`: we found another way to achieve the current maximum length! Accumulate `cnt[i] += cnt[j]`.
At the end, sum `cnt[i]` across all indices `i` where `len[i] == max(len)`.

## Optimal approach

1. Let `n = nums.length`. If `n <= 1`, return `n`.
2. Allocate arrays `len` and `cnt` of size `n`, both initialized to 1.
3. Track `best = 1` for the global maximum LIS length.
4. For `i` from 0 to `n - 1`:
   - For `j` from 0 to `i - 1`:
     - If `nums[j] < nums[i]`:
       - If `len[j] + 1 > len[i]`:
         - `len[i] = len[j] + 1`.
         - `cnt[i] = cnt[j]`.
       - Else if `len[j] + 1 == len[i]`:
         - `cnt[i] += cnt[j]`.
   - Update `best = max(best, len[i])`.
5. Sum `cnt[i]` for all `i` where `len[i] == best`.
6. Return the total count.

Complexity:
- Time: `O(n^2)` because we use two nested loops comparing all pairs `(j, i)` for `j < i`. For `n = 2,000`, `2 \times 10^6` operations takes under 10 milliseconds.
- Space: `O(n)` auxiliary space to maintain the `len` and `cnt` arrays of size `n`.

## Code walkthrough

In the reference implementation:
- `vector<int> len(n, 1), cnt(n, 1);`: initializes every single element as an LIS of length 1 with frequency 1.
- `if (nums[j] >= nums[i]) continue;`: ignores non-increasing predecessors.
- `if (len[j] + 1 > len[i]) { len[i] = len[j] + 1; cnt[i] = cnt[j]; }`: overwrites length and adopts predecessor count when a longer chain is formed.
- `else if (len[j] + 1 == len[i]) cnt[i] += cnt[j];`: merges parallel paths of equal maximal length.
- `for (int i = 0; i < n; i++) if (len[i] == best) ans += cnt[i];`: sums all combinations achieving the peak LIS length.

## Test it out loud

- `nums = [1, 3, 5, 4, 7]`:
  - `i = 0 (1)`: `len = 1, cnt = 1`.
  - `i = 1 (3)`: from 1 -> `len = 2, cnt = 1`.
  - `i = 2 (5)`: from 3 -> `len = 3, cnt = 1`.
  - `i = 3 (4)`: from 3 -> `len = 3, cnt = 1`.
  - `i = 4 (7)`:
    - From 5: `len = 3 + 1 = 4`, `cnt = 1`.
    - From 4: `len = 3 + 1 = 4 == len[4]`, so `cnt[4] += cnt[3] (1) = 2`.
  - Max length is 4, count is `cnt[4] = 2`.
- `nums = [2, 2, 2]`: `best = 1`. All 3 indices have `len = 1, cnt = 1`. Total sum = 3.

## Follow-ups

- Can this be solved in `O(n log n)` time?
  Yes, using a Fenwick Tree or Segment Tree storing `(max_len, count)` pairs keyed by coordinate-compressed values.
- What if we also need to output all the actual subsequences?
  Backtrack recursively through predecessor indices where `len[j] + 1 == len[i]` and `nums[j] < nums[i]`.

## Common mistakes

- Resetting `cnt[i] = 1` instead of `cnt[i] = cnt[j]` when a strictly longer subsequence is found, which loses all combinatorial ways from the previous branch.
- Forgetting to initialize `cnt` with 1s, which leads to 0 combinations for standalone single elements.
- Summing `cnt` at the end without filtering for `len[i] == best`.
