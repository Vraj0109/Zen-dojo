## Clarify first

- What defines the alarm condition? If a node is robbed, neither its direct parent nor any of its direct children can be robbed.
- Are node values non-negative? Yes, constraints specify node values are between 0 and 10,000.
- Can we skip both a parent and a child to rob grandchildren? Yes, skipping a node places no restriction on child nodes; each child can independently be robbed or skipped.
- What are the tree size bounds? Between 1 and 10,000 nodes.

## Examples to say out loud

- Example with root robbed: `root = [3, 2, 3, null, 3, null, 1]`.
  - If we rob root 3, we cannot rob children 2 and 3; we can rob grandchildren 3 and 1. Total = `3 + 3 + 1 = 7`.
  - If we skip root 3, we can rob children 2 and 3, getting `2 + 3 = 5`.
  - Maximum stolen amount is 7.
- Example with children robbed: `root = [3, 4, 5, 1, 3, null, 1]`.
  - Rob root: `3 + 1 + 3 + 1 = 8`.
  - Skip root, rob children: `4 + 5 = 9`.
  - Maximum stolen amount is 9.
- Single node: `root = [1]`. Rob root, returns 1.

## Brute force

A naive recursive approach defines `rob(root)` which computes two options: robbing `root` (adding root's value plus recursive calls on the four grandchildren) versus skipping `root` (recursive calls on the two children). Because subtrees are recomputed repeatedly across overlapping branches, this recursion runs in `O(2^n)` exponential time, which times out even on moderately sized trees.

## The key observation

For any subtree rooted at node `u`, there are only two states we need to return to its parent: `robbed` (the best total if `u` is robbed) and `skipped` (the best total if `u` is not robbed). If `u` is robbed, both children must be skipped: `robbed = u.val + left.skipped + right.skipped`. If `u` is skipped, each child can be independently robbed or skipped: `skipped = max(left.robbed, left.skipped) + max(right.robbed, right.skipped)`.

## Optimal approach

1. Define a helper function `go(node)` that returns a pair `(robbed, skipped)`.
2. Base case: If `node == null`, return `(0, 0)`.
3. Recursively compute post-order values for the children:
   - `l = go(node.left)`
   - `r = go(node.right)`
4. Compute the two outcomes for the current node:
   - `robbed = node.val + l.skipped + r.skipped`
   - `skipped = max(l.robbed, l.skipped) + max(r.robbed, r.skipped)`
5. Return the pair `(robbed, skipped)`.
6. From the main function, call `p = go(root)` and return `max(p.robbed, p.skipped)`.

Complexity:
- Time: `O(n)` because every node is visited once in post-order.
- Space: `O(h)` call stack memory, where `h` is tree height (`O(log n)` balanced, `O(n)` skewed).

## Code walkthrough

In the reference implementation:
- `pair<int, int> go(TreeNode* n)`: computes optimal totals for robbing or skipping subtree `n`.
- `if (!n) return {0, 0};`: base case for leaf boundaries.
- `auto l = go(n->left), r = go(n->right);`: gathers bottom-up child state pairs.
- `int robbed = n->val + l.second + r.second;`: enforces the rule that robbing `n` prohibits robbing children.
- `int skipped = max(l.first, l.second) + max(r.first, r.second);`: frees children to choose their own best local decision.
- `return max(p.first, p.second);`: picks the superior choice at the root level.

## Test it out loud

- `root = [1]`:
  - `l = (0, 0), r = (0, 0)`.
  - `robbed = 1 + 0 + 0 = 1`, `skipped = 0 + 0 = 0`.
  - Returns `max(1, 0) = 1`.
- `root = [2, 1, 3]`:
  - Left child 1: `(1, 0)`.
  - Right child 3: `(3, 0)`.
  - Root 2:
    - `robbed = 2 + 0 + 0 = 2`.
    - `skipped = max(1, 0) + max(3, 0) = 4`.
  - Returns `max(2, 4) = 4`.

## Follow-ups

- How does this generalize to an n-ary tree?
  Sum `child.skipped` across all children for `robbed`, and sum `max(child.robbed, child.skipped)` for `skipped`.
- What if houses are arranged in a line (House Robber I) or circle (House Robber II)?
  House Robber I uses 1D DP `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])`. House Robber II runs that DP twice (excluding first vs excluding last element).

## Common mistakes

- Assuming that skipping a parent forces both children to be robbed, rather than allowing children to choose `max(robbed, skipped)`.
- Using memoization on raw pointers without custom hash functions or causing memory bloat instead of returning a pair bottom-up.
- Forgetting that an empty tree yields 0.
