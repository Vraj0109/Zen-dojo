## Clarify first
- How are coordinates assigned to tree nodes? The root is at `(row = 0, col = 0)`. A left child of `(r, c)` is at `(r + 1, c - 1)` and a right child is at `(r + 1, c + 1)`.
- In what order should the output columns and values appear? Columns must be ordered strictly from leftmost (smallest `col`) to rightmost (largest `col`).
- How are ties handled within the same column? Nodes are ordered primarily by `row` ascending (from top to bottom). If two nodes share both the same `col` and same `row`, they must be ordered by their node values in ascending order.
- Can values be duplicate? Constraints state node values range from 0 to 1000.

## Examples to say out loud
- Consider tree `[3, 9, 20, null, null, 15, 7]`:
  - `3` is at `(0, 0)`.
  - `9` is at `(1, -1)`.
  - `20` is at `(1, 1)`.
  - `15` is at `(2, 0)`.
  - `7` is at `(2, 2)`.
  - Column -1: `[9]`.
  - Column 0: `[3, 15]` (row 0 before row 2).
  - Column 1: `[20]`.
  - Column 2: `[7]`.
  - Result: `[[9], [3, 15], [20], [7]]`.
- Overlapping nodes: Tree `[1, 2, 3, 4, 5, 6, 7]`.
  - Node 5 is right child of 2: row 2, col 0.
  - Node 6 is left child of 3: row 2, col 0.
  - Both share `(2, 0)`. Since `5 < 6`, 5 precedes 6 in column 0.

## Brute force
A brute force approach traverses the tree using BFS or DFS, collecting nodes into a hash map mapping `col -> map<row, multiset<int>>`. After traversal, it extracts all distinct column keys, sorts them, and within each column iterates through the sorted row keys and flattens the sorted node values. This takes O(n log n) time and O(n) space. Storing tuples directly and sorting once achieves the same clean guarantee with minimal overhead.

## The key observation
Every node can be uniquely represented as a tuple `(col, row, val)`.
If we collect this tuple for every node across the entire tree and sort the tuples in standard lexicographical order:
1. Tuples sort primarily by `col` ascending (leftmost column first).
2. For matching `col`, they sort by `row` ascending (topmost row first).
3. For matching `col` and `row`, they sort by `val` ascending (smaller value first).
After sorting, we simply iterate through the sorted list and group values into sub-arrays whenever `col` changes.

## Optimal approach
1. Initialize an empty list of tuples `items`.
2. Perform a DFS (or BFS) traversal starting at the root with `row = 0, col = 0`.
   - If the current node is null, return.
   - Push `{col, row, node->val}` into `items`.
   - Recurse on `node->left` with `(row + 1, col - 1)`.
   - Recurse on `node->right` with `(row + 1, col + 1)`.
3. Sort `items` in ascending lexicographical order.
4. Iterate through `items`:
   - Whenever `col` differs from the previous column, create a new sublist in the output.
   - Append `val` to the current column's sublist.
5. Return the grouped list of columns.

Complexity:
- Time complexity: O(n log n) where n is the number of nodes, dominated by sorting the n tuples. The DFS visits each node in O(n) time.
- Space complexity: O(n) auxiliary space to store the n tuples in `items` and recursion stack depth O(h).

## Code walkthrough
- `dfs(root, 0, 0)`: Recursively visits every node, recording `{col, row, val}`.
- `sort(items.begin(), items.end())`: Enforces column order, vertical row order, and value tie-breaking simultaneously.
- `for (auto& [c, r, v] : items)`: Scans the sorted sequence, appending a new vector whenever `c != prev`, then pushing `v` to the back.
- Returns `out`.

## Test it out loud
- Test single node `[1]`:
  - `items = [(0, 0, 1)]`. Sorted is identical. Output `[[1]]`.
- Test `[1, 2]`:
  - `1` at `(0, 0)`. `2` at `(1, -1)`.
  - `items` sorted: `(-1, 1, 2)`, `(0, 0, 1)`.
  - Output: `[[2], [1]]`. Matches expected leftmost-first order.

## Follow-ups
- How does this problem differ from binary tree vertical order traversal without tie-breaking? In standard vertical order traversal, level-order BFS naturally preserves row order, so values at the same `(row, col)` appear in left-to-right insertion order without needing value sorting.
- Can we achieve O(n) time if values within the same cell do not need sorting? Yes, BFS with a min/max column index allows grouping directly into an array of columns without sorting.

## Common mistakes
- Grouping by `col` and assuming standard BFS guarantees value-based tie-breaking for nodes sharing the same row and column.
- Putting `row` before `col` in the tuple, which sorts by levels rather than vertical columns.
- Forgetting to handle negative column coordinates correctly when using array indexing.
