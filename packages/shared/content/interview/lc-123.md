## Clarify first
- How many transactions are allowed? At most two transactions, where each transaction consists of one buy followed by one sell.
- Can we hold multiple shares simultaneously? No, you cannot engage in multiple transactions at once; you must sell your current share before buying again.
- Can we buy and sell on the same day? Yes, though doing so produces zero net profit.
- What if no profit is possible (e.g. monotonically decreasing prices)? Return 0.

## Examples to say out loud
- Consider `prices = [3, 3, 5, 0, 0, 3, 1, 4]`:
  - Transaction 1: Buy on day 3 at price 0, sell on day 5 at price 3 (profit = 3).
  - Transaction 2: Buy on day 6 at price 1, sell on day 7 at price 4 (profit = 3).
  - Total profit: `3 + 3 = 6`.
- Monotonically increasing: `[1, 2, 3, 4, 5]`:
  - Buy at 1, sell at 5 produces 4. Output: 4.
- Monotonically decreasing: `[7, 6, 4, 3, 1]`:
  - No profitable trades. Output: 0.

## Brute force
A brute force approach splits the days at index `i` from 0 to `n - 1`. It computes the maximum profit from at most one transaction on `prices[0..i]`, computes the maximum profit from at most one transaction on `prices[i..n-1]`, and sums them, taking the maximum over all split days `i`. Using prefix and suffix profit arrays takes O(n) time and O(n) space. However, state-machine DP solves it in a single pass with O(1) auxiliary space.

## The key observation
At any given day, an investor is in one of four distinct states:
1. `buy1`: currently holding the first stock (maximizing balance after buying 1st share).
2. `sell1`: completed the first transaction and holding cash (maximizing profit after selling 1st share).
3. `buy2`: currently holding the second stock (maximizing balance after buying 2nd share using proceeds from 1st sell).
4. `sell2`: completed both transactions and holding cash (maximizing cumulative profit after selling 2nd share).
For each incoming stock price `p`, all four states transition greedily based on the previous states.

## Optimal approach
1. Initialize states:
   - `buy1 = INT_MIN / 2` (cannot hold before first buy)
   - `sell1 = 0` (no profit before first sell)
   - `buy2 = INT_MIN / 2` (cannot hold second before first sell)
   - `sell2 = 0` (no profit before second sell)
2. Iterate through each price `p` in `prices`:
   - `buy1 = max(buy1, -p)` (either keep previous hold or buy 1st share at price `p`)
   - `sell1 = max(sell1, buy1 + p)` (either keep previous profit or sell 1st share at price `p`)
   - `buy2 = max(buy2, sell1 - p)` (either keep previous hold or buy 2nd share using profit from `sell1`)
   - `sell2 = max(sell2, buy2 + p)` (either keep previous profit or sell 2nd share at price `p`)
3. Return `sell2`.

Complexity:
- Time complexity: O(n) where n is the number of days, processing each price in a single pass with O(1) updates.
- Space complexity: O(1) auxiliary space as only four integer variables are maintained.

## Code walkthrough
- `int buy1 = INT_MIN / 2, sell1 = 0, buy2 = INT_MIN / 2, sell2 = 0`: Safe initialization preventing integer overflow.
- `buy1 = max(buy1, -p)`: Tracks lowest effective purchase price for the first transaction.
- `sell1 = max(sell1, buy1 + p)`: Tracks maximum profit achievable with at most one transaction.
- `buy2 = max(buy2, sell1 - p)`: Reinvests gains from the first transaction into buying the second share.
- `sell2 = max(sell2, buy2 + p)`: Captures the global maximum profit with at most two transactions.
- Returns `sell2`.

## Test it out loud
- Test `prices = [1, 2]`:
  - At `p = 1`: `buy1 = -1`, `sell1 = 0`, `buy2 = -1`, `sell2 = 0`.
  - At `p = 2`:
    - `buy1 = max(-1, -2) = -1`.
    - `sell1 = max(0, -1 + 2) = 1`.
    - `buy2 = max(-1, 1 - 2) = -1`.
    - `sell2 = max(0, -1 + 2) = 1`.
  - Returns 1. Correct.
- Test `prices = [2, 1]`:
  - `sell2` remains 0. Returns 0. Correct.

## Follow-ups
- How does this generalize to k transactions (Best Time to Buy and Sell Stock IV)? Maintain arrays `buy[k + 1]` and `sell[k + 1]` updated in a nested loop in O(n * k) time.
- Why is it valid to update `buy1`, `sell1`, `buy2`, and `sell2` in the same loop using the same day's price? Buying and selling on the same day yields net zero gain (`sell1 - p + p = sell1`), so same-day chaining collapses harmlessly to fewer transactions.

## Common mistakes
- Initializing `buy1` and `buy2` to 0 instead of negative infinity, which falsely suggests holding stock at 0 cost before purchasing.
- Using 32-bit `INT_MIN` directly, leading to underflow on `-p`.
- Trying to run two separate maximum subarray passes that can overlap incorrectly.
