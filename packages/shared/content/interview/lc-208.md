## Clarify first

- What characters do words and prefixes consist of? (Only lowercase English letters `'a'` through `'z'`).
- What operations must be supported? (`insert(word)`, `search(word)`, and `startsWith(prefix)`).
- What is the difference between `search` and `startsWith`? (`search` returns `true` only if the exact string was previously inserted as a complete word; `startsWith` returns `true` if any previously inserted word begins with this prefix).
- What are the length and operation count limits? (Length of `word` and `prefix` $\le 2000$; at most $100,000$ operations in total).
- Can duplicate insertions occur? (Yes, inserting an already existing word is idempotent).

## Examples to say out loud

- Differentiation between full word and prefix:
  - `insert("apple")`
  - `search("apple")` $\implies$ `true`
  - `search("app")` $\implies$ `false` (prefix exists, but not marked as a completed word)
  - `startsWith("app")` $\implies$ `true`
  - `insert("app")`
  - `search("app")` $\implies$ `true`

## Brute force

A naive implementation stores all inserted words in a hash set or array list. While `insert` and exact `search` take $O(L)$ time with a hash set, `startsWith(prefix)` would require iterating over all stored words and checking `word.startsWith(prefix)` in $O(N \cdot L)$ time. Across $10^5$ operations, this results in Time Limit Exceeded.

## The key observation

Words sharing common prefixes can share the same initial sequence of tree edges. In a Trie (prefix tree), each node represents a prefix and branches into up to 26 child nodes for letters `'a'` through `'z'`. A boolean flag `endsHere` at each node denotes whether a complete word finishes at that node.
- Both `search` and `startsWith` walk down the tree following matching characters in $O(L)$ time.
- If we hit a null branch, the prefix does not exist.
- If we reach the end of the query string at node $u$, `startsWith` returns `true` unconditionally, whereas `search` returns `u->endsHere`.

## Optimal approach

1. Define a `Node` structure:
   - An array or map of children: `Node* next[26] = {}`.
   - A boolean flag `endsHere = false`.
2. Maintain a root node `root = new Node()`.
3. Helper `walk(s)`:
   - Start with `cur = root`.
   - For each character `ch` in `s`:
     - Look up child `ch - 'a'`. If null, return `nullptr`.
     - Advance `cur = cur->next[ch - 'a']`.
   - Return `cur`.
4. Operation `insert(word)`:
   - Walk from `root`. For each character `ch`:
     - If `cur->next[ch - 'a']` does not exist, instantiate a new `Node()`.
     - Advance `cur = cur->next[ch - 'a']`.
   - Set `cur->endsHere = true`.
5. Operation `search(word)`:
   - Call `n = walk(word)`.
   - Return `n != nullptr && n->endsHere`.
6. Operation `startsWith(prefix)`:
   - Return `walk(prefix) != nullptr`.

Complexity:
- Time: $O(L)$ for each `insert`, `search`, and `startsWith` call, where $L$ is the length of the input word or prefix.
- Space: $O(N \cdot L \cdot \Sigma)$ worst-case total space where $N$ is the number of words, $L$ is the average word length, and $\Sigma = 26$ is the alphabet size.

## Code walkthrough

In the reference implementation:
- `Node* next[26] = {};`: fixed-size pointer array allows $O(1)$ child branch transitions.
- `bool endsHere = false;`: distinguishes intermediate prefix nodes from actual inserted words.
- `Node* walk(const string& s)`: unified traversal routine used by both `search` and `startsWith`.
- `insert`: instantiates missing nodes on demand and sets `cur->endsHere = true` at the final character.
- `search(word)`: verifies both path existence and the terminal word flag.

## Test it out loud

- Empty query / non-existent prefix: `search("a")` or `startsWith("a")` on an empty trie. `root->next[0]` is null, `walk` returns `nullptr`, returns `false`.
- Overlapping prefixes: Insert `"car"`, `"cart"`, `"cat"`.
  - `"car"` and `"cart"` share path `c -> a -> r`.
  - Node at `'r'` has `endsHere = true`, and also has child `'t'` with `endsHere = true`.
  - `search("car")` $\implies true$, `search("ca")` $\implies false$, `startsWith("ca")` $\implies true$.

## Follow-ups

- What if the alphabet includes Unicode or arbitrary symbols?
  Replace the fixed 26-element array with an `std::unordered_map<char, Node*>` to save memory on sparse branching.
- How to implement word deletion in a Trie?
  Recursively walk to the word, unset `endsHere = false`, and prune child nodes backwards if they have no other children and are not marked `endsHere`.
- What is a Radix Tree / Compact Trie?
  It compresses chains of single-child nodes into edge strings (e.g., edge `"appl"` instead of 4 separate nodes), significantly reducing memory usage.

## Common mistakes

- Conflating `search` and `startsWith`: forgetting to check `endsHere` in `search`, causing prefixes to return `true` as if they were full words.
- Memory leaks: failing to free allocated nodes in a destructor when dynamically allocating `new Node()`.
- Index arithmetic bugs: forgetting `- 'a'` when indexing into `next[26]`.
