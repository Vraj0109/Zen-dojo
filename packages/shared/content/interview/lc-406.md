## Clarify first
- What do the pairs `[h, k]` represent? `h` is the person's height, and `k` is the exact number of people in front of them with height greater than or equal to `h`.
- Is the reconstructed queue guaranteed to exist and be unique? Yes, constraints guarantee a valid and unique queue configuration.
- Can heights or k values be duplicate? Multiple people can have the same height, but each `[h, k]` combination in the original queue is distinct.
- What are the input size bounds? Array length is up to 2000, and heights can reach 1,000,000.

## Examples to say out loud
- Consider `people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]`.
  - Sort by height descending; on tie, sort by k ascending:
    `[7,0], [7,1], [6,1], [5,0], [5,2], [4,4]`.
  - Insert one by one at index `k`:
    - Insert `[7,0]` at 0: `[[7,0]]`
    - Insert `[7,1]` at 1: `[[7,0], [7,1]]`
    - Insert `[6,1]` at 1: `[[7,0], [6,1], [7,1]]`
    - Insert `[5,0]` at 0: `[[5,0], [7,0], [6,1], [7,1]]`
    - Insert `[5,2]` at 2: `[[5,0], [7,0], [5,2], [6,1], [7,1]]`
    - Insert `[4,4]` at 4: `[[5,0], [7,0], [5,2], [6,1], [4,4], [7,1]]`
  - Result matches the target order.

## Brute force
A brute force approach checks all `n!` permutations of the queue and validates whether each person satisfies their `[h, k]` condition. For n up to 2000, `n!` is astronomical. Even a backtracking construction trying to place valid people into empty slots requires exponential time without ordering insight.

## The key observation
Shorter people do not affect the `k` requirement of taller people, because only people with height `>= h` contribute to `k`. Therefore, if we place people in descending order of height:
1. Every person already in the reconstructed queue is taller than (or equal in height to) the current person being inserted.
2. Inserting the current person `[h, k]` at position `k` ensures exactly `k` taller people precede them.
3. Any subsequent person inserted will be shorter, so their insertion into the queue will never disrupt the count for any taller person already placed.
Ties in height must be sorted by `k` ascending, so a person needing fewer taller people ahead is placed before one needing more.

## Optimal approach
1. Sort the `people` array using a custom comparator:
   - Primary: height `h` descending (`a[0] > b[0]`).
   - Secondary: count `k` ascending (`a[1] < b[1]`).
2. Initialize an empty result list `out`.
3. Iterate through each person `p = [h, k]` in sorted order:
   - Insert `p` into `out` at index `p[1]`.
4. Return `out`.

Complexity:
- Time complexity: O(n^2). Sorting takes O(n log n), and inserting `n` elements into an array list takes O(n) per insertion, summing to O(n^2).
- Space complexity: O(n) auxiliary space to store the reconstructed output list.

## Code walkthrough
- `sort(people.begin(), people.end(), ...)`: Sorts descending on height `a[0] > b[0]`, breaking ties with ascending k `a[1] < b[1]`.
- `vector<vector<int>> out`: Dynamic array holding the progressively built queue.
- `out.insert(out.begin() + p[1], p)`: Inserts each person at index `k`. Because all currently existing elements are `>= h`, placing `p` at index `p[1]` guarantees exactly `p[1]` taller or equal people are ahead.
- Returns `out`.

## Test it out loud
- Test `[[2,1],[3,0]]`:
  - Sorted: `[3,0], [2,1]`.
  - Insert `[3,0]` at 0: `[[3,0]]`.
  - Insert `[2,1]` at 1: `[[3,0], [2,1]]`.
  - Person `[2,1]` sees 1 person of height >= 2 (`[3,0]`). Correct.
- Test `[[3,1],[3,0]]`:
  - Sorted: `[3,0], [3,1]`.
  - Insert `[3,0]` at 0: `[[3,0]]`.
  - Insert `[3,1]` at 1: `[[3,0], [3,1]]`.
  - Both conditions satisfied. Correct.

## Follow-ups
- How could we improve this to O(n log n) time? By using a Fenwick tree (Binary Indexed Tree) or segment tree over available empty slots in an array of size n, sorting by height ascending, and querying the k-th empty position in O(log n).
- What if multiple people have identical `h` and `k`? The problem statement guarantees a valid unique queue, meaning `[h, k]` pairs are distinct.

## Common mistakes
- Sorting ties with `k` descending, which places higher `k` values first and corrupts the relative position between equal-height individuals.
- Trying to place people from shortest to tallest without a segment tree, which requires scanning for unoccupied slots in O(n^2) without simplifying the list logic.
