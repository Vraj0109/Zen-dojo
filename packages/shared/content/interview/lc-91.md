## Clarify first

- Can a decoding contain numbers with leading zeros like `"06"`? No, `"06"` is invalid because `'0'` does not map to any letter (mappings are `1 = 'A'` through `26 = 'Z'`).
- What should be returned if the entire string cannot be validly decoded (e.g. starts with `'0'`)? Return 0.
- What if the string is empty? Constraints specify `1 <= s.length <= 100`.
- Are there any characters besides digits? Constraints state `s` consists strictly of numeric digits.

## Examples to say out loud

- Two valid segmentations: `s = "12"`.
  - Can be decoded as `"AB"` (1, 2) or `"L"` (12). Total ways = 2.
- Ambiguous multi-digit message: `s = "226"`.
  - Can be decoded as `"BZ"` (2, 26), `"VF"` (22, 6), or `"BBF"` (2, 2, 6). Total ways = 3.
- Leading zero: `s = "06"`. Starts with `'0'`, which cannot map to any letter. Returns 0.
- Trapped zero: `s = "10"`. `'0'` cannot stand alone; it must pair with `'1'` to make 10 (`'J'`). Total ways = 1.

## Brute force

A brute-force recursive solution branches at each index `i`: try decoding 1 digit if `s[i] != '0'`, and try decoding 2 digits if `s[i..i+1]` forms an integer between 10 and 26. Since each position can branch twice, the recursion tree has height `n`, taking `O(2^n)` exponential time. For `n = 100`, this generates `2^{100}` calls and times out immediately.

## The key observation

The number of ways to decode a prefix of length `i` depends strictly on the two preceding prefix lengths:
1. Single digit: If `s[i - 1] != '0'`, we can decode `s[i - 1]` as an individual letter, inheriting `dp[i - 1]` ways.
2. Two digits: If the two-digit substring `s[i - 2..i - 1]` forms a value between 10 and 26, we can decode it as a single letter, inheriting `dp[i - 2]` ways.
This mirrors the Fibonacci recurrence with conditional validity gates. Since `dp[i]` only depends on `dp[i - 1]` and `dp[i - 2]`, we can optimize space to `O(1)` using two rolling variables.

## Optimal approach

1. Let `n = s.length()`.
2. If `s[0] == '0'`, return 0 immediately.
3. Initialize `prev2 = 1` (ways for an empty string) and `prev1 = 1` (ways for the first character).
4. Iterate `i` from 2 to `n`:
   a. Initialize `cur = 0`.
   b. Check 1-digit option: If `s[i - 1] != '0'`, add `prev1` to `cur`.
   c. Check 2-digit option: Let `two = (s[i - 2] - '0') * 10 + (s[i - 1] - '0')`. If `two >= 10 && two <= 26`, add `prev2` to `cur`.
   d. Advance the sliding window: `prev2 = prev1`, `prev1 = cur`.
5. Return `prev1`.

Complexity:
- Time: `O(n)` because we iterate through the string of length `n` once, evaluating constant-time arithmetic per character.
- Space: `O(1)` auxiliary space as we only maintain three scalar integer variables.

## Code walkthrough

In the reference implementation:
- `long long prev2 = 1, prev1 = (s[0] == '0') ? 0 : 1;`: sets base states for length 0 and length 1 prefixes.
- `if (s[i - 1] != '0') cur += prev1;`: absorbs valid single-digit decodings (1 through 9).
- `int two = (s[i - 2] - '0') * 10 + (s[i - 1] - '0');`: parses the 2-digit candidate substring.
- `if (two >= 10 && two <= 26) cur += prev2;`: absorbs valid double-digit decodings between 10 and 26.
- `prev2 = prev1; prev1 = cur;`: rolls the two-step state window forward.
- `return (int)prev1;`: outputs the count of valid decodings.

## Test it out loud

- `s = "12"`:
  - Start: `prev2 = 1, prev1 = 1`.
  - `i = 2`: `s[1] = '2' != '0'` -> `cur += prev1 (1)`. Two digits `"12"` is in `10..26` -> `cur += prev2 (1)`. `cur = 2`.
  - Result: 2.
- `s = "10"`:
  - Start: `prev2 = 1, prev1 = 1`.
  - `i = 2`: `s[1] = '0'` (single digit invalid, add 0). Two digits `"10"` is in `10..26` -> `cur += prev2 (1) = 1`.
  - Result: 1.
- `s = "30"`:
  - `i = 2`: `s[1] = '0'` (invalid single), `"30" > 26` (invalid pair) -> `cur = 0`.
  - Result: 0.

## Follow-ups

- What if `'*'` can represent any digit from 1 to 9 (Decode Ways II, LeetCode 639)?
  Multiply transitions by the number of valid interpretations (e.g. `'*'` alone has 9 choices, `1*` has 9 choices, `2*` has 6 choices) under modulo `10^9 + 7`.
- What if we also need to generate all valid decoded strings?
  Use backtracking with the same validation rules; worst-case output size is `O(2^n)`.

## Common mistakes

- Treating `'0'` as a valid single-digit decoding, which maps to no letter.
- Allowing numbers like `"05"` to be parsed as a 2-digit number (must check `two >= 10`).
- Allocating an `O(n)` array when two scalar variables suffice.
