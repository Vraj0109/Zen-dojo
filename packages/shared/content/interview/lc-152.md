## Clarify first

- Can the array contain zeros? Yes, zeros reset the running product, since any subarray spanning across zero has product 0.
- Can numbers be negative? Yes, values range from -10 to 10.
- Can the optimal subarray be a single element? Yes, the problem requires a non-empty contiguous subarray.
- Will any product overflow standard 32-bit integers? The constraints guarantee the product of any subarray fits in a 32-bit signed integer.

## Examples to say out loud

- Mixed signs: `nums = [2, 3, -2, 4]`.
  - Subarray `[2, 3]` gives product 6.
  - Adding `-2` flips product to `-12`.
  - Max product is 6.
- Double negative flip: `nums = [-2, 3, -4]`.
  - Subarray `[-2]` has product -2.
  - Then 3 gives product 3.
  - Then multiplying `[-2, 3]` by `-4` yields `(-2) * 3 * (-4) = 24`. Max product is 24.
- Array with zero: `nums = [-2, 0, -1]`. Max single element or block is 0.

## Brute force

A brute-force approach computes the product of every contiguous subarray `nums[i..j]` with `0 <= i <= j < n`. By using a nested loop and multiplying running products, there are `n * (n + 1) / 2` pairs, which takes `O(n^2)` time and `O(1)` space. For `n = 20,000`, `n^2` requires `4 \times 10^8` operations, which is prone to timeout in tight interview environments.

## The key observation

Unlike Maximum Subarray (where we only track the maximum running sum), multiplication by a negative number flips signs: a negative number multiplied by a very small (most negative) product becomes a very large positive product. Therefore, at each element `x`, we must maintain both the maximum product `curMax` and the minimum product `curMin` ending at the previous position. The new candidates ending at `x` are `x` alone, `curMax * x`, and `curMin * x`.

## Optimal approach

1. Initialize `curMax = nums[0]`, `curMin = nums[0]`, and `best = nums[0]`.
2. Iterate `i` from 1 to `nums.length - 1`:
   a. Let `x = nums[i]`.
   b. Calculate candidate products using the old states:
      - `a = curMax * x`
      - `b = curMin * x`
   c. Update `curMax = max({x, a, b})`.
   d. Update `curMin = min({x, a, b})`.
   e. Update `best = max(best, curMax)`.
3. Return `best`.

Complexity:
- Time: `O(n)` because we iterate through the array of length `n` once, performing constant-time arithmetic per element.
- Space: `O(1)` auxiliary space since only a few scalar variables are maintained.

## Code walkthrough

In the reference implementation:
- `long long curMax = nums[0], curMin = nums[0], best = nums[0];`: seeds DP states with the first element to handle negative-only arrays.
- `long long a = curMax * x, b = curMin * x;`: caches products before updating variables to avoid using newly mutated states.
- `curMax = max({x, a, b});`: determines the peak positive product terminating at `x`.
- `curMin = min({x, a, b});`: records the most negative product terminating at `x` (ready to be amplified if another negative follows).
- `best = max(best, curMax);`: accumulates the global maximum product.

## Test it out loud

- `nums = [2, -5, -2]`:
  - Start: `curMax = 2, curMin = 2, best = 2`.
  - `x = -5`: `a = 2 * (-5) = -10, b = 2 * (-5) = -10`. `curMax = max(-5, -10) = -5`, `curMin = min(-5, -10) = -10`. `best = 2`.
  - `x = -2`: `a = -5 * (-2) = 10, b = -10 * (-2) = 20`. `curMax = max(-2, 10, 20) = 20`, `curMin = min(-2, 10, 20) = -2`. `best = max(2, 20) = 20`.
  - Output is 20.
- `nums = [-2]`: loop does not execute; returns -2.

## Follow-ups

- What if we need to return the actual subarray slice that produces the maximum product?
  Maintain tracking pointers for the start index of the current positive and negative runs, updating recorded best boundaries whenever `best` is updated.
- What is an alternative two-pass prefix/suffix approach?
  Compute running products from left-to-right and right-to-left, resetting to 1 whenever a 0 is met; the maximum value seen in either direction equals the answer in `O(n)` time and `O(1)` space.

## Common mistakes

- Overwriting `curMax` before computing `curMin`, which mistakenly computes `curMin` using the newly updated `curMax`.
- Forgetting that `x` itself can be the maximum (when previous running products are degraded or zero).
- Initializing `best = 0`, which fails on single negative element arrays like `[-2]`.
