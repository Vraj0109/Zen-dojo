## Clarify first

- What defines a triple booking? (When 3 accepted bookings share at least one common moment in time).
- Are double bookings allowed? (Yes, up to 2 bookings can overlap concurrently).
- Are intervals half-open? (Yes, $[startTime, endTime)$ where the interval ends strictly before $endTime$).
- What should be returned if a booking creates a triple booking? (Return `false` and do NOT store the booking).
- What are the operational bounds? (At most $1,000$ calls to `book`, and timestamps up to $10^9$).

## Examples to say out loud

- Double booking allowed, triple rejected:
  - `book(10, 20)` $\implies$ `true`
  - `book(50, 60)` $\implies$ `true`
  - `book(10, 40)` $\implies$ overlaps `[10, 20)` on `[10, 20)`, creating a double-booked region `[10, 20)`. Returns `true`.
  - `book(5, 15)` $\implies$ overlaps existing double booking `[10, 20)` on `[10, 15)`. This would cause a triple booking, so it is refused; returns `false`.
  - `book(5, 10)` $\implies$ touches 10 without overlap, returns `true`.

## Brute force

A naive simulation tracks a discrete array of counters for every second from 0 to $10^9$. Incrementing timestamps and checking if any timestamp reaches 3 requires $O(10^9)$ space and time, which is impossible.
Alternatively, testing all triplets of intervals takes $O(n^3)$ time, which is too slow.

## The key observation

Two bookings overlap on the intersection $[s, e) = [\max(s_1, s_2), \min(e_1, e_2))$ if and only if $s < e$.
If we maintain:
1. `all`: a list of all accepted single bookings.
2. `doubles`: a list of all intervals where exactly two bookings overlap.
Then a new interval will cause a triple booking if and only if it overlaps with **any interval already in `doubles`**.
If the new booking does NOT overlap with any interval in `doubles`, it is guaranteed safe: we accept it, find its intersections with all existing intervals in `all`, add those intersections to `doubles`, and append the new booking to `all`.

## Optimal approach

1. Maintain two dynamic lists:
   - `vector<pair<int, int>> all`: stores every accepted booking.
   - `vector<pair<int, int>> doubles`: stores ranges shared by two bookings.
2. Operation `book(startTime, endTime)`:
   - First check against `doubles`:
     - For each `[d_s, d_e)` in `doubles`:
       - If $\max(startTime, d_s) < \min(endTime, d_e)$ (i.e. `startTime < d_e && endTime > d_s`):
         - Adding this interval would create a triple booking; return `false`.
   - The booking is safe:
     - For each `[b_s, b_e)` in `all`:
       - Compute intersection: $s = \max(startTime, b_s), e = \min(endTime, b_e)$.
       - If $s < e$, add $\{s, e\}$ to `doubles`.
     - Add $\{startTime, endTime\}$ to `all`.
     - Return `true`.

Complexity:
- Time: $O(n)$ time per `book` call, where $n$ is the number of previously accepted bookings ($n \le 1000$). Checking `doubles` takes $O(|\text{doubles}|) \le O(n)$, and updating `all` takes $O(n)$. Total time for 1000 calls is $O(n^2) \approx 10^6$ operations, executing in under 5 milliseconds.
- Space: $O(n)$ auxiliary space to store at most $n$ intervals in `all` and at most $n$ disjoint double-booked segments in `doubles`.

## Code walkthrough

In the reference implementation:
- `for (auto& d : doubles) if (startTime < d.second && endTime > d.first) return false;`: preemptively checks against all existing double-booked regions.
- `int s = max(startTime, b.first), e = min(endTime, b.second);`: calculates the exact overlap window between two single bookings.
- `if (s < e) doubles.push_back({s, e});`: registers the new double-booked interval for future triple-booking checks.
- `all.push_back({startTime, endTime});`: commits the accepted interval to the primary booking list.

## Test it out loud

- Exact duplicate bookings: `book(1, 5)` returns `true`. Second `book(1, 5)` returns `true` (creating double booking `[1, 5)`). Third `book(1, 5)` overlaps double booking `[1, 5)`, returns `false`.
- Touching endpoints: `book(10, 20)` and `book(20, 30)` share point 20. Point 20 is not included in half-open intervals, so intersection $s < e$ fails ($20 < 20$ is false); no double booking is registered.
- Chain of intervals: Multiple overlapping intervals each produce separate entries in `doubles` without interference.

## Follow-ups

- Can we solve this using a Sweep-Line / Difference Map?
  Yes, use an ordered map `map<int, int> delta`: increment `delta[startTime]++`, decrement `delta[endTime]--`. Iterate through `delta` summing prefix counts; if count exceeds 2, rollback `delta[startTime]--`, `delta[endTime]++` and return `false`. This takes $O(n \log n)$ per call.
- How to generalize to $k$-bookings?
  The difference map approach naturally generalizes to any $k$ by checking `count > k`.
- What if $n$ is up to $10^5$ instead of $1,000$?
  Use a dynamic Segment Tree with lazy propagation, maintaining `max_overlap` across coordinates $[0, 10^9]$ in $O(\log C)$ per booking.

## Common mistakes

- Inserting the interval into `all` or `doubles` before verifying that all double-booking checks pass.
- Using `<=` instead of `<` in `startTime < d.second && endTime > d.first`, treating touching endpoints as overlapping.
- Assuming `doubles` can only have one entry per booking; a single wide booking can intersect multiple existing bookings, creating several entries in `doubles`.
