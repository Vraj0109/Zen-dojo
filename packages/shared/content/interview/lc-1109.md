## Clarify first

- Are flight numbers 1-indexed? Yes, flights are numbered 1 through `n`.
- Are the ranges `[first, last]` inclusive? Yes, every flight from `first` through `last` receives the reservation of `seats`.
- What should be returned? An array of size `n` where index `i` contains the total seats booked on flight `i + 1`.
- What are the constraints on `n` and bookings? `n` is between 1 and 20,000, and `bookings.length` is up to 20,000, with `seats` up to 10,000.

## Examples to say out loud

- Two overlapping bookings: `bookings = [[1, 2, 10], [2, 3, 20]], n = 3`.
  - Booking 1: flights 1 and 2 get 10 seats -> `[10, 10, 0]`.
  - Booking 2: flights 2 and 3 get 20 seats -> `[10, 30, 20]`.
  - Final result: `[10, 30, 20]`.
- Single flight booking: `bookings = [[1, 1, 5]], n = 1`. Result: `[5]`.
- Disjoint bookings: `bookings = [[1, 2, 1], [3, 4, 2]], n = 4`. Result: `[1, 1, 2, 2]`.

## Brute force

A brute-force solution initializes an array of size `n` to zero. For each booking `[first, last, seats]`, loop index `i` from `first - 1` to `last - 1` and add `seats` directly to `ans[i]`. In the worst case where every booking spans all `n` flights, this requires `O(m * n)` operations, where `m = bookings.length`. For `m = 20,000` and `n = 20,000`, this requires `4 \times 10^8` operations, which times out.

## The key observation

Applying a constant addition across a contiguous subsegment `[first, last]` can be converted into two point updates using a difference array: add `+seats` at index `first`, and subtract `-seats` at index `last + 1`. After applying all `m` bookings in `O(1)` time each, taking the prefix sum across the difference array reconstructs the final seat count for all flights in a single `O(n)` linear sweep.

## Optimal approach

1. Allocate a difference array `diff` of size `n + 2` initialized to zero (1-indexed, with padding for `last + 1`).
2. For each booking `[first, last, seats]` in `bookings`:
   a. `diff[first] += seats`.
   b. `diff[last + 1] -= seats`.
3. Allocate output array `ans` of size `n`.
4. Initialize `run = 0`.
5. For `i` from 1 to `n`:
   a. `run += diff[i]`.
   b. `ans[i - 1] = run`.
6. Return `ans`.

Complexity:
- Time: `O(n + m)` where `m` is the number of bookings and `n` is the number of flights. Each booking takes `O(1)` time, and the prefix sum takes `O(n)`.
- Space: `O(n)` auxiliary space for the difference array (or `O(1)` extra space if computed directly in the returned array).

## Code walkthrough

In the reference implementation:
- `vector<int> diff(n + 2, 0), ans(n);`: sets up the difference array and the target result buffer.
- `for (auto& b : bookings) { diff[b[0]] += b[2]; diff[b[1] + 1] -= b[2]; }`: applies boundary delta tags in constant time per reservation.
- `int run = 0;`: maintains running prefix sum representing active booked seats on current flight.
- `for (int i = 1; i <= n; i++) { run += diff[i]; ans[i - 1] = run; }`: folds deltas into total seat allocations.
- `return ans;`: returns the assembled seat count array.

## Test it out loud

- `bookings = [[1, 2, 10], [2, 3, 20]], n = 3`:
  - `diff` size 5:
    - Booking 1: `diff[1] += 10`, `diff[3] -= 10`.
    - Booking 2: `diff[2] += 20`, `diff[4] -= 20`.
  - Prefix scan:
    - `i = 1`: `run = 0 + 10 = 10`, `ans[0] = 10`.
    - `i = 2`: `run = 10 + 20 = 30`, `ans[1] = 30`.
    - `i = 3`: `run = 30 - 10 = 20`, `ans[2] = 20`.
  - Returns `[10, 30, 20]`.

## Follow-ups

- Can we do this in `O(1)` extra space?
  Yes, accumulate `diff` directly inside `ans` (treating `ans` as 0-indexed: `ans[first - 1] += seats`, `if (last < n) ans[last] -= seats`), then run in-place prefix sum.
- What if queries ask for total seats on flight `i` dynamically between updates?
  Use a Binary Indexed Tree (Fenwick Tree) or Segment Tree supporting range update and point query in `O(log n)` time.

## Common mistakes

- Subtracting at `last` instead of `last + 1`, which prematurely drops the booked seats on the last flight of the interval.
- Index out of bounds when `last == n` without allocating sufficient array padding for `last + 1`.
- Performing nested loops over each booking range, causing quadratic runtime.
