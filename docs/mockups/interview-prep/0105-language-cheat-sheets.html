Sort pairs by second value, then first

O(n log n)sortlambda
vector<pair<int,int>> v = {{1, 5}, {2, 3}, {0, 3}};
sort(v.begin(), v.end(), [](auto& a, auto& b) {
    return tie(a.second, a.first) < tie(b.second, b.first);
});

A comparator must be a strict ordering: use < or >, never <= or >=.

TrapComparing with <= can crash std::sort on equal elements.

Binary search: first element not less than x

O(log n)lower_bound
auto it = lower_bound(a.begin(), a.end(), x);
int idx = it - a.begin();          // a.size() when every element is smaller
bool found = it != a.end() && *it == x;

The vector must already be sorted by the same order.

Sort and keep the original positions

O(n log n)argsort
vector<int> idx(n);
iota(idx.begin(), idx.end(), 0);
sort(idx.begin(), idx.end(), [&](int i, int j) { return a[i] < a[j]; });

Min-heap of pairs

C++
priority_queue<pair<int,int>,
  vector<pair<int,int>>,
  greater<>> pq;
pq.push({3, 7});
auto [d, v] = pq.top();
pq.pop();

Default is a max-heap: add greater.

Java
PriorityQueue<int[]> pq =
  new PriorityQueue<>(
    (a, b) -> Integer.compare(a[0], b[0]));
pq.offer(new int[]{3, 7});
int[] top = pq.poll();

Never subtract in a comparator: it can overflow.

Python
import heapq

heapq.heappush(pq, (3, 7))
d, v = heapq.heappop(pq)

Pitfalls, C++

1v.size() - 1 is a huge number when the vector is empty, because size() is unsigned.
2Signed integer overflow is undefined behaviour. Use long long before multiplying.
3vector<bool> is packed; taking a reference to an element does not behave like other vectors.
