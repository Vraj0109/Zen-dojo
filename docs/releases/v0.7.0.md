## Zen Dojo 0.7.0: accounts and cloud sync, solved means tests passed, time limits, a Java playground and an admin portal

Zen Dojo 0.7.0 adds sign-in with GitHub and syncs your progress between devices. A problem now counts as solved when your code passes every test in the app, and the app shows that apart from LeetCode. It also adds a hard time limit for runaway code, a multi-file Java playground, and an admin portal for content.

### Accounts and sync (Plans 0044, 0049, 0050)
- **Sign in with GitHub** from the sidebar. The app still works fully signed out; signing in is only for syncing.
- **Your progress syncs between devices**: solved problems, tasks, settings, notes, saved runs, pack progress, practice and focus history. After you sign in, **Upload this device's progress** (sidebar menu and the Account page) links the device and uploads what you already have. Nothing is deleted.
- Syncing is automatic while a window is open: a change goes up about 5 seconds after you make it, and other devices' changes are checked every 30 seconds and when you return to the window. Only changed rows are sent. Edits made offline upload when you reconnect, and edits to different rows on two devices both survive; if the same row changes on two devices, the later edit wins.
- Your existing database rows are not rewritten. Changes are tracked with SQLite triggers and side tables (`sync_*`). The browser extension pairing key and other secret-looking settings are never uploaded.
- The sync service is a Cloudflare Worker with a D1 database, in `packages/sync-worker`. Sign-in uses short-lived tokens (15 minutes) and refresh tokens that rotate on every use; reusing an old one signs that device out. The Worker rate-limits by address and by account, bans repeat offenders in escalating steps, and caps storage and daily writes per account. The runbook is `docs/sync-security.md`; the design is `docs/sync-design.md`.
- **Account page** (`/profile/account`): your name, devices with "Sign out this device", last synced time, pending changes, Sync now, and Stop syncing this device. The sidebar has a profile menu (Account and devices, Settings, Profile and stats, Admin for admins, Sign out).
- Not synced yet: reading list, stuck list, boss fights, concept progress, pattern notes, streak freezes, weekly reviews, diagrams.

### Solved means every test passed (Plan 0022 follow-up)
- A roadmap problem the judge can run is marked solved only when a run passes every test. The "Mark solved" button no longer gives a first solve for those; re-solves and problems without a judge spec stay manual.
- Marks work like a chat app's ticks: one green tick is solved here, two blue ticks mean also seen on LeetCode, one faint tick means only seen on LeetCode so far.
- The solved totals on `/dsa` count only problems solved here, with a link to count all platforms.
- Each saved run keeps the ids of the tests that failed, not the tests, and shows them when you open the problem.

### Time limit and cancellation (Plan 0042)
- Code that runs past the time limit is stopped at once, including every process it started, and the run reports Time Limit Exceeded with the time taken and the limit. The test that triggered it is highlighted and later tests show "Not run".

### Java playground (Plan 0043)
- LLD and system design pages have a Playground with several Java files in tabs, new and delete file, reset, your work saved in the browser, and a console with output, exit code, time and compiler errors you can click.

### Admin portal (Plan 0045, partly)
- `/admin` is open only to the account listed as admin on the Worker (`ADMIN_USER_IDS`); everyone else gets a 404. It has a dashboard, a problems table with search and filters, and an editor to add or change a problem. Study content pages (`/admin/study`) are not built yet.

### Smaller changes
- Loading skeletons across the main pages (Plan 0047).
- `pnpm test:fast` runs the unit tests without the slow C++ and Java compile suites (about 15 seconds); `pnpm check` still runs everything.
- Four CSES task numbers corrected (Nim Game I 1730, Word Combinations 1731, Exponentiation II 1712, Palindrome Queries 2420); all 136 CSES entries now match cses.fi.

### Things to know
- Sync needs the sign-in service to be reachable. Offline, everything works and changes queue up.
- Open points: the schedule-shift streak decision (Plan 0036), account deletion and export, other sign-in providers, and a phone-friendly account button.
- Back up `data/habit.db` before your first upload. The installer also copies it to `backups/` before a new version first starts.
